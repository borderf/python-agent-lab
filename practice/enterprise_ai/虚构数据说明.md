# DocPilot / ProcureAgent 虚构练习数据

配套[教材第19–28章](../../docs/python-book/教材目录.md)、[项目里程碑](../../docs/python-book/附录E-项目里程碑与交付检查.md)和[项目规格](../../docs/project-practice/项目实践规格.md)。目录提供虚构资料、预期案例和[离线检索基线](retrieval_baseline.py)。W 是里程碑标签；API、持久索引、模型和审批按项目阶段实现。

所有租户、项目、供应商与制度都是编造的教学样例，不作为采购或法律判断依据。不要替换成真实合同、供应商信息或业务凭据提交到公开仓库。

## 从仓库根目录运行参考实验

想把这些单点实验连成项目时，按[从实验到项目交付](../../docs/project-practice/从实验到项目交付.md)启动 API、真实数据库迁移、资料导入与反馈，再运行真实 LangGraph、Qdrant 和 MCP。默认替身用于验证工程行为，真实任务质量需切换模型并人工评测。

- `uv run python -m practice.enterprise_ai.retrieval_baseline` 运行离线字面匹配对照。[真实向量、融合与可选重排](../../docs/python-book/21-混合检索、重排与RAG评测.md)沿用相同数据和评分函数。
- `uv run python -m practice.enterprise_ai.policy_agent --compare --trials 2` 使用教学替身走完工具执行、结果回传和评分。提供 `--model` 后使用本机 Ollama 的原生工具调用。[接入与失败练习](../../docs/python-book/22-ToolCalling与手写AgentLoop.md)
- `uv run python -m pytest tests/test_model_labs.py -q` 验证模型协议、越界参数、证据检查与检索实验。真实任务质量在准备好模型后单独评估。

### 真实模型实验的环境准备

离线实验用仓库的 Python 3.12 和测试依赖即可。运行真实对照时，先在本机启动 Ollama，服务监听 127.0.0.1:11434。若使用桌面版且服务已运行，直接用 `ollama list` 查看已有模型。分别选能生成中文且支持工具调用的聊天模型、适合中文检索的嵌入模型，在 PowerShell 会话设置 `$chatModel` 和 `$embedModel` 为实际标签。开始前记录标签、模型标识、机器和服务版本，先只跑一道题确认资源足够。

检索示例默认直接编码原文。若所选 embedding 的模型说明要求查询和文档使用不同前缀，请分别在 `dense_rank` 的问题编码和来源编码处添加相应前缀，重新计算向量并记录这项变化。首轮只比原始召回；生成式重排需要聊天模型另支持 JSON 输出。

- `uv run python -m practice.enterprise_ai.docpilot_question '本租户预付款比例上限是多少？' --model $chatModel` 用字面检索接真实生成与引用检查；添加 `--embed-model $embedModel` 接入融合检索。
- 连接被拒绝时先看本机服务；HTTP 404 时检查模型标签；输出缺字段、截断或不会调用工具时查看模型能力和对应边界。保留原失败记录，修正配置后再比较。[Ollama 聊天接口](https://docs.ollama.com/api/chat) · [向量接口](https://docs.ollama.com/api/embed)

## 文件

- data/policies.json：当前/旧版制度、另一租户制度、恶意内容测试材料。
- data/projects.json：正常、多异常、资料不足、另一租户项目。
- data/suppliers.json：资格有效、资格过期、资料缺失与另一租户供应商。
- data/retrieval_cases.json：检索与来源隔离种子案例。
- data/review_cases.json：审查、审批、恢复与局部失败场景。

JSON 样例使用 section 引用，无真实 PDF 页码。W05 可用[PDF 导入命令](../../docs/project-practice/从实验到项目交付.md#将文本-pdf-接到同一条链路)解析自己的虚构 PDF，并人工校对页码映射；不能把 JSON 的节号伪装成 PDF 页码。

## 固定约定

- 业务日期默认 2026-10-01，测试时显式传入，不依赖机器当前日期。
- 金额为整数分，百分比为整数百分点，例如 20 表示 20%。
- 制度有效区间为 valid_from <= as_of < valid_to；valid_to=null 表示没有设定截止日期。
- source_id 唯一标识某一来源版本。旧版与新版不能合并成同一个评测 ID。
- 服务端测试身份默认 tenant-a；数据中另有 tenant-b，不能由模型或请求体覆写身份。
- 预付款比例超过有效政策上限、报价超过预算、证书在业务日期前过期分别产生独立风险。
- 预付款或证书缺失返回资料不足，需要复核；不能推断符合要求。
- 示例中 certificate_valid_until 当天仍有效，as_of 超过该日期才算过期。

## 建议练习顺序

1. 用纯函数读取并校验 JSON，针对 P100/P200/P300 写确定性规则检查。
2. 用政策数据回答“当前/历史预付款上限”，记录正确 source_id。
3. 加入 tenant-a 与 tenant-b 的隔离案例，保证后者不进入前者提示。
4. 用 Mock API 暴露项目和供应商，再让工具调用它们。
5. 实现单 Agent 后用同一组数据比较图版与多 Agent 版。

P100 应无预设风险；P200 有三项明确风险；P300 有两项资料缺失。详细标签在 review_cases.json。review_cases 的故障项是测试设计，需自行构造超时、审批或重启，单独读取 JSON 不会自动制造故障。

W07 的离线起点是 11 道有来源开发题、3 道特殊行为题和 4 道有来源留出题。缺省 split 表示开发集。先运行开发集，冻结实现后做留出评测。再请另一人标注新问题与干扰来源，扩展至 20–30 题以上，并保留未调参样例。操作见[离线对照](../../docs/project-practice/评测与故障演练.md#先跑一个离线对照)。

# 先完成初稿，再读反馈

这些是虚构材料的推演，不是经过真实市场或生产验证的建议。

**观察：** legacy与prototype原始完成均为2/3；按预先约定的独立成功定义，分别为2/3和1/3。U2得到提示，不能算独立；U1失败提前结束，较短耗时不能算效率提升。方法顺序只部分交错，任务难度不明，只有3人且存在熟练度差异；既不能证明产品提高效率，也不能推断产品毫无价值。值得优先验证的具体障碍是日期入口与正确版本的来源打开。

**访谈：** U1有最近一次失败的陈述，但缺原始任务记录；U2揭示权限边界；U3是低频、已有替代方案的反例；B1是进入试点的条件，未确认预算或支付。初稿若只摘“愿意试用”，应收窄目标用户并补采购、安全、更新责任和支持时限。下一步可采用相近难度的查证任务、平衡顺序、统一帮助规则，同时记录失败，不只收满意度。

**架构：** mixed为成功2、超时1、拒绝1，不能只保留成功的两条算总体验；baseline与limited各4条成功也不能估计稳定尾延迟。竞争解释包括共享执行器被导入占用、数据库竞争、模型或磁盘抖动，原始材料无法区分。先恢复资源与分段时延记录，再控制导入并发与受理上限，记录对导入吞吐的代价。模块化单体可以作为待验证的保守起点；是否拆分要有独立扩缩容、团队边界或故障隔离证据，不能由四条请求推出。

**正确性：** 可信身份在服务端确定，任务恢复同时验证租户；批准绑定当前版本和载荷，修改即失效。发出效果后结果不明时，先冻结当前动作并按稳定键重放/查询；新动作键可能产生第二次效果。接收方不支持幂等和查询时，需要显式的未知状态与人工对账，不能承诺自动恰好一次。

**账目：** 持续交付贡献为2000−400−200−500=900元/月，按该口径为45%；首月再扣600元导入，剩300元（15%）。这不等于净利润，也不等于现金流：固定工资、税费、获客、退款、回款时间未给出。产品价值和真实付费均未验证，不能把虚构账目用于营收预测。

## 学原理的步骤

1. 先读机制，用自己的话画出“名称/状态/调用/资源”的变化。
2. 遮住实验的断言，逐行预测输出、异常和副作用。
3. 在独立脚本或交互环境运行，比较预测与结果。
4. 阅读反例，再改变一个条件重跑；不要只背当前输出。
5. 回到当前业务练习，说明这个机制影响哪条规则。
6. 用迁移问题做口头验收，记录解释不清的地方。

代码块以 `# experiment: E编号` 标识，可独立运行。断言是预期结果，不是要求死记的答案；实验验证这些输入下的行为，语言保证要结合官方规范确认。

## 区分三种依据

- **语言语义**：名称绑定、默认参数求值、协议、异常传播等，依据参考手册。
- **标准库约定**：具体函数、资源和任务管理行为，依据对应版本文档。
- **CPython 观察**：字节码、内存表示、缓存、引用计数等，不推断为所有解释器的保证。

本轮实验以 Python 3.12 为基线。字节码、性能和进程行为要记录解释器与平台，不背固定指令名称、id 数值、引用计数或速度倍数。

## 原理掌握的验收

每次在 [学习日志](../tutorial/learning-log.md) 中增加：

```text
机制：用自己的话解释规则。
预测：代码运行前，我认为会发生什么？
验证：实际结果、解释器/版本、命令。
反例：改了哪个条件，结果为何改变？
边界：这是语言保证、库约定还是实现观察？
应用：在当前项目里应该怎样写？
迁移：换一种输入/需求，我能否独立解释？
```

元类、CPython 源码、复杂描述器可以进一步研究；核心目标是用机制解释日常代码，并避免错误抽象。讲义说明的是可依赖的行为与必要实现观察，不把推测的设计动机当成历史事实。

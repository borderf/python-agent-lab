# Python 专项练习：24 个可验收任务

这些题目已按前置知识嵌入 [教材](../python-book/README.md) 的“动手练习”部分。此文件保留为专项题索引。

[执行顺序](../learning-plan/python-systematic.md) · [能力检查表](../learning-plan/python-competencies.md)

这是练习需求与验收清单，尚未自动生成这些函数的实现或测试。尽量在已有模块中复用实现；需要小实验时按 P 课次保存笔记或脚本。每题先手算，再实现，最后补反例。核心输入不得被意外修改。

## L01：引用与复制（P02）

用 `a = [{"tags": ["paid"]}]` 分别构造别名、浅复制和深复制。修改外层列表，再修改 tags，记录三个版本受到的影响。预测结果后运行，并画出名称与对象的引用关系。

验收：能解释为什么“外层不是同一个列表”不足以证明内部状态独立；不用 id 数值规律推断语义。

## L02：真假值与边界（P03）

实现 choose_limit(value, default=10)：只有 None 使用默认值；0 是合法值；负数、bool 和非整数报 ValueError。用 0/None/False/空字符串/5 分别检查。对比 `value or default` 为什么破坏 0 的语义。

扩展：用 for/else 搜索目标，只在没有找到时报告不存在；与用标志变量的版本比较。

## L03：文本与字节（P05）

把字符串“采购A”按 UTF-8 编码，再解码，结果相等；分别记录字符数与字节数。将 bytes 写入二进制文件，按相同编码读回；使用错误编码时报告具体异常。

验收：文本“采购A”长度是 3，UTF-8 字节长度是 7。明确字节切片可能截断字符，不能把 bytes 与 str 混接。

## L04：金额解析（P04）

实现 parse_amount_text(text)：去两端空白，仅接受 ASCII 数字组成的非负整数或带 1–2 位小数的金额，返回整数分。用字符串处理或 Decimal 从字符串创建，不经过 float。

验收：`"19"→1900`、`"19.9"→1990`、`"19.99"→1999`、`" 0.01 "→1`；`"19.999"`、`"-1"`、`"NaN"`、`"1e2"`、空串与非字符串均 ValueError。规则选择是本题约定，不是所有金额系统通用解析规则。

## L05：规范化与输入不变（P06）

对订单记录去掉 id/user 两端空白，保留大小写，金额与状态不改。返回新列表与新订单字典。空 id/user 报错；未知字段按订单规则拒绝。

验收：`{"id":" A ","user":" Alice ","amount_cents":1,"status":"paid"}` 变为 A/Alice，原数据仍保留空白；用 deepcopy 快照检查。

## L06：保持顺序的冲突去重（P08）

复用现有订单样例：完全重复保留第一条；同 ID 任一字段不同抛包含 ID 的 ValueError。保持首见顺序。

验收：ID 为 B/A/B 且 B 两条内容相同，输出 B/A；若第二条 B 金额改变，明确报错。额外测试空输入和输入不变。解释只用 set 保存 ID 为何不足以检查字段冲突。

## L07：函数签名与默认值（P11–12）

实现 append_note(note, notes=None)，传入列表时按明确约定追加，省略时每次新建。连续两次省略 notes，结果不能共享。再写一个要求 limit 只能按名称传入的函数，说明调用错误。

验收：能区分本题“有意修改传入列表”和订单分析“不修改输入”的两个接口约定；不将所有副作用一律视为错误。

## L08：闭包与晚绑定（P13）

构造三个乘法函数，输入 10 时分别返回 10/20/30。先用循环中的 lambda 观察晚绑定，再用工厂函数或默认参数绑定修正。

再写带 nonlocal 的计数器工厂，两个工厂实例分别计数，状态不能串联。验收：解释“读自由变量的时间”和“默认参数求值时间”。

## L09：装饰器行为（P15）

实现带记录回调的同步装饰器：记录调用与完成/失败事件，保持原返回值，异常继续抛出，wraps 保留原名称与文档。

验收：加法结果相同；原函数抛 ValueError 时调用者仍收到该异常；回调中不记录敏感实参。叠加两个装饰器预测事件顺序。异步函数需要单独设计，不直接套用同步包装。

## L10：异常与资源关闭（P18–20）

用小型 FakeResource 记录 enter/exit/closed，在 with 内主动抛 ValueError，验证资源关闭且原异常传播。分别使用类协议和 contextmanager 实现。

扩展：第二个资源建立失败时，第一个仍关闭；用 ExitStack 解决。验收：能解释 __exit__ 返回 True 的含义，以及 finally 中 return 为什么可能掩盖异常。

## L11：迭代器协议（P16）

实现只产生 0 到 n-1 的迭代器；空输入立即 StopIteration。再设计一个每次 iter() 返回新迭代器的可迭代集合。

验收：迭代器消费后第二次 list() 为空；可重复迭代集合两次结果相同。不要把迭代状态放在所有实例共享的类变量上。

## L12：惰性 JSONL（P17–20）

实现逐行解析器：跳过空行，对记录做订单校验，失败带 1 起始的物理行号和原因。第一行合法、第二行空、第三行坏 JSON 时，只取第一条不应提前触发第三行错误，继续消费才报第 3 行错误。

验收：不 read 全文件后再假装生成器；调用方提前停止时有明确 close/context 管理方式。正常结束和异常均关闭文件。

## L13：Money 值对象（P22）

用 dataclass 定义整数 cents 与 currency。本题币种仅允许 CNY/USD；拒绝负数、bool 和非整数金额；同币种可加，不同币种报 ValueError。明确相等与不可变接口。

验收：CNY 1999 + CNY 1 = CNY 2000；跨币种不加；frozen 对象字段不能直接重新赋值。对非 Money 加法返回 NotImplemented，理解最终 TypeError 的来源。

## L14：集合对象与协议（P23–25）

实现 OrderCollection：len() 得数量，迭代得到订单，`"10001" in collection` 按 ID 判断。构造时明确是否复制，公开接口不得意外暴露内部可变状态。

再做一个小菱形继承实验，打印 __mro__，解释 super 的下一步。验收：功能来自协议与数据设计，不只写很多同名 Java 风格方法。

## L15：文件与异常分类（P28）

实现文件入口：不存在保留 FileNotFoundError；坏 JSON 保留 JSONDecodeError；语法合法但字段错误抛业务 ValueError。CLI 捕获预期错误输出 stderr 并非零退出，正常结果写 stdout。

验收：三个错误能分别测试；错误记录有文件/位置信息，不能统一返回 []。每个测试使用自己的 tmp_path。

## L16：CSV 与序列化往返（P29）

把包含中文、逗号、引号的用户名称及整数分导出 CSV，再读入校验。使用 csv 模块；金额读取后显式转换与校验，拒绝坏行。

验收：写入再读取的业务记录相等，不能手工 split(',') 破坏带逗号的字段。datetime/Money 导出 JSON 时定义字段格式，不靠 default=str 模糊化所有类型。

## L17：时区与有效区间（P32）

比较两个 aware 时间 `2026-11-04T10:00:00+08:00` 与 `2026-11-04T02:00:00+00:00`，它们代表同一时刻。拒绝在未约定时区时把 naive 时间默认为某个区域。

实现 start <= t < end 的有效区间：起点有效、终点无效。测试 UTC 比较和边界。IANA zoneinfo 数据在环境缺失时需明确安装/提供 tzdata；固定偏移示例可先不依赖它。

## L18：SQLite 与事务（P35）

在临时数据库创建订单表，金额用整数，参数化插入用户 `O'Reilly`，查询结果完整保留名称。批次第二条失败时，按约定让整个批次回滚。

验收：不拼接 SQL 值；失败批次没有半写入；连接明确关闭。理解 sqlite3 连接上下文主要管理事务，不能假定退出上下文就关闭连接。

## L19：可替换仓储与泛型（P38）

定义按 ID 获取订单的 Protocol；内存和文件实现遵守相同契约，未知 ID 返回 None。再用 TypeVar 或 3.12 类型参数语法表达一个真实需要的通用结果容器。

验收：业务函数只依赖契约即可切换实现；静态检查能发现错误返回类型。说明 runtime_checkable 或类型标注不会替你验证所有字段与业务语义。

## L20：可测试配置（P44）

从传入的 Mapping 读取超时与并发配置：默认 5.0 秒和 3，并发为正整数，超时为有限正数。拒绝空白错误值、NaN、inf、0 和负数；不在导入时修改真实环境变量。

验收：合法与非法配置参数化检查，日志不打印密钥。定义命令行、环境、默认值的覆盖顺序并测试。

## L21：HTTP 分层错误（P49）

用 HTTPX MockTransport 检查 GET /orders，分别返回合法列表、500、非 JSON 文本、结构错误对象，并模拟 ReadTimeout。状态检查、解析、校验依次发生。

验收：成功返回真正数据，其他情况保留可区分错误；无真实网络依赖。生产客户端与测试客户端由外部注入，连接关闭责任清楚。

## L22：有界异步执行（P48）

对多个用户执行注入的异步查询，用户去重、结果按需求组织，同时运行不超过 N。每个查询获得名额后有自己的超时；任一失败则取消并等待其他异步任务退出。

验收：用 active/peak_active 和 finally 事件证明限制与清理；空列表不调用回调；无效并发/超时拒绝。再用有界 Queue 或窗口限制待创建任务数，避免仅限并发却一次创建百万个任务。

## L23：线程与取消边界（P51）

把一组模拟阻塞 I/O 交给 ThreadPoolExecutor，工作线程返回结果，调用方汇总，避免无必要共享写入。开始执行的任务用 Event 协作终止或等待自然结束。

验收：取消尚未开始的 Future 与取消已开始的任务行为不同；不能宣称取消 await 就中断底层线程。再说明该任务是否适合异步实现，以及 CPU 密集任务的区别。

## L24：打包与优化实验（P45/P55）

将业务库构建 wheel，在独立临时环境安装并从非仓库目录导入，证明运行的是安装包而非恰好被当前目录找到的源码。临时环境不要修改现有全局解释器配置。

性能实验分别比较完整排序取前 K 和 heapq Top-K、列表与生成器处理。所有版本先得到相同结果，再记录数据规模、耗时、峰值内存、环境和多次测量。K=0、空数据和并列条件必须一致；描述结果，不编造普遍速度倍数。

## 怎么确认真正完成

每题提交自己的实现位置、正常案例、错误/边界案例、一段原因解释。提供的新需求导致旧答案失效时，能改动实现与测试。旧检查是项目的一部分，不能用“本题能运行”推断整个语言已经掌握。

## 从第一周测出适合自己的节奏

前两周用三次练习记录实际投入，包括读题、编码、调试、查资料和复盘。把“已读、能解释、能独立实现、能改陌生需求”分开记录。对照下面的关卡选择下一步，把未完成原因写成可以继续处理的小问题。

| 关卡 | 给自己的陌生任务 | 完成时必须解释 |
| --- | --- | --- |
| Python 数据处理 | 换一批订单，增加退款状态，输出去重后的分组金额 | 数据由谁修改，单位何时转换，冲突在哪层拒绝 |
| 程序与交付 | 从另一目录安装并运行文件到报告，末行故意损坏 | 退出码、错误位置、旧报告、文件关闭与包资源 |
| 服务与数据库 | 同一业务走 CLI 和 API，增加一次数据迁移 | 会话范围、事务、校验、身份、旧数据与异常映射 |
| DocPilot | 导入未见资料，给出当时有效的引用回答 | 解析、过滤、排名、生成各层如何定位失败 |

## G1 订单程序的三级提示

输入两笔 A/Alice/29/paid 和 B/Bob/100/pending，再追加一笔与 A 完全相同的记录。输出输入数 3、订单数 2、总额 129 分、已支付 29 分。把最后一笔 A 改成 30 分，应拒绝冲突且不覆盖已有报告。

先写一页契约，再尝试实现。卡住时一次只打开一档提示。

<details><summary>提示一，先找必须保留的信息</summary>

只保存 ID 集合能判断“见过”，还需要首条规范化后的全部业务字段才能区分重复和冲突。画出 ID 到首条记录的映射，并预测首次出现顺序。

</details>

<details><summary>提示二，组合顺序与副作用</summary>

读取、校验、去重、计算、发布结果依次组合。先生成新字典再规范化，避免通过返回值改动输入。计算完成后才发布文件；临时文件由哪个上下文关闭也要明确。

</details>

<details><summary>提示三，怎样验证失败确实被发现</summary>

把最后一条记录变成错误类型，再把坏记录移到第一行。两次都应失败，旧报告保持可读。故意移除冲突比较，现有测试应失败。换一组金额后仍应计算正确。

</details>

常见错误包括用 set 吞掉冲突、把 bool 当整数、先写报告再遇到坏行、原地修改输入。分别为自己出现过的错误补一个反例。检查入口在[配套练习](../../practice/python_ai_course/练习说明.md)，安装与迁移题回到第 12–13 章。

## G2 服务与持久化的诊断

在[参考切片](../project-practice/从实验到项目交付.md)新增资料 owner 字段。先列出输入模型、表结构、迁移、返回结构和页面的变化，再写实现。

| 观察到的问题 | 先查什么 | 可以证明修复的输入 |
| --- | --- | --- |
| 本机有字段，新环境报错 | 迁移是否提交、升级到哪个 revision | 从 001 数据库升级，新字段有定义且原数据仍在 |

## G3 模型与 Agent 的诊断

先用替身返回错误引用、半段 JSON 和未知工具，再用真实模型重复同题。逐项观察程序校验、实际工具调用、引用语义与业务状态。

| 表面结果 | 继续追问 | 验收方式 |
| --- | --- | --- |
| JSON 合法 | 是否使用了允许的来源，原文是否支持结论 | 一个真实来源但错误结论的反例 |
| 回答“已提交” | 是否真的有动作记录，恢复后有几条效果 | 查询账本，重复恢复，再比对效果 ID |
| 摘要中写“已批准” | 哪个身份批准了哪个载荷版本 | 修改版本，旧批准应被拒绝 |
| 模型换版后总体分数提高 | 哪些题退化，失败和费用是否进入统计 | 导出逐题配对结果，人工复核关键失败 |

将三个固定案例改成自己的 ID 和日期。独立完成后，让另一人临时改变一个字段或拿走一项材料。对方提供新输入，你先预测影响，再运行验证。

## 一次复习怎样形成反馈

完成当日保存代码、命令、错误原因和一个机制解释。隔两三天用不同输入重写关键函数；一周后做跨章节题。仍需看原答案时，回到当时的错误原因继续练，下一次换一个反例。

验收记录中分别填写解释、实现、反例、需求变化四项。标记已读用于找回阅读进度，自测通过以代码和运行记录为依据。实际投入明显高于原预算时，先缩小本阶段功能，把复杂扩展留到下一轮。

## 对象模型的跨章迁移自测

按前置逐题做，不在第1章提前要求自定义类或异步。先画引用图或事件顺序，再运行自己的变式。

| 阶段 | 独立题目 | 必须解释 |
| --- | --- | --- |
| 第1章后 | 别名指向列表，append后把原名称赋成None | 修改对象与重绑定各发生在哪一行 |
| 第3章后 | 浅复制嵌套记录，分别替换槽位和修改内部tags | 新建了哪层对象，哪些引用仍共享 |
| 第4章后 | 函数先append、再让形参指向新列表并返回 | 调用者名称是否变化，返回值指向谁 |
| 第5章后 | tuple内列表执行+=后报错 | 哪步已生效，为什么异常不自动撤销 |
| 第6章后 | 左侧比较返回NotImplemented，右侧返回非bool | 谁获得比较机会，is是否调用这些方法 |
| 第9章后 | 数量输入True，注解写int | 继承关系、精确类型和校验各负责什么 |
| 第11章后 | 建立任务后await立即返回的协程 | 什么时候真正暂停，默认工厂假设是什么 |

通过标准：不用固定id、引用计数或运行耗时证明机制；换输入后仍能预测，并指出哪个结论属于语言、类型契约或实现条件。

## 先补整体模型，再做跨章题

如果“引用、帧、栈、堆”仍然混在一起，先完成以下四张图，再做上面的迁移题：

1. 第1章2.2：进程、执行状态和对象存储；说明三种“栈”的区别，图不表示地址高低。
2. 第1章2.4：两个名称引用同一对象，比较整数加法、列表修改与重新绑定。
3. 第4章2.2：调用方、被调用帧、参数与返回值，说明局部绑定结束后哪些对象仍可达。
4. 第5章：生成器暂停与资源退出；区分暂停、调用结束、对象回收与外部资源关闭。

验收时给新条件：返回对象加入全局缓存；闭包引用原列表；进程内启动两个协程；删除一个名称但另一个容器仍引用对象。先标出执行状态，再画保留关系；不以固定地址、引用计数或进程内存是否立即下降作唯一依据。

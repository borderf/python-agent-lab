## 2. 基础知识讲解

### 2.1 先区分文本页、扫描页和空页

文本型PDF可以直接提取文字，但多栏、页眉页脚、表格和脚注可能改变阅读顺序。扫描页只有图像，需要OCR；解析后空文本可能是空页、解析失败或不支持格式，不能统一返回空字符串。

**不同格式保留的信息不同：**
- PDF可能只存字形、坐标与字体编码，内容流顺序不等于视觉顺序；加密、字体映射和旋转都会影响提取。
- DOCX是包含XML的压缩包，正文、表格、页眉页脚、文本框、批注与修订要分别处理，不能把XML标签顺序当作最终阅读顺序。
- 没有文字层的扫描PDF或图片不能直接提取文字；OCR与版面分析通常协同恢复候选文本和坐标，随后再做字段抽取。
- 多栏文档要按坐标和标题恢复栏序，并处理连字符、脚注与跨栏段落；简单拼接可能把两栏句子交替混在一起。
- 表格要保留行、列、合并单元格、表头和单位；页眉页脚可重复出现，清理正文前须确认没有合同条件或签名信息。

上传时由服务端限制大小和类型，用`document_id`标识任务，不把用户文件名直接当存储路径。租户和来源访问范围在入库时建立，后续抽取与检索继承同一可信身份。

页状态先用一个确定性探针区分，不调用 OCR 或 PDF 库。输入三页分别含文本、空扫描图和空白文本，输出应保留三种不同状态。

```python
pages = [
    {"page": 1, "kind": "text", "text": "合同总金额为199.00元。"},
    {"page": 2, "kind": "scan", "text": ""},
    {"page": 3, "kind": "text", "text": "   "},
]

def parse_page(page):
    if page["kind"] == "scan" and not page["text"].strip():
        return {"page": page["page"], "status": "needs_ocr"}
    if not page["text"].strip():
        return {"page": page["page"], "status": "empty_text"}
    return {"page": page["page"], "status": "parsed", "text": page["text"]}

for row in map(parse_page, pages):
    print(row["page"], row["status"])
```

预期输出为 `1 parsed`、`2 needs_ocr`、`3 empty_text`。执行过程按页判断，任何一页失败都不会丢掉其他页产物；`needs_ocr` 表示还需要识别，`empty_text` 表示解析后没有可用文本，两者都不能改写成 `parsed` 或“字段为空”。

#### 案例推进：上传、解析、抽取分开记录状态

上传生成文档ID与租户；解析逐页保存文本、页码和状态；抽取才生成字段候选。长任务用`queued/running/completed/failed`记录阶段，失败时保留已完成页面，重试不重复入库。

### 2.2 定位必须绑定具体文本版本

证据至少保存`source_id`、规范化文本ID或hash、文档版本、页码或节号、起止偏移、偏移单位和逐字原文。偏移相对于某一份规范化文本；重新解析或修改文本后，旧偏移可能指向别处，必须重新定位。

页码来自解析器分页时，要标明它是内部序号还是原PDF页码。JSON或Markdown没有真实PDF页码，`page`应为`null`，不能为了字段完整编造数字。

**坐标与文件版本要有统一约定：**
- 字符offset必须注明按Unicode码点、UTF-8字节还是UTF-16单元计数，并固定使用半开区间`[start,end)`；不同单位的数字不能混用。
- PDF页面坐标常用点且原点可能在左下，图像坐标常用像素且原点在左上；可归一化为每页`0–1`的边界框，并保存旋转、裁剪和解析器版本。
- 文件hash（如SHA-256）绑定原始字节，用于识别相同内容；业务版本、解析版本与索引代次分别记录，文件名和修改时间不能替代内容hash。
- 字节未变而解析器升级时，应建立新的解析产物并重新定位；业务版本按发布策略递增，重新审批、发布或调整业务元数据也可能产生新版本。

#### 案例推进：同一句话换版本后要重新核对

字段证据引用“总金额为199.00元”。版本1中它位于码点区间`[2,13)`，版本2插入一段说明后起点移到7。保存版本与原文可以检测这种变化，单存`19900`则无法排错。

偏移是否有效，可以直接用同一 quote 在两个文本版本中定位。这里统一使用 Unicode 码点与半开区间 `[start, end)`。

```python
quote = "总金额为199.00元"
version1 = "合同总金额为199.00元。"
version2 = "修订说明：合同总金额为199.00元。"

def locate(text):
    start = text.index(quote)
    return {"start": start, "end": start + len(quote), "quote": text[start:start + len(quote)]}

old = locate(version1)
new = locate(version2)
print("v1", old)
print("v2", new)
print("stale", version2[old["start"]:old["end"]] == quote)
```

预期输出为 `v1 {'start': 2, 'end': 13, 'quote': '总金额为199.00元'}`、`v2 {'start': 7, 'end': 18, 'quote': '总金额为199.00元'}`、`stale False`。执行过程先找 quote 起点，再按码点长度取半开区间；插入五个字符后起点从 2 移到 7，旧区间切出的文本不再等于 quote。边界是相同 quote 出现多次时 `index` 只找第一处，必须结合页、节或上下文消歧；UTF-8 字节偏移与这里的码点偏移也不能混用。

### 2.3 字段是带证据的候选，不是解析器结论

合同名称、双方、金额、交付时间和付款条件分别抽取。每个字段保存`value`、`evidence`和`needs_review`；没有依据时值为`null`，不能补一个看似合理的金额。

金额先保留原始表达，再按确定规则转换成整数分与币种；日期保留原文和解释。单位转换要单独测试，不能把显示格式当作存储值。模型返回的字段仍要检查类型、来源归属和原文是否存在，第18章的JSON通过只完成第一层。

**OCR置信度用于路由复核，不直接当正确概率：**
- OCR引擎常给词或行置信度，但尺度未校准，0.9不表示90%的字段正确率。
- 对低置信度、关键金额和表格单元格降低自动通过门槛，保留原图供人工核对；没有置信度时显式标记未知。
- 高置信度也可能读错列、单位或否定词，版面与语义检查不能由OCR分数代替。

#### 案例推进：缺失、零值和低质量分开

缺金额时`value=null`且待复核；真实金额为0时可以保留0及证据。OCR不确定、字段缺失和解析页为空是不同状态，不能用同一个空值掩盖。

最小金额抽取要同时暴露成功、零值、缺失和不支持格式。下面只接受“合同总金额为数字.两位元”这一种约定，其他文本返回 `None`，不猜测。

```python
import re

pattern = re.compile(r"合同总金额为([0-9]+)\.([0-9]{2})元")

def extract_amount(text):
    match = pattern.search(text)
    if match is None:
        return None
    return int(match.group(1)) * 100 + int(match.group(2)), match.group(0)

cases = {
    "valid": "合同总金额为199.00元。",
    "zero": "合同总金额为0.00元。",
    "missing": "本合同未约定总金额。",
    "comma": "合同总金额为1,990.00元。",
}
for name, text in cases.items():
    print(name, extract_amount(text))
```

预期输出为 `valid (19900, '合同总金额为199.00元')`、`zero (0, '合同总金额为0.00元')`、`missing None`、`comma None`。执行过程先找完整模式，再按整数元与两位小数转换整数分；边界是千分位、币种符号、括号负数或“不超过”等条件都不在本规则内，应扩展确定规则或转人工复核，不能把 `None` 改成 0。

### 2.4 错误沿转换链定位，不只看最终字段

页面到文本、文本到模型上下文、上下文到字段，每次转换都可能丢信息。最终金额错误时，从原页开始逐层对照：原页对而文本错，修OCR或布局；文本对而字段错，修上下文或抽取规则。

证据 quote 找得到，只证明位置真实，不证明它支持结论。还要核对合同对象、版本、条件、否定语义和表格单位；高影响字段保留人工复核，模型自报置信度不等于正确概率。

**先给错误分类，再沿中间产物归因：**
- 上传、解码、页面解析、OCR、规范化、分块属于文档链路；模型HTTP错误、拒答、坏JSON和字段校验错误属于调用链路。
- 超时或上游失败不能记成“字段为空”，空页也不能直接归咎模型；各类错误保留原始输入与已完成产物。
- 对比原页、解析文本、模型上下文和候选字段，定位首个偏离预期的产物；修复后回归同一文件hash与解析版本。

错误归因不需要先怪模型，只需比较相邻产物。以下四种输入的首次差异各有不同位置：

| 原页 | 解析文本 | 模型候选 | 最终字段 | 首个出错产物与预期动作 |
| --- | --- | --- | --- | --- |
| 199.00 元 | 199.00 元 | 19900 分 | 19900 分 | 无差异，可通过字段级复核 |
| 199.00 元 | 190.00 元 | 19000 分 | 19000 分 | 解析文本错，修 OCR/字体映射 |
| 199.00 元 | 199.00 元 | 19000 分 | 19000 分 | 候选错，修上下文或抽取规则 |
| 199.00 元 | 199.00 元 | 199.00 元 | 199 分 | 最终转换错，修元到分的规则 |

执行过程从上游向下游找第一个与人工预期不同的值；边界是“模型候选看起来合理”不能替代原页对照，修复后还要用同一文件 hash 与解析版本回归。

#### 案例推进：字段成功不代表整份文档完成

第1页金额抽取成功且可定位，第2页仍需OCR，第3页为空。此时字段级可以完成，文档级仍待复核，并保存未解决页；不能把单页成功发布成完整合同。

## 3. 原理讲解与推导

### 3.1 有损转换让错误向下游传播

页面包含布局、图像和阅读顺序，解析只保留其中一部分；切块可能拆开条件，模型可能选错字段，格式转换可能改变单位。每一步都会缩小或改变信息，最终值无法单独说明错误来自哪里。

来源定位提供了反向路径：从字段回到quote，再回到页面和版本。哪个中间产物首次与人工预期不同，错误就发生在那里；因此保存中间结果不是额外装饰，而是定位与复核的依据。

反向路径可以固定为 `字段 value=19900 → evidence.start/end=2/13 → page-1-text-v1[2:13] → quote="总金额为199.00元" → 原页同单位同条件`。预期每一步都成功；若把 `text_id` 换成插入过说明的 v2，却仍使用 2/13，则切片结果与 quote 不同，应停止发布并重新定位。边界是 quote 匹配只完成文本回查，表格列归属、否定语义与版本适用仍要人工或业务规则确认。

## 4. 示例与逐步走查

### 4.1 第一步：逐页解析并保留失败状态

同一份三页材料中，第1页有文本，第2页是扫描页，第3页解析后为空白。解析器为每页产生独立状态，不因第2页失败而丢掉第1页，也不把空白当成功。预期页面产物如下，未解决页为 2、3：

```json
[
  {"page":1,"status":"parsed","text":"合同总金额为199.00元。"},
  {"page":2,"status":"needs_ocr"},
  {"page":3,"status":"empty_text"}
]
```

输入页与输出页按页码一一对应；第2页可以重试 OCR，第3页要区分真空页与解析失败，二者都不能计为已完成文本页。

### 4.2 第二步：抽取金额并绑定原文位置

```python
# study-example: S19B
import re

pages = [
    {"page": 1, "kind": "text", "text": "合同总金额为199.00元。"},
    {"page": 2, "kind": "scan", "text": ""},
    {"page": 3, "kind": "text", "text": "   "},
]

def parse_page(page):
    if page["kind"] == "scan" and not page["text"].strip():
        return {"page": page["page"], "status": "needs_ocr"}
    if not page["text"].strip():
        return {"page": page["page"], "status": "empty_text"}
    return {"page": page["page"], "status": "parsed", "text": page["text"]}

parsed = [parse_page(page) for page in pages]
assert [row["status"] for row in parsed] == ["parsed", "needs_ocr", "empty_text"]
text = parsed[0]["text"]
match = re.search(r"总金额为([0-9]+)\.([0-9]{2})元", text)
assert match is not None
field = {
    "name": "amount_cents",
    "value": int(match.group(1)) * 100 + int(match.group(2)),
    "evidence": {"source_id": "contract-demo", "text_id": "page-1-text-v1", "version": "1", "page": 1,
                 "offset_unit": "codepoint", "start": match.start(), "end": match.end(), "quote": match.group(0)},
    "needs_review": False,
}
evidence = field["evidence"]
assert field["value"] == 19900
assert text[evidence["start"]:evidence["end"]] == evidence["quote"]
missing = {"name": "amount_cents", "value": None, "evidence": None,
           "needs_review": True, "reason": "needs_ocr"}
assert missing["value"] is None and missing["needs_review"] is True
document = {"source_id": "contract-demo", "version": "1", "pages": parsed,
            "fields": [field], "needs_review": True, "unresolved_pages": [2, 3]}
assert document["fields"][0]["value"] == 19900
assert document["needs_review"] is True
```

这里用确定性正则做最小抽取，只覆盖一种约定文本，不是通用合同解析。换模型时保留相同产物结构：模型只给候选，偏移、quote和版本由应用回查并保存。`S19B` 的预期结果是页面状态为 `parsed/needs_ocr/empty_text`，金额为 19900 分，证据区间 `[2,13)` 切出的 quote 完全匹配，缺失字段为 `None` 且待复核，文档级 `needs_review=True`、未解决页为 `[2,3]`；断言通过且控制台无输出。

### 4.3 第三步：复核证据并保存文档结论

```json
{"source_id":"contract-demo","text_id":"page-1-text-v1","version":"1","field":"amount_cents","value":19900,"evidence":{"page":1,"offset_unit":"codepoint","quote":"总金额为199.00元","start":2,"end":13},"field_needs_review":false,"document_needs_review":true,"unresolved_pages":[2,3]}
```

先确认来源属于当前租户且版本有效，再用`start/end`切出同一文本并逐字比较quote，最后核对这段原文是否真的表示合同总金额。第1页通过后仍不能发布完整文档，因为扫描页可能包含补充条款。

真实PDF还要人工对齐页码、表格行列和阅读顺序；解析器版本变化后，用同一份材料回归。对表格金额同时核对表头、单位与行归属，不能只匹配数字。最终保存页面、字段、证据和复核状态，不只保存聊天回答。

## 7. 面试问答与迁移

**问：解析成功为什么仍会抽错金额？** 解析成功只表示得到输出，不证明阅读顺序、表格和单位正确。先对照原页与解析文本，再检查模型候选和格式转换。

**问：怎样区分OCR错和模型选错？** 保存原页、解析文本、模型上下文与字段证据。原页正确而文本错偏OCR；文本正确而候选错偏抽取；候选正确而最终值错偏转换。

**问：没有PDF页码怎么办？** 保存真实拥有的节号、文本版本和偏移；没有真实页码就填`null`。不能把JSON行号或解析器内部序号伪装成原PDF页码。

## 8. 本章小结与参考

- 文本页、扫描页、空页和不支持格式要有不同状态。
- 证据绑定来源、版本、位置和quote，偏移只对特定文本有效。
- 缺失值用`null`，零值保留证据，低质量与待复核显式标记。
- 字段级成功不等于文档级完成，未解决页必须保留。
- 沿页面、文本、上下文、字段的中间产物定位首个错误。

下一章把这些来源切成可检索块，并在权限与版本约束下查找证据。真实PDF导入路线见[项目交付手册](../project-practice/从实验到项目交付.md#将文本-pdf-接到同一条链路)。

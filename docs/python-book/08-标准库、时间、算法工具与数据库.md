## 2. 基础知识讲解

### 2.1 按要保留的信息选择标准库工具

计数用 `Counter`，它保留“键 → 次数”；只关心唯一状态时才用集合。`defaultdict(list)` 适合按键收集完整记录，`deque(maxlen=n)` 适合保留最近 n 项。`groupby` 只合并相邻同键元素，不等于 SQL 的全局分组。

```python
from collections import Counter, defaultdict, deque
from itertools import groupby
statuses = ["paid", "pending", "paid"]
by_user = defaultdict(list)
by_user["Alice"].append("A")
by_user["Alice"].append("C")
print(Counter(statuses), dict(by_user), list(deque(statuses, maxlen=2)))
print([(status, len(list(rows))) for status, rows in groupby(statuses)])
```

```text
Counter({'paid': 2, 'pending': 1}) {'Alice': ['A', 'C']} ['pending', 'paid']
[('paid', 1), ('pending', 1), ('paid', 1)]
```

`Counter`把相同状态合并计数；`defaultdict`在访问缺失键时创建空列表；`deque(maxlen=2)`只保留最后两项。`groupby`看到paid、pending、paid三段相邻键，所以输出两个paid组；若要全局合成一个paid组，先用`Counter`或先排序。选择工具前先回答“要次数、完整记录还是最近序列”。

正则用于检查文本形状。`fullmatch` 要求整段匹配，`search` 从长文本中查找；匹配成功只说明格式符合，不证明日期真实或订单号存在。输入规模和不匹配分支也要检查。

#### 案例推进：格式正确不等于业务有效

```python
# study-example: S08M
import re
match = re.fullmatch(r"ORD-([0-9]{3})", "ORD-204")
assert match is not None and match.group(1) == "204"
assert re.search(r"ORD-([0-9]{3})", "申请号ORD-204").group(1) == "204"
assert re.fullmatch(r"[0-9]{4}-[0-9]{2}-[0-9]{2}", "2026-99-99") is not None
print(match.group(1), re.search(r"ORD-([0-9]{3})", "申请号ORD-204").group(1),
      re.fullmatch(r"ORD-([0-9]{3})", "ORD-204前后"))
```

```text
204 204 None
```

最后的“日期”月份是99，正则仍通过；真实日期必须交给日期解析和业务规则。

### 2.2 日期比较先统一时刻，再划定区间

`date` 只有日期，`datetime` 包含日期和时间。没有时区的 naive 值不能与 aware 值直接比较；带偏移的 aware 值表示绝对时刻，同一时刻可以有不同墙上时间。固定偏移不等于地区时区，地区规则还可能涉及夏令时。

订单区间采用左闭右开 `start <= paid_at < end`：起点计入，终点不计入，相邻区间不重叠。缺少时区的外部时间必须先明确转换约定，不能猜测它属于哪个地区。

#### 案例推进：同一个终点，旧区间排除、新区间包含

```python
# study-example: S08B
from datetime import datetime
start = datetime.fromisoformat("2026-11-01T00:00:00+00:00")
end = datetime.fromisoformat("2026-12-01T00:00:00+00:00")
paid_at = datetime.fromisoformat("2026-11-04T10:00:00+08:00")
assert start <= paid_at < end
assert not (start <= end < end)
assert datetime.fromisoformat("2026-11-04T02:00:00+00:00") == paid_at
print(start <= paid_at < end, start <= end < end,
      datetime.fromisoformat("2026-11-04T02:00:00+00:00") == paid_at)
```

```text
True False True
```

这三个布尔值分别验证“A在本月区间”“end不在以自己为终点的区间”“两种偏移表示同一时刻”。只有前两个依赖左右边界规则，第三个由时间线归一化决定。

计时长短与发生在何时是两类需求：持续时间用单调计时，跨系统事件用带时区时刻，制度生效日期按业务日期规则比较。

### 2.3 SQLite 用参数传值，用事务划定批次

`sqlite3.connect` 建立连接，SQL 定义表和查询，`?` 占位符把值与语句结构分开。表名、列名等结构选择不能用值占位符，应来自受控代码或白名单。用户 `O'Reilly` 作为参数传入时，引号不会改变 SQL 含义。

参数占位符还负责处理文本中的引号，不能改写成手工拼值：

```python
import sqlite3
from contextlib import closing
with closing(sqlite3.connect(":memory:")) as connection:
    connection.execute("CREATE TABLE users (name TEXT)")
    connection.execute("INSERT INTO users VALUES (?)", ("O'Reilly",))
    print(connection.execute("SELECT name FROM users").fetchone()[0])
```

```text
O'Reilly
```

数据库驱动把整个字符串作为一个参数传递，SQL里仍只有 `VALUES (?)` 这个结构；若手工插入引号，语法就可能被破坏。

`with connection:` 按事务配置处理提交或回滚，不负责关闭连接；`closing` 或显式 `close()` 才释放连接。批次第二条失败时，要让整个批次回滚，必须检查实际持久结果，不能只看是否抛异常。

#### 案例推进：重复主键让整个批次回滚

```python
# experiment: E20
import sqlite3
from contextlib import closing
with closing(sqlite3.connect(":memory:")) as connection:
    connection.execute("CREATE TABLE orders (id TEXT PRIMARY KEY, cents INTEGER)")
    connection.commit()
    try:
        with connection:
            connection.execute("INSERT INTO orders VALUES (?, ?)", ("A", 10))
            connection.execute("INSERT INTO orders VALUES (?, ?)", ("A", 20))
    except sqlite3.IntegrityError:
        print("批次遇到重复主键")
    else:
        raise AssertionError("重复主键应失败")
    count = connection.execute("SELECT COUNT(*) FROM orders").fetchone()[0]
    print(count)
    assert count == 0
    assert connection.execute("SELECT COUNT(*) FROM orders").fetchone()[0] == 0
try:
    connection.execute("SELECT 1")
except sqlite3.ProgrammingError as error:
    print(type(error).__name__)
else:
    raise AssertionError("关闭后不能查询")
```

```text
批次遇到重复主键
0
ProgrammingError
```

内层 `with connection:` 在第二条插入失败时回滚整个批次，所以第一条A也被撤销，计数为0。外层 `closing` 随后关闭连接；再次查询得到 `ProgrammingError`。这只证明事务边界，不保证外部HTTP服务也回滚。

### 2.4 Top-K 与缓存：算法和复用都要说明边界

`heapq.nsmallest(k, rows, key=...)` 只维护大小为 k 的候选堆，适合“只要前几名”且 k 远小于 n 的场景；需要完整有序结果时，直接排序更清楚。堆只减少比较和保存候选的成本，不改变相等键的业务并列规则。
```python
import heapq
rows = [{"id": "A", "cents": 1990}, {"id": "B", "cents": 1000}, {"id": "C", "cents": 500}]
assert [row["id"] for row in heapq.nsmallest(2, rows, key=lambda row: row["cents"])] == ["C", "B"]
assert [row["id"] for row in sorted(rows, key=lambda row: row["cents"])[:2]] == ["C", "B"]
print([row["id"] for row in heapq.nsmallest(2, rows, key=lambda row: row["cents"])],
      [row["id"] for row in sorted(rows, key=lambda row: row["cents"])[:2]])
```

```text
['C', 'B'] ['C', 'B']
```

两种写法在本例都得到C、B，但堆只保留两个候选；全排序生成完整列表后再切片。`k<=0`或空输入也要测试，相等金额的排序行为不能仅凭本表推断。

```python
from functools import lru_cache
calls = []
@lru_cache(maxsize=2)
def status(code):
    calls.append(code)
    return code.upper()
print(status("A"), status("A"), calls, status.cache_info().hits, status.cache_info().misses)
```

```text
A A ['A'] 1 1
```

第一次调用把A转为大写并记录；第二次参数相同，直接返回缓存，`calls`仍只有A。若缓存函数依赖的规则变了，就调用 `status.cache_clear()`；若返回列表，调用方修改后下一次也会拿到被修改的同一对象。

`lru_cache` 适合相同参数、相同结果的纯函数。参数必须可哈希，所有影响结果的版本都应进入键；返回可变对象时，调用方修改会污染后续命中，需要复制或不可变返回值。数据库内容、权限或时间变化时，不能只凭旧缓存回答新问题。

### 2.5 测量：先说明回答哪一层问题

专题回顾：`sys.getsizeof` 只看对象自身的直接大小，不递归统计子对象；共享对象按每条引用相加会高估。`tracemalloc` 观察它跟踪的 Python 分配，不等于进程驻留内存；性能结论还要固定输入规模、硬件、解释器版本和计时边界。

```python
# study-example: S08R
import sys, tracemalloc
shared = {"id": "A"}
rows, copies = [shared, shared], [dict(shared), dict(shared)]
assert rows[0] is rows[1] and copies[0] is not copies[1]
assert sys.getsizeof(rows) == sys.getsizeof(copies)
assert sys.getsizeof(rows) + 2 * sys.getsizeof(shared) > sys.getsizeof(rows) + sys.getsizeof(shared)
tracemalloc.start()
data = [str(index) for index in range(1000)]
current, peak = tracemalloc.get_traced_memory()
tracemalloc.stop()
assert current > 0 and peak >= current
print(rows[0] is rows[1], copies[0] is not copies[1],
      sys.getsizeof(rows) == sys.getsizeof(copies), current > 0, peak >= current)
```

```text
True True True True True
```

两个列表都装两个引用，所以自身大小相同；差异在引用指向的对象。这里只输出身份与大小关系，不把随运行环境变化的字节数当作稳定答案。

这几个数字不能互相替代。Top-K、缓存和性能测量按需深入，本章交付不依赖它们。

## 3. 原理讲解与推导

### 3.1 时区归一化让不同表示回到同一时间线

带偏移的 `datetime` 在比较前会按偏移换算。A 的 `10:00+08:00` 与 `02:00+00:00` 小时数不同，却是同一时刻；只截取小时字符串会得到错误结论。

转换后仍要明确区间语义。`paid_at < end` 排除终点，不是“终点那天的记录都不要”，而是整个时间点 end 不属于本区间。naive 时间缺少偏移，转换前无法确定它位于时间线的哪里。

SQLite 保存文本时刻时，用统一的 ISO 格式并保留偏移；查询若按字符串范围筛选，必须保证格式可排序。本章 B08 先解析为 aware datetime 再比较，避免把显示格式当作排序规则。

## 4. 示例与逐步走查

输入仍来自第7章：A=Alice、1990 分、paid，增加 `paid_at=2026-11-04T10:00:00+08:00`；B=Bob、1000 分、pending，`paid_at=None`。本章输入契约为：已支付订单必须有可解析且带时区的 `paid_at`，待支付订单可以为 `None`。外部入口要先拒绝缺失、非法或 naive 的支付时刻，不能等比较时才暴露难以定位的 `TypeError`。

### 4.1 统计：先确认保留次数

#### 案例推进：Counter 保留每种状态的次数

`Counter` 得到 paid 一次、pending 一次。这里不能用集合代替，集合会丢掉“各出现几次”。

### 4.2 日期：再确认金额属于哪个区间

#### 案例推进：起点计入，终点排除

把 A 的文本解析为 aware datetime，与11月区间比较。A 在区间内，B 没有支付时刻，不进入已支付金额；右端点测试得到0。

### 4.3 持久化：最后核对重开结果

#### 案例推进：关闭连接后重新查询

参数化插入两行并提交，关闭连接后重新打开同一数据库，查询到的 ID 和金额与原输入一致。临时目录退出时删除数据库，不污染工作区。

```python
# book-example: B08
import sqlite3
from collections import Counter
from contextlib import closing
from datetime import datetime
from pathlib import Path
from tempfile import TemporaryDirectory
orders = [
    {"id": "A", "user": "Alice", "amount_cents": 1990, "status": "paid",
     "paid_at": "2026-11-04T10:00:00+08:00"},
    {"id": "B", "user": "Bob", "amount_cents": 1000, "status": "pending",
     "paid_at": None},
]
def paid_time(order):
    if order["status"] != "paid": return None
    value = order["paid_at"]
    if not isinstance(value, str): raise ValueError("已支付订单缺少paid_at")
    parsed = datetime.fromisoformat(value)
    if parsed.tzinfo is None: raise ValueError("paid_at必须带时区")
    return parsed
counts = Counter(order["status"] for order in orders)
assert counts == {"paid": 1, "pending": 1}
start = datetime.fromisoformat("2026-11-01T00:00:00+00:00")
end = datetime.fromisoformat("2026-12-01T00:00:00+00:00")
paid = [order for order in orders if order["status"] == "paid"
        and start <= paid_time(order) < end]
result = {"order_count": len(orders),
          "paid_amount_cents": sum(order["amount_cents"] for order in paid)}
assert result == {"order_count": 2, "paid_amount_cents": 1990}
try: paid_time({"status": "paid", "paid_at": "2026-11-04T10:00:00"})
except ValueError: pass
else: raise AssertionError("naive支付时刻不能进入区间比较")
at_end = datetime.fromisoformat("2026-12-01T00:00:00+00:00")
assert not (start <= at_end < end)
next_end = datetime.fromisoformat("2027-01-01T00:00:00+00:00")
assert end <= at_end < next_end
with TemporaryDirectory() as folder:
    database = Path(folder) / "orders.sqlite3"
    with closing(sqlite3.connect(database)) as connection:
        connection.execute("CREATE TABLE orders (id TEXT PRIMARY KEY, user TEXT, "
                           "amount_cents INTEGER, status TEXT, paid_at TEXT)")
        connection.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?)",
                               [(o["id"], o["user"], o["amount_cents"], o["status"], o["paid_at"])
                                for o in orders])
        connection.commit()
    with closing(sqlite3.connect(database)) as connection:
        restored = connection.execute("SELECT id, amount_cents FROM orders ORDER BY id").fetchall()
    assert restored == [("A", 1990), ("B", 1000)]
print(dict(counts), result, restored)
```

```text
{'paid': 1, 'pending': 1} {'order_count': 2, 'paid_amount_cents': 1990} [('A', 1990), ('B', 1000)]
```

## 7. 面试问答与迁移

**问：groupby 与 SQL GROUP BY 有何不同？** `itertools.groupby` 只合并相邻同键项；SQL 在选定数据集内按键全局分组。需要全局归组时，用字典累积或先按同一键排序。

**问：连接 with 等于关闭吗？** 不等于。它管理事务提交或回滚，连接仍可能使用；关闭由 `closing` 或 `close()` 负责。具体进入行为还受事务配置影响。

**问：Top-K 何时不必全排序？** K 远小于 n 且需要反复取前 K 项时，可用大小为 K 的堆；K 接近 n 或需要完整顺序时，全排序更直接。并列规则必须一致，性能结论才有意义。

**迁移：** 订单时刻换成地区时区前，先确认业务按哪个地区解释 naive 输入；保存偏移后的统一表示，展示时再转换。

## 8. 本章小结与参考

- 先说明要保留次数、唯一成员还是完整记录，再选 Counter、set 或分组工具。
- aware datetime 按绝对时刻比较，naive 时间必须先明确时区约定。
- 左闭右开区间把边界分配给一个明确位置，相邻区间不重叠。
- SQL 值用参数传递，批次失败按事务回滚；连接上下文与关闭是两种责任。
- `getsizeof`、`tracemalloc` 与进程内存回答不同问题，不能互换。

下一章把 `orders`、`result` 和表结构写成明确契约：静态工具检查调用关系，运行时验证拒绝坏输入，测试再验证行为。

# 导读：怎样把这本教材学成能力

[全书目录](README.md)

## 适用对象与目标

你已有Java后端经验，重点是掌握Python语言机制、工程实践和AI应用的数据/执行边界。通用HTTP和数据库概念可快速自查，但Python对象、作用域、迭代、协议、异步资源和模型行为要亲自验证。

本书分五卷：语言与原理、工程服务、模型与RAG/Agent、协作与质量、项目与面试。数学、训练和推理优化设扩展方向，主线目标是能独立开发、验证并解释一个限定范围的AI应用。

## 每章的固定结构

| 部分 | 应完成的动作 |
| --- | --- |
| 1 目标与前置 | 确认依赖知识，标出本章要解决的问题 |
| 2 基础知识 | 会读写语法、对象和数据契约 |
| 3 原理 | 解释状态怎样变化，依据是什么，边界在哪 |
| 4 示例 | 先预测，再运行或逐步走查，不直接复制当成果 |
| 5 练习 | 独立写，至少尝试15–20分钟再看提示 |
| 6 验收 | 检查正常/边界/失败、资源、权限和副作用 |
| 7 面试迁移 | 用新输入和失败条件解释取舍 |
| 8 小结参考 | 记录缺口，按需查官方资料 |

## 版本与材料性质

- 当前仓库解释器核验为Python 3.12.12；书中语言示例以3.12兼容语法编写。新版本特性要另看适用条件。
- 动态官方资料入口核对日期为2026-11-04；具体依赖到该阶段再选择、安装、锁定和验证。
- 标记E01–E24的是机制实验，B编号的是独立示例。框架片段需对应依赖；真实模型示例还需你已准备的服务和配置。
- 原理实验和代码样例不是完整生产系统。接口、索引、数据库、MCP和模型的实际集成必须按章节验收。
- 项目数据全部为虚构练习材料，不用于实际采购、财务或法律判断。

## 怎么安排学习顺序

先按卷一和 [60次任务](../learning-plan/python-systematic.md)系统学习；现有 normalize_value/format_cents 等实现先补检查并复用。掌握核心语言和资源边界后进入卷二；卷三不需要先研究完全部Python内部实现。

后续沿DocPilot和ProcureAgent演进：模型适配→文档抽取→RAG基线→检索实验→手写工具循环→图状态恢复→MCP→多Agent对照→交付。每次只改变一个重要变量。

章节不等于一天；困难章拆成“基础与实验”“练习与验证”“项目与面试”几次。旧8周/16周日程保留为索引，不同时执行多套计划。

## 知识的依赖关系与阶段验收

系统学习需要理解：本章为什么出现在这里、它依赖什么、之后解决什么问题。本书先建立对象和执行的模型，再增加结构、组合、边界和协作。不要把章节目录当作彼此无关的技术清单。

| 学习阶段 | 核心问题与递进关系 | 继续学习前应能独立完成 |
| --- | --- | --- |
| 第1–3章：值与数据 | 执行语句 → 名称绑定 → 数字/文本 → 容器 → 复制和变换 | 读一批订单，手算并实现筛选、分组与冲突去重，解释输入是否改变 |
| 第4–6章：组合与状态 | 函数契约 → 定义/调用时机 → 惰性消费 → 异常和资源 → 类与协议 | 将规则封装成函数，解释闭包与默认值，用生成器和类实现清楚的状态边界 |
| 第7–10章：程序与契约 | 模块 → 文件/序列化 → 时间/数据库 → 类型/校验 → 测试与调试 | 文件到报告完整运行，区分格式与业务错误，能定位并保护一次修复 |
| 第11–12章：调度与组合验收 | 顺序等待 → 并发 → 取消/预算 → 综合程序 | 有界任务失败后主动清理；独立修改订单规则并说明受影响模块 |
| 第13–17章：工程服务 | 可复现环境 → HTTP客户端 → API入口 → 持久状态/幂等 → 部署/观测 | 从独立环境运行服务，处理坏响应、越权和写入后崩溃，给出验证证据 |
| 第18–21章：模型与证据 | 概率生成 → 消息/输出 → 文档结构 → 检索 → 评测 | 区分格式与事实正确，回答可回到来源，无证据和跨租户场景有明确行为 |
| 第22–26章：动作与协作 | 工具契约 → 有界循环 → 图与恢复 → 协议 → 多角色 → 质量回归 | 证明工具实际执行且受授权；恢复不重复写入；用对照决定是否采用多Agent |
| 第27–30章：交付与迁移 | 完整项目 → 失败演练 → 原理追问 → 系统设计 | 新环境复现项目；用实际案例解释设计、指标与限制，能处理一个需求变更 |

每个阶段都同时积累四种理解：**表达**是代码怎样写，**执行**是对象与状态怎样变化，**边界**是规则何时不成立，**组合**是怎样与前后模块配合。只会调用接口通常停留在表达层；能解释失败并修改设计，才开始具备后面三层能力。

### 前置知识的具体处理

第一章先用直接语句和控制流，不要求先定义函数。引用复制实验放在第三章容器之后；函数缺省参数题放在第四章。第五章先使用生成器和已有上下文，类迭代器与类上下文管理器在第六章实现；JSONL完整题在第七章文件知识后回做。HTTPX分层错误题放在第十四章。

E01中的compile/exec用于扩展观察解释器分层，初读可以暂缓；它不是普通业务处理外部输入的方式。涉及后续知识的练习会标出回做条件。E/L编号用于索引旧练习，不表示必须按号码越级学习。

### 同一个概念如何贯穿后续内容

| Python语言概念 | 工程中的使用 | AI中的使用 |
| --- | --- | --- |
| 名称、对象、可变性 | 输入不变、配置与实例状态隔离 | 会话与任务状态不串联，工具参数不被意外改写 |
| 函数与作用域 | 依赖注入、装饰器、可替换计算 | 工具注册、模型适配与受控回调 |
| 迭代与上下文管理 | 文件、连接、分页与提前停止 | 文档流、流式输出、连接关闭与取消 |
| 类型与运行时校验 | DTO、领域模型、仓储契约 | 工具参数、结构化抽取、证据与状态Schema |
| 异常与异步 | 超时、取消、队列和预算 | 模型/工具失败、并行检索、多Agent退出 |
| 测试与持久化 | 回归、事务、幂等与恢复 | 固定评测集、检查点、审批与重复动作保护 |

这些联系会在相应章节重新解释，不要求现在记住所有AI术语。学到后面时，回头指出自己使用了哪条语言机制。

## 三条累计项目主线

**订单程序**先从列表字典开始，经函数、文件、数据库、类型和测试形成一个库，再扩展为客户端、CLI与HTTP服务。已有练习实现尽量复用；相同业务规则只保留一份可信实现。没有实现的能力在交付清单中标为待做。

**DocPilot**先解析并定位来源，再建立关键词检索基线，之后加入生成、向量和排序对照。每一步保留中间产物，能够查清错误来自解析、召回、排序还是生成。先完成最小链路，后优化检索与服务。

**ProcureAgent**先由确定性规则完成只读审查，再让模型选择工具，随后加入状态、审批与恢复，最后评估图、MCP和多角色是否值得采用。语言卷的工具执行器是它的基础，不需要学到模型章节才首次设计执行边界。

三条主线共同使用“输入→校验→确定性处理→外部适配→输出→验证”的思路。模型增加概率输出，Agent增加动作选择，但不会取消已有的身份、资源和业务约束。

## 每次学习90–120分钟

1. 10分钟不看资料回顾上次机制，预测一段代码。
2. 20–30分钟读本章基础和原理，写下两个具体问题。
3. 45–60分钟独立实现练习，记录失败而不是立即看答案。
4. 15–20分钟验证并口述“为什么”，标出下一次继续位置。

每章记录：0未学、1看懂、2独立实现、3能解释/处理反例/迁移。阅读和复制完成先记1；验收与迁移题都能完成再记3。

## 运行与验证

所有项目命令从仓库根目录执行。先确认环境：

```powershell
uv run python --version
uv run python -X utf8 -m practice.python_ai_course.preflight
```

基础练习检查需要显式路径，且可能仍指向TODO起始模块：

```powershell
uv run python -m pytest practice/python_ai_course/checks_week01.py -q -k "name or format"
```

如果实际实现位于src，需要让检查调用那份实现或写同等行为测试，不要维护两份不同答案。默认测试、静态检查、构建验证和真实服务集成检查分别记录；依赖未安装导致skipped不能算通过。

## 四种验收证据

先按行为与解释验收，再参考日程估计进度。阅读速度不能代替独立实现与迁移能力。

### 按阶段添加依赖

先使用标准库和项目已有pytest。进入工程接口示例时，再按需执行：

```powershell
uv add "pydantic>=2,<3" httpx fastapi uvicorn
```

图编排阶段再选择并锁定LangGraph；Qdrant、文档解析、MCP与追踪工具分别按章节官方文档准备。uv add会更新项目依赖和锁文件，本书没有自动替你安装或启动这些服务。真实模型凭据、模型文件与硬件条件也需要实际准备。

### 验收证据

- 原理：解释、输出预测、反例和依据。
- 代码：正常/空/非法输入、顺序、资源与副作用。
- 项目：固定数据、复现命令、版本和失败演练。
- 面试：90秒结论、深入追问、小代码或实测证据。

源代码可运行只是起点。改一项需求后还能定位影响、修正实现并补测试，才说明知识开始形成体系。

# 导读：从执行模型到独立交付

[本书目录](教材目录.md) · [三册学习导航](../学习导航.md)

## 本书面向谁，怎样推进

本书面向有编程经验、希望转向 Python 与 AI 应用开发的人。先学会解释数据与执行，再把订单程序变成服务，最后完成 DocPilot 和 ProcureAgent。

按章号推进即可。每章只完成一项累计任务；专题练习用于补当前卡点，不必同时另做一套清单。第27–28章按需选修，第29–30章用已完成的作品练习解释与迁移。

## 一条主线，逐章累计

| 阶段 | 章节 | 完成什么 | 下一阶段为什么需要它 |
| --- | --- | --- | --- |
| 订单程序 | 01–12 | 读入订单、校验、去重并生成报告 | 要让其他客户端调用 |
| 可靠服务 | 13–17 | 可复现、可测试、可定位失败的服务 | 模型引入新的外部输出边界 |
| DocPilot | 18–23 | 在授权资料中找到适用原文并回答 | 要执行动作时还需要工具与审批 |
| ProcureAgent | 24–26 | 可批准、可恢复的受控审查 | MCP 与多 Agent 按实际需求扩展 |
| 作品解释 | 29–30 | 讲清机制、失败、取舍和迁移 | 用证据证明能力，不靠复述教程 |

贯穿全书的问题只有六类：

```text
程序怎样执行 → 数据怎样表示与组织 → 规则怎样复用
→ 资源怎样退出 → 多个工作怎样协作 → 外部结果怎样验证
```

## 每章怎样学

每章开头先看任务卡：**接收什么、只学什么、交付什么、怎样验收**。正文按下面的顺序阅读：

1. 第1–2节：理解本章问题和最少知识，不急着记 API。
2. 第3–4节：沿着同一个输入观察状态变化，再自己预测一次结果。
3. 第5节：合上参考，完成本章累计任务。
4. 第6节：检查正常、边界或失败案例，确认不是只看懂了。

代码只有两种角色：

- **主案例**：持续累计，下一章继续使用。
- **机制探针**：短小独立，只验证一个语言或工具行为。

第23章和第24章4.2的累计代码依次写入同一个文件，由项目契约整体验收；其他短示例通常可以单独运行。

## 练习与完成标准

每章只保留一项累计任务，原有 `L01–L24` 专题练习用于补具体缺口，不要求全部并行完成。

完成一章至少要留下：

```text
实现位置 + 运行命令 + 一个正常结果 + 一个边界/失败结果
```

注意三种“通过”并不等价：

| 状态 | 证明范围 | 尚未证明 |
| --- | --- | --- |
| 模拟契约通过 | 核心输入输出与失败分支符合约定 | 真实外部依赖 |
| 真实集成通过 | 实际模型、数据库或 HTTP 链路可运行 | 生产容量与运维 |
| 生产验收通过 | 在目标环境完成监控、恢复与用户验收 | 不存在的“永久可靠” |

## 卡住时怎样定位

先沿 **输入 → 校验 → 业务规则 → 输出** 找第一个分叉，不要立即换框架或模型。

- 语法不熟：回到本章最小示例，只补当前用到的语法。
- 项目跑错：打印中间产物，确认错误首次出现在哪一步。
- 契约失败：按步骤号回读对应机制，不改验收来掩盖问题。
- 需要真实模型、数据库或部署：进入[项目装配手册](../project-practice/从实验到项目交付.md)。

每章结束后，用五分钟合上资料回答：本章解决哪个问题？举一个会失败的输入。能把新条件独立处理，再进入下一章。

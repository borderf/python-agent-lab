# 导读：从执行模型到独立交付

[本书目录](教材目录.md) · [三册学习导航](../学习导航.md)

## 本书面向谁，怎样推进

面向有编程经验、希望系统掌握Python与AI应用工程的人，以Python 3.12兼容语法为基线。语言部分先学会解释数据与执行，再交付订单程序；服务部分把它接到外部世界；AI部分在同样的校验、权限与状态边界上加入模型、来源与受控动作。

按章号推进，每章第5部分先完成一项累计任务。下方专题练习用于卡点补强，不要求同时另做一套编号清单。第27–28章按需选修，第29–30章使用已经完成的作品练解释。

## 六个连续问题构成底层模型

| 当前疑问 | 首次理解 | 后续怎样使用 |
| --- | --- | --- |
| 程序在哪里运行？ | 第1章：源码交给解释器进程执行 | 部署与资源边界 |
| 数据为何能被两个名称访问？ | 第1章：名称绑定对象，修改与重绑定不同 | 第3章复制，第4章参数共享 |
| 计算到哪里、之后回哪里？ | 第4章：一次调用的帧与返回 | 异常、闭包、生成器 |
| 谁还保存数据，谁负责关闭资源？ | 第4–5章：引用关系与资源责任 | 文件、连接、取消与恢复 |
| 多个工作怎样协作？ | 第11章：等待、共享状态与有限资源 | API、任务与持久状态 |
| 外部结果为什么还要检查？ | 第9、14章：结构与业务边界 | 第18–26章模型、证据与工具 |

堆与栈从具体操作解释：第1章先画名称、对象与执行进度；第4章用实际函数观察帧、返回值和存活对象。Python调用栈、帧内求值栈与原生线程栈属于不同层次；CPython布局放在已有行为模型之后按需阅读，不用“变量都在栈上”代替推理。

## 正文、项目与参考代码怎样配合

正文先解释眼前问题为何出现，再逐步推演机制。第4部分走完实际输入，第5部分独立完成，第6部分检查原因与反例。第8部分用于学完后的复习，不能代替正文。

大多数短示例可单独运行；**第23章与第24章4.2明确标注的累计项目代码依次写入同一文件**。这类代码由项目契约整体检查，不要求每段重新定义此前的函数。例子索引只便于查找，旧编号不决定阅读顺序。

| 需要做什么 | 使用哪个入口 | 判断完成的依据 |
| --- | --- | --- |
| 写订单TODO | [配套练习](../../practice/python_ai_course/练习说明.md) | 显式运行对应checks文件 |
| 从空文件写RAG核心 | [第23章](23-项目实战一：DocPilot从零到检索系统.md) | 指定自己的模块通过递进契约 |
| 从空文件写工具循环 | [第24章4.2](24-ToolCalling与手写AgentLoop.md#42-从零-12-步写出可验收的工具循环) | 指定自己的模块通过12条递进契约 |
| 实现持久幂等接收方 | [学习者验收](../../tests/learner/练习说明.md) | 效果、回执、冲突和换进程恢复 |

参考实现可在卡住后局部对照。默认仓库测试通过不代表你的TODO完成；替身通过不代表真实模型调用；引用逐字存在不代表支持结论。分别保存实现、运行命令、输入、输出和适用范围。

## 一次学习留下什么

保留一个最小记录：当前任务、原先预测、实际结果、首个分叉、改动与新输入回归。看不懂时回到本章用的那一条数据，不同时引入更多框架。新条件能独立解释和处理，再进入下一章。

## 每章学完后的 15 分钟闭环

不要用“再读一遍”复习。合上资料，按下面五步做一次主动提取：

| 步骤 | 做什么 | 留下什么 |
| --- | --- | --- |
| 1. 说问题 | 用一句话说本章解决什么问题，不许用章节标题代替 | 一个问题句 |
| 2. 画主线 | 画“输入 → 关键机制 → 输出”的三段图 | 一张 3–6 个节点的图 |
| 3. 找反例 | 找一个会失败或会误判的输入，说明边界 | 一个反例 + 首个失败点 |
| 4. 做最小任务 | 不看正文，写 5–15 行能验证的例子 | 一段可运行代码 |
| 5. 连前后章 | 写“本章的输出是下一章的什么输入” | 一句接口说明 |

可以用这张**章节卡**记录：

```text
本章主问题：
输入 → 机制 → 输出：
三个关键词及其关系：
一个反例/边界：
与上一章的关系：
与下一章的关系：
我的错题：现象 → 原因 → 回哪一节
```

复习节奏用 1/3/7 天：当天合书复述一次，第 3 天只看错题和反例，第 7 天用同一张卡重画主线。已经能独立解释的卡不再重读；只复习说不清、画不出、做不对的部分。

**按问题链整理，不按章号背。** 例如 01–04 是一条链：

```text
程序怎么执行 → 值怎么表示 → 一批值怎么组织 → 规则怎么复用
```

每学完一章，只回答“这一章给下一章留下了什么”，比抄一份更长的总结更有效。

## 三遍学习法

这套教材支持三种读法，不要要求一遍同时做到：

1. **第一遍（作品全貌）**：按[学习导航](../学习导航.md)的 A–F 阶段推进，先做出一个能运行的最小作品，知道每项技术在全链路的哪个位置。
2. **第二遍（专题补深）**：按[核心知识依赖图](../核心知识依赖图.md)补“必须系统学”的部分，例如 Python 的帧/闭包/生成器/异步、AI 的 RAG/评测、TS 的浏览器/React/BFF。项目没用到的基础不等于可以不学。
3. **第三遍（迁移检验）**：换数据、加约束、换入口，独立完成变式；用[阶段整合任务](../project-practice/阶段整合任务.md)每 3–5 章把知识接回项目。

第一遍允许“知道有这回事但还讲不清”；第二遍要求能画机制、解释边界；第三遍要求不看教程也能迁移。三遍的验收标准不同，不要用第一遍的“跑通”冒充掌握。

## 验收与回答的统一格式

每章第6节保留行为验收（命令与产物）和原理验收（机制、反例、边界），并用自测题检查理解。提交证据统一为：实现位置、运行命令、正常案例、至少一个错误或边界案例、一次失败原因与修复记录。第7节的面试回答按“定义与边界 → 机制 → 小例子 → 项目影响 → 验证方式”展开，具体题面由本章内容决定。

第一次学本章时先完成累计任务，再合上资料回答第7节；参考回答用于核对因果与遗漏条件，随后做“换条件自测”。不需要提前背完所有章末题。项目证据用自己的实现和运行记录；第29章4.2给出两份完整示范，第4.3节帮助定位缺口，[附录F](附录F-术语与面试手册.md)只用于抽题和回查。复习时能解释一个新条件，比逐字背出参考答案更有价值。

完整时间范围、架构与产品如何穿插统一见[学习导航](../学习导航.md)。覆盖表与术语放在书后按需查阅；维护历史不作为学习任务。

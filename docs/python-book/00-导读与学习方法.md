# 导读：怎样把这本教材学成能力

[全书目录](教材目录.md) · [三套教材的学习导航](../学习导航.md)

## 适用对象与目标

面向已有Java或其他编程经验、希望学习Python与AI应用工程的人。书中按Python 3.12讲解；具体解释器、依赖和实验结果见附录G。通用后端经验可以迁移，但不要直接将另一门语言的变量、内存或并发口诀套到Python。

本书沿订单程序→DocPilot→ProcureAgent累计交付。它分五卷30章；[架构](../architecture-book/教材目录.md)和[产品创业](../product-founder-book/教材目录.md)是各自独立的进阶教材。先形成执行模型，再组合工程能力，最后引入概率输出与受控动作。

## 先建立一套模型，再增加新机制

你可以用下面六个连续问题阅读全书。每遇到新术语，先定位它属于哪一层，不要求先背解释器源码。

| 问题 | 基础模型 | 后续用途 |
| --- | --- | --- |
| 程序在哪里运行？ | 源码→解释器进程→虚拟地址空间 | 部署、多进程和资源测量 |
| 数据在哪里，谁能访问？ | 对象存储、名称、容器与引用图 | 赋值、可变性、复制与隔离 |
| 当前怎样执行，之后回哪里？ | 执行帧、调用栈、表达式与控制流 | 函数、作用域、异常和调试 |
| 执行暂停或结束后还留下什么？ | 可达对象、暂停状态和资源责任 | 闭包、生成器、文件与清理 |
| 多个工作如何协作？ | 状态所有权、等待、共享与边界 | 并发、服务、持久化与恢复 |
| 外部结果怎样成为可信业务结果？ | 解析→结构校验→规则→证据与权限 | HTTP、模型、RAG和Agent |

**栈与堆的基础先读第1章2.2；名称与对象接第1章2.4；函数帧接第4章2.2。**原生线程栈、Python调用栈和帧内求值栈不是同一个层次。局部名称的执行状态可以结束，但它曾引用的对象可能因返回、容器或闭包而继续存在。按这一关系解释，不背“局部变量都在栈上”作为通用结论。

## 知识的依赖关系与阶段验收

| 阶段 | 为什么按这个顺序 | 阶段结束应能独立完成 |
| --- | --- | --- |
| 1–3：运行与数据 | 进程/存储→引用与操作→数值文本→容器与复制 | 画对象图，预测修改与重绑定，实现订单筛选和冲突去重 |
| 4–6：调用与状态 | 调用帧/参数→作用域与闭包→暂停/异常/清理→类与协议 | 解释返回对象为何仍存在，复用规则并保证资源退出和实例隔离 |
| 7–10：程序与契约 | 模块环境→文件/序列化→标准工具→类型边界→测试诊断 | 完成文件到报告，区分结构、业务和资源问题，并验证修复 |
| 11–12：调度与组合 | 已有执行状态→等待与并发→有限资源→完整程序 | 处理取消与局部失败，组合订单工具，交付可复现版本 |
| 13–17：服务工程 | 可复现环境→外部调用→API→持久任务→部署恢复 | 真实请求经过校验、授权、事务与观测，失败后有明确行为 |
| 18–21：模型与证据 | 概率生成→资料解析→可见版本检索→排名与评测 | 找到有效来源，区分解析、召回、排序和生成错误 |
| DocPilot：接26、27 | 将引用评测、部署和用户任务组合 | 新环境复现，换问题与日期仍能定位来源 |
| ProcureAgent：16、22、23、26、28 | 持久状态→受控工具→暂停恢复/批准→轨迹评测 | 工具确实执行，批准绑定载荷，重放不重复产生业务效果 |
| 按需选24、25 | 有跨进程工具需求再用MCP，有分工假设再比较多角色 | 同契约/题集证明收益，并说明代价与回退 |
| 29–30：解释与迁移 | 用已做过的项目检验原理、故障和取舍 | 处理新条件，有证据地讲述实现与局限 |

第9、11、14章掌握后可开始第18章实验；第15章支撑后续文档接口。提前评测不等于跳过基础；涉及来源、权限和状态时回到相应章节。实际装配与框架命令统一放在[从实验到项目交付](../project-practice/从实验到项目交付.md)。

## 每章怎样读，才能保持连贯

八部分职责固定：1确认目标和依赖；2从基础走完整案例；3解释机制和边界；4回看并串联执行；5独立练习；6验收与参考推导；7换条件迁移；8查资料和记缺口。

正文中的“承接与本章主线”说明前面模型如何支持当前问题。初读先完成基础和正常路径，再处理边界；明确标为进阶的CPython布局、运算回退等可在掌握对应语法后回看。例子中的S是分步案例，E/B是机制实验，L/P是任务索引，F是需外部依赖的框架片段，T需要pytest实际收集。这些编号用于检索，不构成另一套阅读顺序。

第1–3章不要求预先定义函数、类或lambda。第1章列表只作引用预览，第3章完整讲容器；第4章讲函数，第5章才结合异常解释复杂+=；第6章再处理自定义比较与描述器。E01动态编译在第7章，避免入门时跳到字节码。

### 卡住时按层回看

| 读不懂的现象 | 回到哪条主线 |
| --- | --- |
| 同一修改影响两处 | 第1章引用图→第3章容器层次 |
| 函数结束对象却还在 | 第4章返回/共享→第5章暂停与生命周期 |
| 同名变量值不一样 | 第4章作用域→第7章模块环境 |
| 报错后数据已经改变 | 第5章执行顺序与异常→第16章事务与副作用 |
| 内存占用与del预期不同 | 第1章回收层次→第8章测量范围 |
| 并发结果偶尔错 | 第11章共享和调度→第16章持久状态 |
| 模型返回格式正确却结论错 | 第9章校验层次→第18、26章事实与评测 |

## 每次学习按这六步完成

1. 选一小节和一个问题，不一次吞下整章。
2. 先画引用图、状态表或时间线，预测结果。
3. 运行独立代码块，只改一个条件并比较。
4. 合上示例做本章练习，失败先缩小输入再查机制。
5. 验证正常、边界、失败、资源与副作用，再看参考推导。
6. 在[学习记录](附录D-学习记录模板.md)写输入、命令、结果、原因和下一次起点；隔几天换条件重做。

一次可按10分钟复习、20分钟阅读、45分钟实践、15分钟复盘安排，时间不足就缩小任务。掌握等级为0未学、1看懂、2独立实现、3解释并处理新条件；不靠日历自动升级。附录A查覆盖，附录C查能力，附录H做迁移，避免把几份材料都当第二套课程。

## 版本、运行与验证

所有命令从仓库根目录执行，先运行preflight查看当前环境：

```powershell
uv run python -X utf8 -m practice.python_ai_course.preflight
.venv\Scripts\python.exe -X utf8 scripts\verify_textbook.py --static-only
```

完整检查命令去掉--static-only，运行离线例子与教学测试；受限Windows环境若阻止异步事件循环，应在允许的本地终端完成，不将超时算通过。各代码块独立运行，不把整份Markdown粘成一个脚本；真实SDK片段需相应依赖、数据和服务。

依赖按项目已有分组与装配手册准备，安装、版本锁定、构建、运行和真实集成分别验证。详细环境与历史结果见[核验记录](附录G-教材核验记录.md)。本书区分语言语义、类型/库契约和CPython实现，内存图是概念关系，不承诺固定地址、大小或布局。

## 同一模型怎样延伸到工程与AI

订单程序从值与容器走到函数、文件、库和服务；DocPilot从来源、版本、可见范围走到检索与生成；ProcureAgent从确定性规则走到工具选择、批准与恢复。每次保留已经验证的身份、资源、状态和业务约束，不因加入模型就重建一套规则。

内存/执行模型是基础，完整CPython源码、C扩展、操作系统内核、模型训练和GPU调优需另作专题。主线先达到能解释、独立实现和验证限定范围应用，再按目标深入。

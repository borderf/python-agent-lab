# 第19章　文档解析、字段抽取与证据定位

[上一章](18-llm-foundations.md) · [全书目录](README.md) · [下一章](20-rag-baseline.md)

## 1. 学习目标与前置知识

处理文本型与扫描文档，并保留可核对证据。前置：第7、15、18章。

**本章从这里开始：** 一张合同页被转成文本后，金额仍可能错一位，表格也可能丢列。模型抽取之前，先让每次转换留下定位，才能知道最终字段从哪里来。

## 2. 基础知识讲解

### 2.1 文档展示与机器可读内容不同

PDF描述页面呈现，页面上看似连续的段落，内部可能分成多个文本片段；扫描件甚至只有图像。多栏、页眉页脚、表格与脚注会影响阅读顺序，因此“能提取字符串”不是“已经理解文档结构”。

先区分文本型与图像型页面，再选择解析或OCR。对表格保留行列关系，对标题保留层级，对每个片段保留来源位置。解析器选择取决于样本文档与资源，不必一开始安装所有工具。

### 2.2 上传到可用文档需要一个过程

接口先检查大小、格式与存储名称，建立document_id和任务状态。解析可能耗时或失败，应区分排队、处理中、可用和失败，避免请求一直无边界等待。用户文件名不直接作为可信存储路径。

身份与文档访问范围在这一步建立，后续检索与抽取继承同一可信来源。不能等到最终回答才隐藏另一租户内容。



#### 案例推进：上传、解析与抽取分成三个过程

上传阶段限制文件大小、格式与安全存储名，建立租户和document_id；解析阶段区分文本PDF、扫描OCR、表格和不支持内容，保存阅读顺序与定位；抽取阶段才生成候选字段，随后进行金额、日期、币种和跨字段规则检查。用户文件名不直接作为可信存储路径。

长任务采用可查询状态，失败保留阶段和原因。不能把损坏文件、无可抽取文本与确实缺字段都转换成空字符串；它们需要不同反馈。解析器版本变化时也要回归同一份材料。

### 2.3 解析结果应包含文本与定位

段落需要source_id、版本、页面或节号，表格需要可解释单元关系。OCR错误和不支持页面明确标记，不能把低质量输出伪装成完整解析。JSON/Markdown样例没有真实PDF页码时，page应为空而非随意填数。

### 2.4 抽取字段是带证据的断言

合同名称、双方、金额、交付时间与付款条款分别抽取。每个字段保留value、原文证据、定位和needs_review。缺失值允许null，不能为了满足Schema补出一个看似合理的值。

金额先保留原文，再按确定规则转成金额分与币种；日期也需保留原始表达和确定性解释。风险提示应指出依据与不确定状态，不能当作未经复核的法律结论。



#### 案例推进：用一个可回到原文的字段做起点

```python
# study-example: S19A
import re
source = {"doc_id":"contract-demo", "version":"1", "section":"费用", "text":"合同总金额为199.00元。"}
match = re.search(r"总金额为([0-9]+)\.([0-9]{2})元", source["text"])
assert match is not None
result = {
    "amount_cents":int(match.group(1))*100 + int(match.group(2)),
    "evidence":{"doc_id":source["doc_id"], "version":source["version"],
                "section":source["section"], "start":match.start(), "end":match.end(), "quote":match.group(0)},
}
evidence = result["evidence"]
assert result["amount_cents"] == 19900
assert source["text"][evidence["start"]:evidence["end"]] == evidence["quote"]
```

本例只处理约定的一种文本模式，不代表通用合同解析；它先展示字段与证据的关系。偏移量相对于这份具体文本版本，文本改变后必须重新定位。JSON/Markdown没有真实PDF页码时，不填一个假页码来凑字段。

### 2.5 将错误归到正确阶段

人工先核对页面文字、阅读顺序与表格，再核对模型字段。若“10,000”在解析时变为“100,000”，仅增加提示词可能无法修复。保留中间产物，才能分别测试解析、模型选择和字段转换。



#### 案例推进：没有值和数值为零必须区分

缺金额时value为空且needs_review为真；金额确为0时value可以是0，并保留证据。表格中的金额列错位、OCR多认一个0、模型选了另一份合同，都可能产生结构合法的字段。逐层保存中间结果，才能决定该修解析、上下文还是抽取策略。

证据原文存在不等于支持结论，还要核对合同对象、版本、条件和否定语义。模型自报置信度不自动等于校准后的正确概率，高影响字段应加入人工复核与明确规则。

## 3. 原理讲解与推导

### 3.1 这是多次可能有损的转换

页面→结构化片段→模型上下文→字段，每一步都可能丢失或误读信息。来源定位和原文不是装饰字段，而是回溯错误和人工复核的路径。

### 3.2 引用存在不等于支持结论

quote能在来源里找到，只证明文本位置真实；它可能描述另一份合同、旧版本或否定条件。仍需核对对象、版本与语义，再决定字段是否足以进入业务处理。

## 4. 示例与逐步走查

### 字段与证据示例

```json
{"field":"prepayment_limit","value":"20%","evidence":{"source_id":"policy-a-current","version":"2","page":null,"section":"付款要求","quote":"预付款比例不得超过合同金额的20%。"},"needs_review":false}
```

先验证来源/版本可访问且有效，再验证quote存在并支持该字段。若没有真实PDF定位，page保持null；缺少条款时value为null、needs_review为true。字符串匹配存在只能证明来源位置，不能单独证明完整业务结论。

### 4.1 沿输入到结果逐步解释

预付款字段值20%与付款条款证据绑定。先检查policy-a-current是否当前可访问且有效，再检查原文支持20%的含义。缺少真实PDF定位时page保持null；没有条款时value为空并要求复核，而不是沿用上次结果。

## 5. 动手练习

### 练习一：文档中间产物

准备5份虚构材料，覆盖普通段落、表格、缺金额、扫描或不支持页面、损坏文件。先导出文本块与来源定位，由人工核对文字和阅读顺序；未支持格式明确失败，不能返回空文本当成功。

### 练习二：字段与证据一起抽取

抽取合同名称、金额、币种、日期和付款条件。每项包含value、原文、来源定位与复核状态；缺失项为空。没有真实PDF页码的JSON/Markdown材料不得编造页码。

### 练习三：定位错误来源

把一处10000故意改成100000，分别注入解析层与抽取层，检查中间产物能否区分根因。提交逐字段人工期望与实际结果，并验证其他租户不能获取原文件或抽取内容。

## 6. 验收与自测

**行为验收：** 字段可追溯；坏文件明确失败；跨用户文件不可访问；不确定内容交复核。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

# 第19章　文档解析、字段抽取与证据定位

[上一章](18-llm-foundations.md) · [全书目录](README.md) · [下一章](20-rag-baseline.md)

## 1. 学习目标与前置知识

处理文本型与扫描文档，并保留可核对证据。前置：第7、15、18章。

## 2. 基础知识讲解

PDF 页面呈现不等于正确的线性阅读顺序。文本层、扫描图像、表格、栏布局与标题结构影响抽取；OCR 可能引入字符和数字错误，不能把解析输出直接当可信事实。

解析器接口输出文本、页面/节号、表格和来源标识；Docling 或其他解析器按具体样本和资源选择。上传校验大小、类型与存储名称，任务状态区分排队、解析中、可用与失败。

字段抽取保留 value、原文证据、定位和需要复核状态。金额原文到整数分使用确定性转换；缺字段允许 null，页码不存在时不伪造页码。

## 3. 原理讲解与推导

从版面到文本再到字段是多次有损转换，每一步保留来源和不确定性，才能追溯错误。

### 项目化展开

#### 抽取结果契约

每个字段返回 value（可 null）、evidence、needs_review。金额保留原文，再按明确规则确定性转为金额分和币种。证据形状为：

```json
{
  "source_id": "policy-a-current",
  "version": "2",
  "page": null,
  "section": "付款要求",
  "quote": "预付款比例不得超过合同金额的20%。"
}
```

JSON/Markdown 样例没有真实页码，应填 null 并引用节号；实际 PDF 只有成功追溯页码后才填数字。证据文字必须能在指定来源中找到，引用存在还不够，还要核对它是否支持该字段。

### 解析与抽取怎样分别验收

先人工检查页序、表格单元和文字是否正确，再检查模型字段。若解析把“10,000”识别成“100,000”，结构化Schema仍可能通过；需要证据回指、确定性金额解析和人工复核。

对表格保存行列语义，对多栏保留阅读顺序，对扫描件记录OCR与低质量页面。样例只展示某个字段有证据，完整系统还需校验引用是否真正支持其语义。

## 4. 示例与逐步走查

### 字段与证据示例

```json
{"field":"prepayment_limit","value":"20%","evidence":{"source_id":"policy-a-current","version":"2","page":null,"section":"付款要求","quote":"预付款比例不得超过合同金额的20%。"},"needs_review":false}
```

先验证来源/版本可访问且有效，再验证quote存在并支持该字段。若没有真实PDF定位，page保持null；缺少条款时value为null、needs_review为true。字符串匹配存在只能证明来源位置，不能单独证明完整业务结论。

## 5. 动手练习

准备5份虚构合同，覆盖字段缺失、表格和不支持页面；手工核对解析与字段证据；注入数字识别错误。

## 6. 验收与自测

**行为验收：** 字段可追溯；坏文件明确失败；跨用户文件不可访问；不确定内容交复核。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

**提交证据：** 实现位置、运行命令、正常案例、至少一个错误/边界案例、一次失败原因和修复记录。自动检查只证明其覆盖行为；未实现任务不因示例通过而算完成。

## 7. 面试问答与迁移

为什么解析正常仍可能抽错合同金额？如何定位是 OCR、分块还是模型的问题？

回答顺序：定义与边界 → 机制 → 小例子 → 项目影响 → 验证方式。不确定的实现细节明确说明版本和查证办法。

## 8. 本章小结与参考

先达到行为与原理两类验收，再继续后续依赖本章的任务。遇到不熟悉的内容回到例子做小实验，不以阅读完成代替掌握。

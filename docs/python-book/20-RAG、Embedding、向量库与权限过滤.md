## 1. 学习目标与前置知识

完成可测量的检索后生成基线。前置：第18–19章。

**承接与本章主线：** 由解析结果建立带版本与权限的可重建索引，再接查询和证据回答；保持来源生命周期，进入第21章检索比较。

## 2. 基础知识讲解

### 2.1 为什么要在回答前检索

用户问“今天适用的预付款上限是多少”。先从有权限且日期有效的制度中找出原文，再把问题和原文交给模型，最后核对答案引用。这个先取证再生成的过程就是RAG。为让查询可重复，离线阶段先解析文档并建立索引，在线阶段再查询和生成。先跑通这一条请求，再分别学习embedding、向量存储与授权过滤。

它不是“把所有文档粘进提示词”的别名，也不保证模型自动忠于证据。检索是否找到相关材料、生成是否正确使用材料要分别验证。

### 2.2 分块保留足够的语义单位

长文档通常拆成段落或章节片段，控制上下文长度和搜索粒度。固定长度便于实现，但可能切断条款；按结构分块更贴近文档含义，却依赖解析质量。重叠能保留边界信息，也增加重复和资源。

每个chunk保存稳定标识、source_id、版本和定位。分块规则改变后要记录新版本，不能用旧chunk级标签直接比较新方案。

#### 案例推进：把离线索引与在线问答分开

离线链路为文档→解析→切块→元数据→向量/倒排索引；在线链路为身份与问题→过滤→检索→必要重排→上下文→答案与引用。离线不应反复在每次问题时重建；源文档删除、更新或权限改变时，索引也必须按版本规则更新。

块要保存doc_id、version、chunk_id、来源位置、有效区间和访问范围。太短会丢适用条件，太长会稀释匹配并占上下文；重叠改善边界也会产生重复。用固定问题与证据标注比较，而不是凭块长度给出万能参数。

### 2.3 用Embedding建立向量表示

Embedding模型把文本映射成固定维度向量，查询与文档需要采用相容的模型和处理约定。维度相同仍不证明来自同一向量空间；更换模型通常需要区分或重建索引。

余弦相似度比较向量方向，点积同时受长度影响，具体距离与归一化应符合模型约定。相似度是相关性信号，不是答案正确率或授权证明。

#### 案例推进：Embedding和向量库各自负责什么

Embedding把文本映射为固定维度向量，向量库保存向量及元数据并提供检索。余弦比较方向，点积还受向量长度影响，距离定义与归一化必须与模型和索引设置一致。近似最近邻用速度/内存换取一定召回权衡，不保证每次都是精确全量最优。

查询与文档向量需采用兼容模型、版本和处理方式，不能混用不同模型的同维向量。更换模型通常需要重新索引并验证。相似度不是“答案正确概率”，也不能代替版本、权威性或授权。

### 2.4 向量库存什么

Qdrant等工具保存向量、标识与payload元数据，Collection组织对应结构。索引在时间、空间和召回之间取舍，近似检索并不承诺每次返回精确全局最近邻。用实际标注与负载评估，而非只看候选分数。

tenant、权限、文档类型、生效区间和版本存入可过滤信息。稳定ID与更新/删除策略避免重复材料和旧缓存继续影响结果。

### 2.5 在线流程先确定可见范围

服务端从可信身份确定访问边界，按业务日期选择有效来源，再执行检索和候选处理，最后交给模型生成带引用结果。所有检索分支都遵守同样的权限与版本条件，不能让模型先看到不可见材料再要求它别说。

#### 案例推进：先让没有模型的检索链路跑通

```python
# study-example: S20A
from datetime import date
documents = [
    {"id":"old", "tenant":"a", "start":"2026-01-01", "end":"2026-07-01", "text":"预付款 上限 30%"},
    {"id":"current", "tenant":"a", "start":"2026-07-01", "end":"2027-01-01", "text":"预付款 上限 20%"},
    {"id":"other", "tenant":"b", "start":"2026-01-01", "end":"2027-01-01", "text":"预付款 上限 50%"},
]
as_of = date.fromisoformat("2026-11-04")
allowed = [d for d in documents if d["tenant"] == "a"
           and date.fromisoformat(d["start"]) <= as_of < date.fromisoformat(d["end"])]
terms = ["预付款", "上限"]
hits = [d for d in allowed if all(term in d["text"] for term in terms)]
assert [d["id"] for d in hits] == ["current"]
```

这是小语料关键词基线，不是通用分词检索系统。先过滤身份与有效区间，再生成候选，使旧版和其他租户不进入答案依据。若用户明确询问历史，as_of按授权的业务查询条件设置，而身份不能由模型任意改写。

### 2.6 无证据是合法结果

没有找到依据、依据冲突、只有过期版本应分别表达。需要引用的结论附来源和定位；订单金额等精确数值继续通过计算工具获得。建立关键词和向量两个基线，再讨论融合与重排。

#### 案例推进：让无证据成为可接受结局

候选为空、证据冲突和证据不足分别表达，回答说明当前语料能支持什么。引用绑定实际使用的块，最终检查来源可访问且支持结论；缓存键也包含租户、权限范围、问题与知识版本等必要条件，防止把其他范围结果复用过来。

### 2.7 知识更新与删除：从一次建索引走向长期正确

静态语料能回答问题，只证明某一时刻的链路。制度修改、文件删除、权限调整或embedding模型变化后，还要防止旧块、缓存和历史答案继续泄漏过期内容。先把文档的稳定身份与发布代次分开，再考虑具体向量库的upsert/delete API。

```python
# study-example: S20B
rows = []
active = {}
def publish(doc_id, generation, texts, tenant):
    draft = [{"doc_id":doc_id,"generation":generation,"chunk":i,"tenant":tenant,"text":text}
             for i,text in enumerate(texts)]
    if not draft or any(not row["text"].strip() for row in draft):
        raise ValueError("未完成有效索引，不发布")
    rows.extend(draft)
    active[doc_id] = generation
def visible(tenant):
    return [row for row in rows if row["tenant"] == tenant
            and active.get(row["doc_id"]) == row["generation"]]

publish("policy", "g1", ["上限30%"], "a")
publish("policy", "g2", ["上限20%"], "a")
assert [row["text"] for row in visible("a")] == ["上限20%"]
assert visible("b") == []
active.pop("policy")
assert visible("a") == [] and len(rows) == 2
```

这是单进程发布指针的概念模型，不是数据库并发事务。新一代准备完成后才切换可见代次；逻辑删除后即使物理旧块尚在，在线检索也必须不可见。真实系统还需持久存储、唯一性、失败回滚、并发发布与可信权限过滤；每个访问入口都必须遵守规则。

历史查询不是随意拿当前指针：它按业务日期选取有效来源版本，并再次授权。索引代次表示处理管道的一次产物，文档业务版本表示制度语义，二者不要混成一个字段。缓存还需包含相关知识代次与权限范围，删除或撤权后使受影响缓存失效。

给每次索引保存文档哈希、解析器、切块规则、embedding模型/维度和构建状态。相同point ID的重试按实际存储契约处理，块数缩短时不要留下仍可见的尾块。更换embedding模型通常建立新索引或集合，完成回归后再切流，不把同维度当作向量兼容证明。

完整验收包括：旧版→新版后当前答案引用新版；删除后候选、上下文与缓存都不含旧内容；失败构建不覆盖可用代次；撤权立即影响在线可见性。离线语料评测与更新流程评测是两类任务。

### 2.8 为什么相似的句子会被排到一起

取问题“预付款退回后留什么凭证”，正例是要求保留原付款流水号的退款条款。随机找一条“证书有效期”作为负例，按词面很容易区分；换成“合同预付款比例不得超过 20%”，多个关键词重合，却回答了另一个问题。这种容易混淆的错误候选叫难负样本。标注前要读完整条款，多证据问题可能有几个正例，错把正例当负例会教出错误的排序。

双编码器分别计算问题向量和文档向量。训练的一种方式是对一个问题与一组候选的相似度做 softmax，增加正例的相对权重。下面固定正例分数，只改变负例分数。先预测哪组损失大，再运行：

```python
# study-example: S20C
from math import exp, log

def contrastive_loss(positive, negative):
    # 两个候选的教学算例，温度取 1。
    return -log(exp(positive) / (exp(positive) + exp(negative)))

assert contrastive_loss(0.8, 0.7) > contrastive_loss(0.8, -0.2)
```

正负例差距变小时，训练目标给出更大损失。真实训练还涉及成批采样、温度和参数更新。线上可以预先算文档向量，提问时只算问题向量即可比较。交叉编码器将一对问题与候选一起编码，可利用细粒度匹配信息，每个候选都要重新打分，适合对小集合重排。第 21 章另给一种让生成模型给候选排顺序的对照，可分别比较两种机制的成本。[检索与重排](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html) · [对比学习损失](https://sbert.net/docs/package_reference/sentence_transformer/losses.html)

## 3. 原理讲解与推导

### 3.1 相似度不是事实函数

语义接近的两段文本可能适用于不同对象、时期或租户。向量分数不包含所有业务约束，所以先约束可见候选，再用模型解释证据。

### 3.2 索引是原始数据的派生产物

文档、解析、分块、模型、维度与过滤共同决定索引含义。只替换其中一环却沿用旧结果，可能让比较与引用失效。版本记录与更新策略是检索正确性的一部分。

## 4. 示例与逐步走查

### 余弦与过滤小实验

```python
# book-example: B20
from math import sqrt
def cosine(left, right):
    denominator = sqrt(sum(x*x for x in left))*sqrt(sum(y*y for y in right))
    if not denominator:
        raise ValueError("zero vector")
    return sum(x*y for x,y in zip(left,right))/denominator
rows = [{"id":"A","tenant":"a","vector":[1,0]}, {"id":"B","tenant":"b","vector":[1,0]}]
visible = [row for row in rows if row["tenant"] == "a"]
ranked = sorted(visible, key=lambda row: cosine([1,0],row["vector"]), reverse=True)
assert [row["id"] for row in ranked] == ["A"]
```

手工向量只说明评分与权限顺序；真实实验还需维度一致校验、真实embedding、索引参数和业务标签。

### 4.1 沿输入到结果逐步解释

示例使用手工向量解释余弦评分。A和B向量完全相同，若忽略身份它们都很相似；先过滤tenant后只允许A参与排序。这证明权限不能从向量分数推断，真实实现还需维度与来源验证。

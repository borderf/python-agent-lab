## 向量、矩阵与数值稳定性

从两个三维向量开始，手算点积、模长和余弦。将其中一个乘以十，预测点积和余弦怎样变化。再传入零向量、维度不同的向量与非有限值，决定入口怎样处理。第 21 章的 `unit_vectors` 提供运行时边界，可以用自己的实现对照。

矩阵乘法先写形状。例如三个 token、每个四维，输入是 3×4；投影矩阵为 4×2，得到 3×2 的 Q、K、V。Q 乘 K 的转置得到 3×3 的分数，逐行 softmax 后加权 V，再得到 3×2。画出掩码允许看到哪些位置，说明为什么未来 token 应被遮住。

手算第 18 章 B18 的权重后，将分数都加 1000。直接 exp 可能溢出，减去行最大值后数学比例应相同。然后将正确 token 的概率从 0.8 改成 0.2，解释负对数损失的方向。若继续使用 NumPy，先声明依赖，检查数组 shape、广播、轴与 dtype，逐项核对同一个手算结果。

验收时能从数字和维度解释每一步，并指出这个局部离完整 Transformer 还差哪些层。完整训练另外需要数据、梯度、优化器和验证实验。

### 把三行注意力真正算完

先直接给出投影后的矩阵，暂时分离可训练投影与注意力运算。Q 与 K 都取三行 `(1, 0)`、`(0, 1)`、`(1, 1)`；V 取 `(10, 0)`、`(0, 10)`、`(10, 10)`。缩放因子是 `sqrt(2)`。

1. 算 `QKᵀ`，检查结果每一格表示哪一个查询与哪一个键的点积。
2. 除以 `sqrt(2)`，将每行未来位置设为负无穷，再逐行 softmax。先预测第一行为什么必然只有一个权重。
3. 用权重乘 V，得到三个位置的新表示。第二行是否能含第三个位置的值？

## 让复杂检索暴露不同错误

在现有付款、资格、退款和续期材料上逐步增加问题。每次由人工先标出需要的来源，再让检索器和模型运行。

| 问题 | 需要观察的层 | 新增练习 |
| --- | --- | --- |
| “退回那笔款要留什么” | “那笔”是否有明确指代 | 保留上轮任务条件，含糊时先澄清 |
| “预付款上限和缺证明怎么处理” | 是否同时找到付款和资格条款 | 比较只取第一条与多证据回答 |
| 表格写 25%，脚注说特定日期起改为 20% | 解析与适用条件是否分离 | 保留表格位置、脚注与日期，标注冲突的处理 |
| 同一句话在多个版本出现 | 来源去重是否吞掉业务版本 | 按问题日期保留有效证据与可回查位置 |
| 同义表达与精确编号同时出现 | 稠密与字面召回分别漏什么 | 同题比较字面、向量、融合和重排 |

先在新评测导出中找出多证据题的失败，再修改取证或输出策略。将查询改写作为单独变量，保留原始问题，比较是否把金额、身份、时间等约束改丢。重排实验固定候选集合，生成实验固定证据，让失败能回到具体层。

## 比较上下文策略

接第25章的三轮任务变化，另外加入多轮工具结果，使上下文逐渐增长。准备三种策略，共用任务、模型、工具和总预算。

1. 保留完整历史，记录实际 token 用量及失败点。
2. 保留结构化任务事实与最近消息，旧工具输出只保留可重新取得的来源标识。
3. 对旧消息做摘要，再从持久记录重新取得任务、审批、日期与有效证据。

人为在旧消息中放一个已撤销的批准，再将活动项目由 P200 改为 P300。比较三种策略是否继续使用旧证据、是否遗漏缺件，以及摘要能否指回原始记录。模型生成的摘要只作为待核对表示，身份、批准和业务效果由可信记录确认。

记录每题的完成情况、错误类别、输入输出用量、工具次数和总耗时。字符数只用于本地文本规模观察，真实 token 计数采用实际模型或服务的口径。请另一人给出一项新条件，解释策略何时需要改变。[上下文工程参考](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

## 从观察走向模型选择

先列出当前失败是缺事实、缺指令、结构不稳、工具选择错误还是推理容量不足。分别选择补证据、改提示、约束输出、改工具说明或更换模型做一次对照。用固定集与新的留出题观察收益和退化。

如果进一步学习 SFT 或 LoRA，先给数据划分、授权范围、标注质量、泄漏检查与原模型基线，再做小规模训练。应用岗位的首轮项目可以先完成本页的机制解释与推理评测；训练专项按实际目标安排。

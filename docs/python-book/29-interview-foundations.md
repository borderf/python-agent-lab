# 第29章　原理面试：语言、工程与 AI 的追问

## 1. 学习目标与前置知识

把知识变成可推导、可验证的回答。前置：各卷核心章节。

## 2. 基础知识讲解

回答技术题先定义概念和适用边界，再给机制、小例子、工程影响和验证方式。遇到版本相关细节说明解释器/构建；不能把CPython观察说成所有Python规则。

工程面试不仅问“怎么用”，还会追问故障、并发、权限、事务和代价。AI面试还需要区分生成与计算、结构与事实、RAG与微调、模型能力与执行约束。

用本书每章口头题做第一次回答，再换输入和失败条件追问。卡住时回到实验而非再背一段长答案。

## 3. 原理讲解与推导

面试评估应依靠可迁移解释和项目证据，不是关键词数量。复杂题可以明确假设，再逐步收窄。

### 口述题、代码题与故障题

第一轮用90秒定义概念和边界；第二轮写十行代码证明；第三轮换一个条件推演。比如闭包题改为可变默认对象，异步题改为同步阻塞工具，RAG题改为旧版本与另一租户混入。

给出结论后说证据：实际实验、测试、故障记录或官方规则。不会的具体API说明如何查证，不用熟悉的术语覆盖不确定内容。

## 4. 示例与逐步走查

### 一道题的三层回答

题目：默认参数为什么会共享？先说明默认表达式在定义阶段求值；再写两次调用使用同一列表的实验；最后解释请求级默认对象如何造成状态串联，并给None/哨兵/工厂等适合场景的修复。

追问：默认值绑定的是字典或自定义对象呢？闭包里绑定可变对象是否自动复制？这时若只能背例子输出，说明机制还需要复习。

## 5. 动手练习

完成附录问答卡片：每题先90秒口述，追问再深入；对不清楚的机制写小实验。

## 6. 验收与自测

**行为验收：** 核心概念、反例、应用和限制四项齐全；承认不确定点并给查证办法。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

**提交证据：** 实现位置、运行命令、正常案例、至少一个错误/边界案例、一次失败原因和修复记录。自动检查只证明其覆盖行为；未实现任务不因示例通过而算完成。

## 7. 面试问答与迁移

随机抽取附录问题与本章的需求变化题，自评依据是什么？

回答顺序：定义与边界 → 机制 → 小例子 → 项目影响 → 验证方式。不确定的实现细节明确说明版本和查证办法。

## 8. 本章小结与参考

先达到行为与原理两类验收，再继续后续依赖本章的任务。遇到不熟悉的内容回到例子做小实验，不以阅读完成代替掌握。

官方参考：[本章资料](https://docs.python.org/3.12/reference/datamodel.html)。动态框架资料以2026-11-04核对的入口为准，具体SDK版本在实际实践时重新核对并记录锁文件。

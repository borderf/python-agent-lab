## 2. 基础知识讲解

前面已有函数和局部状态，现在把长期保留的模块环境、文件与外部格式放入同一程序。import增加名称绑定并可能触发模块执行；读文件建立资源与对象；序列化转换表示，不自动保持原对象的身份与共享关系。

### 2.1 把文件中的定义变成可复用模块

一个脚本同时包含订单规则、文件读取和命令解析时，别的程序想复用汇总函数，可能顺便触发读取与写文件。模块化要解决这个耦合：定义可以被导入，真正运行由入口决定。接下来再处理持久化：内存对象必须转成外部格式，读回后重建并校验，不能假定原对象身份跨文件保存。

订单计算已经写成函数，另一个文件也想使用它。把定义放进一个.py文件后，可以通过import取得这个模块，再访问其中的函数。先观察一次导入：模块顶层语句可能执行，函数定义建立函数对象，而函数体等调用才执行。因此先把计算定义与“立即读文件、启动网络”分开，再学习from导入、包和搜索路径。

脚本入口通常写在`if __name__ == "__main__":`下，由main组织过程。这样同一份业务模块被测试导入时，不会自动打印报告。不要把“业务函数定义完成”和“程序已经执行”混为一谈。

### 2.2 包结构、路径与运行方式

包组织相关模块；绝对导入从包名称表达依赖，相对导入描述包内关系。`python -m package.module`按包结构运行，直接执行文件路径则有不同的包上下文。当前工作目录决定相对文件路径，不一定是脚本所在目录。

导入失败时先确认解释器、安装包、包名和运行位置，再修改结构。随意向sys.path追加多个目录可能让错误暂时消失，却让测试和部署找到不同模块。

### 2.3 读取文件：路径、模式和编码

Path负责路径操作，open/read_text等负责内容。文本模式读写str，需要编码约定；二进制模式处理bytes。with明确关闭边界，错误路径同样需要处理。文件不存在、权限不足、编码不匹配是不同错误，不应一律转为空内容。

写出报告前说明覆盖规则：直接覆盖可能在失败时留下不完整内容；需要保留旧文件时可采用临时文件与替换策略，但其保证仍取决于文件系统和使用方式。

#### 案例推进：先跑通可控的文件往返

```python
# study-example: S07A
import json
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "orders.json"
    rows = [{"id":"A", "amount_cents":1990}]
    path.write_text(json.dumps(rows, ensure_ascii=False), encoding="utf-8")
    restored = json.loads(path.read_text(encoding="utf-8"))
    assert restored == rows
    assert type(restored[0]["amount_cents"]) is int
```

TemporaryDirectory让例子不依赖个人路径，并在退出时清理。Path组合路径，write_text负责文本到文件，json.dumps负责对象到JSON文本；两个步骤不能混为“保存对象”。读取时逆向进行，解析成功后仍需业务校验。

常见模式r读取，w截断写入，a追加，x要求新建；b表示字节模式。选择w之前明确是否允许覆盖，不能把“打开输出文件”放在输入校验之前而无意清空已有报告。需要原文件不受中途失败影响时，考虑同一文件系统内的临时写入与替换，并说明持久性边界。

### 2.4 序列化是格式转换，不是对象校验

json.loads把文本解析成Python对象，json.dumps把支持的对象转成文本；load/dump与打开文件配合。JSON数组通常变成list，对象变成dict；它没有完整的Python类型系统，日期、Decimal和自定义类需要显式转换。

CSV通过行列保存文本字段，逗号、引号和换行需由csv模块按格式处理。不能用split(',')可靠解析所有CSV，也不能假定读入的金额已经是整数。

#### 案例推进：让CSV模块处理CSV结构

```python
# study-example: S07B
import csv
from io import StringIO

buffer = StringIO(newline="")
writer = csv.DictWriter(buffer, fieldnames=["user", "amount_cents"])
writer.writeheader()
writer.writerow({"user":"Alice, Inc.", "amount_cents":1990})
buffer.seek(0)
row = next(csv.DictReader(buffer))
assert row["user"] == "Alice, Inc."
assert int(row["amount_cents"]) == 1990
```

字段里有逗号，writer按格式引用，reader正确还原。读回的金额仍是文本，需要转换和校验。真实文件配合open(..., newline="", encoding="utf-8")，让csv模块处理换行约定；不要手工split逗号或重复转义。

#### 现在回做JSONL：保留物理行号与惰性

```python
# study-example: S07D
import json
from io import StringIO
def iter_jsonl(lines):
    for line_number, line in enumerate(lines, start=1):
        if not line.strip():
            continue
        try:
            yield json.loads(line)
        except json.JSONDecodeError as exc:
            raise ValueError(f"第{line_number}行JSON损坏") from exc

stream = iter_jsonl(StringIO('{"id":"A"}\n\ninvalid\n'))
assert next(stream) == {"id":"A"}
try:
    next(stream)
except ValueError as exc:
    assert "第3行" in str(exc)
else:
    raise AssertionError("坏行必须报告真实位置")
```

这次把第五章的惰性消费与本章文件格式组合。空行不变成订单，也不改变后续错误的物理行号。真实文件由外层with拥有，迭代器负责解析；记录还需再经过业务校验，不能把合法JSON自动当作合法订单。

### 2.5 给程序一个明确的命令行接口

argparse描述输入路径、输出路径和选项。正常数据写stdout，错误说明写stderr，退出码表示是否完成。核心函数返回数据，main处理命令行和用户可理解反馈；这样同一业务逻辑也可被API或测试调用。

完成“读取→解析→业务校验→去重→汇总→写出”后，再按文件边界拆模块。每步输入输出明确，比一开始创建很多空目录更重要。

#### 案例推进：入口只负责装配与反馈

```python
# study-example: S07C
import argparse
def build_parser():
    parser = argparse.ArgumentParser(description="生成订单报告")
    parser.add_argument("input")
    parser.add_argument("--output", required=True)
    return parser

args = build_parser().parse_args(["orders.json", "--output", "report.json"])
assert args.input == "orders.json" and args.output == "report.json"
```

真实main取得参数，调用已有读取与计算，再输出结果；不要把核心规则只写在命令行分支里。`if __name__ == "__main__"`保护直接执行入口，import时只获得可复用定义。标准输出用于结果，标准错误用于诊断，退出码表达成功与失败。

模块是命名空间，包组织模块；python -m按包上下文运行。相对数据路径从当前工作目录解释，不自动相对源码文件。src布局项目通过安装得到可导入包，随手修改sys.path往往隐藏真实依赖。导入缓存与循环初始化再结合第三部分理解。

### 2.6 先完整写出，再替换旧文件：报告输出的失败边界

读取坏文件时拒绝处理还不够，输出失败也不应随意破坏上一份成功报告。直接用w打开目标会先截断它；若后续计算或写入失败，用户可能失去旧结果。先完成序列化，再在目标同目录创建临时文件，写好后替换，是一种常用的单文件交付方式。

```python
# study-example: S07E
import json
import os
from pathlib import Path
from tempfile import NamedTemporaryFile, TemporaryDirectory
def save_report(path, report):
    payload = json.dumps(report, ensure_ascii=False)
    temporary = None
    try:
        with NamedTemporaryFile("w", encoding="utf-8", dir=path.parent,
                                prefix="report-", suffix=".tmp", delete=False) as stream:
            temporary = Path(stream.name)
            stream.write(payload)
        os.replace(temporary, path)
    finally:
        if temporary is not None:
            temporary.unlink(missing_ok=True)

with TemporaryDirectory() as folder:
    path = Path(folder) / "report.json"
    path.write_text('{"old": true}', encoding="utf-8")
    try:
        save_report(path, {"bad": object()})
    except TypeError:
        pass
    else:
        raise AssertionError("对象不能直接JSON序列化")
    assert json.loads(path.read_text(encoding="utf-8")) == {"old": True}
    save_report(path, {"amount_cents": 1990})
    assert json.loads(path.read_text(encoding="utf-8")) == {"amount_cents": 1990}
    assert not list(Path(folder).glob("*.tmp"))
```

先json.dumps使本例的序列化失败发生在触碰旧文件之前。临时文件在同目录，关闭后才replace，兼顾Windows的文件句柄约束；finally清理剩余临时文件。父目录不存在或替换权限不足仍可失败，调用方应报告，不能返回“成功”。

这里讨论单文件替换，不承诺掉电后的持久性，也没有提供多个文件的一致事务或多写入者的冲突解决。需要更强保证时，还要研究flush/fsync、目录与文件系统语义、版本控制或数据库事务。先写清需求，再选择成本适合的方案。

### 2.7 JSON 文本解码时已经可能丢失信息

模型发送了同一个金额字段两次。进入校验器前，默认解码已经保留最后一个值，事后检查字典无法发现冲突。边界需要拒绝重复字段时，让解码器把每个对象的键值对序列先交给你，再构建字典。相同策略也作用于嵌套对象。

```python
# study-example: S07F
import json

def unique_fields(pairs):
    fields = {}
    for key, value in pairs:
        if key in fields:
            raise ValueError(f"重复字段 {key}")
        fields[key] = value
    return fields

raw = '{"tool":{"amount_cents":29,"amount_cents":99}}'
assert json.loads(raw)["tool"]["amount_cents"] == 99
try:
    json.loads(raw, object_pairs_hook=unique_fields)
except ValueError as error:
    assert "amount_cents" in str(error)
else:
    raise AssertionError("重复字段应在解码时失败")
```

练习：分别输入非法 JSON、重复字段、合法 JSON 但金额为 true。标出三个失败分别由语法解析、对象构造钩子和业务校验中的哪一步发现。若供应商 SDK 已把响应转成字典，注明你能检查的边界，从原始响应入口验收需要保真的字段。

## 3. 原理讲解与推导

### 3.1 导入缓存与名称绑定共同决定观察结果

首次正常导入会建立并执行模块，之后通常复用sys.modules中的对象。from导入绑定的是当时的对象；模块把属性重新绑定到另一个对象，并不自动重写调用方名称。若双方仍引用同一可变对象，原地修改又会被共同看到。

#### 模块不是一块让所有变量自动同步的存储区

模块的命名空间保存名称到对象的关联。import module让调用方取得模块对象，再通过module.name查询其当前属性；from module import name则在调用处增加一个名称绑定。若原模块后来重绑定name，调用处已有别名不会自动转向；若两边仍引用同一可变对象，原地修改则都可见。这与第1章second = first完全同源，不是导入产生了另一种赋值机制。

### 3.2 部分初始化解释循环导入

A导入B时，A的顶层代码可能尚未执行完；B反过来读取A某个尚未定义的对象，就会出问题。修复应考虑依赖方向、公共契约和入口位置，而不是随处延后import掩盖结构问题。

### 3.3 格式转换有损，业务含义需要另存

tuple转JSON再读取可能变成list，金额转文本可能失去单位，时间去掉时区可能失去绝对时刻。先定义可交换的数据契约，再检验往返语义；loads成功只说明文本可解析，不证明订单合法。

### 3.4 导入缓存、部分初始化与字节码缓存

模块导入通常通过sys.modules等机制复用已加载模块；正常再次import不意味着再次从头执行所有顶层语句。为支持导入过程，模块可能在顶层执行完成前就可被其他导入路径看到，因此循环导入可能遇到“模块存在，但所需名称尚未定义”的部分初始化状态。

解决这类问题先画依赖图：两个模块是否都同时承担业务和装配、能否提取共同契约、是否应由入口完成连接。延迟导入有时适用，但不能替代对循环依赖原因的理解。

CPython可能把编译结果缓存为.pyc以减少后续编译成本，这不意味着业务逻辑已经执行，也不保证每次运行的业务计算更快。源码、编译产物、模块对象和程序运行结果处于不同层次，回到第一章的执行分层便能区分。

## 4. 示例与逐步走查

```python
# book-example: B07
import json
from pathlib import Path
from tempfile import TemporaryDirectory
with TemporaryDirectory() as folder:
    path = Path(folder) / "sample.json"
    path.write_text(json.dumps({"user":"甲"}, ensure_ascii=False), encoding="utf-8")
    assert json.loads(path.read_text(encoding="utf-8")) == {"user":"甲"}
```

### 4.1 沿输入到结果逐步解释

程序先把Python字典序列化为JSON文本，再以UTF-8把文本写成文件字节。读取时顺序相反：先按UTF-8得到str，再解析JSON得到新字典。

两次转换为什么不能混成一步？JSON决定对象结构怎样表达，UTF-8决定文字怎样表达为字节。把编码改错会损坏文本；把JSON结构写错则是解析问题，即使字节编码完全正确也可能失败。

读回的值相等不表示同一对象被搬过文件。另一个进程可以从相同字节建立自己的对象；内存身份和内部共享关系需要单独设计，不能靠JSON往返保留。

## 8. 本章小结与参考

### 8.1 主要知识点总结

- 模块组织长期存在的名称环境；导入和直接运行有不同入口。
- 路径、文件内容与编码分别处理，文件到业务值需要解析和校验。
- JSON、CSV等外部表示不自动保留原对象身份、共享关系或全部Python类型。
- 命令行程序应有明确参数、退出状态、错误位置与输出文件策略。

### 8.2 日常工作注意事项

- 避免在模块导入时读业务文件或启动网络请求；将运行入口放在明确函数和__main__判断中，方便测试与复用。
- 不要把工作目录当作固定路径。让输入输出位置由参数或明确配置提供，并在另一个目录验证启动。
- 不可信内容不要交给eval或pickle反序列化；输出报告先完成校验与计算，按约定发布文件，防止坏输入覆盖旧结果。

## 2. 基础知识讲解
按“可导入 → 可读取 → 可校验 → 可交付”推进，四步始终使用同一份订单输入。
### 2.1 模块把定义与启动分开
`.py` 文件定义函数和类，`import` 取得模块中的名称。导入时模块顶层语句会执行，函数体则等调用才执行；因此业务模块不能一被导入就读文件或打印报告。启动代码放在 `main()` 和 `if __name__ == "__main__":` 下。
包组织多个模块，`python -m package.module` 按包上下文运行。相对数据路径从当前工作目录解释，不从源码文件位置猜测；输入输出应作为参数传入。循环导入时先画依赖方向，不要靠到处延迟导入掩盖问题。
编译和执行也是两件事：`compile` 只生成代码对象，`exec` 才在给定命名空间执行。
```python
# experiment: E01
source = "result = 1 + 2"
code = compile(source, "<own-example>", "exec")
namespace = {}
exec(code, namespace)
assert namespace["result"] == 3
try: compile("if True print(1)", "<bad-example>", "exec")
except SyntaxError: pass
else: raise AssertionError("应在编译阶段失败")
```
### 2.2 文件读写与 JSON 是两层转换
`Path` 组合路径，`read_text`/`write_text` 处理 UTF-8 文本，`with open(...)` 明确关闭边界。`json.dumps` 把支持的对象转成文本，`json.loads` 再解析成通用 Python 对象；它不是保存对象身份，也不自动恢复日期、Decimal 或自定义类。
JSON 数组读回为 list，对象读回为 dict；tuple 会变成 list。JSON 能解析只说明语法通过，不证明字段和金额合法。CSV 必须用 `csv` 模块处理逗号、引号和换行，不能手工 `split(",")`；读回的金额仍是文本。
格式转换保留约定字段，不保留全部 Python 类型和对象身份；默认 JSON 解码还会保留重复键的最后一个值。`json.dumps` 返回文本，`json.dump` 写入文件流；两者默认都允许 `NaN/Infinity` 这类非标准 JSON 值，严格交换时应显式设置 `allow_nan=False`。

文件模式也要明确：`"w"` 会截断旧文件，`"a"` 追加，`"x"` 拒绝已存在路径。文本文件用 `encoding="utf-8"`；CSV 读写增加 `newline=""`，让 `csv` 模块自己处理引号、逗号和换行，避免不同操作系统重复转换换行。
```python
import csv
from pathlib import Path
from tempfile import TemporaryDirectory
with TemporaryDirectory() as folder:
    path = Path(folder) / "orders.csv"
    with path.open("w", encoding="utf-8", newline="") as stream:
        writer = csv.writer(stream)
        writer.writerow(["id", "user", "amount_cents"])
        writer.writerow(["A", "Alice, \"A\"", 1990])
    with path.open("r", encoding="utf-8", newline="") as stream:
        rows = list(csv.DictReader(stream))
assert rows == [{"id": "A", "user": "Alice, \"A\"", "amount_cents": "1990"}]
```
读回的金额仍是文本，必须显式转换并校验；CSV 能正确往返结构，不等于字段已经满足订单契约。
```python
# experiment: E19
import json
from datetime import datetime
original = (1, 2); restored = json.loads(json.dumps(original))
assert restored == [1, 2] and type(restored) is list
assert json.loads('{"id":1,"id":2}') == {"id": 2}
left = datetime.fromisoformat("2026-11-04T10:00:00+08:00")
right = datetime.fromisoformat("2026-11-04T02:00:00+00:00")
assert left == right
```
### 2.3 逐行解析后，还要验证订单契约
JSONL 一行一个 JSON 对象。读取时保留物理行号：空行跳过但不重置计数，坏 JSON 抛带行号的 `ValueError`，并用 `from exc` 保留异常链。生成器只在消费时解析，调用方提前停止时由外层 `with` 关闭文件。
进入汇总前检查四件事：字段恰好为 `id/user/amount_cents/status`；ID 和用户名去空白后非空；金额是排除 bool 的非负整数；状态属于 paid/pending/cancelled。重复 ID 内容相同可去重，内容不同必须报冲突。
### 2.4 CLI 负责装配，报告先完整写出再替换
`argparse` 接收输入和 `--output`。核心函数返回报告字典，`main` 调用读取、校验、汇总和保存；正常结果写 stdout，错误写 stderr，成功返回0，失败返回1。业务函数不直接退出进程。
输出前先完成整个 `json.dumps`，再写同目录临时文件，关闭后替换目标。这样序列化失败不会触碰旧报告；`finally` 清理临时文件。PID 只能区分不同进程，不能避免同一进程内并发写同一目标时临时文件重名；生产实现应在目标目录创建唯一临时文件，并在需要时用锁或版本规则决定最终写入者。替换通常是同一文件系统内的原子改名，但不是掉电持久性或跨文件事务，父目录不存在、权限不足仍要明确失败。
#### 案例推进：序列化失败时旧报告仍可读
```python
# study-example: S07E
import json, os
from pathlib import Path
from tempfile import TemporaryDirectory
def save_report(path, report):
    payload = json.dumps(report, ensure_ascii=False)
    target = Path(path); temporary = target.with_name(f"{target.name}.{os.getpid()}.tmp")
    try:
        temporary.write_text(payload, encoding="utf-8"); temporary.replace(target)
    finally: temporary.unlink(missing_ok=True)
    return payload
with TemporaryDirectory() as folder:
    path = Path(folder) / "report.json"; path.write_text('{"old":true}', encoding="utf-8")
    try: save_report(path, {"bad": object()})
    except TypeError: pass
    else: raise AssertionError("对象不能直接序列化")
    assert json.loads(path.read_text(encoding="utf-8")) == {"old": True}
    save_report(path, {"paid_amount_cents": 1990})
    assert json.loads(path.read_text(encoding="utf-8")) == {"paid_amount_cents": 1990}
    assert not list(Path(folder).glob("*.tmp"))
```
## 3. 原理讲解与推导
### 3.1 导入缓存让定义只执行一次，名称绑定仍是一次赋值
标准导入先查 `sys.modules`；首次加载时创建模块对象，再执行顶层代码。再次导入通常复用同一对象，所以顶层定义不重复执行；循环导入却可能拿到“模块已登记、名称尚未定义”的部分初始化状态。
`import module` 让调用方通过模块属性查询当前绑定；`from module import name` 在调用处建立一次名称绑定。原模块后来重新赋值 `name`，调用处的旧绑定不跟随；若双方仍引用同一个可变对象，原地修改则都能看到。这就是第1章的重绑定模型。
```python
# experiment: E17
import importlib, sys
from pathlib import Path
from tempfile import TemporaryDirectory
name = "principles_import_demo"
with TemporaryDirectory() as folder:
    Path(folder, name + ".py").write_text("value = 1\n", encoding="utf-8")
    sys.path.insert(0, folder)
    try:
        first = importlib.import_module(name); second = importlib.import_module(name)
        assert first is second
        from principles_import_demo import value
        first.value = 2
        assert value == 1 and second.value == 2
    finally: sys.path.remove(folder); sys.modules.pop(name, None)
```
## 4. 示例与逐步走查
仓库已有两个真实文件，下面按“读取与计算 → 写出与退出 → 契约自检”三步走查。输入文件是 `practice/chapter_labs/ch07_report/data/orders.jsonl`：
```jsonl
{"id":"A","user":"Alice","amount_cents":1990,"status":"paid"}
{"id":"B","user":"Bob","amount_cents":1000,"status":"pending"}
```
### 4.1 读取与计算：orders_core.py
#### 案例推进：逐行读取，先校验再汇总
`orders_core.py` 负责逐行解析、校验、去重和汇总，导入时不启动批处理。
```python
# file: practice/chapter_labs/ch07_report/orders_core.py
import json
FIELDS = {"id", "user", "amount_cents", "status"}
STATUSES = {"paid", "pending", "cancelled"}
def validate_order(row):
    if not isinstance(row, dict) or set(row) != FIELDS:
        raise ValueError("订单字段必须恰好是 id/user/amount_cents/status")
    for field in ("id", "user"):
        value = row[field]
        if not isinstance(value, str) or not value.strip(): raise ValueError(f"{field} 必须是非空文本")
    amount = row["amount_cents"]
    if type(amount) is not int or amount < 0: raise ValueError("amount_cents 必须为非负整数分")
    if not isinstance(row["status"], str) or row["status"] not in STATUSES:
        raise ValueError(f"非法订单状态: {row['status']!r}")
    return {"id": row["id"].strip(), "user": row["user"].strip(),
            "amount_cents": amount, "status": row["status"]}
def load_orders(path):
    with open(path, encoding="utf-8") as stream:
        for line_number, text in enumerate(stream, 1):
            if not text.strip(): continue
            try: row = json.loads(text)
            except json.JSONDecodeError as exc: raise ValueError(f"第{line_number}行不是合法JSON") from exc
            try: yield validate_order(row)
            except ValueError as exc: raise ValueError(f"第{line_number}行: {exc}") from exc
def report(rows):
    by_id, conflicts = {}, []
    for row in rows:
        key = row["id"]
        if key not in by_id: by_id[key] = row
        elif by_id[key] != row: conflicts.append(key)
    if conflicts: raise ValueError("冲突:" + ",".join(sorted(set(conflicts))))
    paid = [row for row in by_id.values() if row["status"] == "paid"]
    return {"order_count": len(by_id),
            "paid_amount_cents": sum(row["amount_cents"] for row in paid)}
```
A、B 的 ID 不同，都保留；只有 A 已支付，所以汇总为2单、1990分。
### 4.2 写出与退出：report_cli.py
#### 案例推进：先写完整，再替换旧报告
`report_cli.py` 只解析参数、调用核心函数、保存并反馈。写出与读取放在同一个 `try` 中，任一失败都返回1。
```python
# file: practice/chapter_labs/ch07_report/report_cli.py
import argparse, json, os, sys
from pathlib import Path
from .orders_core import load_orders, report
def save_report(path, result):
    payload = json.dumps(result, ensure_ascii=False)
    target = Path(path); temporary = target.with_name(f"{target.name}.{os.getpid()}.tmp")
    try:
        temporary.write_text(payload, encoding="utf-8"); temporary.replace(target)
    finally: temporary.unlink(missing_ok=True)
    return payload
def main(argv=None):
    parser = argparse.ArgumentParser(description="生成订单报告")
    parser.add_argument("input"); parser.add_argument("--output", required=True)
    args = parser.parse_args(argv)
    try:
        result = report(load_orders(args.input)); payload = save_report(args.output, result)
    except (OSError, ValueError) as exc:
        print(f"失败:{exc}", file=sys.stderr); return 1
    print(payload); return 0
if __name__ == "__main__": raise SystemExit(main())
```
在仓库根目录运行：
```powershell
python -X utf8 -m practice.chapter_labs.ch07_report.report_cli practice/chapter_labs/ch07_report/data/orders.jsonl --output .learning-labs/report.json
```
目标父目录必须已存在。正常时 stdout 为 `{"order_count": 2, "paid_amount_cents": 1990}`，退出码0。换成 `data/bad.jsonl` 时，第2行解析失败，旧报告不变；换成 `data/conflict.jsonl` 时，汇总发现 A 冲突，旧报告也不变。
### 4.3 契约自检：B07 验证真实实现
#### 案例推进：合法记录与七类坏记录
B07 从真实模块导入 `validate_order`，不是另写替身。它检查合法记录原样通过，以及 None、数字、错误字段类型、空 ID、空用户名和非法状态均被拒绝。
```python
# book-example: B07
from practice.chapter_labs.ch07_report.orders_core import validate_order
good = {"id": "A", "user": "Alice", "amount_cents": 1990, "status": "paid"}
assert validate_order(good) == good
for bad in (None, 1,
            {"id": [], "user": "Alice", "amount_cents": 1, "status": "paid"},
            {"id": " ", "user": "Alice", "amount_cents": 1, "status": "paid"},
            {"id": "A", "user": " ", "amount_cents": 1, "status": "paid"},
            {"id": "A", "user": "Alice", "amount_cents": 1, "status": "paidd"},
            {"id": "A", "user": "Alice", "amount_cents": 1, "status": []}):
    try: validate_order(bad)
    except ValueError: pass
    else: raise AssertionError(f"应拒绝: {bad!r}")
```
## 5. 动手练习
### 本章累计任务：从文件交付报告
沿现有两个模块完整跑通正常、坏末行、冲突和非法字段四种输入。前三类失败分别定位到解析、去重和单条校验；它们都必须非零退出，旧报告仍可解析。禁止把业务规则复制进 CLI。
第8章接收 `load_orders`、`report`、`save_report` 和 CLI 入口，只增加日期统计与 SQLite 持久化。
### L15：文件与异常分类（P28）
不存在文件保留 `FileNotFoundError`；坏 JSON 包装为带行号的 `ValueError`，`__cause__` 保留 `JSONDecodeError`；字段错误是业务 `ValueError`。CLI 向 stderr 反馈并非零退出，正常结果写 stdout。
验收：三类错误分别测试，坏行有真实位置，不能统一返回空列表；每个测试使用独立 `tmp_path`。
### L16：CSV 与序列化往返（P29）
用 `csv` 模块导出再读入含中文、逗号、引号的用户名和整数分；金额显式转换并校验。datetime/Money 转 JSON 时定义字段格式，不用 `default=str` 模糊所有类型。
验收：业务记录往返相等，带逗号字段不损坏，坏行被拒绝。
### L12：惰性 JSONL（P17–20）
逐行解析并跳过空行，订单错误带1起始的物理行号。第一行合法、第二行空、第三行坏 JSON 时，只取第一条不触发第三行错误，继续消费才报第3行。
验收：不先读全文件伪装生成器；提前停止和异常都关闭文件。

## 7. 面试问答与迁移
**问：为什么导入通常不重复执行顶层代码？** 标准导入先查 `sys.modules`，已加载模块复用缓存对象。清除缓存、reload 或使用不同模块名可能再次执行，不能承诺副作用永远只发生一次。
**问：为什么 JSON 合法不代表订单合法？** JSON 只构造通用数据，不保证字段、单位、状态和权限。格式解析之后还要验证业务契约，重复键等保真问题甚至要在解码时处理。
**问：CLI 为什么不应直接 `exit`？** 核心函数返回数据或抛错，入口统一处理参数、输出和退出码，同一规则才能被测试或其他调用方复用。
**迁移：** 把 JSONL 来源换成 HTTP 响应时，保留“解析 → 校验 → 去重 → 汇总”的顺序；外部状态码、超时和重试另设边界，不能塞进金额计算。
## 8. 本章小结与参考
- 模块承载定义，入口承载启动；导入副作用会让测试和复用不可预测。
- 文件编码、JSON/CSV 解析和业务校验是三层，任何一层通过都不代替下一层。
- JSONL 错误带物理行号；重复键、类型丢失等保真问题要按入口处理。
- CLI 只装配参数、调用核心函数和反馈结果，成功与失败用退出码区分。
- 报告先序列化、再临时写入并替换，保护旧结果；不承诺掉电持久性。

# 第07章　从模块到可运行报告

## 1. 学习目标与前置知识

组织可导入模块，处理外部文本，并提供稳定 CLI。前置：第3–6章。

**承接与本章主线：** 把函数和对象放入模块环境，再接文件与序列化；产出可从命令行运行的程序，供标准库、类型和测试章节继续完善。

**本章从这里开始：** 订单规则已经可以计算，但要让它读取真实文件、被其他模块复用并通过终端使用。接下来把同一个程序分清导入、读取、解析、校验和输出。

## 2. 基础知识讲解

前面已有函数和局部状态，现在把长期保留的模块环境、文件与外部格式放入同一程序。import增加名称绑定并可能触发模块执行；读文件建立资源与对象；序列化转换表示，不自动保持原对象的身份与共享关系。

本章分两段推进：2.1–2.2 先让代码“可被导入、可被复用”，解决命名空间和包边界；2.3–2.7 再让程序“可读取、可校验、可交付”，解决文件、格式、输出和命令行入口。两段共用同一批订单，不换数据。

### 2.1 把文件中的定义变成可复用模块

一个脚本同时包含订单规则、文件读取和命令解析时，别的程序想复用汇总函数，可能顺便触发读取与写文件。模块化要解决这个耦合：定义可以被导入，真正运行由入口决定。接下来再处理持久化：内存对象必须转成外部格式，读回后重建并校验，不能假定原对象身份跨文件保存。

订单计算已经写成函数，另一个文件也想使用它。把定义放进一个.py文件后，可以通过import取得这个模块，再访问其中的函数。先观察一次导入：模块顶层语句可能执行，函数定义建立函数对象，而函数体等调用才执行。因此先把计算定义与“立即读文件、启动网络”分开，再学习from导入、包和搜索路径。

脚本入口通常写在`if __name__ == "__main__":`下，由main组织过程。这样同一份业务模块被测试导入时，不会自动打印报告。不要把“业务函数定义完成”和“程序已经执行”混为一谈。

### 2.2 包结构、路径与运行方式

包组织相关模块；绝对导入从包名称表达依赖，相对导入描述包内关系。`python -m package.module`按包结构运行，直接执行文件路径则有不同的包上下文。当前工作目录决定相对文件路径，不一定是脚本所在目录。

导入失败时先确认解释器、安装包、包名和运行位置，再修改结构。随意向sys.path追加多个目录可能让错误暂时消失，却让测试和部署找到不同模块。

### 2.3 读取文件：路径、模式和编码

Path负责路径操作，open/read_text等负责内容。文本模式读写str，需要编码约定；二进制模式处理bytes。with明确关闭边界，错误路径同样需要处理。文件不存在、权限不足、编码不匹配是不同错误，不应一律转为空内容。

写出报告前说明覆盖规则：直接覆盖可能在失败时留下不完整内容；需要保留旧文件时可采用临时文件与替换策略，但其保证仍取决于文件系统和使用方式。

#### 案例推进：先跑通可控的文件往返

```python
# study-example: S07A
import json
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "orders.json"
    rows = [{"id":"A", "amount_cents":1990}]
    path.write_text(json.dumps(rows, ensure_ascii=False), encoding="utf-8")
    restored = json.loads(path.read_text(encoding="utf-8"))
    assert restored == rows
    assert type(restored[0]["amount_cents"]) is int
```

TemporaryDirectory让例子不依赖个人路径，并在退出时清理。Path组合路径，write_text负责文本到文件，json.dumps负责对象到JSON文本；两个步骤不能混为“保存对象”。读取时逆向进行，解析成功后仍需业务校验。

常见模式r读取，w截断写入，a追加，x要求新建；b表示字节模式。选择w之前明确是否允许覆盖，不能把“打开输出文件”放在输入校验之前而无意清空已有报告。需要原文件不受中途失败影响时，考虑同一文件系统内的临时写入与替换，并说明持久性边界。

### 2.4 序列化是格式转换，不是对象校验

json.loads把文本解析成Python对象，json.dumps把支持的对象转成文本；load/dump与打开文件配合。JSON数组通常变成list，对象变成dict；它没有完整的Python类型系统，日期、Decimal和自定义类需要显式转换。

CSV通过行列保存文本字段，逗号、引号和换行需由csv模块按格式处理。不能用split(',')可靠解析所有CSV，也不能假定读入的金额已经是整数。

#### 案例推进：让CSV模块处理CSV结构

```python
# study-example: S07B
import csv
from io import StringIO

buffer = StringIO(newline="")
writer = csv.DictWriter(buffer, fieldnames=["user", "amount_cents"])
writer.writeheader()
writer.writerow({"user":"Alice, Inc.", "amount_cents":1990})
buffer.seek(0)
row = next(csv.DictReader(buffer))
assert row["user"] == "Alice, Inc."
assert int(row["amount_cents"]) == 1990
```

字段里有逗号，writer按格式引用，reader正确还原。读回的金额仍是文本，需要转换和校验。真实文件配合open(..., newline="", encoding="utf-8")，让csv模块处理换行约定；不要手工split逗号或重复转义。

#### 现在回做JSONL：保留物理行号与惰性

```python
# study-example: S07D
import json
from io import StringIO
def iter_jsonl(lines):
    for line_number, line in enumerate(lines, start=1):
        if not line.strip():
            continue
        try:
            yield json.loads(line)
        except json.JSONDecodeError as exc:
            raise ValueError(f"第{line_number}行JSON损坏") from exc

stream = iter_jsonl(StringIO('{"id":"A"}\n\ninvalid\n'))
assert next(stream) == {"id":"A"}
try:
    next(stream)
except ValueError as exc:
    assert "第3行" in str(exc)
else:
    raise AssertionError("坏行必须报告真实位置")
```

这次把第五章的惰性消费与本章文件格式组合。空行不变成订单，也不改变后续错误的物理行号。真实文件由外层with拥有，迭代器负责解析；记录还需再经过业务校验，不能把合法JSON自动当作合法订单。

JSON文本能解析，不代表字段没有在解码时丢失。下一节处理“重复字段已经被覆盖”的情况，再决定报告怎样安全写出。

### 2.5 JSON 文本解码时已经可能丢失信息

模型发送了同一个金额字段两次。进入校验器前，默认解码已经保留最后一个值，事后检查字典无法发现冲突。边界需要拒绝重复字段时，让解码器把每个对象的键值对序列先交给你，再构建字典。相同策略也作用于嵌套对象。

```python
# study-example: S07F
import json

def unique_fields(pairs):
    fields = {}
    for key, value in pairs:
        if key in fields:
            raise ValueError(f"重复字段 {key}")
        fields[key] = value
    return fields

raw = '{"tool":{"amount_cents":29,"amount_cents":99}}'
assert json.loads(raw)["tool"]["amount_cents"] == 99
try:
    json.loads(raw, object_pairs_hook=unique_fields)
except ValueError as error:
    assert "amount_cents" in str(error)
else:
    raise AssertionError("重复字段应在解码时失败")
```

练习：分别输入非法 JSON、重复字段、合法 JSON 但金额为 true。标出三个失败分别由语法解析、对象构造钩子和业务校验中的哪一步发现。若供应商 SDK 已把响应转成字典，注明你能检查的边界，从原始响应入口验收需要保真的字段。

### 2.6 先完整写出，再替换旧文件：报告输出的失败边界

读取坏文件时拒绝处理还不够，输出失败也不应随意破坏上一份成功报告。直接用w打开目标会先截断它；若后续计算或写入失败，用户可能失去旧结果。先完成序列化，再在目标同目录创建临时文件，写好后替换，是一种常用的单文件交付方式。

```python
# study-example: S07E
import json
import os
from pathlib import Path
from tempfile import NamedTemporaryFile, TemporaryDirectory
def save_report(path, report):
    payload = json.dumps(report, ensure_ascii=False)
    temporary = None
    try:
        with NamedTemporaryFile("w", encoding="utf-8", dir=path.parent,
                                prefix="report-", suffix=".tmp", delete=False) as stream:
            temporary = Path(stream.name)
            stream.write(payload)
        os.replace(temporary, path)
    finally:
        if temporary is not None:
            temporary.unlink(missing_ok=True)

with TemporaryDirectory() as folder:
    path = Path(folder) / "report.json"
    path.write_text('{"old": true}', encoding="utf-8")
    try:
        save_report(path, {"bad": object()})
    except TypeError:
        pass
    else:
        raise AssertionError("对象不能直接JSON序列化")
    assert json.loads(path.read_text(encoding="utf-8")) == {"old": True}
    save_report(path, {"amount_cents": 1990})
    assert json.loads(path.read_text(encoding="utf-8")) == {"amount_cents": 1990}
    assert not list(Path(folder).glob("*.tmp"))
```

先json.dumps使本例的序列化失败发生在触碰旧文件之前。临时文件在同目录，关闭后才replace，兼顾Windows的文件句柄约束；finally清理剩余临时文件。父目录不存在或替换权限不足仍可失败，调用方应报告，不能返回“成功”。

这里讨论单文件替换，不承诺掉电后的持久性，也没有提供多个文件的一致事务或多写入者的冲突解决。需要更强保证时，还要研究flush/fsync、目录与文件系统语义、版本控制或数据库事务。先写清需求，再选择成本适合的方案。

报告能安全写出后，最后给它一个稳定入口：命令行只负责装配参数、调用核心函数和反馈结果，不把业务规则复制到入口里。

### 2.7 给程序一个明确的命令行接口

argparse描述输入路径、输出路径和选项。正常数据写stdout，错误说明写stderr，退出码表示是否完成。核心函数返回数据，main处理命令行和用户可理解反馈；这样同一业务逻辑也可被API或测试调用。

先在纸上列清“读取→解析→业务校验→去重→汇总→写出”每一步的输入输出，再按职责建立核心模块（校验/汇总）和入口模块（参数/反馈），最后逐步接通管道。每步输入输出明确，比一开始创建很多空目录更重要；本章 4 节的两个真实文件就是这种拆分的结果。

#### 案例推进：入口只负责装配与反馈

```python
# study-example: S07C
import argparse
def build_parser():
    parser = argparse.ArgumentParser(description="生成订单报告")
    parser.add_argument("input")
    parser.add_argument("--output", required=True)
    return parser

args = build_parser().parse_args(["orders.json", "--output", "report.json"])
assert args.input == "orders.json" and args.output == "report.json"
```

真实main取得参数，调用已有读取与计算，再输出结果；不要把核心规则只写在命令行分支里。`if __name__ == "__main__"`保护直接执行入口，import时只获得可复用定义。标准输出用于结果，标准错误用于诊断，退出码表达成功与失败。

模块是命名空间，包组织模块；python -m按包上下文运行。相对数据路径从当前工作目录解释，不自动相对源码文件。src布局项目通过安装得到可导入包，随手修改sys.path往往隐藏真实依赖。导入缓存与循环初始化再结合第三部分理解。

## 3. 原理讲解与推导

### 3.1 导入缓存与名称绑定共同决定观察结果

首次正常导入会建立并执行模块，之后通常复用sys.modules中的对象。from导入绑定的是当时的对象；模块把属性重新绑定到另一个对象，并不自动重写调用方名称。若双方仍引用同一可变对象，原地修改又会被共同看到。

#### 模块不是一块让所有变量自动同步的存储区

模块的命名空间保存名称到对象的关联。import module让调用方取得模块对象，再通过module.name查询其当前属性；from module import name则在调用处增加一个名称绑定。若原模块后来重绑定name，调用处已有别名不会自动转向；若两边仍引用同一可变对象，原地修改则都可见。这与第1章second = first完全同源，不是导入产生了另一种赋值机制。

### 3.2 部分初始化解释循环导入

A导入B时，A的顶层代码可能尚未执行完；B反过来读取A某个尚未定义的对象，就会出问题。修复应考虑依赖方向、公共契约和入口位置，而不是随处延后import掩盖结构问题。

### 3.3 格式转换有损，业务含义需要另存

tuple转JSON再读取可能变成list，金额转文本可能失去单位，时间去掉时区可能失去绝对时刻。先定义可交换的数据契约，再检验往返语义；loads成功只说明文本可解析，不证明订单合法。

### 3.4 导入缓存、部分初始化与字节码缓存

模块导入通常通过sys.modules等机制复用已加载模块；正常再次import不意味着再次从头执行所有顶层语句。为支持导入过程，模块可能在顶层执行完成前就可被其他导入路径看到，因此循环导入可能遇到“模块存在，但所需名称尚未定义”的部分初始化状态。

解决这类问题先画依赖图：两个模块是否都同时承担业务和装配、能否提取共同契约、是否应由入口完成连接。延迟导入有时适用，但不能替代对循环依赖原因的理解。

CPython可能把编译结果缓存为.pyc以减少后续编译成本，这不意味着业务逻辑已经执行，也不保证每次运行的业务计算更快。源码、编译产物、模块对象和程序运行结果处于不同层次，回到第一章的执行分层便能区分。

`orders_core.py` 负责读取、逐条校验、去重和汇总，不在导入时执行批处理：

```python
# file: practice/chapter_labs/ch07_report/orders_core.py
"""Order report example for chapter 7: strict input, dedupe, totals."""

import json

FIELDS = {"id", "user", "amount_cents", "status"}
STATUSES = {"paid", "pending", "cancelled"}


def validate_order(row):
    """Return a normalized copy; reject anything outside the order contract."""
    if not isinstance(row, dict) or set(row) != FIELDS:
        raise ValueError("订单字段必须恰好是 id/user/amount_cents/status")
    for field in ("id", "user"):
        value = row[field]
        if not isinstance(value, str) or not value.strip():
            raise ValueError(f"{field} 必须是非空文本")
    amount = row["amount_cents"]
    if type(amount) is not int or amount < 0:
        raise ValueError("amount_cents 必须是非负整数分")
    status = row["status"]
    if not isinstance(status, str) or status not in STATUSES:
        raise ValueError(f"非法订单状态: {status!r}")
    return {"id": row["id"].strip(), "user": row["user"].strip(),
            "amount_cents": amount, "status": status}


def load_orders(path):
    with open(path, encoding="utf-8") as stream:
        for line_number, text in enumerate(stream, 1):
            if not text.strip():
                continue
            try:
                row = json.loads(text)
            except json.JSONDecodeError as exc:
                raise ValueError(f"第{line_number}行不是合法JSON") from exc
            try:
                yield validate_order(row)
            except ValueError as exc:
                raise ValueError(f"第{line_number}行: {exc}") from exc


def report(rows):
    by_id, conflicts = {}, []
    for row in rows:
        key = row["id"]
        if key not in by_id:
            by_id[key] = row
        elif by_id[key] != row:
            conflicts.append(key)
    if conflicts:
        raise ValueError("冲突:" + ",".join(sorted(set(conflicts))))
    paid = [row for row in by_id.values() if row["status"] == "paid"]
    return {"order_count": len(by_id),
            "paid_amount_cents": sum(row["amount_cents"] for row in paid)}
```

`report_cli.py` 只做参数、调用和反馈；安全写出复用本章 2.6 的“临时文件 + 替换 + finally 清理”：

```python
# file: practice/chapter_labs/ch07_report/report_cli.py
"""Run the chapter 7 order report CLI against a JSONL file."""

import argparse
import json
import os
from pathlib import Path
import sys

from .orders_core import load_orders, report


def save_report(path, result):
    payload = json.dumps(result, ensure_ascii=False)
    target = Path(path)
    temporary = target.with_name(f"{target.name}.{os.getpid()}.tmp")
    try:
        temporary.write_text(payload, encoding="utf-8")
        temporary.replace(target)
    finally:
        temporary.unlink(missing_ok=True)
    return payload


def main(argv=None):
    parser = argparse.ArgumentParser(description="生成订单报告")
    parser.add_argument("input")
    parser.add_argument("--output", required=True)
    args = parser.parse_args(argv)
    try:
        result = report(load_orders(args.input))
        payload = save_report(args.output, result)
    except (OSError, ValueError) as exc:
        print(f"失败:{exc}", file=sys.stderr)
        return 1
    print(payload)
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

正常输出 `{"order_count": 2, "paid_amount_cents": 1990}`，退出码为 0。程序**不自动创建父目录**：如果跳过第一行、直接写到不存在的目录，`save_report`会抛`FileNotFoundError`，CLI返回1；这也是“失败不破坏旧报告”的一部分。把输入换成 `data/bad.jsonl` 或 `data/conflict.jsonl`，退出码应为 1，`.learning-labs/report.json` 保持上一次成功内容。

下面是最小契约自检；完整 CLI 的进程验收在 `tests/test_chapter07_cli.py`，不在正文里生成临时模块。

```python
# book-example: B07
from practice.chapter_labs.ch07_report.orders_core import validate_order

good = {"id": "A", "user": "Alice", "amount_cents": 1990, "status": "paid"}
assert validate_order(good) == good
for bad in (None, 1,
            {"id": [], "user": "Alice", "amount_cents": 1, "status": "paid"},
            {"id": " ", "user": "Alice", "amount_cents": 1, "status": "paid"},
            {"id": "A", "user": " ", "amount_cents": 1, "status": "paid"},
            {"id": "A", "user": "Alice", "amount_cents": 1, "status": "paidd"},
            {"id": "A", "user": "Alice", "amount_cents": 1, "status": []}):
    try:
        validate_order(bad)
    except ValueError:
        pass
    else:
        raise AssertionError(f"应拒绝: {bad!r}")
```

### 4.1 沿输入到结果逐步解释

第一次运行：命令行解析参数，导入`orders_core`；`load_orders`逐行读取，`validate_order`检查字典形状、字段、非空文本、整数分和状态；`report`按ID去重，只汇总已支付记录，得到`{"order_count":2,"paid_amount_cents":1990}`；`save_report`写入临时文件并替换`report.json`，退出码0。

第二次把末行截断：`load_orders`在第2行抛`ValueError`；`main`捕获后返回1。此时`save_report`还没有执行，所以旧`report.json`仍是第一次的完整内容。

第三次给同ID A两个金额：`report`发现冲突并抛`ValueError`，同样在写出之前失败。若把状态写成`paidd`，`validate_order`在进入汇总前就拒绝；`null`、数字、列表ID、空ID/用户名也都在同一处失败，而不是等到`by_id`报`TypeError`或把空值当成正常订单。

写出也放进同一个`try`：`save_report`使用带进程号的临时文件，`finally`清理残留；父目录不存在、权限不足等`OSError`会让CLI返回1，而不是从入口直接抛出。把`report`中的冲突判断或状态过滤删掉，`tests/test_chapter07_cli.py`会失败；B07 只是单条记录的契约自检，完整进程验收在测试脚本里。

真实项目里两个模块会分目录、由包安装或`PYTHONPATH`提供，但导入关系、入口分工和失败顺序不变。

## 7. 面试问答与迁移

import 为什么通常不会重复执行？from import 为什么不自动同步重新赋值？JSON 合法为何不代表订单合法？

**参考回答：**

1. 标准导入先查 `sys.modules`；需要加载时，通常先创建并登记模块对象，再执行模块代码。因此循环导入可能拿到尚未初始化完整的模块。正常再次import复用缓存；reload、清除缓存后重新导入或使用不同模块名等情况可能再执行，不能承诺顶层副作用永远只发生一次。[加载顺序](https://docs.python.org/3.12/reference/import.html#loading)
2. `from module import name`取得当时的对象，在当前作用域建立绑定，不是建立对模块属性的实时订阅。模块后来重绑定name，当前绑定不跟随；若两边仍引用同一列表，原地修改则双方可见。这仍是第1章的修改与重绑定模型。
3. JSON解析只确认输入能被解释成通用数据，不保证它是合法订单。进入汇总前再验证字段、整数分和状态；坏JSON在本章读取层包装为带物理行号的ValueError，并以异常链保留JSONDecodeError。CLI负责友好反馈，业务层不直接退出进程。

**换条件自测：** 模块导入时立即发请求，reload或测试重复加载后会发生什么？把副作用移到main或生命周期入口，再用“仅导入不生成报告”的实验检查边界。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** 订单规则已经能算，怎样让它读真实文件、被别的模块复用并从命令行跑出报告？

**一条主线：**

```text
订单文件 → import 与包路径 → 按编码读取、逐行解析 → 校验后计算 → 先写完整再替换旧文件 → CLI 参数与退出状态
```

**三个关键词：** 模块边界、解析、入口。模块边界决定什么可被导入，解析把外部文本变成业务值，入口负责装配、反馈与退出状态。

**最容易错：**

- 模块导入时就读取业务文件或发起网络请求；
- 把当前工作目录当成固定路径；
- 直接覆盖旧报告，坏输入把上一份结果毁掉；
- 认为 JSON 能解析就是合法订单，忘了它不保留对象身份与全部 Python 类型，或把不可信内容交给 `eval`、`pickle`。

**与前后章：** 第6章留下职责明确的对象，本章把它们放进模块，用文件和命令行串成可运行报告。第8章要在这个 CLI 上增加时间区间、状态统计与 SQLite，需要先有稳定的读取、校验和输出边界。

**学完应能：**

- 把计算拆成可导入模块，用 `if __name__ == "__main__"` 隔离运行入口；
- 从另一个目录用参数指定输入输出，仍能生成报告；
- 给坏 JSON 行报告物理行号，并保留异常链；
- 说明“先写完整再替换”怎样避免半份报告和旧结果被毁。

### 8.2 日常工作注意事项

- 避免在模块导入时读业务文件或启动网络请求；将运行入口放在明确函数和__main__判断中，方便测试与复用。
- 不要把工作目录当作固定路径。让输入输出位置由参数或明确配置提供，并在另一个目录验证启动。
- 不可信内容不要交给eval或pickle反序列化；输出报告先完成校验与计算，按约定发布文件，防止坏输入覆盖旧结果。

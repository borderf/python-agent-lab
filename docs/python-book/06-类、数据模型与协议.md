### 2.1 从独立状态开始设计类

两份审查任务各有名称和发现列表，却共用相同操作。把它们放在散落的全局变量中，函数很容易混用另一份任务状态。实例把一份状态聚在一起，方法明确作用于哪一份实例；类提供共同规则。继承、协议和描述器是在这个基础上表达复用与查找，而不是创建对象之前必须背的名词。

先想象同时处理任务A和任务B：A新增一条发现，B的发现列表应保持空。我们需要分别保存两份状态。类用来描述这类对象的结构和行为；创建得到的具体对象叫实例。下面先看创建实例时如何建立name和findings，再看方法怎样修改这一实例。self表示本次调用使用的实例，__init__负责初始化；共享类属性留到两份独立状态验证后再讨论。

```python
class Job:
    def __init__(self, name):
        self.name = name
        self.findings = []
    def add_finding(self, text):
        self.findings.append(text)
```

创建两个Job不应让一个任务的发现混进另一个。是否用类，取决于是否需要维持状态、封装不变量或实现协议；单纯计算常可用函数完成。

#### 案例推进：从两份独立状态开始

```python
# study-example: S06A
class ReviewJob:
    def __init__(self, name):
        self.name = name
        self.findings = []
    def add(self, finding):
        self.findings.append(finding)
    def __len__(self):
        return len(self.findings)
    def __repr__(self):
        return f"ReviewJob(name={self.name!r}, count={len(self)})"

a, b = ReviewJob("A"), ReviewJob("B")
a.add("缺少附件")
assert len(a) == 1 and len(b) == 0
assert a.findings is not b.findings
assert "count=1" in repr(a)
```

创建实例时初始化name与findings；调用a.add会把a绑定为self。len(a)由__len__提供语义，repr用于调试观察。若把findings=[]移到类体且不建立实例属性，两个任务可能修改同一列表；错误不是类这个工具本身造成，而是共享状态的位置不符合需求。

#### 类与实例仍然是同一对象图中的节点

实例和类本身也是对象。实例属性通常通过实例字典或槽位等机制保存对象引用；不能把“实例字段”理解为函数栈上按声明类型嵌入的值。类属性属于类的状态，实例查找到它不等于每个实例都复制了一份。方法调用仍建立第4章的执行状态，self只是本次形参绑定到该实例；方法结束不使实例自动消失。后面的描述器和MRO是在这张图上增加查找规则。

### 2.2 方法、属性与构造入口

通过实例访问普通方法时，通常得到绑定了实例的方法；classmethod绑定类，适合按类构造或处理类相关行为；staticmethod不自动绑定实例，可以表达放在类命名空间内的独立操作。

property把属性读取或更新接到受控代码上，让调用方保持`item.price`形式。它适合维护不变量，不能当作安全隔离。若只读property内部仍引用可变对象，调用方可能通过该对象修改状态。

#### 案例推进：再建立受控属性与构造入口

```python
# study-example: S06B
class Limit:
    def __init__(self, value):
        if type(value) is not int or value <= 0:
            raise ValueError("limit必须是正整数")
        self._value = value
    @property
    def value(self):
        return self._value
    @classmethod
    def from_text(cls, text):
        return cls(int(text))

limit = Limit.from_text("3")
assert limit.value == 3
try:
    limit.value = 4
except AttributeError:
    pass
else:
    raise AssertionError("只读property应拒绝普通赋值")
```

classmethod接收实际类cls，因此替代构造入口能继续使用类本身的校验。property让读取仍采用属性形式，通过描述器参与访问。下划线是内部使用约定，双下划线名称改写也不是权限隔离；Python封装主要服务于接口与维护，不能用它保护不可信代码。

### 2.3 dataclass减少重复但不替代设计

本节只需认识name: str表示字段名与预期类型，labels: list[str]表示文本列表；dataclass读取字段声明生成方法。注解本身不会验证外部数据，完整类型系统在第9章展开。先掌握字段、实例与默认工厂，再研究协议和继承。

dataclass可以生成初始化、repr和比较等方法；用field(default_factory=list)为实例创建独立容器。frozen限制常规字段重新绑定，不递归冻结内部对象。类型标注不会自动验证负金额或错误币种，这些需另外定义。

值对象的相等和哈希要一致。一个可变对象是否适合放入set或作为dict键，不能仅通过开启unsafe_hash解决；先问影响相等的状态会不会改变。

#### 案例推进：数据类减少重复，规则仍需自己写

```python
# study-example: S06C
from dataclasses import dataclass, field
@dataclass
class Report:
    job_id: str
    findings: list[str] = field(default_factory=list)

one, two = Report("A"), Report("B")
one.findings.append("missing")
assert two.findings == []
assert one == Report("A", ["missing"])
```

这里字段后的类型标注先读作字段说明，第九章学习其检查含义。dataclass可以生成初始化和相等比较，但不会自动验证每条finding符合业务。default_factory每次需要默认值时建立列表；frozen限制常规字段绑定，不会递归冻结列表。设计相等、哈希和缓存键时必须同时检查内部可变性。

### 2.4 通过协议参与语言操作

先接回第1章的比较问题：两个独立的任务对象，即使字段看起来相同，也需要明确“相等”按什么规则判断。下面先观察默认行为，再用dataclass按字段生成比较。

```python
# study-example: S06M
from dataclasses import dataclass
class Draft:
    def __init__(self, code):
        self.code = code
left, right = Draft("A"), Draft("A")
assert left is not right
assert left != right

@dataclass
class TaskKey:
    code: str
first, second = TaskKey("A"), TaskKey("A")
assert first == second
assert first is not second
```

Draft继承的默认相等规则没有自动比较code字段；TaskKey由dataclass生成的相等规则比较同类实例的字段。两次创建仍得到不同实例，因此is判断不变。自己实现`__eq__`时也应先写清业务规则，并处理其他类型；相等规则改变后，再检查能否作为集合成员、字典键和缓存键。下文的协议都是类似的连接：先确定语言操作应该表示什么，再实现相应方法。

__repr__服务调试，__str__服务可读展示；__len__、__iter__、__contains__让对象支持长度、遍历和成员检查。实现协议前先定义语义，例如`"A" in orders`按ID还是按完整记录判断。

运算符重载遇到不支持的其他类型可返回NotImplemented，让语言尝试相关回退；它不是NotImplementedError异常。只实现有实际用途且符合直觉的协议。

### 2.5 继承、组合与查找顺序

组合让对象持有一个可替换协作者，例如Job使用Repository；继承需要清楚的可替代关系。多继承下属性/方法依MRO查找，super从当前类之后继续，不应简单翻译成“直接父类”。

描述器参与属性获取与设置，普通函数和property都与它有关。先理解本章常见形式，再研究复杂描述器和元类，避免在尚未定义业务不变量时先堆内部机制。

#### 案例推进：用协议与组合代替无目的的继承

__iter__让对象可遍历，__contains__定义in的含义；需要根据ID查成员时，不必把完整字典比较语义硬套进去。__add__遇到不支持的类型可返回NotImplemented，让语言继续尝试其他运算路径；这不是抛NotImplementedError。

实例持有一个仓储或客户端，是组合；子类承诺可替换父类，是继承。多继承先看__mro__，再解释super的下一步。复杂元类、自定义__getattribute__与__slots__属于深入阅读：__slots__可限制常见实例字段并影响布局，但不自动带来不可变、线程安全或权限控制。

### 2.6 从类的用法走到可替换性：ABC、静态方法与运算回退

类已经能保存状态，下一步是分清接口约束和代码复用。ABC通过显式继承和abstractmethod约束某些实例化条件；Protocol在第9章通过结构描述所需能力。两者都不能单独证明“未知ID如何处理”等业务语义。

```python
# study-example: S06D
from abc import ABC, abstractmethod
class Reader(ABC):
    @abstractmethod
    def read(self):
        raise NotImplementedError
class MemoryReader(Reader):
    def read(self):
        return ["A"]
    @staticmethod
    def clean(text):
        return text.strip()
reader = MemoryReader()
assert reader.read() == ["A"]
assert reader.clean(" A ") == MemoryReader.clean(" A ") == "A"
try:
    Reader()
except TypeError:
    pass
else:
    raise AssertionError("未实现抽象方法不能直接实例化")
```

这里staticmethod不自动接收self或cls，所以从实例和类访问都使用相同参数。若函数与类没有实质关联，模块级函数也可以更直接；classmethod则适合需要实际类参与的构造或类相关行为。ABC主要验证显式层次中的抽象方法是否已实现，不禁止鸭子类型，也不要求所有仓储都继承它。

运算协议还有一个容易混淆的回退。返回NotImplemented表示“本对象不支持与这个类型组合，请语言继续尝试对应路径”，不是表示运行中发生了未实现异常。

```python
# study-example: S06E
class Count:
    def __init__(self, value):
        self.value = value
    def __add__(self, other):
        if not isinstance(other, Count):
            return NotImplemented
        return Count(self.value + other.value)
assert (Count(1) + Count(2)).value == 3
assert Count.__add__(Count(1), 2) is NotImplemented
try:
    Count(1) + 2
except TypeError:
    pass
else:
    raise AssertionError("无其他适用回退时最终应失败")
```

直接调用方法和使用运算符不完全相同：前者看到返回哨兵，后者还经过语言的运算分派。相等、反向运算和子类优先等也有各自规则，先查协议再实现。不要用NotImplementedError代替NotImplemented，也不要为不适合相加的业务对象强行定义加法。

### 2.7 把状态名固定成一组值

任务从待处理变成已完成，允许的值很少。StrEnum 把协议中的字符串集中定义，在边界将输入转换成成员。新建状态与允许怎样转换是两项规则，需要分别验证。

```python
# study-example: S06F
from enum import StrEnum, unique

@unique
class Status(StrEnum):
    PENDING = "pending"
    COMPLETED = "completed"

def finish(raw):
    state = Status(raw)
    if state is not Status.PENDING:
        raise ValueError("仅待处理状态可完成")
    return Status.COMPLETED.value

assert finish("pending") == "completed"
for value in ["closed", "completed"]:
    try:
        finish(value)
    except ValueError:
        pass
    else:
        raise AssertionError(value)
```

第一个失败来自枚举构造，第二个来自合法状态上的非法动作。添加 waiting_approval 后，哪些转换仍应拒绝？在第 9 章用带标签的联合表达“不同状态还伴随不同字段”，到第 16 章将对应版本与状态条件放入数据库更新。

## 3. 原理讲解与推导

### 3.1 实例与类共同参与属性访问

读取task.name不只是查一个字典：默认查找还考虑类及MRO、描述器和后备逻辑。普通函数放在类里参与绑定方法形成；property作为数据描述器可以优先于同名实例字典项。自定义访问方法可能改变过程，要谨慎处理递归。

### 3.2 super表达协作链

多个类遵守兼容签名并继续调用super时，可以沿MRO完成协作；某个节点不继续，后续处理可能消失。显式调用多个父类则可能重复处理共享祖先。这解释了为什么简单组合往往更容易推导。

### 3.3 自动生成方法仍遵循普通对象规则

dataclass没有建立另一套对象系统。其字段默认值、内部引用、相等、哈希和frozen仍需按普通对象语义判断。用实际实例对照，比把“数据类”理解成完整运行时校验容器更准确。

### 3.4 把描述器与MRO放进同一条属性查找路径

在常见实例的默认属性访问中，先沿类的MRO确定相应类属性；若它是数据描述器，优先执行其访问逻辑；否则再考虑实例字典；之后才是非数据描述器或普通类属性。普通查找失败时，若定义了__getattr__，可进入该后备逻辑。自定义__getattribute__、类对象访问以及部分特殊方法查找有额外规则，这条路径不是覆盖所有对象的万能伪代码。

描述器是其类型提供__get__、__set__或__delete__等协议方法的对象。参与读取并定义__set__或__delete__的描述器通常具有数据描述器地位；只有__get__的常见形式属于非数据描述器。property是数据描述器，即使没有setter，同名实例字典项也不会因此覆盖它。普通Python函数是非数据描述器，通过实例读取时形成绑定方法，绑定方法持有原函数与实例。

这解释了两个结果：`obj.method(x)`可以把obj自动交给self，而`obj.__dict__["price"] = 999`不一定能覆盖同名property。前者来自描述器绑定，后者来自查找优先级。仅记“属性先查实例再查类”会同时错过这两个机制。

MRO为多继承提供一致的线性查找顺序，Python采用C3线性化，并要求局部父类顺序等约束相容；无法形成一致顺序的继承结构会在创建类时失败。super并非重新开始查找整个父类树，而是相对当前类与实际实例的MRO继续。E15中的B调用super后可能到C，正是因为实例属于D，其MRO包含D、B、C、A。

#### 比较协议：不是把==直接替换成左侧方法

is直接表达身份关系，不调用__eq__。==按双方类型的富比较规则协商：右侧类型是左侧类型的严格子类时，可能优先尝试右侧实现；不支持时以NotImplemented交给后续候选。双方不支持==时回退到身份关系。NotImplemented不是异常，也不是False，业务代码不应拿它作真值条件。

```python
# study-example: S06Z
events = []
class Left:
    def __eq__(self, other):
        events.append("left")
        return NotImplemented
class Right:
    def __eq__(self, other):
        events.append("right")
        return "matched"
left, right = Left(), Right()
assert (left == right) == "matched"
assert events == ["left", "right"]
assert (left is right) is False
assert events == ["left", "right"]
class Unknown:
    def __eq__(self, other):
        return NotImplemented
one, two = Unknown(), Unknown()
assert (one == two) is False and (one == one) is True
```

上例左右类型互不继承，因此先观察左侧再观察右侧；不能从该事件顺序推出所有继承情况也如此。比较结果甚至可以不是bool；用于if或assert时才解释真假。直接调用left.__eq__(right)可能得到NotImplemented，故与执行left == right并不总是相同。

自定义相等还涉及哈希契约：相等且可哈希的对象必须有相同哈希；不同对象可碰撞。不要依据id实现业务相等后又保留不匹配的哈希。E06用于验证键比较，属性查找路径也不能直接套用于所有隐式特殊方法调用。

```python
    raise AssertionError("字段中的 list 仍不可哈希")
```

## 4. 示例与逐步走查

```python
# book-example: B06
from dataclasses import dataclass, field
@dataclass
class ReviewJob:
    name: str
    findings: list[str] = field(default_factory=list)
a, b = ReviewJob("A"), ReviewJob("B")
a.findings.append("missing")
assert b.findings == []
```

### 4.1 沿输入到结果逐步解释

构造a时，default_factory=list被调用一次，为a建立发现列表；构造b时再次调用，为b建立另一个列表。a.findings.append只修改a持有的列表，因此b.findings仍为空。

如果两个实例共享类属性中的同一个列表，append会沿引用改动同一对象，b就会看到a的发现。问题不在方法是否叫append，而在初始化时建立了几份容器。

把数据类设为frozen仍不能自动冻结字段所引用的内部列表：字段绑定限制与对象内部可变性不同。要实现真正的只读结果，应选择合适的数据表示并限制暴露，而不只加一个装饰器参数。

## 7. 面试问答与迁移

property 为什么不只是 Getter？super 为什么可能调用到兄弟类？frozen 一定可哈希吗？

**参考回答：**

1. property是数据描述器，属性访问可转入getter/setter/deleter；没有setter时，普通赋值会失败，同名实例字典项也不能简单覆盖它。只读property本身就是一种接口设计，但若返回内部列表，调用方仍可修改列表。它维护访问约定，不隔离恶意代码。
2. `super()`相对给定类，在实际对象的MRO中继续查找，不固定为“直接父类”。菱形继承中可能走到兄弟类；协作链要约定兼容签名、是否继续super以及终点，否则可能漏调用或重复初始化。
3. 要分开“生成哈希方法”与“调用成功”。默认 `eq=True, frozen=True` 且没有显式哈希定义时，dataclass会生成 `__hash__`；生成时不逐项证明字段可哈希，真正hash实例时才可能因list字段失败。frozen限制常规属性赋值/删除，不递归冻结内部内容，也不是安全边界。`unsafe_hash`同样不能把list变成可哈希值。[生成规则](https://docs.python.org/3.12/library/dataclasses.html)

**换条件自测：** 先预测创建、修改列表、调用hash分别会怎样，再运行。

```python
# study-example: S06H
from dataclasses import dataclass

@dataclass(frozen=True)
class FrozenReport:
    labels: list[str]

report = FrozenReport([])
assert FrozenReport.__hash__ is not None  # 方法已经生成
report.labels.append("review")           # 内部列表没有冻结
try:
    hash(report)
except TypeError:
    pass
else:
    raise AssertionError("参与哈希的list字段不可哈希")
```

将labels改成tuple后再测；如果某字段不参与比较/哈希，还需重新检查你实际定义的值对象语义，不能用“frozen一定怎样”概括所有配置。

## 8. 本章小结与参考

### 8.1 主要知识点总结

- 类与实例仍是对象；实例状态、共享类状态与本次方法参数要分开。
- dataclass减少重复方法，默认工厂建立独立可变字段，frozen不递归冻结内部对象。
- 属性、方法与特殊方法连接语言操作；相等、哈希与查找遵循相应协议。
- 组合与继承围绕职责和可替代关系选择，不能由类层次替代业务契约。

### 8.2 日常工作注意事项

- 每个任务独立的列表放在实例初始化中，或使用default_factory；把它放在类上容易使多个任务共享修改。
- 定义相等规则后同步检查哈希与可变性；不要用unsafe_hash绕过设计问题后直接把可变业务对象作字典键。
- property和下划线帮助维护接口，不是权限隔离。受控属性仍需验证输入，内部可变值的暴露也要检查。

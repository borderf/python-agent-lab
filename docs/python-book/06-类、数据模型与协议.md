## 2. 基础知识讲解
固定输入：A 是 Alice 的1990分待支付订单，B 是 Bob 的1000分待支付订单。先拥有状态，再收敛修改入口，最后补齐协议。
### 2.1 类把一份订单的数据和规则放在一起
字典能保存订单，却把数据形状和修改规则留给外部函数。类用 `__init__` 准备每个实例自己的属性，用实例方法操作状态。`Order("A", "Alice", 1990)` 创建 A；调用 `a.pay()` 时，Python 自动把 `a` 交给第一个参数 `self`。
#### 案例推进：两份订单，各自持有状态
```python
# study-example: S06A
class Order:
    def __init__(self, order_id, user, amount_cents):
        self.order_id, self.user, self.amount_cents = order_id, user, amount_cents
        self.status = "pending"
    def pay(self): self.status = "paid"
a, b = Order("A", "Alice", 1990), Order("B", "Bob", 1000)
a.pay()
assert a.status == "paid" and b.status == "pending"
```
`__init__` 运行两次，字段分别绑定到两个实例。`a.pay()` 等价于 `Order.pay(a)`，所以只有 A 改变。`self` 只是惯例名，不是关键字；改叫 `order` 不改变自动绑定。
可变状态不要放在类属性上：类体中的 `findings = []` 会被实例共享；每实例一份列表应在 `__init__` 创建，或用 `default_factory`。
### 2.2 从普通属性到受控属性，再选择方法
**普通属性：** 先看最直接的可读写版本。`value` 保存在实例字典中，赋值不会经过额外检查。
```python
class Limit:
    def __init__(self, value): self.value = value
limit = Limit(3)
limit.value = 4
assert limit.value == 4
```
**普通属性 → getter：** 只提供读取入口时，先把值存进 `_value`，再写 `get_value()`。公开写入入口消失，但 `_value` 仍可被直接修改。
```python
class Limit:
    def __init__(self, value): self._value = value
    def get_value(self): return self._value
limit = Limit(3)
assert limit.get_value() == 3
limit._value = 4
assert limit.get_value() == 4
```
**getter → property：** `@property` 把 getter 包装成属性，调用方恢复 `limit.value` 的读取方式，不必显式调用方法；单下划线不是权限限制。
**property → 只读失败：** 只提供 getter 时，公开属性只读。下面读取为3，赋值失败后仍为3；直接改 `_value` 却能得到4。property 维护接口，不锁死对象；返回列表时也仍可修改内容。
```python
# study-example: S06P
class Limit:
    def __init__(self, value): self._value = value
    @property
    def value(self): return self._value
limit = Limit(3)
assert isinstance(Limit.value, property) and limit.value == 3
try: limit.value = 4
except AttributeError: pass
else: raise AssertionError("只读属性应拒绝赋值")
assert limit.value == 3
limit._value = 4
assert limit.value == 4
```
**只读失败 → setter：** 只读源于没有 setter。补上 `@value.setter` 后，构造和修改都走 `self.value = value`，检查只写一次；失败时原值不变。setter 无返回值。`type(value) is int` 排除 bool；允许整数子类时才用 `isinstance`。`@value.setter` 指向上面的 property，不是普通属性；property 控制访问属性时执行什么，方法控制调用时自动绑定谁。
```python
# study-example: S06S
class Limit:
    def __init__(self, value): self.value = value
    @property
    def value(self): return self._value
    @value.setter
    def value(self, new_value):
        if type(new_value) is not int or new_value <= 0: raise ValueError("limit必须为正整数")
        self._value = new_value
limit = Limit(3)
limit.value = 4
assert limit.value == 4
for bad in (-1, True, "4"):
    try: limit.value = bad
    except ValueError: pass
    else: raise AssertionError(bad)
assert limit.value == 4
```
#### 三种方法：定义、调用与自动绑定
| 对比项 | 实例方法 | 类方法 | 静态方法 |
| --- | --- | --- | --- |
| 定义 | `def pay(self)` | `@classmethod` + `def from_text(cls, text)` | `@staticmethod` + `def clean(text)` |
| 调用 | `a.pay()` | `Limit.from_text("3")` | `TextCleaner.clean(" A ")` |
| 自动绑定 | 实例 `a` | 类 `Limit` | 无 |
| 内部收到 | `self=a` | `cls=Limit` | 只有显式参数 |
| 使用数据 | 当前订单状态 | 类本身，常通过 `cls(...)` 创建对象 | 只使用给定参数 |
| 选择问题 | 要处理“这个对象”吗？ | 要使用“这个类”或按它创建吗？ | 只给参数就够吗？ |
类方法适合命名构造。下面通过实例调用：`limit` 只负责找到方法，传给 `cls` 的仍是类 `Limit`。`self`、`cls` 只是惯例名，类型由定义和装饰器决定。静态方法通过类或实例调用相同；可多处复用时，普通函数更直接。`from_text` 先转换再复用构造检查；子类调用时 `cls` 是子类。三种方法分别使用实例、类和显式参数。
```python
# study-example: S06B
class Limit:
    def __init__(self, value):
        if type(value) is not int or value <= 0: raise ValueError("正整数")
        self.value = value
    @classmethod
    def from_text(cls, text): return cls(int(text))
class TextCleaner:
    @staticmethod
    def clean(text): return text.strip()
limit = Limit(3); bound = limit.from_text
assert bound.__self__ is Limit
another = bound("4")
assert type(another) is Limit and another is not limit and another.value == 4
assert TextCleaner.clean(" A ") == TextCleaner().clean(" A ") == "A"
```
### 2.3 用 dataclass 声明值，用规则维护状态

先看 `@dataclass` 自动生成了什么。下面没有手写 `__init__`、`__eq__` 或 `__repr__`，却能构造、按字段比较并打印对象。

```python
# study-example: S06C
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

point = Point(1, 2)
assert point == Point(1, 2)
assert repr(point) == "Point(x=1, y=2)"
assert Point("1", 2).x == "1"
```

最后一条断言说明：字段注解描述预期形状，但 dataclass 默认不做运行时类型校验。自动生成的 `__init__` 只负责把参数写入字段，业务规则仍要显式添加。

接着处理默认值与构造校验。`default_factory=list` 为每个实例分别创建空列表；`__post_init__` 在生成的初始化完成赋值后运行，适合拒绝坏输入或规范化字段。

```python
# study-example: S06G
from dataclasses import dataclass, field

@dataclass
class ReviewJob:
    owner: str
    findings: list[str] = field(default_factory=list)
    def __post_init__(self):
        if not self.owner.strip(): raise ValueError("负责人不能为空")

first, second = ReviewJob("Alice"), ReviewJob("Bob")
first.findings.append("OVER_BUDGET")
assert second.findings == []
try: ReviewJob(" ")
except ValueError: pass
else: raise AssertionError("构造校验应拒绝空负责人")
```

默认值、校验和可变性回答不同问题：默认工厂保证实例不共享列表；`__post_init__` 只检查构造入口，不阻止以后直接修改字段；`frozen=True` 禁止重新绑定字段，但不递归冻结内部列表，也不保证对象可哈希。状态可用 `StrEnum` 固定合法值，但“值合法”不等于“转换合法”，仍需由 `pay()` 检查当前状态。
### 2.4 协议让对象参与语言操作
`__len__`、`__iter__`、`__contains__` 让集合支持 `len`、`for`、`in`；每次 `__iter__` 返回新迭代器，所以集合可重复遍历。frozen 不递归冻结内部对象，也不保证字段可哈希。
**专题：运算回退与抽象接口。** `__add__` 遇到不支持的类型返回 `NotImplemented`，让 Python 尝试其他实现；它不是异常 `NotImplementedError`。ABC 在实例化前检查必须实现的方法，但签名正确仍不代表业务语义正确。
```python
# study-example: S06E
class Count:
    def __init__(self, value): self.value = value
    def __add__(self, other):
        if not isinstance(other, Count): return NotImplemented
        return Count(self.value + other.value)
assert (Count(1) + Count(2)).value == 3 and Count.__add__(Count(1), 2) is NotImplemented
```
```python
# study-example: S06D
from abc import ABC, abstractmethod
class Reader(ABC):
    @abstractmethod
    def read(self): ...
class MemoryReader(Reader):
    def read(self): return ["A"]
assert MemoryReader().read() == ["A"]
try: Reader()
except TypeError: pass
else: raise AssertionError("抽象类不能直接实例化")
```
**上下文管理也由协议驱动。** `__enter__` 返回资源，`__exit__` 收到异常信息；返回 `False` 不抑制异常。
```python
# experiment: E11
events = []
class Resource:
    def __enter__(self): events.append("enter"); return self
    def __exit__(self, exc_type, exc, tb):
        events.append("error" if exc_type else "normal"); events.append("closed"); return False
try:
    with Resource(): raise ValueError("bad data")
except ValueError as error: assert str(error) == "bad data"
assert events == ["enter", "error", "closed"]
```
**专题：字典键与不可变性。** 字典先用哈希定位候选，再用相等区分键；相等对象必须有相同哈希。frozen 只禁止重新赋值，不保证含列表字段的对象可哈希。
```python
# experiment: E06
class Key:
    def __init__(self, value): self.value = value
    def __hash__(self): return 1
    def __eq__(self, other):
        if not isinstance(other, Key): return NotImplemented
        return self.value == other.value
table = {Key("A"): 10, Key("B"): 20}; assert len(table) == 2 and table[Key("A")] == 10
```
```python
# experiment: E16
from dataclasses import dataclass, field, FrozenInstanceError
@dataclass(frozen=True)
class Settings:
    labels: list[str] = field(default_factory=list)
one = Settings(); one.labels.append("A")
try: one.labels = []
except FrozenInstanceError: pass
else: raise AssertionError("frozen禁止重新赋值")
try: hash(one)
except TypeError: pass
else: raise AssertionError("list字段不可哈希")
```
**对象设计：组合优先，继承表达“是”。** 换来源时把来源作为参数传入，是组合；紧急订单真是另一种订单且行为大部分相同时，才考虑继承。组合依赖 `get` 约定，继承用 `super()` 扩展行为。两个来源都有 `get` 时可用不同实现，这是结构多态。只想替换存储时不要添加子类层次。
## 3. 原理讲解与推导
这一节只追踪一条因果链：Python 查找属性与特殊方法，找到可调用对象，再决定绑定和覆盖；业务规则在调用之后才生效。
### 3.1 对象设计：绑定方法记住实例
通过实例读取方法会生成绑定方法。它记住实例，调用时把实例交给第一个参数；普通实例属性通常保存在 `__dict__`。
```python
# experiment: E13
class Task:
    def label(self, suffix): return self.name + suffix
task = Task(); task.name = "review"; method = task.label
assert task.__dict__ == {"name": "review"}; assert method.__self__ is task
assert method.__func__ is Task.label and method("!") == Task.label(task, "!") == "review!"
```
### 3.2 对象设计：super 沿 MRO 继续查找
多继承出现同名方法时，MRO 给出确定顺序。`super()` 不是从运行时实例的 MRO 起点开始找，而是从**定义当前方法的类**在实例 MRO 中的位置之后继续查找；MRO 本身仍由实际实例类型决定，因此下一站不固定等于字面意义上的直接父类。
```python
# experiment: E15
events = []
class A:
    def run(self): events.append("A")
class B(A):
    def run(self): events.append("B"); super().run()
class C(A):
    def run(self): events.append("C"); super().run()
class D(B, C):
    def run(self): events.append("D"); super().run()
D().run()
assert events == ["D", "B", "C", "A"] and D.__mro__ == (D, B, C, A, object)
```
在 `D()` 的 MRO `D → B → C → A → object` 中，`B.run()` 里的 `super().run()` 从 B 之后继续，下一站是 `C.run()`，不是 B 的字面直接父类 A。协作方法还要约定参数兼容、是否继续 `super()` 以及终点；父类顺序冲突时，Python 会在定义子类时拒绝。

### 3.3 属性查找：实例字典、类与描述器谁先接管

读取属性时，Python 先在类上查找属性对象，再按描述器协议决定是否调用 `__get__`；带 `__set__` 的数据描述器优先于实例字典。没有数据描述器时，实例 `__dict__` 中的同名值可以先被找到；普通函数是非数据描述器，因此通过实例读取会生成绑定方法。property 同时定义读取和写入控制，所以即使实例字典里写了同名值，也仍由 property 接管。`__slots__` 则改变实例存储方式，不等于自动校验或禁止通过其他接口修改状态。

```python
# experiment: E14
class Price:
    def __init__(self): self._cents = 10
    @property
    def cents(self): return self._cents
p = Price(); p.__dict__["cents"] = 999; assert p.cents == 10
try: p.cents = 20
except AttributeError: pass
else: raise AssertionError("只读property拒绝赋值")
```

### 3.4 值与协议：特殊方法查找决定语言操作
`len(obj)` 找 `__len__`，`for` 通过 `__iter__` 取得迭代器，`hash(obj)` 找 `__hash__`。`==` 在两侧有继承关系时优先尝试子类，否则通常先试左侧；一侧返回 `NotImplemented` 才试另一侧。协议让调用方不必知道内部用列表还是元组。
### 3.5 设计检查：先查查找结果，再查业务规则
先确认实例能绑定正确方法、属性会被描述器接管、集合协议完整；再检查金额和状态规则。前者决定调用能否到达，后者决定结果是否正确。
### 3.6 选读回顾：with 也是一种协议
`with` 也是特殊方法查找链：先调用 `__enter__`，退出时调用 `__exit__`。完整代码与异常不抑制断言见第2.4节的 E11；它复用了第5章的资源关闭模型。特殊方法让语言操作找到对象能力，但资源是否及时关闭、状态转换是否合法，仍由实现和调用边界决定。
## 4. 示例与逐步走查
### 4.1 构造、操作与组合
#### 案例推进：构造先检查，支付再检查
输入仍为 A=1990分、B=1000分，起初都待支付。`Money` 拒绝坏金额；`Order` 检查标识并转换状态；`pay()` 拒绝重复支付。
#### 案例推进：连续两次遍历都从开头读取
集合保存订单元组，提供计数、遍历和 ID 判断。A 已支付、B 仍待支付，订单状态互不影响。
```python
# book-example: B06
from dataclasses import dataclass
from enum import StrEnum
class Status(StrEnum):
    PENDING = "pending"; PAID = "paid"; CANCELLED = "cancelled"
@dataclass(frozen=True)
class Money:
    cents: int
    def __post_init__(self):
        if type(self.cents) is not int or self.cents < 0: raise ValueError("非负整数分")
@dataclass
class Order:
    order_id: str; user: str; amount: Money; status: Status = Status.PENDING
    def __post_init__(self):
        if (not isinstance(self.order_id, str) or not isinstance(self.user, str)
                or not self.order_id.strip() or not self.user.strip()):
            raise ValueError("标识不能为空")
        if not isinstance(self.amount, Money): raise ValueError("amount必须为Money")
        self.status = Status(self.status)
    def pay(self):
        if self.status is not Status.PENDING: raise ValueError("不能重复支付")
        self.status = Status.PAID
class OrderCollection:
    def __init__(self, orders): self._orders = tuple(orders)
    def __len__(self): return len(self._orders)
    def __iter__(self): return iter(self._orders)
    def __contains__(self, order_id): return any(o.order_id == order_id for o in self._orders)
a, b = Order("A", "Alice", Money(1990)), Order("B", "Bob", Money(1000))
a.pay(); orders = OrderCollection([a, b])
assert len(orders) == 2 and "A" in orders and "missing" not in orders
assert [o.status for o in orders] == [Status.PAID, Status.PENDING]; assert [o.order_id for o in orders] == ["A", "B"]
try: a.pay()
except ValueError: pass
else: raise AssertionError("不能重复支付")
for args in ((1, "Alice", Money(1)), ("A", "Bob", 1)):
    try: Order(*args)
    except ValueError: pass
    else: raise AssertionError("注解不会替代构造校验")
```

## 7. 面试问答与迁移
**问：为什么通过实例调用类方法，`cls` 仍是类？** 类方法绑定的是类，实例只参与查找。`limit.from_text("4")` 中 `cls` 仍是 `Limit`，所以创建新 `Limit`，不修改 `limit`。
**问：实例、类、静态方法怎么选？** 需要当前对象状态用实例方法；需要类或命名构造用类方法；只使用显式参数且逻辑上归在类附近用静态方法。`self`、`cls` 的名字不决定类型。迁移订单来源时，先问“换依赖”还是“定义另一种订单”，再选组合或继承。
## 8. 本章小结与参考
- 类把状态和操作放在一起；`__init__` 准备实例，实例方法自动收到 `self`；dataclass 只生成样板代码。
- property 沿“普通属性 → getter → 只读失败 → setter”递进，控制访问而非安全隔离。
- 实例、类、静态方法按自动绑定的对象选择；`self`、`cls` 只是惯例名，业务规则仍要显式检查。
- 值对象按值比较，协议支持 `len`、`for`、`in`；相等、哈希与可变性一起设计。下一章把模型放进模块，用 JSONL 读入 A、B，再通过 CLI 输出报告。

# 第12章　Python 综合项目与独立验收

## 1. 学习目标与前置知识

整合语言机制，交付订单库、CLI 和工具执行器。前置：第1–11章。

## 2. 基础知识讲解

先定义输入、输出、错误、状态与数据所有权，再拆模块。核心业务保持确定性：校验→去重→计算→报告；文件、数据库和 HTTP 只是可替换的数据来源。

工具执行器组合注册、模型校验、调用、超时和日志；不能因为用了装饰器或 Protocol 就忽视执行结果与副作用。公开 API 应比内部实现更稳定。

交付包含源码、依赖锁、构建产物、正常与错误样例、运行与验收命令。让另一环境按文档运行，是检验隐含假设的方法。

## 3. 原理讲解与推导

高内聚、明确依赖和可替换边界使测试与变更更容易。可维护性的证据来自一次真实需求变更，而不是目录层数。

## 4. 示例与逐步走查

```python
# book-example: B12
def run_report(load, render):
    rows = load()
    result = {"count": len(rows), "total_cents": sum(row["cents"] for row in rows)}
    render(result)
    return result
outputs = []
result = run_report(lambda: [{"cents":7},{"cents":3}], outputs.append)
assert result == {"count":2,"total_cents":10} and outputs == [result]
```

阅读时先预测输入、输出、异常、副作用和资源状态，再执行；修改一处条件验证自己的解释。独立示例有标记，框架片段和项目流程另按依赖/服务条件验证。

## 5. 动手练习

实现真实订单规则和三种来源；构建 CLI 与受控工具执行器；换一条金额或去重规则并补回归。上述示例只展示依赖边界，完整项目仍需校验和资源管理。

## 6. 验收与自测

**行为验收：** 通过 G1/G2/G3；独立重写四个关键函数；构建包可运行；说明失败恢复和仍有的限制。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

**提交证据：** 实现位置、运行命令、正常案例、至少一个错误/边界案例、一次失败原因和修复记录。自动检查只证明其覆盖行为；未实现任务不因示例通过而算完成。

## 7. 面试问答与迁移

如何证明自己会 Python 而不只是会框架？你最近一次需求变更影响了哪些测试？

回答顺序：定义与边界 → 机制 → 小例子 → 项目影响 → 验证方式。不确定的实现细节明确说明版本和查证办法。

## 8. 本章小结与参考

先达到行为与原理两类验收，再继续后续依赖本章的任务。遇到不熟悉的内容回到例子做小实验，不以阅读完成代替掌握。

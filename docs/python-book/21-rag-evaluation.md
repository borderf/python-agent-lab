# 第21章　混合检索、重排与 RAG 评测

[上一章](20-rag-baseline.md) · [全书目录](README.md) · [下一章](22-agent-loop.md)

## 1. 学习目标与前置知识

能证明检索策略是否改善效果，并解释代价。前置：第20章。

## 2. 基础知识讲解

关键词/稀疏检索擅长不同形式的词项匹配，Dense 捕捉某些语义近似；二者失误并不完全相同。混合检索需要候选策略与融合，不应直接把不同分数尺度相加。

RRF 用排名融合，reranker 对候选重新判断相关性。重排不能召回从未进入候选的证据，候选数增大也会增加时间与资源代价。

评测先约定查询、相关来源、权限、业务日期、粒度和候选范围。Recall@K、引用支持性、无答案处理、延迟和用量分别说明不同问题；无相关证据案例不能直接混入有答案召回率分母。

## 3. 原理讲解与推导

把召回、排序、版本选择和生成忠实性分别归因。固定调参集并留验证样例，避免只记一个漂亮总分。

### 项目化展开

### 检索指标

本轮先按 source_id 评估；不同版本有不同 source_id。检索返回多个同源 chunk 时先对 source_id 去重。若以后改为 chunk 级指标，要重新标注并在报告中说明，不能混用结果。

对有答案且允许访问的查询 q：

```text
Recall@5(q) = |相关来源集合 ∩ 前5个唯一检索来源| / |相关来源集合|
```

对所有此类查询取均值，并报告样本数。这里是唯一来源层级的 Recall@5；另外记录实际召回的 chunk 数、去重策略和候选上限。无相关来源、越权和证据冲突案例分别统计，避免除零或用它们抬高召回率。

- 引用正确率：被人工核对为确实支持对应结论的引用数 / 已核对引用数；同时记录回答中应有证据但没引用的结论数。
- 来源可定位性：引用是否存在、版本/节号/页码是否正确。它不能替代内容支持性。
- 无答案处理：没有证据时是否说明不足；不能用一个泛泛的回答当作正确。
- 权限隔离：固定越权案例中的不可见来源不能进入候选结果、提示和响应。

### 对照实验约束

比较固定工作流/单 Agent/多 Agent 时，共用数据、权限、模型、提示版本、工具、案例和总任务预算。另可做“各自最佳配置”的实验，但不要与受控对照混为一组。

依次只改变一项：检索策略、重排、分工、并行、核验返工。记录额外模型次数、候选数和资源。质量没有提高或改善不足以抵偿代价时，明确保留基线。

### 检索误差的分层排查

标准证据没有入库是解析/索引问题；入库但不在候选是召回问题；候选中有但排序靠后是排序问题；正确证据进入提示却回答错，是生成/提示或事实核对问题。

RRF常见形式 `score(d)=Σ 1/(k+rank_i(d))`，rank从1开始，k为平滑参数；它使用排名，避免直接混合不同尺度分数，但仍需确定候选数量、过滤、去重和并列策略。重排器只处理候选，不会凭空补回漏召回内容。

## 4. 示例与逐步走查

### 按排名融合的机制示例

```python
# book-example: B21
def rrf(rankings, k=60):
    scores = {}
    for ranking in rankings:
        for position, source_id in enumerate(dict.fromkeys(ranking), 1):
            scores[source_id] = scores.get(source_id, 0) + 1/(k+position)
    return sorted(scores, key=lambda sid: (-scores[sid], sid))
assert rrf([["A","B"],["B","C"]])[0] == "B"
```

每条排名先去重，结果并列按ID固定顺序。本示例未执行向量检索；真实融合前还要统一权限、版本与候选范围。比较是否改善Recall与引用支持性，而不只看融合分数。

## 每项如何记录

用四级状态替代“看过即完成”：0 未学；1 能看懂；2 能独立实现并测正常情况；3 能解释机制、处理反例并迁移到新需求。日期、代码位置、运行命令与仍不确定之处另记在学习日志。

核心项目标为 3。标记“理解”的机制要求能通过小实验说明，具体实现细节可查文档；不以背诵解释器实现或全部标准库为目标。

## 三个阶段关卡

### G1：独立写程序（第7、12章）

给你一份新订单文件，不看原实现，能够读取、校验、去重、汇总并通过 CLI 输出；能处理中文、空文件内容、错误 JSON、重复冲突和输出失败。解释发生异常时资源怎样关闭。

### G2：独立设计可维护模块（第9、12章）

为文件/数据库定义可替换仓储；模型边界、公共接口、错误和类型清楚；能说明为何选函数、dataclass、TypedDict 或校验模型。对“某字段不再必填”之类变更，能找到测试和代码影响。

### G3：独立处理外部调用（第11、14章）

请求有明确超时与有限重试；同时请求有并发/队列限制；父任务取消、子任务失败后能清理；日志可定位错误。不会把执行失败转为空结果或掩盖未完成任务。

## 综合验收（第12章）

- [ ] 从一条命令启动，换数据来源无需改计算逻辑。
- [ ] 从公开接口解释输入、输出、异常和副作用，不看内部代码也说得清。
- [ ] 关键业务和重要错误路径有测试；故意注入一处错误时能被发现。
- [ ] 能在合适的临时环境安装构建产物并运行。
- [ ] 任选四个核心函数合上资料重写，再处理一个新边界需求。
- [ ] 比较过至少一个同步/异步/线程/进程选择，说明证据和限制。
- [ ] 为性能结论保留数据规模、环境、结果正确性和多次测量。
- [ ] 整理仍不熟悉的三个问题，以及查证方式和后续练习。

每周回看上两周的两个薄弱项；“查资料后可正确实现”与“完全不熟悉”分开记录。元类、复杂描述器、CPython 源码和 C 扩展可成为后续专题，不阻塞常规语言验收。

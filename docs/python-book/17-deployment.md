# 第17章　部署、可观测性与可靠性

## 1. 学习目标与前置知识

理解启动、故障、回滚与运维边界。前置：第13–16章。

## 2. 基础知识讲解

镜像固定可部署环境，配置与密钥在运行时注入；卷保存需要持久化的数据。健康检查说明进程是否活着，就绪检查说明当前是否能接服务，两者不要混为一谈。

日志记录事件，指标聚合趋势，trace 连接一次任务的检索、模型、工具和审批。采集前脱敏，权限和保留周期同样需要设计。

熔断、限流、缓存、重试、隔离和降级针对不同失败模式。每个措施要说明触发条件、恢复方式和对结果正确性的影响；Compose 启动不等于高可用。

## 3. 原理讲解与推导

可靠性来自可观察、可限制、可恢复和可验证的故障行为。先做最小部署和资源测量，再增加组件。

### 项目化展开

### 必做故障矩阵

| 场景 | 必须观察到的行为 |
| --- | --- |
| 空/损坏/不支持文档 | 明确状态，不制造字段/引用 |
| 数字或 JSON 格式错误 | 校验失败，不触发后续业务动作 |
| 旧版本政策与当前政策并存 | 按业务日期选择，无法消除冲突则要求复核 |
| 另一租户数据 | 服务端拒绝或过滤，模型看不到不可访问来源 |
| 文档中的恶意指令 | 当作不可信文档内容，不提升权限或执行指令 |
| 工具/模型超时 | 分类记录，限制重试，任务及连接清理 |
| 子 Agent 超时 | partial/needs_review，说明缺失部分 |
| checkpoint 后重启 | 正确映射任务与身份并恢复，外部动作可对账 |
| 重复提交/重复 resume | 幂等记录可核对，模拟业务效果不重复 |
| 审批拒绝或载荷变更 | 不执行；旧审批不能用于新载荷 |
| trace 输出 | 可以追踪但不泄露凭据、敏感原文和越权数据 |

### W16 最终演示脚本

1. 按 README 同步并启动最小配置，检查健康与就绪状态。
2. 用有权限身份上传样例，展示解析、字段证据、制度引用。
3. 审查正常、多个异常、资料不足三个项目，核对风险与证据。
4. 暂停到审批，重启后恢复，分别演示拒绝与批准；重复请求核对效果数。
5. 注入一个工具/子任务超时和越权请求，展示正确状态与审计事件。
6. 导出受控基线比较、固定回归结果和已知限制。

这些验证支持学习项目的工程结论。真实上线还需要业务方确认规则、身份与数据权限设计、安全检查、容量、备份恢复和运维要求。

### 指标与失效策略

延迟拆分为排队、检索、模型首token、生成、工具与持久化，才能知道优化对象。平均值可能隐藏尾部问题；报告p50/p95时同时给出样本数、负载、冷启动与硬件条件。

降级应说明结果失去了什么能力：模型不可用时可返回检索证据，但不能伪装成已完成审查。重试放大依赖负载时需要限额/熔断；恢复判据和人工介入路径同样要定义。

## 4. 示例与逐步走查

### 分解一次任务耗时

```json
{"task_id":"T1","queue_ms":5,"retrieve_ms":20,"model_ms":300,"tool_ms":30,"persist_ms":5,"status":"completed"}
```

这些数字仅为格式示例，不是项目实测。实际trace要说明是否含并行、重试与重叠区间，不能机械相加所有span就得到端到端耗时。模型错误时保留错误阶段，脱敏后再导出。

## 6. 验收与自测

**行为验收：** 启动可复现；持久数据恢复；任务与客户端状态一致；失败可定位；预算达到上限有明确反馈。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

**提交证据：** 实现位置、运行命令、正常案例、至少一个错误/边界案例、一次失败原因和修复记录。自动检查只证明其覆盖行为；未实现任务不因示例通过而算完成。

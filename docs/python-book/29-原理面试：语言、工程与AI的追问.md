## 2. 基础知识讲解

### 2.1 用机制组织回答

先说概念边界，再画对象或时间线，然后用最小实验和反例验证，最后说明工程后果。结论、机制、证据和限制分开，听者才能判断你是理解还是记住了输出。

| 步骤 | 要回答的问题 | P200示例 |
| --- | --- | --- |
| 结论 | 先给可被判断的答案 | 原键同载荷恢复，不能换键盲写 |
| 机制 | 为什么导致这个结果 | 接收方按租户和动作键去重，新键会形成新动作 |
| 例子 | 最小路径怎样走到结论 | 冻结版本2→远端提交→回执丢失→原键重试 |
| 边界 | 什么条件下结论失效 | 接收方无稳定键或查询能力时，只能保持未知并对账 |
| 证据 | 凭什么说它成立 | 任务记录、原回执与效果账本；参考输出不算个人实测 |

回答卡按这五格写，未知项先声明再推导；不要把“设计上应该”混进“我运行过”。

### 2.2 语言题区分语义与实现观察

定义时求值、引用共享和原地修改属于可推导的语义；某次`id`、缓存或字节码表现可能依赖具体实现。回答时注明环境，不用一次观察冒充语言保证。

**Java到Python按机制迁移，不做词类替换：**
- Spring/DI Bean → 显式构造与组合根；Python语言不强制注入，但FastAPI等框架可提供依赖注入，隐藏全局单例反而增加测试和并发耦合。
- 受检异常 → 异常仍在，但解释器不强制声明；接口边界要显式校验、分类和映射，不能把`except Exception`当错误契约。
- `synchronized` → 先判断线程、协程还是进程：GIL不保护复合业务状态，协程也不会在普通同步代码间自动切换。
- JDBC/DAO → 上下文管理器、显式事务与数据访问层；重点说清连接所有权、提交边界和参数化查询。
- Java `Optional` → Python常用`None`表达缺失；先区分“缺失”与“值为0/空字符串”，再按契约决定默认值或异常。

#### 案例推进：从P200请求对象开始提问

下面是机制探针，不是ProcureAgent实现。默认字典在`def`执行时创建，两次调用共享同一对象。

```python
# study-example: S29A
def review(payload={"project_id": "P200", "findings": []}):
    payload["findings"].append("checked")
    return payload

one = review()
two = review()
assert one is two and one["findings"] == ["checked", "checked"]
```

追问“显式传入新字典”“只复制外层”“返回后修改”时，继续画引用关系，不重新背输出。

### 2.3 工程题先画故障时间线

超时只说明本地等待结束，不说明远端没有效果。依次确认失败阶段、动作键、载荷版本、批准、接收方契约和效果账本，再决定查询、重试或人工对账。

**失败案例按“根因—修复—回归”讲：**
- 先写预期、观察、输入与环境，定位第一个分叉；区分触发条件、直接症状和可修复根因，不说“模型不稳定”就结束。
- 用最小实验验证根因，说明修复怎样切断因果链、为何不采用更复杂方案，以及修复引入的新边界。
- 回归必须包含原失败、相邻边界和无副作用检查；例如禁止换键后，既验证重复提交不增效果，也验证同键同载荷仍返回原回执。
- 证据链接到提交、测试和脱敏轨迹；讲清修复前失败、修复后通过，不把偶然一次成功当回归。

### 2.4 AI题把事实、检索与生成分开

模型生成的是条件概率下的文本，不是事实账本。RAG先检查来源、版本、权限和召回，再检查引用是否逐项支持结论；Agent再检查工具参数、执行轨迹和状态。P200的20%来自制度工具，不来自模型猜测。

**记忆与推断分开：** 记忆是已保存且可定位的数据或状态，推断是模型基于上下文生成的新主张；前者要能追溯，后者必须验证。
| 类别 | 证据要求 | 常见反例 |
| --- | --- | --- |
| 来源记忆 | 文档ID、版本、租户、日期与原文定位 | 召回过期制度，却把20%当作当前事实 |
| 会话/任务记忆 | 明确存储位置、写入者、有效期与快照 | 把上下文出现过的摘要当成永久事实 |
| 模型推断 | 输入、输出、校验器和支撑证据 | 语言流畅或重复出现，不代表真的“记得” |

“模型参数里记得”不是可审计证据；无来源时明确说未知或推断，引用也要核对它是否支持当前结论，而非只检查URL存在。

### 2.5 四段式推导：结论、机制、反例、迁移

面试回答不要停在名词。先给可判断的结论，再沿输入与步骤推出结果；随后找一个会推翻误判的反例；最后改变租户、日期、对象所有权或接收方契约，说明结论怎样变化。每段都应能指向一个探针或作品产物。

| 追问 | 结论 | 推导 | 反例 | 迁移 |
| --- | --- | --- | --- | --- |
| 默认字典为什么跨调用共享 | 默认值在函数定义时求值 | 两次调用复用同一字典及内层列表 | 显式传新字典或默认None可隔离 | 改为冻结快照时仍要防嵌套修改 |
| 丢回执为什么不能换键 | 新键形成新动作 | 原键同载荷才能命中接收方去重 | 接收方无幂等键时只能保持未知 | 先查账本，再决定重试或人工对账 |
| P200为什么是20% | 数字来自适用制度而非模型 | 租户+日期过滤，唯一来源返回20%，规则比较25% | 同语义旧制度30%或两条同时生效 | 改日期重选来源，改租户重新授权 |

用最小制度表把AI题的推导跑出来。输入是制度列表、可信租户与日期；输出必须恰好一条适用制度，零条或多条都失败，不能让模型自行挑选。

```python
import json

policies = [
    {"tenant": "tenant-a", "source_id": "policy-a-old", "valid_from": "2026-01-01",
     "valid_to": "2026-07-01", "limit_percent": 30},
    {"tenant": "tenant-a", "source_id": "policy-a-current", "valid_from": "2026-07-01",
     "valid_to": None, "limit_percent": 20},
]

def select_limit(rows, tenant, as_of):
    visible = [row for row in rows if row["tenant"] == tenant
               and row["valid_from"] <= as_of
               and (row["valid_to"] is None or as_of < row["valid_to"])]
    if len(visible) != 1:
        raise LookupError("适用制度不存在或不唯一")
    return dict(visible[0])

current = select_limit(policies, "tenant-a", "2026-10-01")
old = select_limit(policies, "tenant-a", "2026-06-30")
assert current["source_id"] == "policy-a-current" and current["limit_percent"] == 20
assert old["source_id"] == "policy-a-old" and old["limit_percent"] == 30
try:
    select_limit(policies, "tenant-b", "2026-10-01")
except LookupError:
    pass
else:
    raise AssertionError("越租户制度不能用于回答")
ambiguous = policies + [{"tenant": "tenant-a", "source_id": "policy-a-duplicate",
                         "valid_from": "2026-07-01", "valid_to": None, "limit_percent": 15}]
try:
    select_limit(ambiguous, "tenant-a", "2026-10-01")
except LookupError:
    pass
else:
    raise AssertionError("多条适用制度必须暴露冲突")
print(json.dumps({"current": current, "old": old}, ensure_ascii=False, sort_keys=True))
```

预期当前返回`policy-a-current/20`，6月30日返回`policy-a-old/30`；越租户和双制度都抛`LookupError`。失败点在过滤后的数量校验，而不是最后的文本润色。回答时主动说“这个探针验证日期与租户选择，不证明真实模型一定调用它”，就把理解范围和证据范围分开了。

**判定对错：** 每个回答都有结论、至少两步推导、一个会改变结果的反例和一条迁移条件，且与探针输出一致，才算通过；只背“默认参数不能变”“超时可能重复”等标题不通过。

## 3. 原理讲解与推导

### 3.1 解释能迁移，是因为它跟踪了条件变化的因果链

对象创建时机决定共享，提交与回执顺序决定恢复动作，来源过滤与证据匹配决定回答可信度。换一个条件后仍沿同一链条推导，才说明机制成立；只复述原输出则不能。

项目数字要能复查：写清公式、分子/分母、单位、成功与失败是否都计入，以及数据、代码提交、提示词、模型/数据版本、随机种子和重复次数。原始逐题结果与汇总同时保留；只给平均值会隐藏长尾与失败，只给最好一次会隐藏波动。估算、实测和设计目标使用不同标签，不能混算。

## 4. 示例与逐步走查

### 4.1 用引用图回答语言追问

#### 案例推进：第一步，画清外层与内层引用

**问：把请求字典浅复制一次，就能隔离审查状态吗？** 不一定。先看所有权：外层字典可以独立，内层列表仍可能共享。用副本保存批准时展示的载荷，再修改原请求，检查副本是否真的冻结。

```python
# study-example: S29B
from copy import deepcopy

request = {"project_id": "P200", "findings": ["OVER_BUDGET"]}
shallow = request.copy()
frozen = deepcopy(request)
request["findings"].append("PREPAYMENT_TOO_HIGH")
assert shallow["findings"] == ["OVER_BUDGET", "PREPAYMENT_TOO_HIGH"]
assert frozen["findings"] == ["OVER_BUDGET"]
assert shallow is not request and frozen is not request
```

这不是“深复制总是更好”的规则。若对象是连接或文件，问题转为资源所有权，不能随意复制。

### 4.2 两份完整回答：怎样从结论走到证据

#### 案例推进：第二步，用作品时间线回答工程与AI追问

**问：P200报告已批准，远端提交后回执丢失，为什么不能换动作键重试？**

- **结论：** 保持原租户、原动作键和原载荷，先查询或同键同载荷重试，不能换键盲写。
- **推导：** 接收方按动作键去重。换键会变成一条新动作，于是远端第一次效果仍存在，第二次效果又被创建；本地checkpoint只记录执行进度，不能撤销远端提交。
- **反例：** 如果接收方既不支持稳定键，也不能按原键查询，那么“原键重试”也无法保证一次效果。此时应保留`unknown`并对账，而不是把重试说成安全。
- **迁移：** 面试官把失败点移到远端提交前，可按已确认未执行且策略允许时重试；移到提交后，则必须查效果账本。改变的是失败阶段，不是“超时一定失败”的规则。

**问：为什么P200的上限是20%，不是模型算出来的？**

- **结论：** 20%是程序按`tenant-a`和`2026-10-01`选出的制度值，模型只负责提出查询与组织语言。
- **推导：** 日期过滤排除6月30日有效的旧制度30%，当前制度`policy-a-current`成为唯一候选；工具返回20%，确定性规则再比较预付款25%，得到`PREPAYMENT_TOO_HIGH`。
- **反例：** 如果两条制度同时适用，或检索返回旧版，即使模型流畅地说20%也不能证明正确；应暴露冲突或先修版本过滤。
- **迁移：** 改成2026-06-30应选30%，预付款25%不再超限；改租户则必须重新授权并取该租户制度，不能复用tenant-a答案。

### 4.3 把解释限制到证据范围

#### 案例推进：第三步，逐项标明证据与缺口

| 追问 | 自己的证据 | 改变条件后的预测 |
| --- | --- | --- |
| 默认对象何时创建 | S29A/S29B对象关系与断言 | 显式新字典可隔离缺省状态 |
| 丢回执怎样恢复 | 第26章任务表与效果账本 | 换键可能重复，原键同载荷返回原回执 |
| 引用为什么可信 | DocPilot逐字引用或P200来源ID | 旧日期选旧制度，越租户来源不可见 |

只展示参考输出时，应说“理解了设计”；只有自己的实现和故障记录才能说“验证过”。

## 7. 面试问答与迁移

**问：怎样区分Python语义与CPython实现观察？**
答：先查语言规范或明确契约，再用最小实验验证，并记录版本。`id`数值、缓存和字节码细节不当作通用保证；不确定时给出查证路径，不猜成事实。

**问：被问到没有测过的并发或收益怎么办？**
答：说明已知环境、缺失变量和验证计划，不把教材数字当经历。可以给容量估算，但必须标明假设，并用压测或固定集实验补齐证据。

# 项目里程碑与交付检查

[教材目录](教材目录.md) · [项目规格](../project-practice/项目实践规格.md) · [评测方法](../project-practice/评测与故障演练.md)

本文件细化DocPilot与ProcureAgent的交付任务，不是另一套学习路线。W01–W16是已有样例和故障标签使用的历史里程碑编号，不代表必须用16周完成，也不替代教材章节顺序。

DocPilot 的 D1–D4 版本定义及 API、数据库、界面、评测与部署的累计运行命令，统一见[项目装配手册](../project-practice/从实验到项目交付.md)。W04–07 对应这些版本的局部能力，W15–16 用于累计验收，完成一个 W 标签不自动等于完成整个版本。

先按[学习导航](../学习导航.md)选择当前作品。W01 复核 Python 的文件到报告，W02、W03 的校验、HTTP 超时与清理能力在服务阶段练。第 9、11、14 章能力达标即可开始第 18 章的模型实验，上传文档前补齐第 15 章的接口能力。

## 如何按岗位交付

DocPilot 用 W04–07 开发和比对检索效果，交付时选用 W15 的引用回归与 W16 的部署、故障和恢复演示。W02 的工具注册器、W03 的通用工具执行器可在进入 ProcureAgent 时补齐。ProcureAgent 再做 W08 的固定流程和单 Agent 对照，以及 W10 的持久化审批。采用图编排时先做 W09；采用数据库状态机时，同样要通过 W10 的中断、重放和载荷变更检查。

W11 适用于工具需要跨进程或被多个客户端复用的情形。W12–14 用于验证路由、并行与有限返工的收益，可在首版发布后按一次失败选做。求职交付时在进度表标明已验证、待完成和暂缓理由，提交对应的评测与故障记录。

### W01：Python 风格与订单程序

对应教材第1–8、12章。已会内容通过自测即可，不重装环境或重新做全部入门题。

1. 学：名称绑定、引用与复制、list/dict/set。练：自己解释输入被修改的反例，完成筛选和 ID 提取。
2. 学：函数参数、默认值、返回值。练：分组与汇总，修复可变默认参数问题。
3. 学：推导式、生成器、金额单位。练：统一整数分，写全部/已支付金额函数。
4. 学：去重、稳定排序、异常。练：完全重复、同 ID 冲突、并列金额三类输入。
5. 学：JSON、Path、模块入口。练：读取、校验、去重、报告和 CLI。
6. 验收：第一阶段检查与自加反例；解释空输入和失败路径。

完成标准：基础样例全部金额 129600 分、已支付金额 79800 分；重复数据不重复计费；冲突报错；调用前后输入不变。做不出时先缩到两笔订单，修好一个失败再回到完整文件。

### W02：类型与同步工具注册

对应教材第4、9–10、12章；此时工具由代码直接调用，不需要模型。

1. 学：TypedDict、dataclass、Protocol。练：分别描述订单、执行结果和可替换客户端，不用继承层次掩盖简单函数。
2. 学：Pydantic 严格校验。练：定义工具参数模型，拒绝额外字段和错误金额类型。
3. 学：函数作为对象。练：先用 register(name, handler, input_model) 实现工具注册与查找。
4. 学：闭包和装饰器。练：给已有注册逻辑加装饰器入口，重复名称注册明确报错。
5. 学：pytest 参数化、fixture、项目配置。练：覆盖未知工具、非法参数、正常结果和业务异常；检查 Ruff 反馈。
6. 验收：合上示例重写最小注册器；区分错误类别，业务函数不依赖模型 SDK。

完成标准：先校验参数再执行；校验失败时 handler 调用次数为零。Ruff/pytest 是验证工具，不用为了“全绿”删除需要的检查。

### W03：异步工具与 HTTP 客户端

对应教材第11、14章。Tool Lab 是仓库中的模块练习，暂不新建第三个独立服务。

1. 学：HTTPX Client、状态码、JSON、连接超时。练：用 MockTransport 构造成功、500、坏 JSON 与超时。
2. 学：协程、任务、await/gather。练：对相同查询比较顺序与并发实现。
3. 学：Semaphore、超时。练：实现最大并发与单次执行时限，验证 peak_active。
4. 学：取消与清理。练：一个工具失败后取消并等待剩余任务，finally 能结束。
5. 学：有限重试与副作用。练：只为约定的幂等查询重试临时故障；同步阻塞工具采用受控线程边界，并解释取消不能保证中断底层线程。
6. 验收：异步工具注册、参数校验、超时、未知工具、清理与调用记录有可重复案例。

完成标准：客户端关闭、并发可控、任务不泄漏；取消不是“捕获后继续成功”。未达到时先补本阶段，不直接叠加图编排。

### W04：DocPilot 聊天 API

配套[服务生命周期](15-FastAPI、接口模型与服务生命周期.md)、[部署与观测](17-部署、可观测性与可靠性.md)和[模型消息与输出](18-大模型基础、消息与结构化输出.md)。选择一种模型服务做首轮，定义自己的 ModelClient/消息结果接口。

1. 学：FastAPI 请求、响应、依赖与异常。练：GET /health、POST /api/chat。
2. 学：模型请求与返回结构。练：适配客户端，支持假模型与真实模型替换，配置从环境读取。
3. 学：消息上下文、截断、用量。练：记录耗时、模型标识、可获得的 token 用量和错误。
4. 学：流式协议。练：POST /api/chat/stream，用明确事件格式传文本、结束和失败，处理客户端断开。
5. 学：接口测试与边界。练：超时、非法结构、上游失败；创建第一批固定问答/错误样本。
6. 验收：离线接口测试与少量真实服务人工验收分开，日志脱敏。

完成标准：模型 SDK 调用集中在适配层；超时和流断开有清理；普通错误不返回伪成功。鉴权接口先确定当前用户/租户，后续检索和工具复用同一身份来源。

### W05：文档解析与字段证据

1. 学：上传大小/格式、任务状态。练：上传后返回 document_id 与解析状态，空文件、坏格式有错误。
2. 学：文档内容与来源定位。练：从文本型 PDF 提取页码和段落；使用一种解析器跑通，再按结构化/表格需求评估 Docling。
3. 学：扫描件与 OCR 局限。练：标注不支持或低质量页面，缺页码/证据时不猜测；扫描件识别可扩展。
4. 学：结构化输出与证据校验。练：抽取合同名称、双方、金额原文、付款条款和交付时间。
5. 学：字段缺失与人工复核。练：字段值允许 null，保留原文与定位；确定性转换金额，风险提示保留证据和不确定状态。
6. 验收：至少 5 份虚构文档，覆盖字段缺失、表格、无法解析和模型坏输出，人工核对抽取。

完成标准：抽取值能追溯；格式正确不替代事实核对；用户只能访问自己有权限的文档。不将原文或未经校验的模型判断直接当作业务事实。

### W06：RAG 基线与数据过滤

1. 学：版本、租户、来源和检索标签。练：使用配套虚构制度，确定 as_of 日期与可见来源。
2. 学：分块。练：保留 source_id、version、页码或节号；手工标出若干问题的相关来源。
3. 学：Embedding 与向量维度。练：选择一个模型，将模型/分块版本记录进索引配置。
4. 学：Qdrant 存储和过滤。练：小规模入库，按租户与生效时间过滤；身份来自服务端认证上下文。
5. 学：检索后生成与证据。练：返回引用，无证据时说明不足；检查同文档旧版和另一租户隔离。
6. 验收：关键词与向量两条基线，固定问题的检索结果与来源可导出。

完成标准：授权过滤覆盖所有检索分支；越权来源不进入提示词。不能只在最终回答中隐藏不该检索到的内容。

### W07：混合检索与重排实验

1. 学：关键词/稀疏与 Dense 的不同召回特性。练：分析基线错误，不先假定更复杂一定更好。
2. 学：RRF 等融合思路。练：用相同过滤和候选集约定比较纯向量、关键词与融合。
3. 学：Rerank。练：增加一组重排实验，记录输入候选数、输出数和额外耗时。
4. 学：指标口径。练：先跑[离线对照](../project-practice/评测与故障演练.md#先跑一个离线对照)，查看首个相关来源排名与多证据覆盖。再补到 20–30 个人工核对问题，固定 source/chunk 粒度并保留未调参题。
5. 学：对照与误差分析。练：区分召回不到、排序靠后、版本错误、生成不忠实四类问题。
6. 验收：保留基线与实验结果，按质量/延迟/资源代价选择默认方案，剩余方案可作为实验分支。

完成标准：写出实验结论；检索通过后仍检查引用是否真的支持回答。没有资源部署重排模型时，完成可复现的融合对照并把重排列为扩展。

### W08：ProcureAgent 手写单 Agent

配套[工具调用与手写循环](24-ToolCalling与手写AgentLoop.md)和[ProcureAgent 综合项目](26-项目实战二：ProcureAgent审查系统.md)。先用虚构业务 API 验证只读审查。

1. 学：采购样例与审查结果契约。练：区分明确违规、资料不足和没有发现异常。
2. 学：工具 Schema。练：实现 search_policy/get_project/query_supplier/check_rules 四个只读工具。
3. 学：调用循环与模型原生工具请求。练：校验、执行、回传，再决定继续或完成。
4. 学：结束与预算。练：最大步骤、工具次数、请求超时、任务时限和上下文预算。
5. 学：错误恢复与证据链。练：缺字段、未知供应商、工具失败时返回明确状态；记录工具轨迹。
6. 验收：固定采购场景，模型选择合适工具；数值与规则由确定性代码核对。

完成标准：只读单 Agent 基线可重复评估。真实多源任务能完成多步查询；简单任务允许提前结束。缺资料不能被解释为合规。

### W09：迁移到 LangGraph

1. 学：State、Node、Edge、条件边。练：画出已有循环，逐个对应为图节点。
2. 学：状态更新。练：明确输入、消息、证据、结果与错误各放在哪里。
3. 学：工具节点与退出。练：迁移调用流程，保留同一模型、工具与预算。
4. 学：图的错误传播。练：处理工具失败和模型输出不合法，不隐藏异常。
5. 学：等价比较。练：对相同案例运行手写版和图版，比较结果与轨迹。
6. 验收：解释采用框架解决了什么，记录尚未解决的业务和执行问题。

完成标准：迁移不改变已有业务规则；不是为采用框架而重写数据、规则和评测集。

### W10：持久化、人工审核与写入控制

1. 学：业务状态与恢复位置的区别。练：保存 task_id、状态、操作者与已确认的动作；图实现另存执行标识和 checkpoint 映射。
2. 学：持久化和恢复。练：先用测试存储理解机制，再接所选持久化实现；验证服务重启。
3. 学：暂停与恢复。练：审查完成后生成待确认提案，持久化 waiting_approval；用图的 interrupt/resume 或数据库状态转换从该任务继续。
4. 学：审批绑定与幂等。练：审批绑定操作者、任务、动作和载荷版本；变化后旧审批失效；重复写入只产生一个模拟业务效果。
5. 学：拒绝、取消、重试。练：重复 resume、拒绝后继续、工具执行中重启和取消的场景。
6. 验收：审批通过前零业务效果；复核权限后执行；业务事件与持久状态可以对账，图实现另核对 checkpoint。

完成标准：在模拟业务服务中演示可恢复和防重复写入。重放可能重复进入节点，外部写入不能只靠“节点执行过”的内存标记。

### W11：MCP 与服务边界

1. 学：MCP 的参与者、工具发现、传输和错误。练：画出应用、Client、Server、业务 API 的关系。
2. 学：服务适配。练：先暴露两个只读工具，复用原业务函数。
3. 学：Client 调用与校验。练：将结果转换成内部 ToolResult，记录版本和失败类型。
4. 学：认证与授权边界。练：Server 根据可信身份再次校验权限，不相信模型传来的 tenant_id/role。
5. 学：连接关闭与协议失败。练：Server 不可用、超时、字段不匹配和断开连接。
6. 验收：同一工具本地调用和 MCP 调用结果一致；越权请求均被拒绝。

完成标准：明确 MCP 是协议层，编排与业务权限仍需各自实现；此时不必把所有工具迁成远程服务。

### W12：Router 与串行专业 Agent

1. 学：任务路由。练：DocPilot 区分制度问答、合同抽取、数值查询；提供不确定时的澄清路径。
2. 学：任务拆分与上下文隔离。练：将采购审查分成资格、预算、合同三个结构化任务。
3. 学：Supervisor/Agent as Tool。练：先串行执行，子 Agent 仅有所需工具与数据权限。
4. 学：结果契约。练：使用共同 Finding/ReviewResult 格式，不直接拼接三段自然语言。
5. 学：对照公平性。练：与固定规则工作流、单 Agent 使用同一案例和资源预算。
6. 验收：提交适用任务、失败类型与初始成本比较；不能证明收益时保留单 Agent 主路径。

### W13：并行、局部失败与合并

1. 学：fan-out/fan-in。练：三个相互独立的审查任务并行执行。
2. 学：状态隔离与 reducer。练：子任务返回独立结果，合并按 finding_id 和证据标识去重。
3. 学：超时与局部失败。练：一个子任务超时标 partial/needs_review，不伪装整体通过。
4. 学：取消和资源竞争。练：取消父任务后清理子任务；避免多个 Agent 重复写相同记录。
5. 学：结果冲突。练：保留来源、版本、规则和冲突项，不能只按多数投票。
6. 验收：比较串行、并行的结果、p50/p95、费用与失败率；记录是否值得保留。

### W14：Evaluator 与有限补充调查

1. 学：结构/引用/业务约束检查。练：优先用程序检查，不把所有评估交给另一个模型。
2. 学：证据核验。练：发现引用旧制度或缺失资料时标出具体问题。
3. 学：定向返工。练：只重新获取有问题的资料，限制调查次数和总任务预算。
4. 学：动态与固定流程比较。练：用复杂任务比较预设分工和有限动态拆分。
5. 学：模型意见的局限。练：Evaluator 也会犯错；保留人工标签和原始证据。
6. 验收：形成单 Agent、串行专家、并行专家、带返工四组实验，给出采用或回退结论。

### W15：追踪、回归与执行约束

1. 学：span 与关联标识。练：task_id、模型、工具、检索、审批、错误可以串起来。
2. 学：Langfuse 或等价轨迹适配。练：先复用已有事件日志，再按需接入；发送前脱敏。
3. 学：固定数据与版本回归。练：记录模型、提示、工具 Schema、索引与代码版本。
4. 学：提示注入与访问边界。练：文档中恶意指令、其他租户数据、伪造工具参数等场景。
5. 学：预算与降级。练：次数/时限/费用达到阈值时标明状态，可退回只读证据结果。
6. 验收：相同案例可重跑并定位失败，不以一个总分掩盖越权或未审批写入。

### W16：部署、故障演练与交付

1. 学：进程、配置与健康检查。练：API、数据服务和模型配置分离，提供启动说明。
2. 学：Compose、卷与版本。练：优先启动最小 API + PostgreSQL + Qdrant 配置；MCP/追踪按需启用。
3. 学：存储恢复。练：备份/恢复样例数据，验证重启、重复请求和恢复中的任务。
4. 学：依赖不可用。练：暂停项目已接入的一项依赖，观察状态与客户端反馈，然后恢复并复验。
5. 学：容量与代价。练：小规模并发观察资源与延迟，记录硬件和负载，避免无依据性能承诺。
6. 验收：从 README 复现演示，交付测试、评测、架构演进、故障记录和限制说明。

完成标准：得到可复现的工程实践系统。Compose 启动成功不能代表高可用、安全审计、真实生产容量或商业可用性已经得到验证。

## 每周固定交付

- 可运行的一个小版本；未做的功能明确列出。
- 至少一个新增或更新的自动化行为测试，加一组必要人工评测。
- 一页记录：上版问题 → 本次改动 → 验证结果 → 代价 → 下次任务。
- 可复现命令、依赖/数据/模型版本；涉及真实服务时说明网络和资源条件。

每周约 60% 编码调试、25% 阅读、15% 验证复盘。验收日优先补失败案例；功能和依赖只随当前阶段加入。

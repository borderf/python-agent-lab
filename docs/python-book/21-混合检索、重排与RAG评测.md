## 2. 基础知识讲解

### 2.1 先为不同信号建立基线

关键词检索依赖词项匹配。BM25同时考虑词频、文档频率与长度归一化：常见词区分力弱，重复词收益逐渐饱和，长文档不会仅因词多而占优。中文检索还要固定实际分词器，不能直接照搬英文空格切分。

稠密向量擅长语义相近表达，但可能忽略精确编号。先用“制度POL-17写了什么”和“付款前最多能先付多少”分别观察两路结果，记录候选数、过滤条件和去重单位。改变候选范围本身就会改变召回，不能把所有变化都归给融合。

BM25可近似看成 `IDF(t) × tf × (k1+1)/(tf+k1×(1-b+b×文档长度/平均长度))`：`tf`是词频，`k1>0`控制重复词收益饱和，`b∈[0,1]`控制长度归一化；`b=0`不惩罚长文，`b=1`使用完整长度比例，IDF还受文档频率与实现平滑方式影响。它是排序公式而非“包含关键词就相关”的规则，词项加权、字段加权和平滑参数应在验证集调，不能只背默认值。
关键词与向量应各自保留过滤后的候选池，再明确并集、去重键与每路深度。设两路候选并集为C，最终Recall@K不会超过对C的召回；扩大池可能提高上限，却增加融合、重排和上下文成本。若标准证据不在C，先检查分词、向量、权限或候选深度，而不是先调RRF。

#### 案例推进：同一问题先看两路遗漏

固定租户、日期与Top-K，导出关键词和向量各自的前五来源。对每题标明“哪一路找到标准证据、哪一路漏掉、是否返回越权或旧版”。这张表是后续所有改进的起点。

### 2.2 RRF只整合排名

不同检索器的原始分数尺度可能不同，直接相加会偏向某一路。倒数排名融合RRF按 `1/(k+rank)` 累加，rank从1开始；同一路径内的重复来源先去重，避免重复占位。参数k、候选深度和并列规则都属于实验条件，不是固定真理。

`k`越大，前几名与后几名的贡献越接近；`k`越小越强调头部排名，但都可能受并列与池深影响。RRF默认各路等权，既不校准分差，也不知道相关程度；若某一路质量明显更差，可在验证集比较降权、配额或只用单路，不能把换权重误报为调k。
融合只能组合已经召回的候选。两条路径都没找到的证据，不会因为计算了融合分数而出现。

#### 案例推进：手算一次融合

A、B两路结果分别为 `["A","B"]` 与 `["B","C"]`。B获得两次贡献，排第一；A与C各一次，按名次分开。下一步再运行4.1的B21，确认实现与手算一致。

### 2.3 先定义答案与指标分母

每题固定允许访问的相关来源、业务日期和版本。按source_id还是chunk评分必须统一；同一来源多个chunk如何去重也要说明。

Recall@K看所需来源找回多少，Precision@K看返回项中相关多少，单题RR是第一个相关位置的倒数，多题RR求平均才是MRR。引用位置正确、引用支持结论、答案事实正确是三件事，不能用一个指标代替。

无答案题没有相关来源召回率的分母，应单列拒答表现，不能记成100%后混入平均分。

多证据或分级相关性可用nDCG@K：先算 `DCG@K=Σ rel_i/log2(i+1)`，再除以同批标注按相关性降序排列得到的理想DCG。`K≥1`，没有相关标注时为N/A；它同时惩罚相关项靠后和非相关项插队，但不能代替Recall。标注集要冻结题目、身份、日期、来源粒度和相关性等级，记录双人分歧与裁决理由；开发集调参后再一次性看保留集，避免反复查看保留集造成隐性过拟合。

```python
from math import log2

def ndcg_at_k(relevances, k):
    if type(k) is not int or k < 1:
        raise ValueError("k必须为正整数")
    if any(type(rel) not in (int, float) or rel < 0 for rel in relevances):
        raise ValueError("相关性等级必须为非负数")
    ranked = relevances[:k]
    ideal = sorted(relevances, reverse=True)[:k]
    dcg = sum(rel / log2(rank + 1) for rank, rel in enumerate(ranked, 1))
    idcg = sum(rel / log2(rank + 1) for rank, rel in enumerate(ideal, 1))
    return None if idcg == 0 else dcg / idcg

assert ndcg_at_k([3, 2, 0], 2) > ndcg_at_k([2, 3, 0], 2)
assert ndcg_at_k([0, 0], 2) is None
```

#### 案例推进：用分母理解指标

```python
# study-example: S21B
relevant = {"A", "B"}
retrieved = ["C", "A", "D"]
recall = len(set(retrieved[:3]) & relevant) / len(relevant)
precision = len(set(retrieved[:3]) & relevant) / 3
first_rank = next((i for i, item in enumerate(retrieved, 1) if item in relevant), None)
reciprocal_rank = 0 if first_rank is None else 1 / first_rank
def reciprocal(labels, ranked):
    first = next((i for i, item in enumerate(ranked, 1) if item in labels), None)
    return 0 if first is None else 1 / first
def mrr(pairs):
    if not pairs:
        raise ValueError("至少需要一道题")
    return sum(reciprocal(labels, ranked) for labels, ranked in pairs) / len(pairs)
assert recall == 0.5 and precision == 1/3 and reciprocal_rank == 0.5
assert mrr([({"A", "B"}, ["C", "A", "D"]), ({"E"}, ["E"])]) == 0.75
```

### 2.4 重排只处理已有候选

Reranker联合比较问题与候选，能调整顺序，也会增加计算与等待。正确证据若没进入候选，重排无法补回。候选数量、重排模型和总预算应一次只改变一个主要变量。

双塔向量检索分别编码问题与文档，可提前建索引；cross-encoder把问题与每个候选共同编码后打分，交互更强但不能替代大规模召回。它只重排传入的候选，受模型最大长度、截断策略、候选数和批量大小影响；长条款被截掉关键条件时，分数高也不代表证据完整。
逐题错误按解析、过滤、召回、排序、版本和生成分类。先修数量最多且可定位的一类，再跑保留题；少量题适合练习，不能外推成普遍提升。归因记录应包含首个失败阶段、预期与实际候选、标准证据所在位置及证据快照；同一题可有多因，但要固定首个可修复分叉，避免把生成错误记成召回错误。

#### 案例推进：把错误归到首个分叉

标准来源不在索引里，先查解析和权限过滤；在候选却掉出上下文，再查排序与截断；进入上下文仍答错，才检查生成是否误读证据。每一步都保留中间产物，避免直接更换模型。

## 3. 原理讲解与推导

### 3.1 上游缺失不能由下游补回

检索是一条有损流水线：未入库、被过滤、未召回、排序靠后和误读证据是不同失败。把每阶段产物导出，就能找到错误首次发生的位置；在错误位置之前增加计算，通常只会增加成本，不能恢复丢失的信息。

## 4. 示例与逐步走查

### 4.1 同一查询：先融合，再逐题评测

对“付款前最多能先付多少”固定同一语料、租户与日期。先记录关键词和向量候选，再用下面的RRF融合；重排版只改变候选顺序，不改变授权范围。

```python
# book-example: B21
def rrf(rankings, k=60):
    scores = {}
    for ranking in rankings:
        for position, source_id in enumerate(dict.fromkeys(ranking), 1):
            scores[source_id] = scores.get(source_id, 0) + 1/(k+position)
    return sorted(scores, key=lambda sid: (-scores[sid], sid))
assert rrf([["A","B"],["B","C"]])[0] == "B"
```

### 4.2 同一查询：判断收益来自哪一步

| 版本 | 记录 | 要回答的问题 |
| --- | --- | --- |
| 关键词 | 前K来源、Recall、RR | 精确词项是否足够 |
| 向量 | 前K来源、Recall、RR | 同义表达是否改善召回 |
| 融合 | 各路候选与融合结果 | 是否找回单路漏掉的证据 |
| 融合加重排 | 重排前后顺序、耗时与费用 | 正确证据是否已召回，只改善顺序 |

对每题同时检查引用是否支持结论。若质量提高但延迟或费用超过预算，仍可选择简单基线。返回全部来源也可能得到高Recall，却不证明排序有用。

## 7. 面试问答与迁移

**问：Recall高而答案差，可能是什么原因？** 命中正确文件不等于取到正确条款，也不证明模型按证据作答。继续检查版本、候选截断、引用位置、语义支持与生成忠实性。

**问：Rerank能修复什么？** 只能在已召回候选中调整顺序。先提高候选覆盖，再比较重排的质量、延迟与成本；不能把漏召回问题交给重排。

**换条件自测：** 一题需要两条证据却只命中一条，按“命中任一来源”的成功率可为1，按来源Recall只有1/2。再用无答案题验证分母没有混用。

## 8. 本章小结与参考

- 固定题集、身份、日期、语料版本和候选预算，再比较检索组件。
- RRF整合排名，不直接比较原始分数；重复项先去重。
- 重排只调整已有候选，不能恢复上游漏召回。
- 逐题记录质量与代价，按错误首次发生的位置决定改进。

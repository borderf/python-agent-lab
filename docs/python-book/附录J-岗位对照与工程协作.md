# 岗位对照与工程协作

[第 30 章](30-转行准备、项目讲述与系统设计面试.md) · [阶段自测](附录H-阶段自测与复习.md) · [项目交付](../project-practice/从实验到项目交付.md)

每完成一份可交付作品，就把目标岗位中的实际任务与自己的证据对照。保存岗位来源、日期和原文任务句，判断匹配程度时采用具体任务。

## 形成自己的岗位对照表

先选三至五个你实际愿意投递的职位。把任务拆成能被观察的动作，再填写下表。不同职位的必需项与加分项各按原文记录。

| 岗位任务 | 已有经验可以迁移什么 | 当前作品能展示什么 | 下一项最小补法 |
| --- | --- | --- | --- |
| 独立开发 AI 应用接口 | Java 接口、异常、事务、测试 | Python API、模型适配与坏输出处理 | 现场增加一个字段并保留兼容 |
| 建立可衡量的知识库 | 数据建模、搜索与数据治理经验 | 同题检索、引用与版本回归 | 用陌生资料定位一次漏召回 |
| 开发可恢复 Agent | 状态机、幂等、消息与故障经验 | 真实工具轨迹、批准和重放结果 | 改载荷后恢复，核对业务效果 |
| 推动产品采用 | 需求沟通与上线协作 | 用户任务、反馈、一次范围调整 | 邀请一人独立完成新任务并记录 |

如果岗位明确要求训练或推理平台经验，另列训练、GPU 与服务容量专项。用现有工程背景描述已验证能力，再用个人项目说明新积累的模型与执行经验。

## Java 经验怎样在 Python 中重新验证

| 熟悉的职责 | Python 中要亲手观察的差异 | 实验 |
| --- | --- | --- |
| DTO 与接口校验 | 注解与运行时验证分别承担什么 | 对 bool 金额、缺失与 null 经过真实接口测试 |
| 依赖注入与事务 | 应用客户端、请求会话、取消与关闭 | 在模型等待前释放事务，失败后重开连接 |
| 线程池与异步 | 创建协程、调度任务与阻塞调用的区别 | 比较串行、有界并发、取消和队列上限 |
| 业务写入与重试 | 本地提交与远程效果的不同提交点 | 持久图恢复与原动作键对账 |

选择一条自己熟悉的 Java 接口契约，在隔离环境用 Python 客户端调用。先用 HTTP 替身覆盖成功、超时、坏 JSON 和版本变化，再接真实 Java 实现。保留同一份请求响应样本与调用次数；将调度、模型和持久状态变化分别说明。

## 用 AI 协作，同时验证自己的掌握

挑一项具体变更，例如给资料增加 owner 字段。先独立写出验收样本与受影响位置，再请编码助手提出实现计划。记录建议、你接受或修改的部分，以及用什么证据作决定。

审查重点包括是否漏迁移、是否在异步路由放入阻塞工作、是否吞异常、是否信任请求中的租户、是否把测试改成固定答案。让生成的实现经过真实路由、迁移与旧题回归，再随机选一个函数合上资料重写。

一次协作交付应包含需求、计划、变更 diff、运行命令、故障与修复。对自己解释不清的部分保留待练状态。可以在独立练习副本故意加入可变默认值或无上限重试，请助手评审后再由你验证。

## 三次有条件变化的模拟面试

1. 语言与工程轮用 45 分钟完成一个小变更，例如订单新增退款状态。先说输入契约，再写函数、测试和错误处理，最后解释包、CLI 与接口的影响。
2. 调试轮给出“接口偶发超时，用户重试后出现重复效果”。先收集请求标识、日志、任务与动作记录，定位后只改一项，并说明如何验证。
3. AI 设计轮由对方临时改变日期、权限或模型可用性。先走用户任务，再画链路，演示来源、工具、状态、预算和恢复如何配合。

反馈表逐项填写准确性、解释、独立实现、证据和取舍。把最薄弱的一项转成下一周练习，再用新输入复验。完成 DocPilot 后开始第一轮，完成 Agent 后加入恢复和动作案例。

## 形成可复查的作品包

每份作品准备一页问题与范围、一组启动命令、一段用户操作演示、逐题评测、一项失败修复和一份设计取舍。简历中的数字使用自己测得的样本口径，个人实践、真实工作与设计计划分别表述。

收到岗位沟通或面试反馈后，记录对方追问的是语言、工程、模型效果、业务理解还是协作。优先修补目标岗位反复追问且缺少证据的部分，把新的反馈接回同一个项目。

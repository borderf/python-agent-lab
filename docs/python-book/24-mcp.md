## 1. 学习目标与前置知识

理解协议层、编排层和业务后端分工。前置：第14、16、22章。

## 2. 基础知识讲解

MCP 用统一交互方式描述应用与工具/资源服务之间的发现和调用。Host、Client、Server 的生命周期、传输和能力协商要与所用规范/SDK版本一致。

Tools、Resources、Prompts 各有用途；暴露接口不等于赋予调用者全部权限。Server 必须依据可信身份重新校验，模型参数里的租户和角色不可信。

将本地工具包装为 MCP 适配时复用业务逻辑，转换错误和结果格式，处理超时、连接关闭与服务不可用；不要为了使用协议把所有本地函数都拆成远程微服务。

## 3. 原理讲解与推导

协议提供互通边界，不自动提供业务授权、事务或 Agent 决策。区分 SDK 功能与协议保证，并核对版本协商。

### 版本、身份与结果适配

先确认使用的协议版本、传输方式与SDK，再对照工具发现、调用和错误。工具输入Schema是契约，不是授权凭证；客户端和服务端都要保留正确身份上下文。

REST可以表达已有业务接口，MCP提供面向模型应用的能力交互约定，Tool Calling表达模型的调用意图，LangGraph负责执行编排。把它们混为同一层会造成重复规则和无法定位的错误。

## 4. 示例与逐步走查

### 工具发现与输入契约走查

```json
{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}
```

某个工具描述可包含：

```json
{"name":"get_project","description":"查询当前身份可访问的虚构项目","inputSchema":{"type":"object","properties":{"project_id":{"type":"string"}},"required":["project_id"],"additionalProperties":false}}
```

这不是完整会话或授权流程。实际Client须先按协议与SDK完成连接/协商，再发现、调用和处理结果；Server用可信身份重新判定project_id权限。

**行为验收：** Client/Server 可独立验证；无权限拒绝；结果和错误与原工具一致；断开连接有清理。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

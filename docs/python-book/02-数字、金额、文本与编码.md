## 2. 基础知识讲解

### 2.1 整数分：先固定单位，再计算

199元等于19900分。整数分适合累计、比较和传输，因为业务已经约定最小单位是一分。`divmod(cents, 100)` 同时得到元和余数。

```python
cents = 19901
yuan, remainder = divmod(cents, 100)
assert (yuan, remainder) == (199, 1)
```

这里两个名称分别接收商和余数，叫解包。格式说明 `02d` 只负责展示时补零，不改变整数对象。若执行 `print(cents, yuan, remainder)`，实际输出为：

```text
19901 199 1
```

`divmod(19901, 100)` 先做整除得到199，再取余数得到1；解包只是把这两个结果分别绑定到 `yuan` 和 `remainder`。这和先写 `yuan = cents // 100`、`remainder = cents % 100` 得到相同数值，但一次调用同时表达“按单位拆分”。

`/` 总是得到浮点结果，`//` 向负无穷方向取整，`%` 的余数符号跟随除数；它们与先截断的“向零取整”不同。乘除、`//`、`%`、`**` 通常高于加减，幂运算还高于左侧一元正负号。`int("ff", 16)` 按显式进制解析，`0b1010` 是二进制字面量，`1e3` 则是浮点科学计数法；金额解析仍按2.2拒绝最后一种形状。

显式转换要按目标类型的输入契约使用：`int(2.9)` 截断为2，`int("2.9")` 则失败；`float("1e2")` 接受科学计数文本，`str(19)` 得到文本。`round(2.5)` 采用平局取偶规则，不等于所有业务都想要的四舍五入。内置数值还包括 `bool` 和 `complex`，例如 `1 + 2j` 的实部为1、虚部为2；复数适合数学计算，不应拿来保存订单金额。

```python
assert 7 / 2 == 3.5 and isinstance(7 / 2, float)
assert 7 // 2 == 3 and 7 % 2 == 1
assert -7 // 2 == -4 and -7 % 2 == 1
assert -2 ** 2 == -4 and (-2) ** 2 == 4
assert int("ff", 16) == 255 and 0b1010 == 10
assert 1e3 == 1000.0 and isinstance(1e3, float)
assert int(2.9) == 2 and float("1e2") == 100.0 and str(19) == "19"
assert (1 + 2j).real == 1 and (1 + 2j).imag == 2
```

位运算 `&`、`|`、`^`、`~`、`<<`、`>>` 按整数位模式计算，逻辑运算 `and`、`or`、`not` 按真假值和短路规则工作，二者不能互换。混合表达时用括号明确意图。

| 表达式 | 实际结果 | 原因 |
| --- | --- | --- |
| `6 & 3` | `2` | 二进制 `110 & 011 = 010` |
| `6 and 3` | `3` | 6为真，返回最后一个操作数3 |
| `-7 // 2` | `-4` | 向负无穷取整，不是向零取整 |
| `int(2.9)` / `int("2.9")` | `2` / 失败 | 前者截断浮点，后者不接受小数文本 |

```python
assert 6 & 3 == 2 and 6 | 3 == 7 and 6 ^ 3 == 5
assert ~2 == -3 and (1 << 4) == 16 and (16 >> 2) == 4
assert (6 & 3) == 2 and (6 and 3) == 3
```

### 2.2 金额文本：先规定合法形状

本书约定：去两端空白后，只接受 ASCII 数字组成的非负金额；可有小数点，但小数部分为1–2位。科学计数、负号、`NaN` 和三位小数都不接受。

```python
amount_text = " 19.90 "
cleaned = amount_text.strip()
parts = cleaned.split(".")
yuan_text = parts[0]
fraction_text = parts[1] if len(parts) == 2 else ""
valid = (
    len(parts) in (1, 2)
    and yuan_text.isascii() and yuan_text.isdigit()
    and (len(parts) == 1 or (
        fraction_text.isascii() and fraction_text.isdigit()
        and 1 <= len(fraction_text) <= 2
    ))
)
amount_cents = int(yuan_text) * 100 + int(fraction_text.ljust(2, "0")) if valid else None
assert amount_cents == 1990
assert amount_text == " 19.90 "
```

`split` 产生片段列表，`strip` 返回新文本。`ljust(2, "0")` 把一位小数右侧补成两位，所以 `19.9` 解释为90分，而不是9分。非法形状先得到 `None`，正式函数接口的错误行为在第4–5章补齐。

把同一规则套到一组输入，才能同时看到正常值和拒绝边界。下面没有定义函数，也没有提前转换，因此非法文本不会进入 `int`：

```python
samples = ["19", "19.9", " 19.90 ", "19.999", "-1", "1e2", ""]
for amount_text in samples:
    cleaned = amount_text.strip()
    parts = cleaned.split(".")
    yuan_text = parts[0] if parts else ""
    fraction_text = parts[1] if len(parts) == 2 else ""
    valid = (
        len(parts) in (1, 2)
        and yuan_text.isascii() and yuan_text.isdigit()
        and (len(parts) == 1 or (
            fraction_text.isascii() and fraction_text.isdigit()
            and 1 <= len(fraction_text) <= 2
        ))
    )
    amount_cents = int(yuan_text) * 100 + int(fraction_text.ljust(2, "0")) if valid else None
    print(repr(amount_text), "->", amount_cents)
```

```text
'19' -> 1900
'19.9' -> 1990
' 19.90 ' -> 1990
'19.999' -> None
'-1' -> None
'1e2' -> None
'' -> None
```

逐步看 `"19.9"`：`strip` 不改变它，`split` 得到 `["19", "9"]`，`"9".ljust(2, "0")` 得到 `"90"`，于是 `19 * 100 + 90 = 1990`。`"19.999"` 的小数位为3，`valid` 为假，条件表达式选择 `None`，不会执行右侧转换。常见错误是只用 `float` 转换再看是否为整数，或给 `split` 加 `maxsplit`；前者绕过ASCII和科学计数规则，后者可能把多余的小数点吞进片段。

### 2.3 精确表示：float 管近似，结算管约定

二进制浮点不能精确表示十进制的 `0.1`。输入先取近似值，加法结果还可能再舍入，因此 `0.1 + 0.2 != 0.3`。这不是所有浮点运算都错，`0.5 + 0.25` 可以精确等于 `0.75`。

`Decimal("0.1")` 从文本保留十进制含义；`Decimal(0.1)` 接收的已经是浮点近似。格式化成两位只能改变显示，不能修复之前的计算。

```python
# experiment: E04
from decimal import Decimal
assert 0.1 + 0.2 != 0.3
assert f"{0.1 + 0.2:.2f}" == "0.30"
assert Decimal("0.1") + Decimal("0.2") == Decimal("0.3")
assert Decimal(0.1) != Decimal("0.1")
assert 1999 + 1 == 2000
assert divmod(2000, 100) == (20, 0)
q, r = divmod(-7, 3)
assert (q, r) == (-3, 2)
assert -7 == q * 3 + r
print(repr(0.1 + 0.2), Decimal("0.1") + Decimal("0.2"), divmod(-7, 3))
```

```text
0.30000000000000004 0.3 (-3, 2)
```

普通订单累计直接用整数分。折扣或分摊产生不足一分的结果时，还要另外规定舍入时机与余数归属，不能靠换类型自动解决。

近似值是否足够接近，应使用 `math.isclose` 并明确相对误差 `rel_tol` 与绝对误差 `abs_tol`，不能随意扩大容差迎合结果。`NaN` 与自身不相等且大小比较为假；正负 `inf` 表示溢出或特殊结果，`math.isfinite` 才能排除它们，`isclose(inf, inf)` 为真并不表示数值有限。

```python
import math
from decimal import Decimal, ROUND_HALF_UP
assert math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9, abs_tol=1e-12)
nan = float("nan")
assert nan != nan and not math.isfinite(nan)
assert math.isinf(float("inf"))
assert Decimal("19.995").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP) == Decimal("20.00")
print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9, abs_tol=1e-12), nan, math.isfinite(nan),
      Decimal("19.995").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
```

```text
True nan False 20.00
```

`Decimal.quantize` 只按指定指数和舍入模式改变小数位；`ROUND_HALF_UP` 在恰好半值时远离零。十进制上下文仍会影响其他运算，目标小数位超过上下文精度时还可能失败，所以“用了 Decimal”不等于自动获得安全结算。

### 2.4 文本与字节：显示和存储是两种对象

`str` 表示 Unicode 文本，`bytes` 表示字节序列。`text.encode("utf-8")` 把文本编码为字节，`raw.decode("utf-8")` 按 UTF-8 解释回文本。字符数与字节数可能不同。

```python
text = "采购A"
raw = text.encode("utf-8")
assert len(text) == 3 and len(raw) == 7
assert raw.decode("utf-8") == text
assert isinstance(raw, bytes) and not isinstance(raw, str)
print(text, len(text), raw, len(raw), raw.decode("utf-8"))
```

```text
采购A 3 b'\xe9\x87\x87\xe8\xb4\xadA' 7 采购A
```

编码必须与读取方约定一致。按字节切片可能切断一个字符的 UTF-8 序列，解码时才会暴露错误；不能把字节数当成字符数。`"采购A".encode("utf-8")[:1]` 只拿到“采”的第一个字节，调用 `.decode("utf-8")` 会得到 `UnicodeDecodeError`；这说明切片本身可以成功，坏字节要到解码边界才被发现，本章暂不捕获它。

需要原地修改字节时可用 `bytearray`，但切片替换和删除仍按字节，不按字符；只改半个字符会让后续 UTF-8 解码失败。文本修改通常应构造新 `str`，不要把字节缓冲当成天然字符序列。

```python
buffer = bytearray("A中".encode("utf-8"))
buffer[0] = ord("B")
assert buffer.decode("utf-8") == "B中"
print(buffer.decode("utf-8"))
del buffer[1:]
assert buffer == b"B"
print(buffer.decode("utf-8"))
```

```text
B中
B
```

第一行输出说明只替换ASCII字节A时编码仍完整；`del buffer[1:]` 删除“中”的三个字节后，第二次输出只剩B。若按字符位置删一个字节，留下的UTF-8序列就可能不完整。

```python
# study-example: S02J
code = "A-1234"
assert code[0] == "A" and code[-1] == "4"
assert code[2:5] == "123"
assert code[2:] == "1234"
assert code[2::2] == "13"
assert code[::-1] == "4321-A"
assert code[20:] == ""
assert code == "A-1234"
print(code[2:5], code[2::2], code[::-1])
```

```text
123 13 4321-A
```

切片终点不包含；越界的普通切片可得到短结果，单个越界下标则会失败。切片产生新文本，原对象不变。

```python
# study-example: S02K
raw = "  Paid-A  "
cleaned = raw.strip()
normalized = cleaned.lower()
assert cleaned == "Paid-A" and normalized == "paid-a"
assert normalized.startswith("paid-")
assert normalized.endswith("a")
assert normalized.find("paid") == 0
assert normalized.find("missing") == -1
assert normalized.replace("paid", "pending") == "pending-a"
assert raw == "  Paid-A  "
print(cleaned, normalized, normalized.find("paid"), normalized.find("missing"))
```

```text
Paid-A paid-a 0 -1
```

`find` 返回位置或 `-1`，所以位置 `0` 虽然为假，也代表找到。是否清理空白、统一大小写应由字段规则决定，不能默认改写业务内容。

### 2.5 文本构造：拆分、拼接与边界

字符串是不可变对象，“修改”通常指方法返回新文本。`split(sep, maxsplit)` 返回列表，`join(iterable)` 要求每个元素都是字符串；`find` 对未找到内容返回 `-1`，`index` 对同样情况抛 `ValueError`。`removeprefix/removesuffix` 只在边界匹配时删除一次，不像全局 `replace` 那样替换所有出现位置。

```python
# study-example: S02L
text = "  paid,A-001,notes  "
parts = text.strip().split(",", 2)
assert parts == ["paid", "A-001", "notes"]
assert "|".join(parts) == "paid|A-001|notes"
assert parts[1].index("-") == 1
assert parts[1].find("missing") == -1
assert parts[0].removeprefix("p") == "aid"
assert parts[0].removesuffix("d") == "pai"
assert parts[0].replace("a", "o") == "poid"
assert "Straße".casefold() == "strasse"
print(parts, "|".join(parts), parts[0].removeprefix("p"), parts[0].removesuffix("d"))
```

```text
['paid', 'A-001', 'notes'] paid|A-001|notes aid pai
```

`lower` 主要处理大小写，`casefold` 用于更激进的 Unicode 大小写折叠；是否适合业务键要按约定验证。拆分时先决定分隔符、最多拆几次和是否保留空字段，例如 `"a,,b".split(",")` 会保留中间空字符串，不能悄悄过滤。拼接大文本时优先收集片段后 `join`，避免反复 `+=` 带来多次复制。

## 3. 原理讲解与推导

### 3.1 错误发生在哪一层，就回到哪一层修

金额错误沿 **输入文本→内部数值→展示文本** 传播。若解析时把 `19.9` 当成199分，错误已经进入整数对象；最后格式化成两位无法恢复意图。若解析正确但分摊规则错误，应修改舍入与余数分配，而不是改编码。

因此先检查输入形状和单位，再检查计算规则，最后检查展示。格式化是输出层，不是精度修复工具。

| 层 | 本章对象 | 正确例子 | 在这一层出错的现象 |
| --- | --- | --- | --- |
| 输入文本 | `" 19.90 "` | 去空白后得到合法形状 | 原始文本被无意改写 |
| 内部数值 | `1990` 整数分 | 元乘100，小数补到两位 | 少乘100或把9分当90分 |
| 展示文本 | `"19.90"` | 商与余数格式化 | 显示位数不对，但内部金额仍正确 |
| 编码字节 | `b"..."` | UTF-8编码与解码成对 | 截断后无法解码 |

同一个最终字符串可能由不同错误路径产生，所以定位时从上游逐层核对，不从最终显示反推。

## 4. 示例与逐步走查

#### 案例推进：第一步，拆分原始金额

```python
# study-example: S02A
amount_text = " 19.90 "
cleaned = amount_text.strip()
yuan_text, fraction_text = cleaned.split(".")
amount_cents = int(yuan_text) * 100 + int(fraction_text)
assert amount_cents == 1990
assert amount_text == " 19.90 "
```

这个走读只针对已知合法且恰好两位小数的输入。`strip` 清理两端，`split` 得到元和小数字符串，`int` 分别取得整数。此时 `amount_text` 仍为 `" 19.90 "`，`amount_cents` 为 `1990`；若一起打印类型，会看到 `<class 'str'> <class 'int'>`。

#### 案例推进：第二步，允许一位小数

```python
amount_text = "19.9"
cleaned = amount_text.strip()
parts = cleaned.split(".")
yuan_text = parts[0]
fraction_text = parts[1] if len(parts) == 2 else ""
valid = (
    len(parts) in (1, 2)
    and yuan_text.isascii() and yuan_text.isdigit()
    and (len(parts) == 1 or (
        fraction_text.isascii() and fraction_text.isdigit()
        and 1 <= len(fraction_text) <= 2
    ))
)
amount_cents = int(yuan_text) * 100 + int(fraction_text.ljust(2, "0")) if valid else None
assert amount_cents == 1990
```

一位小数先补成 `"90"`，再转整数。若输入没有小数点，空字符串补成 `"00"`，所以 `"19"` 得到1900分。两种输入最终都得到 `amount_cents == 1990`（`"19"` 则为1900），但它们经过的片段不同：`"19.9"` 有小数位，`"19"` 没有。把同一段代码的 `amount_text` 改为 `"19.999"`，`valid` 为假，结果是 `None`，不会进入 `int`；这与2.2和验收使用同一条规则。

#### 案例推进：第三步，格式化回元

```python
# book-example: B02
cents = 1990
yuan, remainder = divmod(cents, 100)
label = f"{yuan}.{remainder:02d}"
assert label == "19.90"
assert cents == 1990
```

`divmod` 拆回19元与90分，f-string 负责补零和拼接。展示文本是新对象，原整数分没有被修改。若打印 `cents, type(cents).__name__, label, type(label).__name__`，结果为 `1990 int 19.90 str`，这正是内部单位与展示层的边界。

## 7. 面试问答与迁移

**问：为什么不用 float 算结算金额？** 答：有限位二进制表示会引入近似，不同计算路径可能得到不同结果。整数分或约定下的 Decimal 更合适，但舍入规则仍要明确。

**问：整数分能自动解决分摊吗？** 答：不能。100分分三份，余数归谁仍要规定；类型只保存结果，不替业务做决定。

**问：str 与 bytes 为什么不能混用？** 答：文本按字符处理，字节按编码单位处理。接口应约定编码，并验证完整往返；文件读取与异常处理留到第5章。

## 8. 本章小结与参考

- 金额内部用整数分，单位写进字段名。
- 解析前规定合法形状，一位小数要补成两位分。
- float 适合近似，不直接作为结算表示；格式化不修复计算。
- str 是文本，bytes 是字节，编码与解码必须成对。
- 下一章用容器保存一批订单，并保持原始输入不变。

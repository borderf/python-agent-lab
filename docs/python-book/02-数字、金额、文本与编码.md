## 2. 基础知识讲解

### 2.1 整数分：先固定单位，再计算

199元等于19900分。整数分适合累计、比较和传输，因为业务已经约定最小单位是一分。`divmod(cents, 100)` 同时得到元和余数。

```python
cents = 19901
yuan, remainder = divmod(cents, 100)
assert (yuan, remainder) == (199, 1)
```

这里两个名称分别接收商和余数，叫解包。格式说明 `02d` 只负责展示时补零，不改变整数对象。

`/` 总是得到浮点结果，`//` 向负无穷方向取整，`%` 的余数符号跟随除数；它们与先截断的“向零取整”不同。乘除、`//`、`%`、`**` 通常高于加减，幂运算还高于左侧一元正负号。`int("ff", 16)` 按显式进制解析，`0b1010` 是二进制字面量，`1e3` 则是浮点科学计数法；金额解析仍按2.2拒绝最后一种形状。

```python
assert 7 / 2 == 3.5 and isinstance(7 / 2, float)
assert 7 // 2 == 3 and 7 % 2 == 1
assert -7 // 2 == -4 and -7 % 2 == 1
assert -2 ** 2 == -4 and (-2) ** 2 == 4
assert int("ff", 16) == 255 and 0b1010 == 10
assert 1e3 == 1000.0 and isinstance(1e3, float)
```

### 2.2 金额文本：先规定合法形状

本书约定：去两端空白后，只接受 ASCII 数字组成的非负金额；可有小数点，但小数部分为1–2位。科学计数、负号、`NaN` 和三位小数都不接受。

```python
amount_text = " 19.90 "
cleaned = amount_text.strip()
parts = cleaned.split(".")
yuan_text = parts[0]
fraction_text = parts[1] if len(parts) == 2 else ""
valid = (
    len(parts) in (1, 2)
    and yuan_text.isascii() and yuan_text.isdigit()
    and (len(parts) == 1 or (
        fraction_text.isascii() and fraction_text.isdigit()
        and 1 <= len(fraction_text) <= 2
    ))
)
amount_cents = int(yuan_text) * 100 + int(fraction_text.ljust(2, "0")) if valid else None
assert amount_cents == 1990
assert amount_text == " 19.90 "
```

`split` 产生片段列表，`strip` 返回新文本。`ljust(2, "0")` 把一位小数右侧补成两位，所以 `19.9` 解释为90分，而不是9分。非法形状先得到 `None`，正式函数接口的错误行为在第4–5章补齐。

### 2.3 精确表示：float 管近似，结算管约定

二进制浮点不能精确表示十进制的 `0.1`。输入先取近似值，加法结果还可能再舍入，因此 `0.1 + 0.2 != 0.3`。这不是所有浮点运算都错，`0.5 + 0.25` 可以精确等于 `0.75`。

`Decimal("0.1")` 从文本保留十进制含义；`Decimal(0.1)` 接收的已经是浮点近似。格式化成两位只能改变显示，不能修复之前的计算。

```python
# experiment: E04
from decimal import Decimal
assert 0.1 + 0.2 != 0.3
assert f"{0.1 + 0.2:.2f}" == "0.30"
assert Decimal("0.1") + Decimal("0.2") == Decimal("0.3")
assert Decimal(0.1) != Decimal("0.1")
assert 1999 + 1 == 2000
assert divmod(2000, 100) == (20, 0)
q, r = divmod(-7, 3)
assert (q, r) == (-3, 2)
assert -7 == q * 3 + r
```

普通订单累计直接用整数分。折扣或分摊产生不足一分的结果时，还要另外规定舍入时机与余数归属，不能靠换类型自动解决。

近似值是否足够接近，应使用 `math.isclose` 并明确相对误差 `rel_tol` 与绝对误差 `abs_tol`，不能随意扩大容差迎合结果。`NaN` 与自身不相等且大小比较为假；正负 `inf` 表示溢出或特殊结果，`math.isfinite` 才能排除它们，`isclose(inf, inf)` 为真并不表示数值有限。

```python
import math
from decimal import Decimal, ROUND_HALF_UP
assert math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9, abs_tol=1e-12)
nan = float("nan")
assert nan != nan and not math.isfinite(nan)
assert math.isinf(float("inf"))
assert Decimal("19.995").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP) == Decimal("20.00")
```

`Decimal.quantize` 只按指定指数和舍入模式改变小数位；`ROUND_HALF_UP` 在恰好半值时远离零。十进制上下文仍会影响其他运算，目标小数位超过上下文精度时还可能失败，所以“用了 Decimal”不等于自动获得安全结算。

### 2.4 文本与字节：显示和存储是两种对象

`str` 表示 Unicode 文本，`bytes` 表示字节序列。`text.encode("utf-8")` 把文本编码为字节，`raw.decode("utf-8")` 按 UTF-8 解释回文本。字符数与字节数可能不同。

```python
text = "采购A"
raw = text.encode("utf-8")
assert len(text) == 3 and len(raw) == 7
assert raw.decode("utf-8") == text
assert isinstance(raw, bytes) and not isinstance(raw, str)
```

编码必须与读取方约定一致。按字节切片可能切断一个字符的 UTF-8 序列，解码时才会暴露错误；不能把字节数当成字符数。

需要原地修改字节时可用 `bytearray`，但切片替换和删除仍按字节，不按字符；只改半个字符会让后续 UTF-8 解码失败。文本修改通常应构造新 `str`，不要把字节缓冲当成天然字符序列。

```python
buffer = bytearray("A中".encode("utf-8"))
buffer[0] = ord("B")
assert buffer.decode("utf-8") == "B中"
del buffer[1:]
assert buffer == b"B"
```

```python
# study-example: S02J
code = "A-1234"
assert code[0] == "A" and code[-1] == "4"
assert code[2:5] == "123"
assert code[2:] == "1234"
assert code[2::2] == "13"
assert code[::-1] == "4321-A"
assert code[20:] == ""
assert code == "A-1234"
```

切片终点不包含；越界的普通切片可得到短结果，单个越界下标则会失败。切片产生新文本，原对象不变。

```python
# study-example: S02K
raw = "  Paid-A  "
cleaned = raw.strip()
normalized = cleaned.lower()
assert cleaned == "Paid-A" and normalized == "paid-a"
assert normalized.startswith("paid-")
assert normalized.endswith("a")
assert normalized.find("paid") == 0
assert normalized.find("missing") == -1
assert normalized.replace("paid", "pending") == "pending-a"
assert raw == "  Paid-A  "
```

`find` 返回位置或 `-1`，所以位置 `0` 虽然为假，也代表找到。是否清理空白、统一大小写应由字段规则决定，不能默认改写业务内容。

## 3. 原理讲解与推导

### 3.1 错误发生在哪一层，就回到哪一层修

金额错误沿 **输入文本→内部数值→展示文本** 传播。若解析时把 `19.9` 当成199分，错误已经进入整数对象；最后格式化成两位无法恢复意图。若解析正确但分摊规则错误，应修改舍入与余数分配，而不是改编码。

因此先检查输入形状和单位，再检查计算规则，最后检查展示。格式化是输出层，不是精度修复工具。

## 4. 示例与逐步走查

#### 案例推进：第一步，拆分原始金额

```python
# study-example: S02A
amount_text = " 19.90 "
cleaned = amount_text.strip()
yuan_text, fraction_text = cleaned.split(".")
amount_cents = int(yuan_text) * 100 + int(fraction_text)
assert amount_cents == 1990
assert amount_text == " 19.90 "
```

这个走读只针对已知合法且恰好两位小数的输入。`strip` 清理两端，`split` 得到元和小数字符串，`int` 分别取得整数。

#### 案例推进：第二步，允许一位小数

```python
amount_text = "19.9"
parts = amount_text.split(".")
fraction_text = parts[1] if len(parts) == 2 else ""
amount_cents = int(parts[0]) * 100 + int(fraction_text.ljust(2, "0"))
assert amount_cents == 1990
```

一位小数先补成 `"90"`，再转整数。若输入没有小数点，空字符串补成 `"00"`，所以 `"19"` 得到1900分。

#### 案例推进：第三步，格式化回元

```python
# book-example: B02
cents = 1990
yuan, remainder = divmod(cents, 100)
label = f"{yuan}.{remainder:02d}"
assert label == "19.90"
assert cents == 1990
```

`divmod` 拆回19元与90分，f-string 负责补零和拼接。展示文本是新对象，原整数分没有被修改。

## 7. 面试问答与迁移

**问：为什么不用 float 算结算金额？** 答：有限位二进制表示会引入近似，不同计算路径可能得到不同结果。整数分或约定下的 Decimal 更合适，但舍入规则仍要明确。

**问：整数分能自动解决分摊吗？** 答：不能。100分分三份，余数归谁仍要规定；类型只保存结果，不替业务做决定。

**问：str 与 bytes 为什么不能混用？** 答：文本按字符处理，字节按编码单位处理。接口应约定编码，并验证完整往返；文件读取与异常处理留到第5章。

## 8. 本章小结与参考

- 金额内部用整数分，单位写进字段名。
- 解析前规定合法形状，一位小数要补成两位分。
- float 适合近似，不直接作为结算表示；格式化不修复计算。
- str 是文本，bytes 是字节，编码与解码必须成对。
- 下一章用容器保存一批订单，并保持原始输入不变。

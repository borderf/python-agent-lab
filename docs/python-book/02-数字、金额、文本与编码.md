## 2. 基础知识讲解

### 2.1 为什么金额不能只看“算出了什么数字”

页面输入10元和20元，合计应当是30元。程序除了会做加法，还得回答：10代表元还是分？输入能否带小数？计算过程能否接受近似？最终出现半分钱时谁决定取舍？选择int、float或Decimal，是在回答这些问题。

先用int保存物品数量2。它表达精确的整数；同样可以约定1990代表1990分。float适合测量、图形等允许近似的小数计算，不适合直接作为金额的结算表示。为什么小数还需要近似，从一个熟悉的除法开始。

#### 十进制的1/3，帮助理解二进制的1/10

在十进制中，0.3、0.33、0.333都越来越接近1/3，但任意有限位都不相等：分母为10、100、1000的分数，约分后不会得到分母3。

二进制小数的位权依次是1/2、1/4、1/8。因此0.5=1/2可以有限表示，0.75=1/2+1/4也可以；但0.1=1/10约分后仍有因子5，无法写成整数除以2的某个幂。展开后需要无限重复的二进制位。常见float只有有限有效位，必须取附近可表示的值。

所以问题在输入字面量转成float时就已出现。`0.1 + 0.2`相加的是两个存储近似值，和还可能再舍入；右侧`0.3`又有自己对应的近似值。两条计算路径不保证最后落在同一个可表示数上。它们非常接近，却可能严格不等。

```python
# study-example: S02L
numerator, denominator = (0.1).as_integer_ratio()
assert numerator * 10 != denominator
assert 0.1 + 0.2 != 0.3
assert 0.5 + 0.25 == 0.75
```

as_integer_ratio给出当前float精确对应的整数分数。若它真是1/10，交叉相乘应有numerator×10=denominator；断言验证不是如此。第三条又说明float不是所有加法都会失真：能精确表示的输入和结果可以严格相等。不能由一个反例推出“浮点运算全部错误”。

#### 用位权看二进制小数为什么有限

小数点右边每一位也有位权。十进制依次是1/10、1/100、1/1000；二进制依次是1/2、1/4、1/8。二进制0.101表示1/2+0/4+1/8，也就是十进制0.625。0.5只需第一位，所以可有限表示。

| 位 | 二进制权重 | 怎样接近十进制0.1 |
| --- | --- | --- |
| 第1位 | 1/2 | 太大，取0 |
| 第2位 | 1/4 | 太大，取0 |
| 第3位 | 1/8 | 仍太大，取0 |
| 第4位 | 1/16=0.0625 | 取1，剩0.0375 |
| 第5位 | 1/32=0.03125 | 取1，剩0.00625 |
| 继续 | 更小的2的幂的倒数 | 不能在有限位恰好结束 |

常见float只保存有限有效位，因此需要选一个临近可表示值。0.1和0.2分别近似，求和后还要舍入；单独写0.3也形成其近似值，路径不同就可能得到不同的最后几位。打印时常用较短的可往返表示，所以看到“0.1”不代表内部是精确的1/10。理解这一步后，再选择Decimal或整数分才有原因。

#### Decimal为什么要从字符串创建

如果输入本来就是十进制金额，我们希望保留“十进制的1/10”，而不是先取得它的二进制近似。Decimal可以用十进制数字和指数表达有限十进制值：0.1是1×10⁻¹，0.2是2×10⁻¹；相加可得到3×10⁻¹。下面这些小数在足够的当前精度下可精确运算。

`from decimal import Decimal`只是从Python自带的标准库取得类名。`Decimal("0.1")`接收十进制文本；`Decimal(0.1)`的实参却是已经求值的float，构造器接到近似值后不会猜测用户原先想输入哪个十进制数。

#### 有精确输入，为什么还需要舍入

假设业务计算的精确结果为1.005元，但最终支付只允许整数分。1.005元等于100.5分，不存在同时保留这个金额又只使用整数分的表示，必须由规则选择。

若采用本例的ROUND_HALF_UP，1.005恰在1.00与1.01的中间，取离零较远的1.01；负数中点也离零，例如-1.005得到-1.01。它不是永远向正无穷取整。quantize的Decimal("0.01")指定结果指数为百分位；rounding参数决定舍弃更细部分时怎样选择。

#### 案例推进：把表示、计算和结算规则连接起来

```python
# study-example: S02B
from decimal import Decimal, ROUND_HALF_UP
assert 0.1 + 0.2 != 0.3
exact = Decimal("0.1") + Decimal("0.2")
assert exact == Decimal("0.3")
rounded = Decimal("1.005").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
assert rounded == Decimal("1.01")
```

这里三条判断依次检查不同的事：二进制表示的近似、十进制输入的保留、业务结算精度。把结果格式化成两位小数只生成展示文本，不能反向修复之前的计算。下一节把内部单位固定为分，就能将普通金额累计变成整数加法；遇到折扣、分摊等产生不足一分的结果时，仍需明确舍入规则和时机。

Decimal也不是无限精度：1/3在十进制仍无法有限表示，运算受精度上下文约束。金额正确性来自输入、单位、计算与舍入的共同约定，不来自换一个类型名称。

#### 负数、近似比较与特殊浮点值

`/`是真除法，`//`向下取整，`%`与它共同满足整数商余关系。例如-7//3为-3，余数为2，因为-7=(-3)*3+2；它不同于简单截去小数。幂用**，不能照搬其他语言把^当乘方，^是按位异或。

```python
# study-example: S02E
import math
assert (-7 // 3, -7 % 3) == (-3, 2)
assert math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9, abs_tol=1e-12)
assert not math.isfinite(float("nan"))
assert not math.isfinite(float("inf"))
```

近似计算可以使用与需求相符的相对/绝对容差，尤其接近零时不要只靠相对容差；金额则先选正确表示。NaN有特殊比较行为，输入为float时应明确有限性与范围，不能只比较是否大于零就认为全部异常值都已处理。

### 2.2 把单位写进变量与接口


199元若以分保存，就是19900。推荐字段amount_cents，而不是依赖注释猜amount采用什么单位。汇总一直使用整数分，最后展示才拆为元与分：

```python
cents = 19901
yuan, remainder = divmod(cents, 100)
print(f"{yuan}.{remainder:02d}")  # 199.01
```

divmod同时返回商和余数；赋值中的两个名称接收两个结果，叫解包。格式`02d`要求整数至少两位、不足补零。展示格式不改变原始cents。分摊、折扣与税费另需规定舍入和余数分配。

#### 案例推进：先分开表示层，再做转换

输入原文、业务值和展示文本服务不同需求。原文用于定位错误，整数分用于计算，展示文本面向用户。转换时应写出单位，避免把1990分当成1990元。

```python
# study-example: S02A
amount_text = " 19.90 "
cleaned = amount_text.strip()
yuan_text, fraction_text = cleaned.split(".")
amount_cents = int(yuan_text) * 100 + int(fraction_text)
yuan, fraction = divmod(amount_cents, 100)
amount_label = f"{yuan}.{fraction:02d}"
assert amount_text == " 19.90 "
assert amount_cents == 1990
assert amount_label == "19.90"
```

这段是已知合法、恰好两位小数的走读，不是完整解析器。split得到两个片段，解包将它们分别绑定；int将数字文本转成整数，divmod再拆回商与余数。strip没有改变原文，说明字符串操作通常产生新值。

输入若是“19.9”，不能直接把9加成9分，而应按一位小数规则解释为90分；输入“19.999”在本书约定下拒绝。完整解析器要先检查字符、片段数和小数位数，再转换。第四章定义函数后再将这些步骤封装，不能让小例子承担它没有实现的输入保证。

### 2.3 用字符串表达和加工文本

str用单引号或双引号创建；转义序列例如`\n`表示换行。字符串不可变，strip、replace等操作返回新字符串。下标取得字符，切片`text[start:stop]`取一段，右端不包含；负下标从末尾计数。

split按规则拆成多个片段，join把一组文本合并。调用`",".join(parts)`前，应确认parts中的元素都是文本。处理用户名称可先strip两端空白，但不能默认改写大小写或内部字符，是否规范化由业务决定。

#### 先把索引和切片画在编号上

用编号A-1234观察位置：从左数是0到5，从右数最后一个位置是-1。索引取得一个位置，切片按起点、终点、步长取得一段。

```python
# study-example: S02J
code = "A-1234"
assert code[0] == "A" and code[-1] == "4"
assert code[2:5] == "123"
assert code[2:] == "1234"
assert code[2::2] == "13"
assert code[::-1] == "4321-A"
assert code[20:] == ""
assert code == "A-1234"
```

切片终点不包含，省略终点取到末尾，步长2每次前进两个位置，负步长可反向取得内容。普通越界切片可为空，单独访问code[20]则会失败。切片取得结果后原文本仍在；若要替换首字符，应组成新的文本并重新绑定名称。

#### 查找、清理和转换大小写分步观察

```python
# study-example: S02K
raw = "  Paid-A  "
cleaned = raw.strip()
normalized = cleaned.lower()
assert cleaned == "Paid-A" and normalized == "paid-a"
assert normalized.startswith("paid-")
assert normalized.endswith("a")
assert normalized.find("paid") == 0
assert normalized.find("missing") == -1
assert normalized.replace("paid", "pending") == "pending-a"
assert raw == "  Paid-A  "
```

strip只处理两端，lower产生小写结果，是否允许规范化取决于业务字段。查找得到0代表从开头找到，-1代表没有找到；用`位置 != -1`判断find是否命中。只问成员是否存在时也可写`"paid" in normalized`，先选择问题需要的返回形式。换成一个没有前缀的输入，分别预测startswith与find。

#### 案例推进：把字符串方法按任务组合起来

```python
# study-example: S02C
raw = " A-001, Alice, paid "
parts = raw.split(",")
order_id = parts[0].strip()
user = parts[1].strip()
status = parts[2].strip()
label = " | ".join((order_id, user, status))
assert label == "A-001 | Alice | paid"
assert order_id[:1] == "A" and order_id[-3:] == "001"
```

split、strip、join依次完成拆分、局部清理和重新组织。这里用到的有序容器将在第三章正式介绍，先把parts理解为一组片段。这不是通用CSV解析：字段本身含逗号或引号时，简单split会破坏结构，第七章改用csv模块。

切片右端不包含，超出范围的普通切片通常可以得到较短结果，单个越界下标却会失败。replace可以替换指定文本，startswith适合前缀判断，find返回位置或-1；不能写if text.find(...)就判断是否找到，因为位置0是假值、-1却是真值。

### 2.4 f-string把值转换成可读结果

f-string以f开头，在花括号内放表达式：`f"数量：{count}"`。冒号后是格式说明，例如`.2f`显示两位小数，`06d`显示至少6位整数。格式化用于展示，不能作为财务精度方案。

接收输入时先区分格式与数值：int("12")可以得到12，int("12.5")会失败。金额文本应先规定允许哪些写法；本书练习只接受非负ASCII数字和最多两位小数，不接受科学计数、NaN或多余小数位。

### 2.5 在文本和字节之间明确转换

磁盘、网络传输的是字节，程序处理的文本是Unicode。`text.encode("utf-8")`得到bytes；`raw.decode("utf-8")`得到str。两个边界必须采用相容编码，错误编码不应随意用ignore隐藏。汉字与组合字符说明“字符数量”与“字节长度”是两个不同要求。

#### 案例推进：从字符走到字节

```python
# study-example: S02D
text = "采购A"
raw = text.encode("utf-8")
assert len(text) == 3 and len(raw) == 7
assert raw.decode("utf-8") == text
```

编码把Unicode文本变为字节，解码按规则把字节解释回文本。相同编码往返成立，不表示任意按字节切片仍能解码。后面读取文件与HTTP内容时，继续明确当前对象是str还是bytes。

#### 再区分：不可变字节与可变缓冲区

```python
# study-example: S02I
text = "订单A"
raw = text.encode("utf-8")
assert type(raw) is bytes
buffer = bytearray(b"AB")
buffer[0] = 67
assert buffer == b"CB"
assert bytes(buffer) == b"CB"
```

str表达文本，bytes表达不可变的字节序列，bytearray表达可修改的字节序列。例子中的b"AB"只含ASCII字符；字节索引修改接受0到255的整数，67对应C。改变缓冲区与按某种编码解释文本是两项操作。最后用bytes取得不可变字节表示，再检查哪里需要编码或解码。

## 3. 原理讲解与推导

### 3.1 用三层表示定位金额错误

第2.1节已从分母推导float的近似。现在沿一次业务错误定位：输入文本是原始意图，内部数值是已选表示，格式化文本是输出。若错误在输入转换成float时引入，修改最后的打印位数只能掩盖差异；应回到输入边界选择合适的内部表示。若错误在分摊时引入，则要修改分摊与舍入，而非编码方式。

### 3.2 Decimal也必须有输入和运算约定

从Decimal("0.1")开始，十进制输入的含义能够保留；从Decimal(0.1)开始，接收的已经是浮点近似。Decimal运算还受上下文精度与舍入影响。先选择单位和合法输入，再决定是否使用Decimal，不应把更换类型当成全部财务问题的答案。

### 3.3 Unicode码点与编码字节不一一对应

str长度统计码点，UTF-8为不同码点使用不同字节数；用户看见的一个字形还可能由多个码点组成。按字节截断可能把一个编码序列切断。名称规范化、长度限制和文件大小限制要分别定义。

### 3.5 按需补充：其他数值写法与位运算

Python的int没有固定32位上限，但数值增大仍会增加存储与计算代价。bool是int的子类，True可与1相等；数量或金额若只允许实际整数，应在入口明确排除布尔值。表示能力和业务允许范围是两层要求。

金额主线不依赖本节；处理进制转换、复数或位标记时再读。

#### 补充识别：进制、科学计数与复数

二进制0b、八进制0o和十六进制0x是整数字面量的不同写法。先将它们转换回熟悉的十进制观察：

```python
# study-example: S02G
assert 0b1010 == 10
assert 0o12 == 10
assert 0xA == 10
assert int("1010", 2) == 10
assert bin(10) == "0b1010"
assert 1e3 == 1000.0
assert (2 + 3j).imag == 3.0
```

int的第二个参数在这里指定按几进制解释文本；bin等展示函数得到文本，不会把原整数改成另一种类型。科学计数1e3表示浮点数1000.0。Python还支持用j写复数，例如`2 + 3j`；业务金额不因此需要换成复数，数值类型按当前任务选择。

#### 选读：位运算与真假运算处理什么

若一个整数的不同二进制位表示不同标记，可用位运算检查它。先只取两个正整数手算：6写作110，3写作011；按位与得到010，即2，按位或得到111，即7。

```python
# study-example: S02H
assert (6 & 3) == 2
assert (6 | 3) == 7
assert (6 ^ 3) == 5
assert (3 << 1) == 6
assert (6 >> 1) == 3
assert (~3) == -4
```

`& | ^`分别按位做与、或、异或；左右移在本例移动二进制位。Python整数的按位取反满足`~n == -n - 1`。它们与第1章按真假短路的and/or不同，不能随意替换。先识别符号，遇到位标记、二进制协议等任务再深入。

## 7. 面试问答与迁移

为什么 0.1+0.2 不精确？整数分不能自动解决哪些分摊问题？str/bytes 混用为何出错？

**参考回答：**

1. 有限位二进制浮点数无法精确表示十进制的0.1、0.2和0.3。输入先取近似值，加法结果再舍入，因此 `0.1 + 0.2 == 0.3` 为假。这不是所有浮点加法都错，例如0.5可以被精确表示。测量值可按误差约定近似比较；结算金额则先确定单位、精度与舍入规则。
2. 整数分解决存储单位，不解决所有运算规则。100分平分三份，独立舍入为33分会少1分；应明确余数归属，例如按固定顺序分为34、33、33，并检查总额守恒。`Decimal("0.1")` 避免先引入浮点近似，但除法精度和结算舍入仍要规定。
3. `str` 表达Unicode文本，`bytes` 表达字节序列；编码将文本变成字节，解码反向解释。UTF-8中的一个汉字占多个字节，截取一个字节不能当作完整字符解码；文本按码点切片也未必等于用户看到的完整字形。接口约定编码，错误发生后先查原始字节及使用的编码。

**换条件自测：** 将“100分分三份”改成“101分按2∶1分配”，先写总额守恒与余数规则，再计算。只给出两个看似合理的数，还没有定义完整的结算行为。

## 8. 本章小结与参考

### 8.1 主要知识点总结

- 整数分、Decimal与float服务不同精度需求；字段名和接口应表达单位。
- 文本转换先定义允许的格式；格式化输出不等于修正内部数值。
- 字符串不可变，索引与切片、查找与成员判断各有返回规则。
- str表达文本，bytes表达字节；编码、解码与字节缓冲区修改是不同操作。

### 8.2 日常工作注意事项

- 金额入口不要先经过float再转Decimal；按业务使用整数分或从合法文本创建Decimal，并明确舍入规则。
- 收到True时，isinstance(value, int)也可能成立。严格金额入口要单独排除布尔值，并检查范围和单位。
- 读取文本时明确编码；find返回0也代表命中。遇到坏编码或坏金额应报告失败，避免静默忽略或改成0。

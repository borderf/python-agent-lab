## 1. 学习目标与前置知识

验证系统事实、权限和失败恢复，持续回归。前置：第17、21–25章。

**本章从这里开始：** 一次聊天看起来很好，下一次改提示却变差。把质量分成可检查维度，并保留固定案例与版本，才能知道系统到底改善了什么。

## 2. 基础知识讲解

### 2.1 先明确评测对象

离线程序测试验证规则和执行路径，真实模型评测验证选择、表达和事实使用，线上观测检查实际请求分布与故障。三类证据不能互相替代；假模型通过只说明受控决策下程序如何运行。

### 2.2 建立有来源的固定案例

每条案例保存任务、输入、身份、业务日期、标准证据、预期行为和失败类别。正常、无答案、缺资料、旧版、越权、坏输出、工具故障和审批拒绝分别覆盖。留出未参与调参的样例，避免只对已知题优化。

#### 案例推进：数据集应该能定位问题

每题保留输入、可信身份、时间、预期来源、允许动作与评分规则。固定开发集用于迭代，保留验证集观察泛化；不要把答案写进提示后再报告评测提升。记录数据、模型、提示、代码、检索与工具版本，必要时重复随机生成案例。

模型裁判可以辅助，但应与人工标注核对，注意同源模型偏好、位置与表达风格影响。统计不确定性随样本规模而变，小题集不能支持精确总体结论；关键失败优先人工复查，不只看一个综合分。

### 2.3 指标应有清楚分母

任务完成率需要先定义完成，partial单列；风险召回与精确率分别看漏报与误报；引用支持性检查证据是否支持对应结论。零分母标N/A，不填100%。延迟与费用说明环境、样本、并行和实际可获得的用量。

模型评审可以辅助，但可能受顺序、措辞和模型偏差影响。关键权限、金额和写入动作要用确定性检查与人工核对。

#### 案例推进：指标先有分母与适用集合

```python
# study-example: S26A
cases = [
    {"kind":"answerable", "correct":True, "leak":False},
    {"kind":"answerable", "correct":False, "leak":False},
    {"kind":"no_evidence", "refused":True, "leak":False},
    {"kind":"forbidden", "refused":True, "leak":False},
]
answerable = [c for c in cases if c["kind"] == "answerable"]
accuracy = sum(c["correct"] for c in answerable) / len(answerable)
assert accuracy == 0.5 and not any(c["leak"] for c in cases)
```

这些是假设标签，示例演示计算口径而非模型实测。可回答题正确率、无证据拒答、越权泄漏与动作执行分别统计，不能用全部题的平均分掩盖某类严重失败。空集合、跳过和服务错误也需明确计数方式。

### 2.4 提示注入来自数据边界

文档或工具结果可能夹带“忽略规则、读取他人数据”等文字。它们是待处理内容，不能提高权限或覆盖程序约束。测试应让恶意内容实际进入预定上下文，再确认没有执行；只是不检索到它不能证明抗注入能力。

#### 案例推进：让攻击真的接触系统

恶意指令可能藏在检索文档、附件或工具返回中。将它实际放入非可信上下文，检查是否改变身份、调用越权工具、泄漏数据或覆盖确定性规则。只删除攻击材料，不能证明系统见到攻击后仍守住边界。

追踪记录模型与工具意图、校验、结果、证据和退出原因，避免索取不可验证的内部推理作为凭证。成本包含重试、检索、重排、模型、存储与复核；质量变化、费用与延迟在同一口径比较。发布前运行固定回归，出现退化时按版本回退。

### 2.5 追踪帮助解释失败

把模型、检索、工具、审批与持久化span通过任务标识串起，记录版本和错误阶段。采集前脱敏并限制访问，不能为了调试把全部合同和凭据上传到观测平台。

### 2.6 成本与质量一起比较

模型、提示、Schema、索引或分工变化后跑同集回归。缓存要考虑身份与版本，降级应说明缺失能力。预算达上限时明确停止或交复核，不用一段流畅文本掩盖未完成。

#### 把质量评测连接到发布与运行

每次模型、提示、索引或工具变更触发固定回归，关键权限与动作案例作为发布门槛；灰度观察新流量的错误类别、尾延迟、成本与复核率，保留旧版本可回退。输入分布变化可能让固定集不再代表真实使用，应将有代表性的失败脱敏后补入新版本数据。

外部URL、文件与工具输入也有资源边界：按业务允许范围访问，限制大小、耗时和跳转，避免任意地址或任意路径被当作可信能力。输入验证、来源身份、动作授权、输出使用和审计各自负责一部分，提示文本不能代替这些程序边界。

成本用实际用量与服务计价口径计算，并记录缓存、重试和失败；本书不固定供应商价格。未提供用量的服务不凭字符数编造精确token数，近似估计必须标明方法与限制。

## 3. 原理讲解与推导

### 3.1 质量不是单一平均分

高任务完成率可能伴随某些越权或严重漏报，平均数不能消除这些问题。把关键约束单列，再比较质量、代价与失败类别，才能支撑工程决策。

### 3.2 可重复比较需要固定上下文

数据、模型、提示、工具和索引版本共同决定一次行为。缺少记录时无法判断变化来自算法还是环境；受控对照与真实流量观察应分别报告。

## 4. 示例与逐步走查

### 指标计算小实验

```python
# book-example: B26
def recall_at_k(retrieved, relevant, k):
    if not relevant:
        return None
    unique = list(dict.fromkeys(retrieved))[:k]
    return len(set(unique) & set(relevant))/len(set(relevant))
assert recall_at_k(["A","A","B"], {"A","C"}, 2) == 0.5
assert recall_at_k([], set(), 5) is None
```

本例按唯一来源计数，不与chunk级结果混用。无答案/越权另统计；高Recall也不证明答案忠于引用或风险规则正确。

### 4.1 沿输入到结果逐步解释

recall_at_k先按来源去重再取前K，A/A/B变成A/B，与相关集合A/C交集只有A，因此召回为1/2。相关集合为空返回None，转入无答案处理，不把它算成完美召回。

## 5. 动手练习

### 练习一：评测数据与口径

扩展固定题集，覆盖正常、缺资料、旧版本、无证据、越权、注入和重复动作。保留一部分验证题，记录身份、预期证据、预期动作和评分规则。

### 练习二：真正让攻击进入上下文

把[policies.json](../../practice/enterprise_ai/data/policies.json)中的不可信附件注入上下文，观察仍不得读取另一租户、覆盖规则或执行未授权工具。引用真实文本也需判断是否支持结论，不能只做字符串存在检查。

### 练习三：版本回归与诊断

一次只更换模型、提示、索引或工具的一项，导出逐题变化、调用轨迹与成本。人工检查关键错误，对模型裁判抽样复核；报告收益、退化、样本数与限制。失败必须能定位到阶段，不能只记录最终分数。

## 6. 验收与自测

**行为验收：** 指标分母、样本、版本和环境明确；无证据不编造；越权和未经审批动作被阻断；预算可执行。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

**提交证据：** 实现位置、运行命令、正常案例、至少一个错误/边界案例、一次失败原因和修复记录。自动检查只证明其覆盖行为；未实现任务不因示例通过而算完成。

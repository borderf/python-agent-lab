## 1. 学习目标与前置知识

建立模型能力与工程限制的基本认识。前置：第9、11、14章。

**本章从这里开始：** 模型为什么会给出流畅但没有依据的答案？理解它先预测下一个token，再生成整个回答，才能判断提示、检索、结构化输出和微调各自解决什么。

## 2. 基础知识讲解

### 2.1 先认识模型处理的输入

语言模型并不直接把“一个汉字”当成固定计算单位。Tokenizer按其规则把文本转为token编号，编号再映射成向量表示；同一段文字在不同模型的tokenizer下长度可能不同，因此不能用字符数精确推算上下文或费用。

单token的向量表示与用于文档检索的句子/文档embedding也不是同一个接口。后者通常经过适合检索的训练和汇聚方式，输出固定维度的表示。理解两者都使用向量，但任务和生成方法不同，是避免术语混淆的起点。

### 2.2 从下一token预测理解生成

自回归语言模型根据已有上下文产生下一token的分布，再按解码策略选取一个token，加入上下文并继续。所谓“回答”是多次选择组成的序列，不是从数据库取出一段已核实事实。

temperature等参数影响概率分布的使用，top-p等策略限制采样范围；具体支持和组合取决于服务。降低随机性不能证明事实正确，也不能保证跨模型、硬件和服务版本完全复现。

#### 案例推进：用最小概率例子理解生成

假设下一token只有三个候选，其概率分别为0.6、0.3、0.1。选择最大概率是一种解码，按分布采样是另一种；随后把已选token加入上下文，再预测下一项。完整回答是逐步生成的结果，不是从可信数据库提取一条已核验结论。

token由tokenizer决定，不固定等于一个汉字或一个单词。模型参数是已学习数值，推理输入是当次上下文；RAG改变上下文，微调改变参数。提示可以明确任务与格式，却不能给缺失事实提供来源。

### 2.3 Transformer怎样结合上下文

向量可以先理解为固定长度的数字序列。两个等长向量的点积，是对应位置相乘后相加；例如[1,0]与[1,0]点积为1，与[0,1]点积为0。真实模型的Q/K/V通常由已学习的投影得到，因此“数字大就更重要”不是通用语义解释。

softmax把一组实数分数转成正权重：每项先取指数，再除以指数之和。计算时减去最大分数可改善数值稳定性，不改变数学上的比例。缩放点积注意力还除以键向量维度的平方根，以调节分数尺度；多个头让模型在不同投影下组合信息，残差等结构再将这些结果接入后续层。

训练的下一token交叉熵可以直观理解为对正确token的低预测概率施加更大惩罚，例如单目标的负对数概率。优化器据此调整参数，但低训练损失不等于业务答案已被事实验证。应用工程必须用独立数据测试真实任务质量。

注意力机制让一个位置根据查询Q与键K的匹配，对值V加权组合。缩放点积与softmax把分数转成权重；实际Transformer还有多头、位置表示、残差、归一化和前馈层，不是一条公式就能完整描述。

因果语言模型的掩码约束哪些位置可被看到。上下文变长增加可用信息，也增加计算/缓存代价；模型能容纳长文本，不代表能稳定定位其中每个关键证据。

#### 案例推进：把Transformer公式拆成可观察步骤

先得到token向量与位置信息，再通过学习的投影形成Q/K/V；Q和K产生匹配分数，缩放后softmax变为权重，权重组合V。多头、残差、归一化和前馈层共同更新表示，因果掩码约束可见位置。B18只演示其中“分数→权重→组合”的局部，不是完整Transformer实现。

训练可用负对数概率衡量目标token被预测得多好，优化器据此调整参数。参数规模、训练数据、目标和对齐方式共同影响行为，不能从一个模型名称直接推断所有业务能力。prefill处理输入，decode逐步输出，KV cache复用计算状态；上下文越长、并发越高，资源代价也可能增加。

### 2.4 训练、微调与推理分别改变什么

预训练通过数据与目标调整参数，常见下一token损失鼓励给目标token更高概率。指令或偏好训练进一步塑造行为；微调需要数据、评估和计算资源。推理使用已经得到的参数处理当次输入，不等于每次对话都训练模型。

RAG把外部证据放入上下文，通常不修改模型参数。选择RAG、提示调整或微调时，先区分需求是事实更新、任务格式、行为风格还是能力不足；不要把所有问题都归为“再训练一次”。

#### 继续认识SFT、LoRA与推理部署

监督微调SFT使用任务示例优化模型行为，仍需要独立验证集、数据质量与防泄漏。领域事实更新、输出格式、任务行为和基础能力不足是不同需求，不应全部交给微调。评测题不能混入训练后再用同题证明泛化。

LoRA用低秩更新表达部分权重变化：若W是d_out×d_in，可用B(d_out×r)和A(r×d_in)形成ΔW=BA，r较小时新增参数少于完整矩阵。实际实现通常还带有缩放系数，例如alpha/r，具体按所选方法核对。它降低某些可训练参数与相关代价，不代表训练无需显存，也不保证效果与全量训练相同。量化训练方法还要明确量化的是哪部分、哪些参数更新。

应用主线先完成可评测的调用、RAG和工具，不要求先训练模型。对训练/部署岗位，再补线性代数、概率、反向传播、优化器、数据处理和实际训练；实践需要记录数据、种子、模型基线、硬件与复现实验，不能把这里的原理介绍当作已完成训练。

推理部署还涉及批处理、KV占用、调度和量化。吞吐、首token、单请求延迟与并发相互影响，优化前固定质量集和负载。模型权重能加载只是第一步，真实服务容量必须实测。

### 2.5 把模型能力放到消息协议中

应用通过服务规定的消息结构组织系统约束、用户输入、助手历史和工具结果。角色和字段必须正确映射，课程内部的final/tool_call字典并非所有供应商的原生格式。

模型适配层集中处理模型标识、消息、参数、超时、用量与返回转换。这样业务服务不必到处了解SDK细节，也可以注入假模型做离线测试。

#### 案例推进：调用前先写一份提示与消息契约

提示包含任务、可信约束、非可信输入、输出格式和允许的不确定状态。少样例用于说明规则，不能与正式评测题混在一起。系统/用户/工具角色按供应商协议映射，历史压缩需要保留当前任务与证据，不能因为token不足随意删掉权限约束。

流式结果按事件累积，首token时间与完整延迟分开观察；工具参数未收完整前不执行。真实接入时记录实际模型与服务版本、上下文/输出限制、参数和可用用量。低temperature不能保证事实正确或跨环境完全复现。

### 2.6 结构化与流式输出

结构化输出先要求模型按约定产生结果，再检查语法、Schema和业务语义。字段齐全且类型正确的合同金额仍可能是编造的，需要回到来源验证。截断、缺字段、拒绝回答和上游错误分别处理。

流式接口分片或按事件返回，不一定能直接用一次json()解析。工具参数也可能分片，必须等协议确认完整后再校验和执行。TTFT、完整生成时间与token用量分别描述不同代价，KV cache主要复用计算状态，不是业务长期记忆。

#### 案例推进：先把输出校验做成可执行边界

```python
# study-example: S18A
import json
def parse_answer(text):
    payload = json.loads(text)
    if not isinstance(payload, dict) or set(payload) != {"answer", "source_ids"}:
        raise ValueError("字段不符合契约")
    if not isinstance(payload["answer"], str) or not payload["answer"].strip():
        raise ValueError("answer不能为空")
    ids = payload["source_ids"]
    if not isinstance(ids, list) or not all(isinstance(item, str) and item for item in ids):
        raise ValueError("source_ids格式错误")
    return payload

result = parse_answer('{"answer":"20%", "source_ids":["policy-a-current"]}')
assert result["source_ids"] == ["policy-a-current"]
```

它验证JSON与结构，尚未证明20%受该来源支持，也没有检查来源是否可访问。接下来分别核对身份、版本、原文与语义。模型原生结构化能力可以降低格式失败，但应用仍要处理拒绝、截断、上游错误和业务不符。

## 3. 原理讲解与推导

### 3.1 概率生成为什么需要事实边界

模型优化的是训练目标下的预测与行为，不保证每个输出都来自当前可信来源。应用应把检索、数值计算、授权和执行交给可验证边界，模型负责理解、选择和表达，不能仅凭语气确定可信度。

### 3.2 注意力中的权重从哪里来

先用Q与每个K点积取得匹配分数，按维度缩放，再经softmax得到非负且和为1的权重，最后组合V。下面的二维例子只保留这一局部机制，不能代表真实模型的全部表示和训练。

### 3.3 输出约束逐层减少不确定性

格式约束减少解析失败，Schema减少结构错误，业务规则与证据验证再约束事实和动作。任何一层通过都不能替代后续层；这与HTTP数据校验的分层思想一致。

### 3.4 参数、上下文和缓存分别占用什么资源

模型参数是训练后保存的数值，推理需要加载相应权重；当次输入与生成过程还使用中间状态和KV cache等资源。更长上下文、更大批次和更多并发都可能增加内存需求，单看模型文件大小不足以准确判断服务能承受多少请求。

量化降低部分数值表示精度以节约资源，具体方案对权重、激活或缓存的处理不同，效果与硬件/实现相关。不能仅凭一个量化标签就承诺速度和质量，也不能用参数量直接替代任务评测。应用开发先记录实际模型、运行环境、输入规模和并发，再观察质量、首token时间与完整延迟。

这种资源分层对应工程中的不同控制：模型部署决定可用容量，输入策略限制上下文，输出预算限制生成，队列与并发限制控制同时占用。它们共同约束系统，而不是只设置一个temperature就决定全部行为。

## 4. 示例与逐步走查

### 单查询注意力的数学小实验

```python
# book-example: B18
from math import exp, sqrt
query = [1.0, 0.0]
keys = [[1.0, 0.0], [0.0, 1.0]]
values = [10.0, 20.0]
scores = [sum(q*k for q,k in zip(query,key)) / sqrt(2) for key in keys]
largest = max(scores)
weights = [exp(score-largest) for score in scores]
weights = [value/sum(weights) for value in weights]
output = sum(weight*value for weight,value in zip(weights,values))
assert abs(sum(weights)-1.0) < 1e-12
assert weights[0] > weights[1] and 10 < output < 20
```

这个示例仅说明分数→归一化→加权组合，不能代表完整模型、训练或真实embedding。改变query后解释权重变化，再阅读模型基础资料。

### 4.1 沿输入到结果逐步解释

注意力示例的query更匹配第一个key，因此softmax后的第一项权重大于第二项。两个权重和为1，组合值落在10与20之间；更改query会改变组合。它演示权重计算，不涉及真实tokenizer、投影参数或训练。

## 5. 动手练习

### 练习一：从数字推演生成机制

运行B18前手算两组点积，预测权重关系；将query改为[0,1]和[0,0]，分别解释权重交换与均匀权重。写出这个实验省略了哪些真实Transformer结构。

### 练习二：先实现假模型边界

定义内部模型响应契约与适配器。假模型依次返回合法结构、坏JSON、缺字段、截断、超时与显式拒绝；检查解析、Schema与业务验证在哪层失败。结构完整但证据不支持的答案不能标为事实正确。

### 练习三：再接一个真实服务

选择已有条件可用的服务，记录实际模型标识、参数与用量字段，不编造token数。用固定问题分别提供/不提供证据，比较内容、来源与不确定性；流式路径注入中途断开，不执行半段工具参数。提交适配层、离线检查与实际调用记录，真实服务未准备时明确记为待做。

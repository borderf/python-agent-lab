## 2. 基础知识讲解

### 2.1 先认识模型处理的输入

用户输入一句话，模型怎样把它变成回答？先把文本编码为token，再根据上下文产生候选分布，逐步选择输出。这个过程解释了模型为什么会给出流畅但未核实的说法。应用先建立消息、响应校验和证据边界；注意力与训练推导随后解释能力来源，不是第一次调用的前置条件。

先把一句“查询预付款上限”交给模型的分词工具，观察得到若干token编号。token是模型处理文本的单位，划分规则由具体tokenizer决定，不能假定一个汉字就是一个token。模型随后把编号转换成用于计算的向量。先理解文本到编号、编号到向量这两步，再解释注意力与输出概率；用同一句话比较不同模型时，也要记录各自的token计数口径。

单token的向量表示与用于文档检索的句子/文档embedding也不是同一个接口。后者通常经过适合检索的训练和汇聚方式，输出固定维度的表示。理解两者都使用向量，但任务和生成方法不同，是避免术语混淆的起点。

### 2.2 从下一token预测理解生成

自回归语言模型根据已有上下文产生下一token的分布，再按解码策略选取一个token，加入上下文并继续。所谓“回答”是多次选择组成的序列，不是从数据库取出一段已核实事实。

temperature等参数影响概率分布的使用，top-p等策略限制采样范围；具体支持和组合取决于服务。降低随机性不能证明事实正确，也不能保证跨模型、硬件和服务版本完全复现。

#### 案例推进：用最小概率例子理解生成

假设下一token只有三个候选，其概率分别为0.6、0.3、0.1。选择最大概率是一种解码，按分布采样是另一种；随后把已选token加入上下文，再预测下一项。完整回答是逐步生成的结果，不是从可信数据库提取一条已核验结论。

token由tokenizer决定，不固定等于一个汉字或一个单词。模型参数是已学习数值，推理输入是当次上下文；RAG改变上下文，微调改变参数。提示可以明确任务与格式，却不能给缺失事实提供来源。

### 2.3 把模型能力放到消息协议中

先通过本节与2.4–2.5完成消息、校验与一次调用。首轮只需理解token、概率生成及上下文；注意力、损失和LoRA的完整推导放在3.5–3.6，完成首次调用后再读，不先用训练公式阻塞应用实验。

应用通过服务规定的消息结构组织系统约束、用户输入、助手历史和工具结果。角色和字段必须正确映射，课程内部的final/tool_call字典并非所有供应商的原生格式。

模型适配层集中处理模型标识、消息、参数、超时、用量与返回转换。这样业务服务不必到处了解SDK细节，也可以注入假模型做离线测试。

#### 案例推进：调用前先写一份提示与消息契约

提示包含任务、可信约束、非可信输入、输出格式和允许的不确定状态。少样例用于说明规则，不能与正式评测题混在一起。系统/用户/工具角色按供应商协议映射，历史压缩需要保留当前任务与证据，不能因为token不足随意删掉权限约束。

流式结果按事件累积，首token时间与完整延迟分开观察；工具参数未收完整前不执行。真实接入时记录实际模型与服务版本、上下文/输出限制、参数和可用用量。低temperature不能保证事实正确或跨环境完全复现。

### 2.4 结构化与流式输出

结构化输出先要求模型按约定产生结果，再检查语法、Schema和业务语义。字段齐全且类型正确的合同金额仍可能是编造的，需要回到来源验证。截断、缺字段、拒绝回答和上游错误分别处理。

流式接口分片或按事件返回，不一定能直接用一次json()解析。工具参数也可能分片，必须等协议确认完整后再校验和执行。TTFT、完整生成时间与token用量分别描述不同代价，KV cache主要复用计算状态，不是业务长期记忆。

#### 当一个汉字被拆到两次网络读取中

第 2 章见过截断 UTF-8 字节时的解码错误。这里让模型返回一行含“采购”的 JSON，约定换行符标记一条记录结束。第一次读取只收到“采”的首字节。先预测此时哪些文字可以显示、哪些数据可以交给 JSON 解析器。

```python
# study-example: S18E
import codecs
import json

wire = '{"text":"采购"}\n'.encode("utf-8")
cut = wire.index("采".encode("utf-8")) + 1
decoder = codecs.getincrementaldecoder("utf-8")()
prefix = decoder.decode(wire[:cut])
assert prefix == '{"text":"'

line = prefix + decoder.decode(wire[cut:], final=True)
assert line.endswith("\n")
assert json.loads(line) == {"text": "采购"}

truncated = codecs.getincrementaldecoder("utf-8")()
truncated.decode(wire[:cut])
try:
    truncated.decode(b"", final=True)
except UnicodeDecodeError:
    pass
else:
    raise AssertionError("流在半个字符处结束，应报告截断")
```

增量解码器把不完整的字节留给下一次读取，在流结束时用 `final=True` 检查尾部。再把切点移到最后的换行符之前。此时文本能被 JSON 解析器接受，但按这道题的行协议仍应等待换行；实际服务要按它声明的事件协议判断边界。最后再问一层：即使已收到一个完整事件，工具的多段参数可能仍在传输，何时才能校验参数并执行？在第24章用工具调用次数验证你的判断。[Python 增量解码器](https://docs.python.org/3.12/library/codecs.html#codecs.IncrementalDecoder.decode)

#### 案例推进：先把输出校验做成可执行边界

```python
# study-example: S18A
import json
def parse_answer(text):
    payload = json.loads(text)
    if not isinstance(payload, dict) or set(payload) != {"answer", "source_ids"}:
        raise ValueError("字段不符合契约")
    if not isinstance(payload["answer"], str) or not payload["answer"].strip():
        raise ValueError("answer不能为空")
    ids = payload["source_ids"]
    if not isinstance(ids, list) or not all(isinstance(item, str) and item for item in ids):
        raise ValueError("source_ids格式错误")
    return payload

result = parse_answer('{"answer":"20%", "source_ids":["policy-a-current"]}')
assert result["source_ids"] == ["policy-a-current"]
```

它验证JSON与结构，尚未证明20%受该来源支持，也没有检查来源是否可访问。接下来分别核对身份、版本、原文与语义。模型原生结构化能力可以降低格式失败，但应用仍要处理拒绝、截断、上游错误和业务不符。

### 2.5 从离线结果到真实模型适配：数据、协议和错误分层

前面的例子解释模型机制，但完成真实接入还需要一个适配器。它把服务响应转为内部结果，并把网络、服务错误、未完成输出、错误形状和业务不符分别交给合适层处理。不要让整个业务到处直接索引供应商响应字段。

先用不联网的输入验证最小响应转换。以下只适配普通文本聊天，不接受工具调用或多模态输出；后续工具场景应设计相应分支。

```python
# study-example: S18B
def extract_text(payload):
    if not isinstance(payload, dict) or payload.get("done") is not True or payload.get("done_reason") == "length":
        raise ValueError("响应未完成")
    message = payload.get("message")
    if not isinstance(message, dict) or message.get("role") != "assistant" or message.get("tool_calls"):
        raise ValueError("响应消息结构不符合文本聊天契约")
    text = message.get("content")
    if not isinstance(text, str) or not text.strip():
        raise ValueError("缺少非空文本结果")
    return text
assert extract_text({"done":True,"message":{"role":"assistant","content":"你好"}}) == "你好"
for bad in ({}, {"done":False}, {"done":True,"message":{"role":"assistant","content":""}},
            {"done":True,"done_reason":"length","message":{"role":"assistant","content":"半句话"}}):
    try:
        extract_text(bad)
    except ValueError:
        pass
    else:
        raise AssertionError("不能接受未完成或错误结构")
```

再接真实服务。下面采用Ollama的HTTP聊天入口，需要HTTPX、本机已启动服务以及已准备模型；不会替你下载模型。模型名从环境读取，避免把文档示例误当作所有硬件都能运行的推荐型号。

```python
# framework-example: F18
import os
import httpx
model = os.environ["OLLAMA_MODEL"]
with httpx.Client(base_url="http://localhost:11434", timeout=httpx.Timeout(30.0, connect=5.0)) as client:
    response = client.post("/api/chat", json={
        "model":model, "messages":[{"role":"user","content":"用一句话解释订单去重。"}],
        "stream":False,
    })
    response.raise_for_status()
    payload = response.json()
    if not isinstance(payload, dict) or payload.get("done") is not True or payload.get("done_reason") == "length":
        raise ValueError("响应没有完整结束")
    message = payload.get("message")
    if (not isinstance(message, dict) or message.get("role") != "assistant" or message.get("tool_calls")
            or not isinstance(message.get("content"), str) or not message["content"].strip()):
        raise ValueError("不符合本例的普通文本结果契约")
    print(message["content"])
```

本例显式stream=False才能按一个JSON整体解析。流式时按服务事件格式消费；某些服务的事件可能是NDJSON，另一些使用SSE，不能统一按字符串换行随意拆。HTTP读取超时不等于整次任务总预算，上层仍需deadline。生产适配器复用已有extract_text或统一验证层，本独立代码块展开检查是为了可单独阅读。

先用HTTPX MockTransport验证请求方法、消息映射、500、坏JSON和空结果，再做真实调用。记录模型、服务与提示版本、可获得的输入/输出用量和耗时；没有用量不要编造精确token。格式校验通过后，仍需核验引用、事实与授权。

选择技术时先定位问题：当前事实缺失→查询/RAG；任务边界不清→提示与协议；稳定任务行为需要调整→在数据与验证集支持下评估SFT；推理容量不足→测量部署与负载。LoRA是参数更新方式，不能替代上述问题分析。

## 3. 原理讲解与推导

### 3.1 概率生成为什么需要事实边界

模型优化的是训练目标下的预测与行为，不保证每个输出都来自当前可信来源。应用应把检索、数值计算、授权和执行交给可验证边界，模型负责理解、选择和表达，不能仅凭语气确定可信度。

### 3.2 注意力中的权重从哪里来

先用Q与每个K点积取得匹配分数，按维度缩放，再经softmax得到非负且和为1的权重，最后组合V。下面的二维例子只保留这一局部机制，不能代表真实模型的全部表示和训练。

### 3.3 输出约束逐层减少不确定性

格式约束减少解析失败，Schema减少结构错误，业务规则与证据验证再约束事实和动作。任何一层通过都不能替代后续层；这与HTTP数据校验的分层思想一致。

### 3.4 参数、上下文和缓存分别占用什么资源

模型参数是训练后保存的数值，推理需要加载相应权重；当次输入与生成过程还使用中间状态和KV cache等资源。更长上下文、更大批次和更多并发都可能增加内存需求，单看模型文件大小不足以准确判断服务能承受多少请求。

量化降低部分数值表示精度以节约资源，具体方案对权重、激活或缓存的处理不同，效果与硬件/实现相关。不能仅凭一个量化标签就承诺速度和质量，也不能用参数量直接替代任务评测。应用开发先记录实际模型、运行环境、输入规模和并发，再观察质量、首token时间与完整延迟。

这种资源分层对应工程中的不同控制：模型部署决定可用容量，输入策略限制上下文，输出预算限制生成，队列与并发限制控制同时占用。它们共同约束系统，而不是只设置一个temperature就决定全部行为。

### 3.5 机制深化：Transformer怎样结合上下文

向量可以先理解为固定长度的数字序列。两个等长向量的点积，是对应位置相乘后相加；例如[1,0]与[1,0]点积为1，与[0,1]点积为0。真实模型的Q/K/V通常由已学习的投影得到，因此“数字大就更重要”不是通用语义解释。

softmax把一组实数分数转成正权重：每项先取指数，再除以指数之和。计算时减去最大分数可改善数值稳定性，不改变数学上的比例。缩放点积注意力还除以键向量维度的平方根，以调节分数尺度；多个头让模型在不同投影下组合信息，残差等结构再将这些结果接入后续层。

训练的下一token交叉熵可以直观理解为对正确token的低预测概率施加更大惩罚，例如单目标的负对数概率。优化器据此调整参数，但低训练损失不等于业务答案已被事实验证。应用工程必须用独立数据测试真实任务质量。

注意力机制让一个位置根据查询Q与键K的匹配，对值V加权组合。缩放点积与softmax把分数转成权重；实际Transformer还有多头、位置表示、残差、归一化和前馈层，不是一条公式就能完整描述。

因果语言模型的掩码约束哪些位置可被看到。上下文变长增加可用信息，也增加计算/缓存代价；模型能容纳长文本，不代表能稳定定位其中每个关键证据。

#### 案例推进：把Transformer公式拆成可观察步骤

先得到token向量与位置信息，再通过学习的投影形成Q/K/V；Q和K产生匹配分数，缩放后softmax变为权重，权重组合V。多头、残差、归一化和前馈层共同更新表示，因果掩码约束可见位置。B18只演示其中“分数→权重→组合”的局部，不是完整Transformer实现。

训练可用负对数概率衡量目标token被预测得多好，优化器据此调整参数。参数规模、训练数据、目标和对齐方式共同影响行为，不能从一个模型名称直接推断所有业务能力。prefill处理输入，decode逐步输出，KV cache复用计算状态；上下文越长、并发越高，资源代价也可能增加。

#### 数字实验：训练目标到底惩罚什么

对一个已知正确的下一个token，负对数概率`-log(p)`越小，表示模型给这个目标的概率越高。多个位置的损失可以按约定平均；词表归一化、掩码、批次与优化步骤在真实训练中还有额外处理。

```python
# study-example: S18C
from math import log
def target_loss(probability):
    if not 0 < probability <= 1:
        raise ValueError("概率须位于(0,1]")
    return -log(probability)
assert target_loss(0.8) < target_loss(0.2)
assert target_loss(1.0) == 0.0
average = (target_loss(0.8) + target_loss(0.2)) / 2
assert target_loss(0.8) < average < target_loss(0.2)
```

它解释训练目标的一个局部，不是完整训练程序。得到某个目标token的高概率不等于该句符合最新事实，也不等于模型自报置信度已经校准。困惑度常由平均负对数似然导出，但只有在数据、tokenizer、掩码与计算口径可比时才有意义，不能拿不同基准上的数字直接比较业务质量。

### 3.6 机制深化：训练、微调与推理分别改变什么

预训练通过数据与目标调整参数，常见下一token损失鼓励给目标token更高概率。指令或偏好训练进一步塑造行为；微调需要数据、评估和计算资源。推理使用已经得到的参数处理当次输入，不等于每次对话都训练模型。

RAG把外部证据放入上下文，通常不修改模型参数。选择RAG、提示调整或微调时，先区分需求是事实更新、任务格式、行为风格还是能力不足；不要把所有问题都归为“再训练一次”。

#### 继续认识SFT、LoRA与推理部署

监督微调SFT使用任务示例优化模型行为，仍需要独立验证集、数据质量与防泄漏。领域事实更新、输出格式、任务行为和基础能力不足是不同需求，不应全部交给微调。评测题不能混入训练后再用同题证明泛化。

LoRA用低秩更新表达部分权重变化：若W是d_out×d_in，可用B(d_out×r)和A(r×d_in)形成ΔW=BA，r较小时新增参数少于完整矩阵。实际实现通常还带有缩放系数，例如alpha/r，具体按所选方法核对。它降低某些可训练参数与相关代价，不代表训练无需显存，也不保证效果与全量训练相同。量化训练方法还要明确量化的是哪部分、哪些参数更新。

应用主线先完成可评测的调用、RAG和工具，不要求先训练模型。对训练/部署岗位，再补线性代数、概率、反向传播、优化器、数据处理和实际训练；实践需要记录数据、种子、模型基线、硬件与复现实验，不能把这里的原理介绍当作已完成训练。

推理部署还涉及批处理、KV占用、调度和量化。吞吐、首token、单请求延迟与并发相互影响，优化前固定质量集和负载。模型权重能加载只是第一步，真实服务容量必须实测。

#### 数字实验：低秩更新为何能减少可训练参数

矩阵按“行数×列数”写维度。若W为2×2，A为1×2，B为2×1，BA仍是2×2；它用一个列向量与一个行向量组合更新。下面手工给出更新值，只验证矩阵形状与组合，不进行反向传播或优化。

```python
# study-example: S18D
from math import isclose
base = [[1.0, 0.0], [0.0, 1.0]]
a = [[1.0, 2.0]]
b = [[3.0], [4.0]]
delta = [[b[row][0] * a[0][column] for column in range(2)] for row in range(2)]
adapted = [[base[row][column] + 0.1 * delta[row][column] for column in range(2)] for row in range(2)]
assert delta == [[3.0, 6.0], [4.0, 8.0]]
assert isclose(adapted[0][0], 1.3) and isclose(adapted[1][1], 1.8)
assert base == [[1.0, 0.0], [0.0, 1.0]]
full_parameters = 4096 * 4096
update_parameters = 4096 * 8 + 8 * 4096
assert update_parameters < full_parameters
```

2×2玩具矩阵主要展示形状，不能体现大规模节省；4096与r=8的计数才说明小秩下可训练参数更少。真实LoRA还包括缩放、选定模块、优化状态、激活内存与验证；基础模型参数通常保持冻结。少更新参数不等于零显存成本，也不保证适合当前任务，需要固定数据对照。

## 4. 示例与逐步走查

### 单查询注意力的数学小实验

```python
# book-example: B18
from math import exp, sqrt
query = [1.0, 0.0]
keys = [[1.0, 0.0], [0.0, 1.0]]
values = [10.0, 20.0]
scores = [sum(q*k for q,k in zip(query,key)) / sqrt(2) for key in keys]
largest = max(scores)
weights = [exp(score-largest) for score in scores]
weights = [value/sum(weights) for value in weights]
output = sum(weight*value for weight,value in zip(weights,values))
assert abs(sum(weights)-1.0) < 1e-12
assert weights[0] > weights[1] and 10 < output < 20
```

这个示例仅说明分数→归一化→加权组合，不能代表完整模型、训练或真实embedding。改变query后解释权重变化，再阅读模型基础资料。

### 4.1 沿输入到结果逐步解释

query=[1,0]与第一个key的点积为1，与第二个为0；除以sqrt(2)后得到约0.707与0。softmax把它们转为正权重，第一项约0.67、第二项约0.33，总和为1。

把权重乘以values中的10和20再求和，得到约13.3。因为更匹配第一个key，输出更接近它携带的10，但并非直接挑10；两个值都按权重参与了组合。

减去最大分数不会改变归一化比例，却能减少指数过大的风险。此例的作用是解释“匹配→权重→组合”这一小步，没有学习投影矩阵或训练参数，不能据此说已实现Transformer。

### 接入模型后，给第一个答案做一次归因实验

使用同一模型和同一业务日期，让它回答“当前预付款上限是多少，并给出依据”。先单独提供当前制度，再给当前和旧版并标清生效日期，最后移除所需条款。固定问题、输出结构、解码参数和输出预算，每组重复运行并保存匿名化输入、实际响应与结束原因。手工给每个结果标三个独立项：结构可解析、数值受当日条款支持、引用能定位。第三组期望说明证据不足。

## 8. 本章小结与参考

### 8.1 主要知识点总结

- token、上下文与概率生成解释模型怎样接收和生成文本。
- 消息角色与模型接口构成请求协议，输入、输出和用量都需要记录版本口径。
- 结构化输出减少格式不一致，结果仍需解析、校验和事实核对。
- 训练、推理、检索与量化解决不同问题，应用选型从当前失败与约束出发。

### 8.2 日常工作注意事项

- 处理模型返回时检查截断、空内容、坏JSON和缺字段；不要把一次流畅回答当成可靠接口结果。
- 字符数不能精确替代token用量；记录实际模型与服务口径，限制上下文、输出与调用预算。
- 提示词、模型配置或版本变化后跑固定题和留出题；不要仅凭温度设置推断结果完全可复现。

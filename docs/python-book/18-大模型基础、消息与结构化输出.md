## 2. 基础知识讲解
### 2.1 模型逐步预测token，不自动查询事实

模型先把文本分成token，再根据已有上下文预测下一token的概率，选取一个并继续生成。完整回答是多次选择组成的序列，不是从可信数据库取出已核验结论。

`temperature`等参数影响采样方式，低随机性不能证明事实正确，也不能保证跨模型、版本和硬件逐字复现。token由具体分词器决定，不等于一个汉字或一个单词。

**先理解分词与采样参数：**
- BPE从基础符号开始，迭代合并训练语料中的高频相邻符号；token ID与合并规则属于特定分词器，换模型通常要重新计数。
- 字节回退让罕见Unicode字符拆成可表示的字节片段，避免直接失败；同一段UTF-8文本的token数仍可能随分词器变化。
- `temperature`缩放logit后再归一化；0通常走贪心选择，但并列分数、数值 kernel 与服务实现仍可能造成差异。
- `top-k`只保留最高概率的候选；`top-p`保留累计概率达到阈值的最小候选集，候选数会随分布变化，裁剪顺序依服务协议。
- `max_tokens`限制生成长度，但是否计入推理token依供应商而定；`stop`按字符串停止，可能截断JSON，结束后仍须检查完成原因与结构。

下面的`B18`只演示“分数 → 归一化权重 → 加权组合”。它用二维向量和一个注意力步骤解释局部机制，不是完整Transformer，也不是真实模型调用。

```python
# book-example: B18
from math import exp, sqrt
query = [1.0, 0.0]
keys = [[1.0, 0.0], [0.0, 1.0]]
values = [10.0, 20.0]
scores = [sum(q*k for q,k in zip(query,key)) / sqrt(2) for key in keys]
largest = max(scores)
weights = [exp(score-largest) for score in scores]
weights = [value/sum(weights) for value in weights]
output = sum(weight*value for weight,value in zip(weights,values))
assert abs(sum(weights)-1.0) < 1e-12
assert weights[0] > weights[1] and 10 < output < 20
```

第一项权重约为0.67，第二项约为0.33，加权结果约为13.3。减去最大分数只改善数值稳定性，不改变比例；真实模型还涉及学习投影、多头、位置表示和训练。
### 2.2 消息协议区分约束、输入和工具结果

应用通常把任务约束放在系统消息，把用户问题放在用户消息，把工具执行结果放回工具消息。角色与字段必须按供应商协议映射，不能把课程内部字典当作所有SDK的原生格式。

用户文本和文档内容都是不可信输入，不能拼进系统约束来提升优先级。提示可以说明任务与格式，却不能提供服务端授权；身份、租户和可执行动作仍由应用决定。

**工具结果要回到受控协议：**
- 助手的`tool_calls`只是调用提议，应用核对`tool_call_id`、工具名、参数与权限后才执行，并把结果放入对应工具消息。
- 工具返回文本同样不可信，其中要求改系统规则、读取其他租户或执行新动作的内容都不能直接升级为指令。
- 角色标签帮助模型区分上下文，却不是安全隔离；工具输出长度、敏感字段和可执行动作仍要由服务端限制。

#### 案例推进：调用前固定消息契约

为订单问答固定三条消息：系统约束只允许使用给定证据；用户消息包含问题和证据；助手历史只保留当前任务需要的部分。压缩历史时不能删掉权限、预算或输出格式。
### 2.3 JSON合法不等于业务结果正确

结构化输出要依次检查响应完成、JSON可解析、字段与类型符合Schema、业务规则成立。`{"answer":"20%","source_ids":["policy-a"]}`即使格式正确，也可能引用旧版、越权来源或不支持结论的原文。

缺字段、截断、显式拒答、上游500和空内容要分成不同错误。供应商原生JSON模式可以降低格式失败，应用仍须处理拒绝、截断和语义不符。

**JSON mode不等于Schema约束：**
- JSON mode通常只保证输出可解析为JSON，不保证字段名、必填项、枚举或业务类型符合应用契约。
- Schema constrained output按JSON Schema或供应商语法限制结构，可减少缺字段和非法枚举，但支持范围与能力因服务而异。
- 即使供应商声称受Schema约束，应用仍要检查完成原因、实际字段、类型、额外字段、来源与业务规则；Schema不能证明事实或权限合法。

#### 案例推进：把候选与事实分开

适配器只返回候选，不把`20%`直接写入订单。下一章保存字段与证据，第20章再核对来源身份、版本、定位和语义支持。任一层失败都不能用“模型很有把握”跳过。
### 2.4 流式输出要等协议确认完整

流式响应可能按UTF-8字节、SSE事件或NDJSON记录到达。文本片段出现不代表JSON已闭合，更不代表工具参数已经完整；应等声明的事件边界后再解析和执行。

HTTP读取超时不等于整个任务总预算。上层仍需限制排队、生成和重试的总时间，并记录首token时间、完整延迟与实际用量；没有返回用量时留空，不用字符数编造token数。完成原因应按供应商协议使用白名单，`length`、过滤、未知错误或缺失结束信号都不能当作成功；NDJSON记录边界、SSE事件边界与整个流结束也要分别确认。

#### 当一个汉字被拆到两次网络读取中

第2章看过半个UTF-8字符的解码错误。这里第一次读取只收到“采”的首字节：增量解码器应保留这半字节，等下一次补齐；流在`final=True`时仍不完整则报截断。即使一行JSON已可解析，也要等服务声明的结束事件。工具参数未收完整前绝不执行，迁移练习见第24章。

```python
# study-example: S18E
import codecs, json
wire = '{"text":"采购"}\n'.encode("utf-8")
cut = wire.index("采".encode("utf-8")) + 1
decoder = codecs.getincrementaldecoder("utf-8")()
prefix = decoder.decode(wire[:cut])
assert prefix == '{"text":"'
assert json.loads(prefix + decoder.decode(wire[cut:], final=True)) == {"text": "采购"}
truncated = codecs.getincrementaldecoder("utf-8")()
try:
    truncated.decode(wire[:cut], final=True)
except UnicodeDecodeError:
    pass
else:
    raise AssertionError("半个字符结束应报告截断")
```
### 2.5 参数、上下文与缓存占用不同资源

参数是训练后保存在模型里的权重；上下文是本次请求输入和已生成文本；推理缓存是服务为实现保存的中间结果，例如注意力计算中的键和值。缓存可能复用相同前缀的计算，但会占用内存，并且不能跨模型、版本或无权会话共享。

上下文窗口决定一次能容纳多少输入与输出。历史压缩或截断可能删掉权限、证据和格式要求，因此要保留必要约束，并按供应商返回的实际用量记录成本；不能用本地字符数冒充token计数。

**usage是计费与预算依据：**
- 输入、输出、推理和缓存token可能分别计价，缓存写入、读取与存储也可能另计；单价与计费项依模型和供应商而定。
- 预算同时限制单请求与租户周期成本，不能只按输出长度估算；提示变长、检索块变多或重试都会改变账单。
- 流式调用通常要在结束事件汇总usage，中途累计值可能不完整；供应商未返回时记“未知”，不能把缺失当0。

### 2.6 选读：训练改变参数，检索改变上下文

训练用目标函数衡量预测与目标的差距。交叉熵对正确类别概率取负对数：概率越接近1，损失越小。这个最小计算只说明目标，不包含真实语料、反向传播和完整训练。

```python
# study-example: S18C
from math import log

correct_probability = 0.8
wrong_probability = 0.2
assert -log(correct_probability) < -log(wrong_probability)
assert -log(1.0) == 0.0
```

LoRA不直接更新全部权重，而是学习一个低秩增量。若原权重是2×2，用1×2和2×1两个矩阵就能表示一个秩至多1的增量；可训练参数从4个变为4个，在这个极小方阵例子里没有减少，放大到高维矩阵后收益才明显。

```python
# study-example: S18D
base = [[1.0, 0.0], [0.0, 1.0]]
a = [[1.0, 2.0]]
b = [[3.0], [4.0]]
delta = [[b[i][0] * a[0][j] for j in range(2)] for i in range(2)]
updated = [[base[i][j] + delta[i][j] for j in range(2)] for i in range(2)]
assert delta == [[3.0, 6.0], [4.0, 8.0]]
assert updated == [[4.0, 6.0], [4.0, 9.0]]
assert base == [[1.0, 0.0], [0.0, 1.0]]
assert len(a) * len(a[0]) + len(b) * len(b[0]) == 4
rank = 16
full_parameters = 4096 * 4096
lora_parameters = 2 * 4096 * rank
assert lora_parameters == 131072
assert lora_parameters < full_parameters
```

4096×4096方阵取秩16时，两个低秩矩阵合计为`2×4096×16=131072`个可训练参数，少于原方阵的16777216个参数；这里只比较参数规模，不证明训练质量或推理速度。

SFT改变模型参数以适应示范数据，LoRA是参数高效微调的一种；RAG在调用时提供可更新证据。它们解决不同问题，公式成立也不代表已经完成训练或证明质量提升。完整推导见[AI基础原理册的训练章](../ai-foundations/05-训练.md)。

## 3. 原理讲解与推导
### 3.1 校验层减少错误，但不能把候选变成事实

模型根据上下文生成候选，解析层把字节或事件转成对象，Schema层限制字段和类型，业务层再检查来源与规则。每层只排除一类问题：JSON合法不排除编造，引用存在不排除版本错误，摘要匹配也不排除批准无效。

因此错误应停在最先失败的层。连接与HTTP错误交给调用层，截断交给协议层，字段错误交给适配层，无证据或语义不符交给业务层；不能让下游把上游缺失的事实补成肯定结论。
## 4. 示例与逐步走查
### 4.1 第一步：给订单问题构造消息

#### 案例推进：把约束与证据放在不同角色

```json
{"model":"配置中的实际模型标识","stream":false,"messages":[{"role":"system","content":"只根据证据回答，输出answer和source_ids；证据不足时明确说明。"},{"role":"user","content":"问题：订单T1的当前预付款上限是多少？证据：制度v2规定上限为20%。"}]}
```

系统消息规定任务，用户消息携带问题与证据。这里的制度文本是教学输入，不是模型自带知识；真实服务还要把租户和日期绑定到可信证据。
### 4.2 第二步：用假响应验证适配与结构

```python
# study-example: S18B
import json

def extract_text(payload):
    if (not isinstance(payload, dict) or payload.get("done") is not True
            or payload.get("done_reason") not in {"stop"}):
        raise ValueError("响应未正常完成")
    message = payload.get("message")
    if not isinstance(message, dict) or message.get("role") != "assistant" or message.get("tool_calls"):
        raise ValueError("消息角色或类型错误")
    content = message.get("content")
    if not isinstance(content, str) or not content.strip():
        raise ValueError("消息缺少文本")
    return content

def parse_answer(text):
    value = json.loads(text)
    if not isinstance(value, dict) or set(value) != {"answer", "source_ids"}:
        raise ValueError("字段不符合契约")
    if not isinstance(value["answer"], str) or not value["answer"].strip():
        raise ValueError("answer不能为空")
    ids = value["source_ids"]
    if not isinstance(ids, list) or not all(isinstance(item, str) and item for item in ids):
        raise ValueError("source_ids格式错误")
    return value

payload = {"done": True, "done_reason": "stop", "message": {"role": "assistant", "content":
          '{"answer":"20%","source_ids":["policy-a-v2"]}'}}
assert parse_answer(extract_text(payload))["source_ids"] == ["policy-a-v2"]
for bad in ({}, {"done": False}, {"done": True, "done_reason": "length"},
            {"done": True, "message": {"role": "assistant", "content": ""}}):
    try:
        extract_text(bad)
    except ValueError:
        pass
    else:
        raise AssertionError("不能接受未完成或错误结构")
```

这个替身验证调用链，不证明模型理解。它接受普通文本聊天，拒绝工具调用；`source_ids`只通过格式检查，是否真实存在且支持答案要在后续证据层验证。
### 4.3 第三步：配置真实服务并保留实际结果

下面使用已有HTTPX依赖调用本机Ollama。先设置`LAB_MODEL`为已安装模型标签，并确认服务已启动；未配置或为空会直接报错，不会静默使用替身，也不会把未调用写成成功。

```python
# framework-example: F18
import json, os
import httpx
model = os.environ.get("LAB_MODEL", "").strip()
if not model:
    raise RuntimeError("未配置LAB_MODEL，本次没有调用真实模型")
base_url = os.environ.get("LAB_OLLAMA_URL", "http://127.0.0.1:11434")
messages = [
    {"role": "system", "content": "只根据证据回答，输出JSON字段answer和source_ids。"},
    {"role": "user", "content": "订单T1的证据：制度v2规定预付款上限20%。问：上限是多少？"},
]
with httpx.Client(base_url=base_url, timeout=httpx.Timeout(30.0, connect=5.0)) as client:
    response = client.post("/api/chat", json={"model": model, "messages": messages,
                         "stream": False, "format": "json"})
    response.raise_for_status()
    payload = response.json()
    if (not isinstance(payload, dict) or payload.get("done") is not True
            or payload.get("done_reason") not in {"stop"}):
        raise ValueError("真实模型响应未正常结束")
    message = payload.get("message")
    if not isinstance(message, dict) or message.get("role") != "assistant" or message.get("tool_calls"):
        raise ValueError("真实模型消息不符合文本契约")
    content = message.get("content")
    if not isinstance(content, str) or not content.strip():
        raise ValueError("真实模型消息缺少文本")
    answer = json.loads(content)
    if not isinstance(answer, dict) or set(answer) != {"answer", "source_ids"}:
        raise ValueError("真实模型结构化结果不符合契约")
    if not isinstance(answer["answer"], str) or not answer["answer"].strip():
        raise ValueError("真实模型答案不能为空")
    ids = answer["source_ids"]
    if not isinstance(ids, list) or not all(isinstance(item, str) and item for item in ids):
        raise ValueError("真实模型来源标识不符合契约")
    print(content)
```

只有真实响应通过检查后才打印内容。保存模型标签、服务版本、提示版本、结束原因、耗时和实际返回的用量；网络失败、HTTP失败与坏JSON分别记录。一次真实调用只证明该环境的一次行为，不证明引用有效或任务质量达标。

## 7. 面试问答与迁移

**问：Prompt、RAG和微调分别解决什么？** Prompt给任务与约束，RAG在调用时提供可更新证据，微调改变参数以适应固定行为。缺当前事实时先查来源，不要默认靠训练补齐。

**问：temperature=0能保证复现吗？** 不能承诺跨服务、模型版本和硬件逐字一致。固定模型、提示、证据和参数，用重复运行与回归集观察波动。

**问：流式内容出现后能执行工具吗？** 不能。要等服务协议确认参数完整，通过JSON与参数校验后才执行；半段汉字、半个事件或半个参数都不构成完整调用。
## 8. 本章小结与参考

- 模型逐token生成概率候选，流畅与低随机性都不是事实证明。
- 消息角色承载约束、输入与工具结果，权限必须由服务端提供。
- 响应完成、JSON、Schema和业务证据是不同校验层，不能互相替代。
- 流式输出按协议等完整事件；用量缺失留空，不编造token。
- 真实调用要记录模型与环境；未配置时没有调用成功。

## 1. 学习目标与前置知识

将前文组合为可演示、可评测的项目。前置：第15、18–21、26章。

## 2. 基础知识讲解

用同一套虚构制度和合同逐步实现：聊天API→上传/解析→结构化抽取→索引→问答→检索实验。每版只引入当前问题需要的组件，留下改动前后证据。

Document、Chunk、Extraction、Citation、QueryResult 等契约保持来源与权限。模型适配、解析器、检索器和业务API可以替换；数据更新和索引重建也要有版本记录。

项目展示重点是“为什么这样做，以及有什么证据”，而不是界面和框架数量。数值分析走确定性工具，文档说明走检索证据。

## 3. 原理讲解与推导

从输入文档到最终结论每步都可能引入错误，因此要保留可追溯中间产物，分别评估解析、检索和生成。

### 项目化展开

### 二、DocPilot：文档、抽取与知识检索

#### 业务范围

用户上传虚构合同/制度，查询可访问的材料。系统给出字段抽取或基于证据的说明。文档中的风险提示是学习样例，业务结论需结合规则和人工复核。

#### 最小接口

| 接口 | 本阶段要求 |
| --- | --- |
| GET /health | 进程可用；另用 readiness 检查必需依赖，二者含义分开 |
| POST /api/chat | 输入消息、返回文本和请求标识；通过模型适配层调用 |
| POST /api/chat/stream | 明确事件类型及结束/失败；客户端断开能清理 |
| POST /api/documents | 校验上传，返回 document_id/任务状态；不将用户文件名直接拼进存储路径 |
| GET /api/documents/{id} | 返回解析/入库状态；检查访问权限 |
| POST /api/extractions | 指定可访问 document_id 与抽取字段集合 |
| POST /api/search | 返回有来源的候选片段，支持受控历史日期与类型过滤 |
| POST /api/questions | 检索、生成并返回 answer、citations、needs_review |

所有输入都有模型和大小/长度边界。identity/tenant 来源于可信认证上下文，不能相信请求体自报身份。早期单用户可用服务端注入的固定测试身份，但要保留边界并写越权测试。

#### 抽取结果契约

每个字段返回 value（可 null）、evidence、needs_review。金额保留原文，再按明确规则确定性转为金额分和币种。证据形状为：

```json
{
  "source_id": "policy-a-current",
  "version": "2",
  "page": null,
  "section": "付款要求",
  "quote": "预付款比例不得超过合同金额的20%。"
}
```

JSON/Markdown 样例没有真实页码，应填 null 并引用节号；实际 PDF 只有成功追溯页码后才填数字。证据文字必须能在指定来源中找到，引用存在还不够，还要核对它是否支持该字段。

#### 检索管道

```text
解析 → 规范化来源/版本/权限 → 分块 → 向量化 → 索引
查询 → 确定用户可见范围/业务日期 → 过滤检索 → 可选融合/重排 → 证据回答
```

每个片段保存 source_id、版本、chunk_id、租户、授权范围、生效区间与来源位置。更换 embedding 的维度/模型时创建可区分的新索引配置，不混入旧向量；重复入库要有稳定标识和更新策略。

Dense、稀疏和重排的候选都必须经过相同权限与版本约束；工具输出与提示词也不能泄露不可见材料。空召回、来源冲突、来源过期分别处理。

#### 分阶段交付

- W04：聊天适配、错误与假模型测试；起始固定样本。
- W05：文本型 PDF 解析和字段证据；不支持的文档明确报告。
- W06：带版本与权限的基线 RAG；关键词/向量结果可导出。
- W07：固定集上的融合/重排比较；选默认策略。
- W12：问题 Router；不确定时要求澄清，数值查询交给确定性工具。

### 实施里程碑与代码边界

第一版完成模型适配和API；第二版解析并输出带证据字段；第三版做权限过滤的检索；第四版比较混合/重排。每一步可单独运行、测试和回退，不要求一次装齐所有基础设施。

领域层使用Document/Chunk/Citation等契约；解析器、embedding、向量库和模型通过适配器替换。先完成一条数据流，再优化布局、索引和前端。

## 4. 示例与逐步走查

### DocPilot 固定演示

输入tenant-a、业务日期2026-10-01和问题“预付款上限是多少”；从policy-a-current返回20%及有效版本证据。换到2026-06-01应引用policy-a-old回答30%；询问另一租户规则不得暴露其材料。

记录三条请求的检索来源、最终引用和错误/拒绝原因。这三条是种子案例，不足以取代20–30条标注集，也不能证明真实政策正确性。

## 5. 动手练习

按项目规格完成最小接口、五份虚构文档与20条问题；导出向量/关键词/融合对照和无证据案例。

## 6. 验收与自测

**行为验收：** 新环境可复现；引用正确；权限不越界；模型/数据版本可定位；记录已知限制。

**原理验收：** 合上资料解释本章一个机制，预测一个反例，说明规则属于语言语义、库约定还是实现观察。

**提交证据：** 实现位置、运行命令、正常案例、至少一个错误/边界案例、一次失败原因和修复记录。自动检查只证明其覆盖行为；未实现任务不因示例通过而算完成。

## 7. 面试问答与迁移

用五分钟讲清DocPilot架构、一个失败案例及一次实际改进，展示前后指标而非泛泛“效果提升”。

回答顺序：定义与边界 → 机制 → 小例子 → 项目影响 → 验证方式。不确定的实现细节明确说明版本和查证办法。

## 8. 本章小结与参考

先达到行为与原理两类验收，再继续后续依赖本章的任务。遇到不熟悉的内容回到例子做小实验，不以阅读完成代替掌握。

# 核心知识依赖图：哪些必须系统学，哪些可以后补

[学习导航](学习导航.md) · [Python 教材](python-book/教材目录.md) · [AI 基础原理](ai-foundations/教材目录.md) · [TypeScript 教材](typescript-book/教材目录.md) · [架构](architecture-book/教材目录.md) · [产品](product-founder-book/教材目录.md)

这张图解决两个极端：

- 只按当前项目缺什么学，容易留下基础空洞；
- 按 85 章平均读，容易学完很多章却做不出作品。

用法：**项目主线负责“连起来”，这张图负责“补完整”。** 每完成一个阶段，回来看当前方向哪些“必须系统学”还没过；不要求第一遍全部精通，但要知道自己跳过了什么。

## 四条知识链

### 1. Python：运行模型 → 函数/类 → 迭代/异步 → 工程服务

```text
名称/对象/可变性
→ 调用帧/作用域/闭包
→ 类/协议/数据模型
→ 迭代器/生成器/异常/with
→ 模块/类型/测试/文件
→ 线程/进程/异步
→ 数据库/HTTP/API/部署
```

| 层级 | 内容 | 处理方式 |
| --- | --- | --- |
| 必须系统学 | 名称与对象、可变性、复制、作用域、调用帧、闭包、类与协议、迭代/生成器、异常/with、模块、类型与运行时校验、测试、异步、HTTP、事务 | 按 Python 1–17 主线走；不能因为项目暂时没用到就跳过 |
| 先了解后深入 | 描述器/MRO 细节、CPython 帧槽位、GC 实现、元类 | 第4、6章标了“第二遍”；排错或读框架源码时再深入 |
| 按方向选学 | C 扩展、性能调优、分布式任务、MCP/多 Agent | 有明确任务再学 |

**尤其不能跳过：** 生成器/`with` 的清理、异常分层、事务边界、异步取消。小项目可能碰不到，但服务故障时会集中出现。

### 2. AI：机制 → RAG → Agent → 评测与交付

```text
token/embedding/attention 直觉
→ 训练与推理的区别
→ 文档解析/切块/检索/重排/引用
→ 权限/版本/更新/删除
→ 工具调用/状态/预算/审批/恢复
→ 评测/成本/延迟/安全
```

| 层级 | 内容 | 处理方式 |
| --- | --- | --- |
| 必须系统学 | token 与上下文、embedding/相似度、Transformer 直觉、训练/SFT/推理区别、RAG 全链路、引用与忠实性、租户/日期过滤、评测分母、工具循环与审批 | AI 原理 1–8 + Python 18–26；每学一个机制，回答它改变了哪个设计决定 |
| 先了解后深入 | 反向传播推导、RLHF/DPO 细节、分布式训练、量化内核 | 需要读论文/做训练时再补；应用开发先能解释边界 |
| 按方向选学 | MCP、多 Agent、复杂图编排 | 先有跨进程/分工问题，再读 Python 27–28 |

**关键连接：** “相似度高”不推出“有权限/版本正确/支持结论”；“模型能答”不推出“可以执行写操作”。这两条要贯穿 RAG 和 Agent。

### 3. TypeScript 与全栈：浏览器 → 语言 → React → BFF → 数据 → 交付

```text
浏览器/HTTP/JSON
→ JavaScript 运行时/事件循环
→ TypeScript 类型与收窄
→ 运行时校验/错误边界
→ 异步/取消/流式
→ React 组件、状态、表单、路由
→ 数据请求/缓存
→ BFF/认证/权限
→ SQL/事务
→ 测试/观测/部署
```

| 层级 | 内容 | 处理方式 |
| --- | --- | --- |
| 必须系统学 | 浏览器请求/响应、JS 事件循环与 Promise、TS 类型擦除/收窄、运行时校验、异步取消、React 状态归属、表单/路由、BFF 身份边界、测试 | TS 1–16；B+ 先做无框架页面，C 再做 React/BFF |
| 先了解后深入 | 打包器内部、SSR/RSC、复杂性能优化、设计系统 | 有产品/团队需求再深入 |
| 按方向选学 | 专职前端的浏览器原理、渲染性能、组件库架构 | 目标不是前端专家时，先保证完整链路 |

**前端不能只学“类型 + fetch”：** 还要能处理加载/空/错误、表单校验、取消请求、键盘操作和基本无障碍；否则页面只是能跑，不是能交付。

### 4. 架构与产品：跟项目持续练，不另开同等强度课程

| 方向 | 每个阶段的最小动作 | 什么时候系统深入 |
| --- | --- | --- |
| 架构 | 写一页 ADR：问题、约束、选项、决定、代价、复查条件 | 遇到并发、容量、恢复、发布问题时读架构对应章 |
| 产品 | 写用户/任务/证据：谁、什么任务、观察到什么、哪个假设被改写 | 需要定价、渠道、组织、创业资源时读产品对应章 |

架构/产品不是“学完技术再说”，也不是“每阶段读完整册”。它们是**每个作品上的小任务**，遇到问题再展开。

## 项目没用到，但必须知道的例子

| 暂时没用到 | 为什么不能跳过 | 何时补 |
| --- | --- | --- |
| 生成器 `close`/`with` 清理 | 服务取消、超时、文件句柄会用到 | Python 5，阶段 B 前 |
| 数据库事务/并发 | 单机演示不会暴露，双请求会 | Python 8、16，阶段 B/D |
| React 状态归属/取消 | 单人页面可能不暴露，快速切换会 | TS 8–10，阶段 C |
| RAG 评测分母/权限过滤 | 小语料返回全部也能“看起来对” | Python 20–22，阶段 D |
| 发布回滚/迁移 | 本机能跑不等于可回滚 | Python 17、TS 18，阶段 D/F |
| 审批/幂等/对账 | 只做只读搜索不会遇到 | Python 16、24–26，阶段 E |

## 主线完成后的进阶路线

主线不是终点。完成 A–F 后，按目标选一条深入：

- **后端/架构**：数据库并发与隔离、消息与一致性、容量与可靠性、发布与回滚；
- **前端工程**：浏览器渲染、复杂状态、性能、可访问性、组件设计；
- **AI 应用**：评测体系、检索优化、成本/延迟、真实模型与向量库运维；
- **产品/创业**：真实用户研究、定价与单位经济、渠道与客户成功。

每条进阶路线都回到同一个作品：换真实数据、加真实约束、记录失败和取舍。不要另起一个只演示成功路径的“新项目”。

## 一页自检

每完成一个阶段，回答：

1. 这个作品证明了什么？还没证明什么？
2. 这条知识链里，哪些“必须系统学”我只是照着做、还不能解释？
3. 哪个反例能推翻我现在的设计？
4. 下一阶段要补的一个基础空洞是什么？

答不出第 2 题，说明项目跑通但掌握层还没过；答不出第 3 题，说明还没有真正理解边界。

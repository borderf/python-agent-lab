# 第12章　AI系统架构与技术选型

[上一章](11-部署发布与渐进式演进.md) · [本书目录](教材目录.md) · [下一章](13-架构评审技术领导与协作.md)

## 1. 目标、前置与问题

前置：第4–10章；能区分确定性程序与模型候选，基本检索和工具流程在本章说明。能在确定性工作流、RAG和Agent之间做选择。问题：什么时候值得让模型决定下一步？

## 2. 概念与基础

确定性流程适合规则明确、动作有限的任务；RAG为回答提供检索证据；Agent允许模型在约束内选择动作。多Agent增加协作与合并成本，不能仅因任务复杂就假设收益更高。

模型适配层隔离协议和供应商差异，但并不能消除输出质量、工具语义和价格差异。结构化输出减少格式问题，不证明事实正确或动作获授权。可信身份、业务规则、权限和动作账本留在确定性边界。

## 3. 机制与推导

AI 系统的组件应对应可观察的失败。资料没有解析出来，换更强模型不能补出缺失原文；候选中没有正确来源，重排也不能凭空找回；流程固定时引入动态规划，会增加不确定性而未必增加价值。

先做确定性基线，分离检索与生成。检索返回来源，生成基于来源提出候选回答，可信程序检查结构、引用和权限。模型不能成为数据库状态、身份或批准的所有者。

```mermaid
flowchart LR
    A[授权资料] --> B[解析与版本]
    B --> C[检索基线]
    C --> D[可见证据]
    D --> E[模型候选]
    E --> F[校验与人工复核]
    F --> G[业务结果]
```

选型比较任务质量、协议、时限、限额、成本、运行位置与维护负担。SDK 可以简化协议，但不能代替正确的事件、取消和工具调用处理。切换供应商必须重测坏输入、拒答、引用、长上下文与工具参数。

增加 Agent、多角色或路由前，先写清基线在哪类题失败，以及新组件靠什么机制改善。同一开发题集用于迭代，另保留未参与调参的题检查迁移；不把小样本数字包装成总体效果。

## 4. 案例逐步推演

做一个完全虚构的选型练习：8道开发题中，关键词基线找到6道，融合找到7道，但新增方法多一项依赖。先逐题查看新增的1道是否来自真实语义补足，是否牺牲其他题与权限；不能只比较总数。

再看生成：引用原文写“上限20%”，模型回答“可以80%”。即使引用字符串存在，结论仍错误。DocPilot 的自动引用验收只能证明位置与范围，语义支持需要确定性规则或人工标注，二者不能混称。

最后将“自动提交”加入需求。先确定批准与动作账本，再决定是否需要 Agent 选择工具。动态选择仍经过允许清单、参数校验、可信身份和总预算，不能因为模型更聪明就省略执行边界。

### 4.1 从失败目录选择下一项技术

| 首个失败点 | 应先调查 | 不足以单独解决它的改动 |
| --- | --- | --- |
| 原文未提取 | 格式、阅读顺序、解析中间产物 | 换聊天模型 |
| 正确来源被过滤 | 身份、日期、来源版本 | 增加reranker |
| 进入候选却排后 | 排名、候选预算与重排 | 扩大模型参数量 |
| 引文真实而结论错 | 规则、上下文、语义评分 | 只校验JSON |
| 动作声称成功但未执行 | 工具轨迹、状态与回执 | 加一个总结角色 |

每次改动只针对一个机制假设，重新跑原题和留出题。若加入新组件只修复一道题，却引入关键越权或显著维护负担，不能用平均总分掩盖它。

真实流式调用还要处理增量字符与协议事件、工具参数分片、结束状态和断开清理。优先选一个实际供应商完成完整适配，不同时维护多个只有正常响应的薄包装。外部SDK与服务版本按当前官方文档核对，仓库离线通过不代表已经完成这些集成。

## 5. 分层练习

先完成：用自己的失败清单选择一个组件改动，写“失败—机制假设—对照—质量与代价”。若准备真实模型，保存实际模型标识、日期、题集、错误与用量；离线替身只用于验证程序边界。

## 8. 迁移与阅读

### 8.1 一页知识地图

**本章主问题：** 什么时候值得让模型决定下一步，而不是写死流程？

**一条主线：**

```text
失败目录 → 机制假设 → 确定性基线与检索生成分离 → 单组件对照与选型
```

**三个关键词：** 确定性基线、候选、执行边界。基线定位失败在哪一层，候选只在证据指向它时加入，身份、批准与账本始终留在确定性程序里。

**最容易错：**

- 用“技术更新”当改进理由，所有错误都去调提示词。
- 换个更强模型，想补出根本没解析出来的原文。
- 把引用存在率当事实正确率，引文写“上限 20%”而结论写“80%”。
- 为一个失败点加组件，却引入越权或维护负担，再用平均分掩盖。

**与前后章：** 上一章的发布门槛与拒绝样本约束了选型；下一章把已有证据与仍有争议的部分交给评审。

**学完应能：**

- 按首个失败点选下一项技术，并写出失败、机制假设、对照与代价。
- 把检索与生成分开，让可信程序校验结构、引用与权限。
- 保留未参与调参的留出题，记录模型标识、日期与用量。

实现背景见[AI评测实现](../python-book/22-AI评测、提示注入、追踪与成本.md)；生产集成应按所选服务当前协议重新核验。

# 第11章　部署发布与渐进式演进

[上一章](10-安全多租户与隐私边界.md) · [本书目录](教材目录.md) · [下一章](12-AI系统架构与技术选型.md)

## 1. 目标、前置与问题

前置：第7、9章。能设计可追溯构建、兼容发布和数据迁移。问题：代码回滚成功，为什么服务仍可能无法恢复？

## 2. 概念与基础

构建产物应可识别版本，配置和密钥在环境中管理。CI验证代码与契约，CD组织发布；自动部署不代表必须自动发布给所有用户。容器封装运行环境，编排解决调度等问题，不能自动消除数据和业务风险。

滚动发布意味着新旧版本共存；蓝绿使用两套环境切换；金丝雀先向小范围暴露。每种方式都需要兼容、指标、停止条件和回退。功能开关将部署与功能开放分离，也需要负责人和清理期限。

## 3. 机制与推导

数据库演进可采用扩展—迁移—收缩：先增加兼容字段或结构，再回填与验证，最后停止旧读写并清理。先删旧字段再发布新代码可能破坏仍运行的旧实例。

回滚代码不能自动还原已改变的数据和外部副作用。为不可逆迁移准备备份、前向修复、只读窗口或其他适当措施。渐进替换旧系统时，先选可隔离边界，通过路由或适配器转移一小部分流量，避免长期不受控双写。

### 3.1 从开发环境到运行环境的最小拓扑

浏览器→HTTPS入口/反向代理→应用→数据库与必要外部服务。静态文件可独立托管，也可同源提供；选择应交代缓存、认证与部署成本。容器端口声明不等于已对外发布，数据库无需直接暴露给公网。Docker端口发布含义见[官方说明](https://docs.docker.com/get-started/docker-concepts/running-containers/publishing-ports/)。

发布前依次检查产物版本、配置、数据库迁移、readiness、关键任务与监控；先在测试环境完整走一遍。首次部署和升级部署都应有复现说明，不能只留下机器上的手工状态。

## 4. 案例逐步推演

DocPilot把文档单一状态改为解析状态和索引状态。先新增字段，新版本能够兼容旧记录；后台回填并核对；观察新旧版本混合部署；切换读路径；最后确认没有旧消费者再考虑清理。

若上线后错误升高，关闭新读路径并回退兼容代码，保留新增字段。索引迁移先建新索引并验证来源与权限，再切换；旧索引删除是独立决定，不能等同于代码回滚。

### 4.1 发布门槛与停止门槛

把成功任务、权限、错误、延迟和数据约束作为门槛。若出现越权、迁移校验失败或未知副作用，应停止扩大流量并调查。前向修复与回滚分别写条件，不在事故现场临时决定哪些数据可删。

## 5. 分层练习

基础：列出应用、数据库、索引和外部API版本。应用：写上述迁移步骤、检查点和回退。挑战：模拟回填中断和新旧实例共存，证明用户看到的状态可解释。

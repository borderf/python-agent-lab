## 两个真实 PostgreSQL 会话

准备隔离的教学数据库及其连接配置，安装 architecture 依赖组。实验会创建唯一的 course_ 前缀 schema，结束时清理自己创建的 schema。当前账户需要相应建表权限。

```powershell
uv sync --locked --group architecture --inexact
# LAB_POSTGRES_DSN 由本机环境提供，避免把密码写进教材或提交到仓库。
uv run --group architecture python -m practice.integration_labs.postgres_race
```

A、B 先分别读到版本 7。A 条件更新成功后提交，B 用版本 7 更新影响 0 行。先预测去掉 WHERE version=7 的后果，再在练习副本验证，并把 0 行结果映射为明确的竞争响应。

下一轮将两行共同保护一个不变量，例如至少一个资料负责人在岗。各行各自版本正确仍可能违反跨行规则，分别设计锁与更强隔离的实验。记录数据库版本、隔离配置、执行顺序和完整事务重试。[双会话脚本](../../practice/integration_labs/postgres_race.py) · [PostgreSQL 隔离说明](https://www.postgresql.org/docs/current/transaction-iso.html)

## 从稳定到突发的排队实验

```powershell
uv run python -m practice.integration_labs.capacity
```

程序有两个 worker，每个服务时间设为 40 毫秒，等待队列最多四项。分别发送稳定与突发的 20 个请求，记录完成、拒绝、排队和端到端时间。总请求应等于完成加拒绝，拒绝项始终保留在原始记录中。先根据均值估算容量，再看实际调度和突发如何改变结果。

突发使用 `sleep(0)` 让出执行权，紧接着发下一项；不依赖 1 毫秒定时器。不同系统的调度粒度会改变短间隔实验，记录实际到达时间后再解释差异。

将 worker 数改成 1，再把等待上限改成 1。分别预测完成数、拒绝数与排队分布，运行后解释偏差。下一轮将固定等待换成真实模型客户端或数据库查询，记录连接等待、服务限额和取消；这时才能把结论用于自己的应用。

从原始记录计算分位数时明确算法、样本数和时间窗口。单列失败与拒绝，避免用成功快请求的平均值代表全部体验。持续压测要设计到达速率、持续时间、停止条件和资源采样，完整保留负载发生器与被测服务配置。[容量脚本](../../practice/integration_labs/capacity.py)

## 一次带旧数据的迁移

DocPilot 的 001 版本保存资料与回答，002 增加反馈。先在旧结构写入样例，再升级并读取同一批资料。对应回归会检查这条路径。

```powershell
uv run --group web python -m pytest tests/test_integration_labs.py -q -k migration
```

自己增加一个有业务含义的字段，例如资料负责人。按新增兼容字段、分批回填、核对、切换读取、收缩旧字段推进。模拟旧实例仍在读和回填进行一半时停止。记录哪些步骤可以回滚，哪些需要前向修复；恢复到隔离库后核对资料、回答与反馈的关联。

## 将实测转成一页 ADR

每页记录一个决定，附上需求、候选方案、原始数据、失败、采用条件和复查时机。下面给出需要自己填写的数据口径。

| 决定 | 证据 | 会促使你调整方案的观察 |
| --- | --- | --- |
| 使用条件更新保护审批 | 双会话时间线、影响行数、业务不变量 | 不变量扩大到多行，当前保护无法覆盖 |
| 给导入任务限额并设置有限等待 | 成功、拒绝、排队、资源曲线 | 真实流量或任务大小改变，瓶颈转移 |
| 分阶段升级资料 Schema | 旧新读路径、回填记录、恢复结果 | 旧客户端无法兼容，或回填无法在窗口内完成 |

把同一份失败交给同伴做评审，让对方改变一个约束。你应能据此修改方案和验证，而不仅复述原图。真实数据库和负载结论分别记录环境；本机固定延迟算例用于验证测量过程。

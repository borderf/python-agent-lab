# 用手机阅读与维护文档网站

网站从现有 Markdown 教材生成；主教材三套（Python、架构、产品），另有 TypeScript 第一册。手机打开发布地址，使用「章节目录」切换章节，用「搜索教程」查术语；正文的折叠答案可以点开，代码与宽表格可以左右滑动。

## 手机学习怎样使用

- 在章节顶部选 Python 基础、AI 应用、Agent、软件架构或产品创业路线。页首和文末的「按主线继续」按前置关系前进；全书上一/下一节仍按目录顺序翻阅。
- 选择 16、17、19 或 21 的正文字号。已读标记和路线计数方便复习，阶段是否掌握仍按自测与独立练习验收。
- 返回首页点「继续上次阅读」，恢复最近文章及滚动位置。位置和设置仅保存在当前浏览器；清除网站数据、更换设备或浏览器后不会自动同步。
- 流程图靠近阅读位置时加载，点「放大查看流程图」后可横向查看，用关闭按钮或 Esc 返回。加载失败可重试，也能查看源码。

查找当前阶段操作时，打开[从实验到项目交付](project-practice/从实验到项目交付.md)；每隔一段时间按[阶段自测](python-book/附录H-阶段自测与复习.md)换一组输入复验。

## 在电脑上预览

安装 Node.js 22 或更新的 LTS 版本，在仓库根目录运行。首次从 GitHub 拉取本配置后，先按锁文件安装网站依赖。

```powershell
npm ci
npm run docs:dev
```

打开终端显示的 Local 地址即可阅读，修改 Markdown 后页面会更新。要在同一 Wi-Fi 下用手机预览，运行下面的命令，再用手机访问终端显示的 Network 地址。电脑需要保持运行，系统防火墙需允许该进程在专用网络上提供服务。

```powershell
npm.cmd run docs:dev -- --host 0.0.0.0
```

上面的局域网命令使用 Windows 的 npm.cmd，避免 PowerShell 的 npm.ps1 吞掉参数；macOS/Linux 使用 `npm run docs:dev -- --host 0.0.0.0`。

正式发布前做一次生产构建与预览。网站输出到 `.vitepress/dist`；预览地址包含 `/python-agent-lab/`，与 GitHub Pages 的项目路径一致。

```powershell
npm run docs:test
npm run docs:build
python scripts/verify_docs_site.py
npm run docs:preview
```

## 首次发布到 GitHub Pages

1. 将本次的网站配置、`package.json`、`package-lock.json`、首页、使用说明和工作流一起提交并推送到 `main`。`node_modules` 和生成的网页已加入忽略规则。
2. 在仓库的 Settings → Pages → Build and deployment 中，将 Source 设为 **GitHub Actions**。
3. 在 Actions 中打开 **Publish learning docs**。推送会自动触发，也可以点 **Run workflow** 重新执行。首次推送发生在启用 Pages 之前时，启用后重跑即可。
4. 等 `build` 和 `deploy` 均成功，打开工作流部署结果中显示的地址。当前仓库预期地址为 `https://borderf.github.io/python-agent-lab/`，以实际部署结果为准。
5. 用手机浏览器打开该地址并收藏。以后更新教材并推送到 `main`，工作流会重新构建和发布。

Pages 的 Source 配置按 GitHub 官方步骤操作。[GitHub Pages 发布源设置](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site#publishing-with-a-custom-github-actions-workflow)

## 怎样维护

- Python、架构和产品的侧边栏按文件章号及书内分卷生成。修改标题会更新侧栏文字，新增章节时检查 `.vitepress/config.mjs` 中的分卷范围。
- 图片、公式、Mermaid 图或正文链接改动后，执行 `npm run docs:build`。断开的章节链接会使构建失败，修好后再提交。
- 构建后运行 `python scripts/verify_docs_site.py` 检查生成网页的本地目标与章节锚点。GitHub 发布前也会运行它，以及阅读设置和路线顺序检查。
- 非 Markdown 的源码、数据文件和目录链接会跳转到 GitHub。网页阅读中的练习检查仍在电脑的 Python 环境运行。
- 新增或升级网站依赖时同步提交 `package-lock.json`，GitHub 使用 `npm ci` 安装锁定版本。
- 仓库更名或使用独立域名时，在 `.vitepress/config.mjs` 修改 `base`。当前值是 `/python-agent-lab/`，修改后重新构建并核对首页、章节和搜索结果链接。

## 发布失败时看哪里

Windows 若在 esbuild 删除系统临时文件时出现 `Access is denied`，可在当前终端把构建临时目录设到工作区后重试。在仓库根目录执行：

```powershell
$docsBuildTemp = Join-Path (Get-Location) ".learning-labs/build-tmp"
New-Item -ItemType Directory -Force -Path $docsBuildTemp | Out-Null
$env:TMPDIR = $docsBuildTemp
$env:TMP = $docsBuildTemp
$env:TEMP = $docsBuildTemp
npm run docs:build
```

这些环境设置只作用于当前终端及其子进程；关闭终端即恢复。临时目录位于已忽略的学习实验区，不提交生成物。构建成功后再运行 `uv run --frozen python scripts/verify_docs_site.py` 检查实际产物；本地构建成功不代表线上已经发布。

| 现象 | 检查位置与处理 |
| --- | --- |
| Actions 提示找不到 Pages 站点 | 确认 Settings → Pages 的 Source 已设置为 GitHub Actions，再重跑工作流 |
| 构建提示 dead links | 根据构建日志找到源 Markdown，修正目标文件或链接路径，本地重新构建 |
| 首页有内容，样式或章节 404 | 核对 `.vitepress/config.mjs` 的 `base` 和实际项目地址 |
| 手机看到旧内容 | 先确认对应提交的部署已成功，再刷新当前页面 |

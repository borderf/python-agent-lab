# 第04章　Transformer：注意力怎样组合上下文

[上一章](03-Embedding.md) · [全书目录](教材目录.md) · [下一章](05-训练.md)

## 1. 学习目标与前置知识

能跟着一个小例子说明：当前位置怎样给其他位置分配权重，再组合它们的信息。先理解Q/K/V、softmax和因果掩码，之后再学习多头、位置信息及其余网络层怎样配合。前置：第3章；会点积和指数即可。

**本章从这里开始：** “苹果”在“苹果手机”和“吃苹果”里含义不同。模型怎样让当前位置读取上下文，而不是孤立地看每个 token？

## 2. 基础知识讲解

### 2.1 一句话版本

Transformer 的一层大致做两件事：

1. **注意力**：先计算当前位置与其他可见位置的匹配程度，再给它们分配权重，最后按权重组合信息。下面用Q、K、V分别表示查询、匹配依据与实际被组合的内容。
2. **前馈网络**：注意力组合好信息后，再对各个位置的表示做一次非线性变换，继续提取特征。这里“独立”指各位置分别应用这一步，不是说它们此前没有读取上下文。

先掌握这两步，再补其他部分：残差让变换前的信息也能继续传下去，归一化调整数值尺度，位置信息帮助区分顺序。把这样的处理重复多层，就得到用于后续预测的上下文表示。

### 2.2 Q/K/V 是什么

先为同一个位置准备三种用途的向量：**Q（Query）**用来查询当前需要什么信息，**K（Key）**用来与查询计算匹配分数，**V（Value）**是在匹配后实际参与加权组合的内容。这只是帮助理解分工的说法，不代表每个数都有可读的含义。

计算上，把输入表示`X`分别乘三个可训练矩阵，得到Q、K、V。若有`n`个token，每个输入向量有`d`个数，`X`就是`n × d`的矩阵。本例 n=3、d=2，取 X 为下面的三个行向量，并令三个投影矩阵都为 2×2 单位矩阵，则 Q=K=V=X，形状仍是 3×2；单位矩阵只用于看清形状，真实投影会改变数值。

```text
X  = [[1,0],[0,1],[1,1]]
Q = X W_Q
K = X W_K
V = X W_V
```

- Query：当前位置“想找什么”；
- Key：每个位置“能被怎样匹配”；
- Value：每个位置“提供什么内容”。

Q/K/V 都是训练得到的投影，不是人类规则；“注意力权重大”也不等于“这个 token 对结论最重要”。

### 2.3 缩放点积注意力

```text
scores = Q K^T / sqrt(d_k)
masked = mask(scores)          # 因果模型遮住未来位置
weights = softmax(masked, 行)
output = weights V
```

`QK^T`先得到各位置之间的匹配分数，除以`sqrt(d_k)`用来控制这些分数的尺度。随后逐行做softmax，把每一行分数变成非负、总和为1的权重，再按这些权重组合V。这里的权重回答“这次怎样组合信息”，并不是结论正确的概率。

小例子（2 维，3 个 token）：

```text
Q = [[1,0],[0,1],[1,1]]
K = 同上
V = [[10,0],[0,10],[10,10]]
```

`QK^T` 的第一行是 `[1,0,1]`：查询 1 与三个键的未缩放点积。因为 `d_k=2`，缩放后为 `[0.707,0,0.707]`。softmax 的指数是 `[2.028,1,2.028]`，除以总和 5.056，得到 `[0.401,0.198,0.401]`；乘 V 后输出 `[8.022,5.989]`。**无掩码时**第 3 个位置也能贡献。

若加因果掩码，未来位置分数变成负无穷：第 1 个位置只能看自己，权重 `[1,0,0]`，输出 `[10,0]`；第 2 个位置的可见分数是 `[0,0.707]`，权重约为 `[0.330,0.670,0]`，输出约为 `[3.302,6.698]`。第 4 节代码运行的是无掩码版本，因此第一行应与 `[0.401,0.198,0.401]` 对应，不能与因果版本混用。完整计算见 [Python 教材附录I](../python-book/附录I-AI原理与复杂任务实验.md)。

### 2.4 多头注意力

把 d 维拆成 h 个头，每个头有自己的 Q/K/V 投影，分别做注意力，再拼接、乘输出投影。若 d=4、h=2，每个头 d_k=2；两个输出各为 n×2，拼成 n×4，再乘 4×4 的 W_O 回到 n×4。头数翻倍不会自动让信息翻倍，只是提供多组可学习的匹配方式。

```text
head_i = Attention(Q_i, K_i, V_i)
MultiHead = Concat(head_1,...,head_h) W_O
```

不同头可以关注不同模式（局部、指代、语法、位置等），但“每个头有可解释的单一功能”通常是过度简化。

### 2.5 因果掩码

自回归语言模型不能看到未来 token，否则训练时就是“抄答案”。掩码把未来位置的分数设为负无穷，softmax 后权重为 0。训练和推理都必须保持这个方向。

### 2.6 位置信息

注意力本身对顺序不敏感（打乱 token 只改变对应行），所以需要位置信息：

- 正弦/余弦绝对位置编码；
- 可学习位置 embedding；
- RoPE（旋转位置编码）等相对位置方法，常见于现代开源模型。

位置编码让模型区分“A 在 B 前”与“B 在 A 前”；长上下文外推仍是研究/工程问题。

最小观察：输入两行 `X_A=[1,0]`、`X_B=[0,1]`，交换行顺序后，纯注意力的输出也会按同样顺序交换；没有位置信号时，“A 在 B 前”和“B 在 A 前”得到同一组表示。若任务是判断“先批准后付款”，这个顺序差异不能丢。

### 2.7 残差、归一化与前馈层

```text
x = x + Attention(Norm(x))     # pre-norm 常见写法
x = x + FFN(Norm(x))
FFN(x) = activation(x W1 + b1) W2 + b2
```

- 残差让梯度更容易穿过深层；
- LayerNorm 稳定每层分布；
- FFN 对每个位置独立变换，常比注意力有更多参数；
- 多层堆叠逐步形成更抽象的表示。

残差的最小代入：某位置 x=`[1,2]`，注意力子层输出增量 `[-0.5,0.5]`，相加后为 `[0.5,2.5]`，原信息仍以 `[1,2]` 的形式保留。若子层学成接近 0，残差至少让输出接近输入，深层不必每层从头重建全部信息。边界：残差不能修复错误证据，只是让信息与梯度更容易传播。

### 2.8 输出层

最后一层 hidden state 乘词表投影，得到每个 token 的 logits，再 softmax 成下一个 token 的概率。很多模型共享输入 embedding 与输出投影（权重 tying），但不是所有模型都如此。

若 hidden state 为 `[1,0]`，词表投影矩阵三行是 `[2,0]、[1,0]、[0,0]`，输出 logits 就是 `[2,1,0]`；代入 softmax 得到约 `[0.665,0.245,0.090]`。这解释了第 01/06 章的三候选分数怎样从网络末端产生；投影矩阵是训练参数，不是预设的答案表。

## 3. 原理讲解与推导

### 3.1 复杂度

序列长度 n、维度 d，先分开看“矩阵形状、计算量、存储量”：

- Q、K、V 各是 n×d；
- 单头分数矩阵 `QK^T` 的形状是 n×n，元素数是 n²；
- 计算这个分数矩阵约需 O(n²d) 次乘加；
- 如果显式保存每个头的分数矩阵，存储约 O(h·n²) 个数值（h 为头数）；实际实现可能不物化完整矩阵，或用分块/FlashAttention 降低峰值显存；
- 前馈层约 O(n·d²)；
- KV cache 每层保存历史 K/V，约 O(n·d) 个数值（乘层数、批大小和并发）。

因此不能把“分数矩阵 n² 个元素”和“计算量 O(n²d)”记成同一个公式。上下文翻倍时，n² 的元素数和计算量都约四倍，这是长上下文昂贵的主因之一；具体显存还受头数、层数、是否保存、是否分块和实现影响。

代入 n=4096、d=4096：单层单头分数矩阵有 `4096×4096=16,777,216` 个元素；计算 `QK^T` 约需 `4096×4096×4096≈68.7×10^9` 次乘加。若只按单头口径保存 32 层，元素总数为 `32×16,777,216=536,870,912`，FP16 约 1 GiB；若 32 层、32 头都显式保存，则再乘 32，为 `17,179,869,184` 个元素，FP16 约 32 GiB。n 变 8192 时，分数矩阵元素数、`QK^T` 计算量和显式分数存储量都约乘 4，但 FFN 的 O(n·d²) 只随 n 翻倍。

**缩放、掩码、softmax 不是一件事**：缩放调整分数数值尺度，掩码决定哪些位置可见（例如因果模型不能看未来），softmax 把可见分数归一化成权重。漏掉缩放会训练不稳，漏掉因果掩码会让训练“看到答案”，二者不能用同一个开关代替。

KV cache 复用历史 K/V，降低逐步生成时的重复计算，但缓存本身占显存，随上下文/并发增长。

### 3.2 注意力不是“解释”

权重表示“在这个头、这一层，查询怎样分配”，不等于因果重要性，也不等于人类可读的理由。用注意力做解释要非常谨慎，最好结合扰动/归因/评测。

### 3.3 为什么需要多层

一层注意力只能做一次组合；多层可以逐步构建指代、句法、语义和任务相关表示。深层网络的残差/归一化/初始化对训练稳定性很关键。

## 4. 示例与逐步走查

```python
# runnable
import math

def softmax(values):
    maximum = max(values)
    exps = [math.exp(value - maximum) for value in values]
    total = sum(exps)
    return [value / total for value in exps]

def attention(query, keys, values):
    scores = [sum(q * k for q, k in zip(query, key)) / math.sqrt(len(query)) for key in keys]
    weights = softmax(scores)
    output = [sum(weight * value[dim] for weight, value in zip(weights, values))
              for dim in range(len(values[0]))]
    return weights, output

q = [1.0, 0.0]
ks = [[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]]
vs = [[10.0, 0.0], [0.0, 10.0], [10.0, 10.0]]
weights, output = attention(q, ks, vs)
print("输入:", {"q": q, "keys": ks, "values": vs})
print("中间结果:", {"scores": [1 / math.sqrt(2), 0, 1 / math.sqrt(2)], "weights": weights})
print("输出:", {"weights": weights, "value": output})
assert abs(weights[0] - 0.4011120926797859) < 1e-12
assert abs(weights[2] - weights[0]) < 1e-12
assert abs(sum(weights) - 1) < 1e-12
assert abs(output[0] - 8.022241853595718) < 1e-12
assert abs(output[1] - 5.988879073202141) < 1e-12

causal_weights, causal_output = attention([0.0, 1.0], ks[:2], vs[:2])
print("因果第二行:", {"weights": causal_weights + [0.0], "value": causal_output})
assert abs(causal_output[0] - 3.302384506733431) < 1e-12
assert abs(causal_output[1] - 6.697615493266569) < 1e-12
```

逐步解释：

1. 点积算匹配分数：`[1,0,1]`；
2. 除以 `sqrt(2)` 缩放：`[0.707,0,0.707]`；
3. softmax 得到权重：`[0.401,0.198,0.401]`；
4. 权重乘 V 得到新表示：`[8.022,5.989]`；
5. 这是单头、无掩码的局部演示，不是完整 Transformer；代码随后只保留第 2 个位置的前两个键来复算因果版本，权重约为 `[0.330,0.670,0]`，加权输出约为 `[3.302,6.698]`。一般因果掩码仍应按练习一实现为“位置 i 只能看 0..i”。

## 7. 面试问答与参考回答

**问：Self-Attention 的计算过程？**

输入投影得到 Q/K/V；Q 与 K 点积、缩放、掩码、softmax 得权重；权重乘 V 得输出；多头拼接后再投影。它让每个位置按匹配关系组合上下文。

**问：为什么要除以 sqrt(d_k)？**

维度增大时点积方差变大，softmax 容易饱和/梯度变小；缩放把分数控制在更稳定范围。它是训练稳定性的工程选择。

**问：Attention 权重能当解释吗？**

不能直接当因果解释。权重是特定头/层的分配，受多层、残差、多头和后续层影响；解释要结合扰动、归因和任务评测。

**问：长上下文为什么贵？**

注意力分数矩阵随 n² 增长，KV cache 随上下文/并发占显存；计算和内存都不是线性。分块、稀疏注意力、缓存和检索是不同层的优化。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** “苹果”在“苹果手机”和“吃苹果”里意思不同，模型怎样让当前位置读到上下文？

**一条主线：**

```text
token 向量 → Q/K/V 投影 → 缩放点积+掩码+softmax → 加权 V → 残差/FFN 堆叠 → 上下文表示
```

**三个关键词：** Q/K/V、缩放点积注意力、位置——Q/K/V 给出三种角色，缩放点积注意力按匹配分配权重，位置信息补上注意力本身缺的顺序。

**最容易错：**

- 漏掉 `sqrt(d_k)` 缩放或因果掩码，让训练时“看到未来”；
- 把注意力权重当成因果解释或“最重要的 token”；
- 把分数矩阵 n² 个元素和 O(n²d) 计算量记成同一个公式；
- 以为没有位置编码也能分清“A 在 B 前”和“B 在 A 前”。

**与前后章：** 上一章给出 token 与句子向量，本章回答同一序列里这些向量怎样互相组合；下一章往前一步，问这些投影矩阵和参数最初怎样训练出来。

**学完应能：**

- 写出 Q/K/V 的形状，手算 2–3 个 token 的注意力权重；
- 说明缩放、掩码、softmax 各自解决什么问题；
- 解释多头、位置编码与残差/归一化在深层堆叠中的作用；
- 估算上下文翻倍时注意力计算量与 KV cache 的增长方向。

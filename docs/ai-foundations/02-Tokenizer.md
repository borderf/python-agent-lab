# 第02章　Tokenizer：模型看到的不是字

## 1. 学习目标与前置知识

能解释 token 与字符/单词的区别，说明 BPE 的基本合并过程、特殊 token、上下文长度和计费口径，并能估算中英文/代码的 token 数。前置：第1章。

**本章从这里开始：** 同一个“预付款”在中文里是 3 个汉字，在某个 tokenizer 里可能是 1 个 token，也可能是 2–4 个 token；同一段文字换模型，token 数、上下文占用和费用都变了。为什么不能按字数估算？

## 2. 基础知识讲解

### 2.1 token 是“词表里的编号”

模型不直接处理字符串，而是处理整数编号。tokenizer 做两件事：

1. 把文本切成 token 序列；
2. 把每个 token 映射为词表 ID。

```text
"预付款上限" -> ["预", "付款", "上限"] -> [1234, 5678, 9012]
```

切法由 tokenizer 的词表和合并规则决定，不由“一个汉字=一个 token”决定。不同模型有自己的词表，ID 不能跨模型复用。

### 2.2 BPE：从字符开始，合并高频片段

BPE（Byte Pair Encoding）的直觉：

1. 初始把文本拆成最小单位（字节或字符）；
2. 统计相邻单位对的出现频率；
3. 把最高频的一对合并成新 token；
4. 重复，直到词表达到目标大小。

玩具例子：

```text
语料：low lower lowest
初始：l o w _ l o w e r _ l o w e s t
高频对：l+o -> lo
再合并：lo+w -> low
...
```

常见词/词根会变成更长的 token，生僻词被拆成多个片段。这样词表有限，又能表示任意文本；代价是 token 数不固定。

### 2.3 字节级 BPE 与多语言

现代模型常用 **byte-level BPE**：先把 UTF-8 字节映射到可打印字符，再在字节序列上合并。好处是任何 Unicode 文本都能表示，不会出现“未登录字符”；代价是一个汉字可能占多个 token。

- 英文常见词可能 1 个 token；
- 中文常见词可能 1–2 个 token，生僻字更多；
- emoji、代码符号、空格/换行可能被单独切分；
- 数字常被拆成多位片段，精确计算不能靠模型“心算”。

### 2.4 特殊 token

对话模型还有特殊 token/标记，例如：

- 系统/用户/助手角色边界；
- 序列开始/结束；
- 工具调用开始/结束；
- 填充 token。

这些 token 参与训练和协议解析，但通常不显示给用户。自己拼接消息时要用服务规定的协议，不要手写特殊 token 字符串。

### 2.5 上下文窗口与计费

上下文窗口是 **token 数**上限，不是字符数。输入 + 输出 + 工具结果 + 历史都占额度。费用通常按输入/输出 token 分别计价，缓存命中、批处理、模型版本会影响单价。

估算时：

```text
中文：约 1–2 token/汉字（随 tokenizer 与词变化）
英文：约 0.75–1.3 token/单词
代码/符号：可能比自然语言更碎
```

这些只是量级，不是合同；真实计数用目标模型的 tokenizer。长文档要先分块/检索，而不是整篇塞入。

## 3. 原理讲解与推导

### 3.1 为什么 token 不是“语义单位”

token 是统计压缩的单位，不是词法/句法单位。一个 token 可能跨词边界，也可能只是半个词；模型通过上下文和位置来组合它们。因此“token 数”不能直接当“信息量”或“事实数量”。

### 3.2 为什么同一句话换模型 token 数会变

词表大小、合并规则、是否 byte-level、训练语料语言比例都不同。同一段中文在 A 模型可能是 100 token，在 B 模型可能是 140 token；上下文窗口和费用要按各自 tokenizer 算。

### 3.3 截断的边界

按 token 截断可能把一个词/多字节字符/工具参数切断。对话历史要保留系统约束、当前任务和证据；长文用分块 + 检索 + 引用，不要只截前 N 个 token。

## 4. 示例与逐步走查

```python
# 伪代码：不同 tokenizer 的计数口径不同
text = "预付款上限为20%。"
for tokenizer in [tokenizer_a, tokenizer_b]:
    ids = tokenizer.encode(text)
    print(tokenizer.name, len(ids), ids)
```

逐步检查：

1. 先用目标模型 tokenizer 计数，不用 `len(text)`；
2. 检查是否包含特殊 token/消息模板开销；
3. 输入 + 预期输出 + 工具结果是否超窗口；
4. 超限时选择分块/摘要/检索，不要无声截断证据；
5. 记录 tokenizer/模型版本，换版本后重算。

## 7. 面试问答与参考回答

**问：token 和字符、单词有什么区别？**

token 是模型词表里的离散单位，由 tokenizer 决定；字符是文本单位，单词是语言学单位。一个 token 可能是一个字、一个词片段或一个字节序列。

**问：BPE 的基本思想？**

从最小单位开始，反复合并最高频相邻对，扩充词表；常见片段变长，生僻内容拆成多个 token，从而用有限词表表示任意文本。

**问：为什么不能按字数估算上下文和费用？**

不同 tokenizer 的切分不同，中文、代码、符号、空格都可能变化；上下文和计费按 token 计，必须用目标模型 tokenizer 实测。

## 8. 本章小结与参考

- token 是词表单位，不等于字/词；BPE 用高频合并构造词表。
- 中文/代码/符号的 token 数差异大，换模型要重算。
- 上下文窗口和费用按 token；截断要保留约束与证据。
- 特殊 token 属于协议，不要手写拼接。

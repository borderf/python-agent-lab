## 1. 学习目标与前置知识

能区分困惑度、任务指标、检索指标和忠实性，设计固定集/留出集/对照实验，解释 LLM-as-judge 的偏差，并能用“定义→机制→例子→边界→验证”回答 AI 面试题。前置：第1–7章。

**本章从这里开始：** 新模型在演示里“明显更好”，上线后用户投诉更多。是模型变差，还是评测题泄漏、指标选错、只看平均分、没看失败类型？

## 2. 基础知识讲解

### 2.1 困惑度（perplexity）

语言模型给正确 token 的概率越高，困惑度越低：

```text
loss = -1/N * sum log P(token_i | context)
perplexity = exp(loss)
```

困惑度衡量“模型对这段文本有多惊讶”，适合比较同一 tokenizer/数据/口径下的语言建模；不能直接当业务正确率，也不能跨 tokenizer 随便比。

### 2.2 任务指标

| 任务 | 指标 | 注意 |
| --- | --- | --- |
| 分类 | accuracy/precision/recall/F1 | 类别不平衡看每类 |
| 抽取 | exact match/F1 | 字段粒度、规范化 |
| 生成 | 人工评分/LLM judge/通过率 | 评分标准、偏差 |
| 检索 | Recall@k/MRR/nDCG | 分母、相关性标注 |
| RAG 忠实性 | citation support/faithfulness | 引用是否支持结论 |
| 拒答 | 正确拒答率/误拒率 | 不能只看覆盖率 |

指标要写：分子、分母、样本来源、标注规则、置信区间。平均值会掩盖长尾/高危错误。

### 2.3 检索指标

- **Recall@k**：相关文档有多少进了前 k；
- **RR（reciprocal rank）**：单道题第一个相关结果的排名倒数；
- **MRR（mean reciprocal rank）**：多道题 RR 的平均；
- **nDCG**：考虑排序位置和相关性等级。

Recall 高但答案差，可能是排序/上下文/生成问题；Recall 低时，如果答案必须有检索依据，证据缺失会构成瓶颈，但模型仍可能凭参数知识“答对”，只是缺乏可靠依据。先固定 k 和相关性标注，再比较。

### 2.4 忠实性与引用

“引用存在”不等于“支持结论”。检查：

- 引用文本是否包含结论所需信息；
- 是否断章取义/旧版本/越权来源；
- 多个引用是否互相冲突；
- 回答是否超出引用范围。

可用人工标注、规则检查（引文子串/来源 ID）、LLM judge 辅助，但不能把 judge 当唯一真相。

### 2.5 LLM-as-judge 的偏差

- 位置偏差：偏好第一个/最后一个；
- 长度/格式偏差：更长、更 Markdown 的回答分高；
- 同源偏好：偏爱同家族模型；
- 提示敏感：评分标准措辞改变结果；
- 不稳定：同答案多次评分波动。

校准方法：人工标注小样本、交换顺序、多评委、给 rubric、报告一致性；关键决策仍需人工。

### 2.6 数据泄漏与污染

训练数据可能包含评测题/答案；公开基准可能被刷。要保留**未参与调参的留出集**，检查近重复，记录数据来源和版本；上线后用真实流量做 shadow/A-B。

### 2.7 实验设计

固定：模型版本、提示、工具、数据、参数、评测脚本；只改一个变量；同时看质量、延迟、成本、失败类型；给置信区间/样本量；预设采用/回退条件。

## 3. 原理讲解与推导

### 3.1 指标是“对任务的近似”

没有任何单一指标等于“好用”。分类看错误类型，生成看事实/忠实/有用，系统看端到端任务完成。指标要能驱动决策：低于阈值回退，某类错误上升阻止发布。

### 3.2 离线与在线

离线固定集可复现、便宜，但可能不代表真实分布；在线 A/B 真实，但成本/风险高。先离线筛，再小流量在线验证；上线保留回滚。

### 3.3 面试答题结构

```text
定义：这个东西是什么
机制：它怎样工作/为什么有效
例子：一个小数字/项目例子
边界：什么时候失效
验证：用什么指标/实验证明
```

只背定义会在“为什么”“失败怎么办”追问中暴露；准备一个自己项目的失败案例。

## 4. 示例与逐步走查

```python
# runnable
def recall_at_k(relevant, retrieved, k):
    if not relevant:
        raise ValueError("relevant 不能为空")
    hits = len(set(relevant) & set(retrieved[:k]))
    return hits / len(relevant)

def reciprocal_rank(relevant, retrieved):
    for index, item in enumerate(retrieved, 1):
        if item in relevant:
            return 1 / index
    return 0.0

def mrr(relevant_sets, retrieved_lists):
    if len(relevant_sets) != len(retrieved_lists) or not relevant_sets:
        raise ValueError("每题都要有标注与结果")
    return sum(
        reciprocal_rank(relevant, retrieved)
        for relevant, retrieved in zip(relevant_sets, retrieved_lists)
    ) / len(relevant_sets)

queries = [
    ({"d1", "d3"}, ["d1", "d2", "d3"]),  # RR = 1
    ({"d2"}, ["d1", "d2"]),              # RR = 1/2
]
assert recall_at_k({"d1", "d3"}, ["d1", "d2", "d3"], 3) == 1.0
assert reciprocal_rank({"d1", "d3"}, ["d2", "d1", "d3"]) == 0.5
assert mrr([item[0] for item in queries], [item[1] for item in queries]) == 0.75
```

逐步解释：

1. Recall 只看“有没有进前 k”，不看顺序；
2. `reciprocal_rank` 是**一道题**的 RR；
3. `mrr` 对多道题取平均；单题值不能叫 MRR；
4. 两者都不能说明生成答案是否忠实；指标要配合逐题失败分析。

仓库的 `practice/enterprise_ai/retrieval_baseline.py` 已按逐题计算 `recall_scores` / `reciprocal_ranks` 再取平均，可用它核对同一个口径。

## 7. 面试问答与参考回答

**问：困惑度和业务准确率有什么区别？**

困惑度衡量语言模型对 token 的预测概率，适合同口径语言建模比较；业务准确率要按任务/标注/用户目标定义，两者不能互相替代。

**问：Recall@k 高为什么答案还差？**

召回只说明相关文档进了前 k；排序、上下文选择、生成忠实性、引用和权限仍可能错。要分层评测，不要只看一个指标。

**问：LLM-as-judge 能替代人工吗？**

不能完全替代。它有位置/长度/同源/提示偏差和不稳定性；适合大规模初筛，关键决策要人工校准/抽检，并报告一致性。

## 8. 本章小结与参考

- 困惑度、任务指标、检索指标、忠实性各回答不同问题。
- 指标要写分母、样本、标注、置信区间；平均分会掩盖高危错误。
- Judge 有偏差，需校准/交换/多评委/人工抽检。
- 先离线固定集，再小流量在线；预设采用/回退条件。

## 1. 学习目标与前置知识

能为实际任务选指标，用固定问题比较前后版本，并保留一批不参与调参的题检查是否真的改善。会检查模型评分器的偏差，再把项目证据组织成有定义、原理、例子和限制的面试回答。前置：第1–7章。

**本章从这里开始：** 新模型在演示里“明显更好”，上线后用户投诉更多。是模型变差，还是评测题泄漏、指标选错、只看平均分、没看失败类型？

## 2. 基础知识讲解

### 2.1 困惑度（perplexity）

先把一段已知文本交给模型，看它给每个真实的下一个token分配了多少概率。如果它经常把真实token排得更可能，语言建模损失通常更低。困惑度（Perplexity）是从这种损失换算出的指标，公式如下；它检查的是文本预测，不是直接给业务答案打分：

```text
loss = -1/N * Σ_i log P(token_i | context)
perplexity = exp(loss)
```

三个真实 token 的概率为 0.9、0.5、0.1 时，`loss=-(ln0.9+ln0.5+ln0.1)/3≈1.034`，困惑度 `exp(1.034)≈2.81`。预期困惑度不小于 1；它的直觉是“平均每个位置约在 2.81 个候选间犹豫”，不是“答对 1/2.81”。

困惑度衡量“模型对这段文本有多惊讶”，适合比较同一 tokenizer/数据/口径下的语言建模；不能直接当业务正确率，也不能跨 tokenizer 随便比。

### 2.2 任务指标

| 任务 | 指标 | 注意 |
| --- | --- | --- |
| 分类 | accuracy/precision/recall/F1 | 类别不平衡看每类 |
| 抽取 | exact match/F1 | 字段粒度、规范化 |
| 生成 | 人工评分/LLM judge/通过率 | 评分标准、偏差 |
| 检索 | Recall@k/MRR/nDCG | 分母、相关性标注 |
| RAG 忠实性 | citation support/faithfulness | 引用是否支持结论 |
| 拒答 | 正确拒答率/误拒率 | 不能只看覆盖率 |

指标要写：分子、分母、样本来源、标注规则、置信区间。以 100 条分类样本为例：真实正类 10 条，模型预测正类 20 条，其中 8 条正确，则 TP=8、FP=12、FN=2、TN=78。准确率 `(8+78)/100=86%`，精确率 `8/20=40%`，召回率 `8/10=80%`，F1 `2×0.4×0.8/(0.4+0.8)≈0.533`。全部预测为负也能得到 90% 准确率，却没有任何正类召回，所以类别不平衡不能只看 accuracy。平均值会掩盖长尾/高危错误。

### 2.3 检索指标

- **Recall@k**：相关文档有多少进了前 k；
- **RR（reciprocal rank）**：单道题第一个相关结果的排名倒数；
- **MRR（mean reciprocal rank）**：多道题 RR 的平均；
- **nDCG**：考虑排序位置和相关性等级。

Recall 高但答案差，可能是排序/上下文/生成问题；Recall 低时，如果答案必须有检索依据，证据缺失会构成瓶颈，但模型仍可能凭参数知识“答对”，只是缺乏可靠依据。先固定 k 和相关性标注，再比较。

把公式写成数字：某题相关文档为 `{d1,d3}`，前 3 个召回为 `[d1,d2,d3]`，Recall@3=`2/2=1`；前 1 个只召回 d1，Recall@1=`1/2=0.5`。若列表是 `[d2,d1,d3]`，第一个相关结果在第 2 位，单题 RR=`1/2=0.5`。两题 RR 分别为 1 和 0.5，MRR=`(1+0.5)/2=0.75`。边界：没有相关标注时 Recall 的分母为 0，应报告“不适用/待复核”，不能硬算成 1。

### 2.4 忠实性与引用

“引用存在”不等于“支持结论”。检查：

- 引用文本是否包含结论所需信息；
- 是否断章取义/旧版本/越权来源；
- 多个引用是否互相冲突；
- 回答是否超出引用范围。

可用人工标注、规则检查（引文子串/来源 ID）、LLM judge 辅助，但不能把 judge 当唯一真相。

10 条回答中 8 条结论被引用支持，引用支持率为 `8/10=80%`；其中 1 条虽引用存在但使用旧版，仍应判失败。若把“citation 字段非空”当分子，会得到虚高的 100%。因此分子必须定义为“通过来源、版本和 claim 支持的条数”，分母是全部应引用回答，规则在评测前冻结。

### 2.5 LLM-as-judge 的偏差

- 位置偏差：偏好第一个/最后一个；
- 长度/格式偏差：更长、更 Markdown 的回答分高；
- 同源偏好：偏爱同家族模型；
- 提示敏感：评分标准措辞改变结果；
- 不稳定：同答案多次评分波动。

先请人给一小批题写清评分标准，再比较模型评委的结果是否一致。还可以交换两个答案的呈现顺序、比较多个评委，并统计与人工判断的差异。例如 25 题中评委与人工一致 18 题，一致率 `18/25=72%`；交换 A/B 后 6 题评分改变，就说明位置或稳定性需要进一步排查。这里的rubric就是具体评分规则，例如“事实正确、引用支持、没有遗漏关键限制”分别怎样判；关键决定仍需人工核对。

### 2.6 数据泄漏与污染

训练数据可能包含评测题/答案；公开基准可能被刷。要保留**未参与调参的留出集**，检查近重复，记录数据来源和版本；上线后用真实流量做 shadow/A/B。

100 道题可分成 60 道开发、20 道验证、20 道留出，三者 ID 不重叠；开发集改提示，验证集选方案，留出集只在方案冻结后跑一次。若同一题换个标点又留在两边，近重复泄漏仍会发生。边界：留出集跑过多次后也会间接参与选择，应限制查看次数并版本化。

### 2.7 实验设计

固定：模型版本、提示、工具、数据、参数、评测脚本；只改一个变量；同时看质量、延迟、成本、失败类型；给置信区间/样本量；预设采用/回退条件。

例如升级检索器，固定问题集、embedding、top-k=5、生成模型和提示，只换召回实现。采用条件可写为：Recall@3 不低于 0.80、引用支持率不低于 0.90、P95 延迟不增加 10%、越权召回为 0；任一高危条件失败就回退。样本仅 20 题时，0.80 到 0.85 可能只是 1 题差异，应同时报告题数和逐题结果。

## 3. 原理讲解与推导

### 3.1 指标是“对任务的近似”

没有任何单一指标等于“好用”。分类看错误类型，生成看事实/忠实/有用，系统看端到端任务完成。指标要能驱动决策：低于阈值回退，某类错误上升阻止发布。

### 3.2 离线与在线

离线固定集可复现、便宜，但可能不代表真实分布；在线 A/B 真实，但成本/风险高。先离线筛，再小流量在线验证；上线保留回滚。

### 3.3 面试答题结构

```text
定义：这个东西是什么
机制：它怎样工作/为什么有效
例子：一个小数字/项目例子
边界：什么时候失效
验证：用什么指标/实验证明
```

只背定义会在“为什么”“失败怎么办”追问中暴露；准备一个自己项目的失败案例。

## 4. 示例与逐步走查

```python
# runnable
import math

def recall_at_k(relevant, retrieved, k):
    if not relevant:
        raise ValueError("relevant 不能为空")
    hits = len(set(relevant) & set(retrieved[:k]))
    return hits / len(relevant)

def reciprocal_rank(relevant, retrieved):
    for index, item in enumerate(retrieved, 1):
        if item in relevant:
            return 1 / index
    return 0.0

def mrr(relevant_sets, retrieved_lists):
    if len(relevant_sets) != len(retrieved_lists) or not relevant_sets:
        raise ValueError("每题都要有标注与结果")
    return sum(
        reciprocal_rank(relevant, retrieved)
        for relevant, retrieved in zip(relevant_sets, retrieved_lists)
    ) / len(relevant_sets)

queries = [
    ({"d1", "d3"}, ["d1", "d2", "d3"]),  # RR = 1
    ({"d2"}, ["d1", "d2"]),              # RR = 1/2
]
rr_scores = [reciprocal_rank(relevant, retrieved) for relevant, retrieved in queries]
mean_rr = mrr([item[0] for item in queries], [item[1] for item in queries])
token_probabilities = [0.9, 0.5, 0.1]
perplexity = math.exp(sum(-math.log(p) for p in token_probabilities) / len(token_probabilities))
evidence = "预付款上限为20%。"
answers = ["20%", "30%"]
support = [answer in evidence for answer in answers]
citation_support_rate = sum(support) / len(support)
reordered_retrieved = ["d1", "d3", "d2"]
reordered_rr = reciprocal_rank(queries[1][0], reordered_retrieved)
reordered_mrr = mrr([queries[0][0], queries[1][0]], [queries[0][1], reordered_retrieved])
print("输入:", {"queries": [{"relevant": sorted(relevant), "retrieved": retrieved}
                             for relevant, retrieved in queries],
                "token_probabilities": token_probabilities, "evidence": evidence, "answers": answers})
print("中间结果:", {"rr_scores": rr_scores, "mean_rr": mean_rr, "support": support,
                    "d2_to_third": {"retrieved": reordered_retrieved, "rr": reordered_rr,
                                    "MRR": reordered_mrr}})
print("输出:", {"recall@3": recall_at_k({"d1", "d3"}, queries[0][1], 3), "MRR": mean_rr,
                "perplexity": perplexity, "accuracy_if_all_negative": 0.90})
print("反例:", "Recall@3=1 且答案30%，证据却写20%：召回高不等于回答正确")
print("指标:", {"recall@3": 1.0, "MRR": mean_rr, "citation_support_rate": citation_support_rate,
                "d2_to_third": {"recall@3": recall_at_k({"d2"}, reordered_retrieved, 3),
                                "RR": reordered_rr, "MRR": reordered_mrr}})
assert recall_at_k({"d1", "d3"}, ["d1", "d2", "d3"], 3) == 1.0
assert reciprocal_rank({"d1", "d3"}, ["d2", "d1", "d3"]) == 0.5
assert mrr([item[0] for item in queries], [item[1] for item in queries]) == 0.75
assert recall_at_k({"d2"}, reordered_retrieved, 3) == 1.0
assert reordered_rr == 1 / 3 and abs(reordered_mrr - 2 / 3) < 1e-12
assert abs(perplexity - 2.8114422176724974) < 1e-12
assert support == [True, False] and citation_support_rate == 0.5
```

逐步解释：

1. Recall 只看“有没有进前 k”，不看顺序；
2. `reciprocal_rank` 是**一道题**的 RR；
3. `mrr` 对多道题取平均；单题值不能叫 MRR；
4. 两者都不能说明生成答案是否忠实；指标要配合逐题失败分析。
5. 把第二题的 d2 从第2降到第3，Recall@3仍为1，但该题RR变为1/3，两题MRR由0.75变为2/3；若仍答30%，引用支持检查为False。

仓库的 `practice/enterprise_ai/retrieval_baseline.py` 已按逐题计算 `recall_scores` / `reciprocal_ranks` 再取平均，可用它核对同一个口径。

## 5. 练习

### 练习一：跟写

给 10 个问题标注相关文档，计算 Recall@3 与 MRR；至少找两个“Recall 高但答案差”的例子。完成标准：逐题记录相关集合、前 k ID、Recall 与 RR，再平均；两个失败例子分别指向排序/上下文和生成/忠实性。

### 练习二：改造

为 LLM judge 写一个 rubric：事实性、引用支持、完整性、拒绝不当；交换 A/B 顺序，比较评分是否稳定。完成标准：每维有 0/1/2 分定义和反例；报告顺序翻转前后改变评分的题数及人工一致率。

### 练习三：独立

设计一次模型升级实验：固定集、留出集、在线 shadow、采用/回退条件；列出质量、延迟、成本、失败类型四类证据。完成标准：只改模型版本，其他条件固定；采用条件同时包含质量阈值与高危错误不增加，回退条件在实验前写好。

## 6. 验收与自测

**行为验收：** 能算 Recall@k/MRR；能解释困惑度边界；能设计固定集/留出集；能说出 judge 的至少三种偏差。

**原理验收：** 能说明指标的分母/偏差；能区分离线/在线；能用五段式回答一个 AI 面试题。

**操作：** 运行两题检索指标，再把第二题相关项 d2 从第2降到第3位（`["d1","d3","d2"]`），并把该题答案改成30%。**预期：** 原 MRR 0.75；d2 降序后 Recall@3 仍为1、RR 变为1/3、两题 MRR 为2/3；答30%时引用支持为False。**证据：** 保留相关集合、排序列表、RR 分项、困惑度和逐题失败；没有分母与标注规则的指标数字不验收。

## 7. 面试问答与参考回答

**问：困惑度和业务准确率有什么区别？**

困惑度衡量语言模型对 token 的预测概率，适合同口径语言建模比较；业务准确率要按任务/标注/用户目标定义，两者不能互相替代。

**问：Recall@k 高为什么答案还差？**

召回只说明相关文档进了前 k；排序、上下文选择、生成忠实性、引用和权限仍可能错。要分层评测，不要只看一个指标。

**问：LLM-as-judge 能替代人工吗？**

不能完全替代。它有位置/长度/同源/提示偏差和不稳定性；适合大规模初筛，关键决策要人工校准/抽检，并报告一致性。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** 新模型演示里“明显更好”、上线后投诉更多，怎样用指标证明它到底变没变好？

**一条主线：**

```text
业务问题 → 选指标（困惑度/任务/检索/忠实性）→ 固定集+留出集 → 对照实验 → 采用或回退
```

**三个关键词：** 指标口径、留出集、LLM-as-judge——口径决定数字的含义，留出集防泄漏，judge 只适合初筛、必须校准。

**最容易错：**

- 拿困惑度或单一平均分当业务正确率，忽略高危错误和长尾；
- 用调参用过的题当测试集，或忽略训练数据污染；
- 把 LLM-as-judge 当唯一真相，不交换顺序、不给 rubric、不看一致性；
- 只跑离线固定集就上线，没有小流量在线验证和回退条件。

**与前后章：** 上一章给出 RAG 的分层修法，本章回答“修完怎样证明有效”；下一章把八章机制和指标压进同一个订单问答案例走一遍。

**学完应能：**

- 为分类/抽取/生成/检索/RAG 各选一个指标，写清分子分母；
- 手算 Recall@k、单题 RR 与多题 MRR，说明三者差别；
- 说出 judge 至少三种偏差和对应的校准手段；
- 设计一次模型升级实验：固定集、留出集、在线 shadow、采用/回退条件。

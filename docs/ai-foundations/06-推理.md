## 2. 基础知识讲解

### 2.1 从 logits 到 token

模型最后一层输出词表大小的 logits 向量。softmax 后得到概率：

```text
p_i = exp(z_i) / sum_j exp(z_j)
```

实际服务常先做温度缩放、top-k/top-p 截断，再采样。logits 不是概率，温度会改变分布形状。

### 2.2 解码策略

| 策略 | 做什么 | 特点 |
| --- | --- | --- |
| greedy | 每步选最高概率 | 稳定、易重复、缺少多样性 |
| beam search | 保留多个候选序列 | 质量可能更好，成本高，开放对话不一定合适 |
| temperature | 缩放 logits | <1 更尖锐，>1 更平坦；不改变事实 |
| top-k | 只保留前 k 个候选 | 限制长尾，k 难统一 |
| top-p | 保留累计概率 ≥p 的最小集合 | 动态候选数，常用 |
| repetition penalty | 惩罚重复 token | 缓解复读，可能伤害必要重复 |

`temperature=0` 通常近似贪心，但不保证跨版本/硬件完全复现。

### 2.3 小数字例子

候选概率 `0.6/0.3/0.1`：

- 贪心总选 0.6；
- 按分布采样，约 60% 选第一个；
- 温度 0.5 让 0.6 更占优；
- top-k=1 等价贪心；top-p=0.9 会保留 0.6+0.3，去掉 0.1。

### 2.4 prefill 与 decode

一次生成分两段：

- **prefill**：并行处理输入 prompt，建立 KV cache；首 token 延迟（TTFT）主要受它影响；
- **decode**：逐步生成，每步只处理新 token，复用历史 K/V；每输出 token 的时间（TPOT）受它影响。

```text
prefill: 输入 n 个 token -> 并行计算 -> 首 token
decode: 新 token + 历史 KV -> 下一个 token -> ...
```

输入越长，prefill 越贵；输出越长，decode 越久。流式界面看到的“逐字出现”就是 decode 过程。

### 2.5 KV cache

自注意力需要历史 K/V；每生成一个 token，把新 K/V 追加到缓存，避免重复计算旧 token。缓存大小约随 `层数 × 头数 × 维度 × 上下文长度 × 并发` 增长，是长上下文/高并发的主要显存成本之一。

缓存不是业务记忆：请求结束通常释放；多轮对话要重新发送/保存必要历史，不能假设服务端替你永久记住。

### 2.6 量化与批处理

- **权重量化**：用更低比特存权重，降显存/带宽；
- **激活/KV 量化**：进一步省资源，但更易影响精度；
- **批处理**：把多请求一起算，提高吞吐，但可能增加单请求延迟/显存；
- **投机解码**：小模型草稿 + 大模型验证，可能加速，但依赖实现/负载。

量化效果取决于方法、硬件、模型和任务；不能只看“4bit”标签承诺质量。

## 3. 原理讲解与推导

### 3.1 为什么首 token 慢、后续快

prefill 要处理整段输入并建立缓存；decode 每步只处理一个 token（加缓存），单步计算小，但串行、受内存带宽和采样开销影响。长输入 TTFT 高，长输出总时长高。

### 3.2 为什么温度不修复事实

温度只改变分布形状/采样随机性；它不改变客观事实，也不保证提升事实性，但会改变本次生成的答案，可能让原本“碰巧答对”的采样变成答错，反之亦然。如果模型对错误答案给高概率，降低温度只会更稳定地重复错误；事实要靠检索、工具、校验和评测。

### 3.3 吞吐 vs 延迟

批处理提高 GPU 利用率/吞吐，但请求要排队，单请求延迟可能变差。SLO 要分别定义 TTFT、TPOT、P95/P99，而不是只看平均吞吐。

## 4. 示例与逐步走查

```python
# runnable
import math

def softmax_with_temperature(logits, temperature=1.0):
    if temperature <= 0:
        raise ValueError("temperature 必须大于 0")
    scaled = [value / temperature for value in logits]
    maximum = max(scaled)
    exps = [math.exp(value - maximum) for value in scaled]
    total = sum(exps)
    return [value / total for value in exps]

print(softmax_with_temperature([2.0, 1.0, 0.0], 0.5))
print(softmax_with_temperature([2.0, 1.0, 0.0], 2.0))
```

逐步解释：

1. logits 先除温度；
2. 减最大值只为数值稳定；
3. exp/归一化得概率；
4. 温度低→分布尖；温度高→分布平；
5. 采样还要加 top-k/top-p/随机数。

## 7. 面试问答与参考回答

**问：temperature、top-k、top-p 的区别？**

温度缩放整个分布；top-k 固定保留前 k 个；top-p 按累计概率保留动态集合。它们都改变采样候选/形状，不改变模型事实能力。

**问：prefill 和 decode 有什么区别？**

prefill 并行处理输入、建立 KV cache，决定首 token 延迟；decode 逐步生成、复用缓存，决定每 token 时间。两者成本随输入/输出长度变化。

**问：KV cache 为什么省时间又费显存？**

它复用历史 K/V，避免每步重算旧 token；但缓存随层数、上下文、并发增长，长上下文/高并发会吃显存。

## 8. 本章小结与参考

- logits→softmax→温度/截断→采样；温度不修复事实。
- prefill 管首 token，decode 管逐 token；KV cache 复用历史但占显存。
- 量化/批处理有权衡；指标要分 TTFT、TPOT、P95。
- 可复现要固定模型/参数/环境/输入。

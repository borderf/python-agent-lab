# 第05章　训练：从下一个 token 到人类偏好

[上一章](04-Transformer.md) · [全书目录](教材目录.md) · [下一章](06-推理.md)

## 1. 学习目标与前置知识

能解释训练怎样根据预测错误调整参数，再区分预训练、示例式微调（SFT）、偏好训练和LoRA分别改什么。面对实际问题时，先判断缺的是资料、回答方式还是能力，再选择提示、检索、微调或换模型。前置：第1–4章。

**本章从这里开始：** 模型“知道”很多知识，却不会按公司格式回答；或者回答风格不合适。应该再训练吗？训练改变的是参数，参数不是知识库；先分清“缺事实、缺行为、缺能力”。

## 2. 基础知识讲解

### 2.1 预训练：把下一 token 预测做到极致

先给模型一段已有文本，并用训练文本中真实接下来的token作为本次目标。模型会给各个候选token分配概率：给真实目标的概率越低，这次预测应受的惩罚就越大。训练用一个数表示这种惩罚，叫**损失**；这里采用目标token概率的负对数：

```text
loss = -log P(正确 token | 上下文)
```

正确 token 的概率为 0.8 时，`loss=-ln(0.8)≈0.223`；概率降到 0.2 时，`loss=-ln(0.2)≈1.609`。**预期：概率越低，损失越大。** 若三个位置的概率分别是 0.9、0.5、0.1，平均损失为 `(0.105+0.693+2.303)/3≈1.034`。平均 Loss 低仍可能藏着 0.1 这种困难样本，所以要继续看逐题错误。

一段文本中的多个位置都可以这样预测，再把损失汇总或取平均。反向传播计算损失对各参数的变化率，称为梯度；优化器据此调整参数。反复处理大量训练样本后，模型逐渐学到更有助于预测的语言模式与关联。

关键点：

- 训练目标是预测，不是“保证事实正确”；
- 数据规模、质量、去重、配比影响能力；
- 训练损失低不等于业务任务好；
- 训练数据有时间截止，知识会过时。

### 2.2 梯度与优化器直觉

先把梯度理解为当前参数附近的局部变化信息：参数稍微改变，损失倾向怎样变化。优化器利用它安排下一步更新。实际还要设定每步调整多大（学习率）、每次用多少样本（批大小）等；Adam/AdamW、warmup和权重衰减是进一步控制更新过程的工具，下面直接展开。

不需要手推反向传播，但要能解释：

- 梯度爆炸/消失会让训练不稳；
- 残差、归一化、合理初始化有帮助；
- 小数据微调容易过拟合；
- 训练/验证/测试要分开，不能用评测题训练。

标量直觉：`L(w)=(w-1)²` 在 w=3 时梯度为 4；学习率 0.1 使 w 更新为 2.6，损失从 4 降到 2.56。学习率 2 却使 w=-5、损失升到 36。梯度的符号告诉你局部往哪边走，学习率决定走多远。

**SGD只看当前梯度；Adam多看历史梯度。** Adam为每个参数维护一阶矩 `m`（梯度的指数移动平均）和二阶矩 `v`（梯度平方的指数移动平均），默认衰减率常为0.9与0.999。更新时先修正小样本起步造成的偏差，再计算方向与步长，常见形式是：

```text
m_t = β1*m_(t-1) + (1-β1)*g_t
v_t = β2*v_(t-1) + (1-β2)*g_t²
m_hat = m_t / (1-β1^t)，v_hat = v_t / (1-β2^t)
w_t = w_(t-1) - η*m_hat / (sqrt(v_hat) + ε)
```

`m`平滑方向，`v`按梯度尺度缩放步长，`ε`防止分母为0。**AdamW在Adam的自适应更新之外，对参数直接做解耦权重衰减**：`w ← w*(1-η*λ)-η*...`。它约束参数幅度，不等于“把大梯度裁小”；梯度裁剪是另一项安全阀。

**warmup**让学习率从较小值在若干步内升到目标值，之后可再衰减。它常用于大批次训练的早期，避免第一步更新过猛；不是所有任务都必须用。看一个从 w=3 开始的极简 AdamW 两步手算：梯度按上面的 `L(w)=(w-1)²` 实时计算，省略 Adam 的偏差修正，只用于看清机制。

```python
w, m, v, eta, decay = 3.0, 0.0, 0.0, 0.1, 0.01
rows = []
for step in range(1, 3):
    gradient = 2 * (w - 1)
    m = 0.9 * m + 0.1 * gradient
    v = 0.999 * v + 0.001 * gradient ** 2
    w = w * (1 - eta * decay) - eta * m / (v ** 0.5 + 1e-8)
    rows.append((step, round(gradient, 4), round(m, 4), round(v, 6), round(w, 4), round((w - 1) ** 2, 4)))
print(rows)
```

输出为 `[(1, 4.0, 0.4, 0.016, 2.6808, 2.825), (2, 3.3615, 0.6962, 0.027284, 2.2566, 1.5791)]`。每行依次是步数、当前梯度、`m`、`v`、`w`、损失。第一步方向由当前梯度主导，损失从4降到约2.825；第二步梯度随 w 靠近1而降到约3.3615，二阶矩变大后步长继续被自适应缩放，损失降到约1.579。若采用warmup，可把这两步的学习率设为0.05、0.1；若关闭衰减，只需把`decay`设为0。真实模型参数众多，还需 AdamW、裁剪和 warmup 控制更新。

### 2.3 缩放定律与数据质量

经验上，模型能力随参数量、数据量、计算量增加而提升，但有边际收益，且受数据质量/重复/配比影响。缩放定律是趋势/预算工具，不是“参数量翻倍，业务指标必翻倍”。

数据工作常比模型结构更影响结果：去重、清洗、授权、标注一致性、难例覆盖、防泄漏。

### 2.4 SFT：教“怎样回答任务”

监督微调（SFT）用“输入→理想输出”的示例继续训练：

```text
用户：把这段制度总结成三条
助手：1... 2... 3...
```

训练损失通常只计算助手回答 token：系统、用户和提示部分用标签掩码置为忽略，否则模型会被训练去复述输入。具体掩码由训练框架和对话模板决定，不能只凭“把整段文本喂进去”假设损失口径正确。

它主要塑造行为/格式/任务模式，也能注入少量领域知识，但：

- 示例质量比数量重要；
- 覆盖边界/拒答/不确定；
- 训练题不能和评测题重叠；
- 事实更新仍优先检索。

最小数据设计：60 条正常格式、20 条字段缺失、10 条应拒答、10 条错误格式纠正，共 100 条；按 80/10/10 分训练/验证/测试并检查 ID 不重叠。验证集看 JSON schema 通过率，测试集看事实与拒答，不能只用“训练损失下降”证明格式学会。

### 2.5 RLHF 与 DPO

人类偏好训练让模型更偏向“人类更喜欢的回答”：

- **RLHF**：训练奖励模型，再用强化学习（如 PPO）优化策略；流程复杂，需防奖励黑客。
- **DPO**：直接用偏好对（chosen/rejected）优化，不需要单独奖励模型和 RL 循环；更简单，但仍需高质量偏好数据。

偏好训练优化的是“被偏好的概率”，不自动保证事实正确；偏好标注者的偏差会进入模型。

最小偏好对：同一问题下 chosen 是“依据 B，上限20%”，rejected 是“上限30%”。DPO 直接利用这对样本提高 chosen 相对 rejected 的概率；RLHF 还要先学奖励，再用策略优化。两者都不会自动核对 B 是否有效，所以偏好集也必须包含事实错误、旧版和拒答边界。

### 2.6 LoRA：低秩更新

全量微调更新所有参数。LoRA 冻结原权重 `W`，只训练两个小矩阵 `A`、`B`，用 `ΔW = B A` 近似更新：

```text
W' = W + (alpha/r) B A
```

若 W 是 `d_out × d_in`，A 是 `r × d_in`，B 是 `d_out × r`，r 远小于 d 时，可训练参数显著减少。以 4096×4096、r=8 为例，全量为 16,777,216，LoRA 只训练 65,536，比例 `65536/16777216≈0.0039=0.39%`。但：

- 前向仍要加载原模型；
- 激活/优化器状态仍占显存；
- 低秩限制可能不适合所有任务；
- 量化 + LoRA 的组合要明确量化哪部分。

### 2.7 灾难性遗忘与数据配比

只在窄领域微调，可能让通用能力退化。常见做法是混入通用数据、保留基线评测、早停、低学习率、适配器；但不存在“绝不遗忘”的保证。

最小观察：微调前领域格式通过率 70%、通用指令通过率 90%；微调后分别 92%、82%，说明领域提升 22 个百分点，通用下降 8 个百分点。是否采用要看业务阈值，不能只报领域分数。可尝试混入通用数据或降低学习率，再用同一留出集比较，避免“修了格式却坏了拒答”。

## 3. 原理讲解与推导

### 3.1 训练目标与业务目标不是同一个

下一 token 损失优化“像训练数据一样预测”，业务要的是“事实正确、引用可靠、权限合规、延迟可接受”。所以训练后必须用独立任务评测；损失下降不能替代业务验收。

### 3.2 预训练/SFT/偏好训练的分工

| 阶段 | 数据 | 主要改变 |
| --- | --- | --- |
| 预训练 | 大规模无标注文本 | 语言/世界知识/基础能力 |
| SFT | 任务示例 | 指令遵循、格式、行为 |
| 偏好训练 | chosen/rejected 对 | 风格、有用性、安全性偏好 |
| LoRA | 小规模任务数据 | 低成本适配 |

### 3.3 什么时候不该微调

- 知识每天变：优先 RAG；
- 只是格式/角色：提示 + 结构化输出可能够；
- 数据不足/授权不清：先补数据治理；
- 基础能力不足：微调小模型通常补不上，换更大模型/工具更直接；
- 需要可追溯：参数记忆不可引用，RAG 更合适。

## 4. 示例与逐步走查

### 4.1 三个位置的平均损失

```python
# runnable
from math import log

def cross_entropy(probability_of_target):
    if not 0 < probability_of_target <= 1:
        raise ValueError("概率必须在 (0,1]")
    return -log(probability_of_target)

probabilities = [0.9, 0.5, 0.1]
losses = [cross_entropy(p) for p in probabilities]
average_loss = sum(losses) / len(losses)
print("输入:", probabilities)
print("中间结果:", {"losses": losses})
print("输出:", {"average_loss": average_loss, "p=0.8": cross_entropy(0.8), "p=0.2": cross_entropy(0.2)})
assert cross_entropy(0.8) < cross_entropy(0.2)
assert abs(average_loss - 1.033697596403939) < 1e-12
```

逐步解释：

1. 模型输出词表分布；
2. 取正确 token 的概率；
3. 负对数得到损失；三个位置约为 `0.105/0.693/2.303`；
4. 反向传播求梯度；
5. 优化器更新参数；
6. 在验证集看是否真的变好。

### 4.2 从损失走到一次参数更新

用一个标量玩具说明优化器，不把它当作神经网络反向传播。设 `L(w)=(w-1)²`，`w=3` 时损失为 4，梯度 `2(w-1)=4`；学习率 0.1 时更新 `w←3-0.1×4=2.6`，新损失 `(2.6-1)²=2.56`。预期损失下降。若学习率写成 2，新 w 变成 -5，损失反而升到 36，这说明“有梯度”不保证乱设学习率也能稳定训练。

LoRA 也可用形状核对：4096×4096 的 W 有 16,777,216 个参数；秩 r=8 时 A 是 8×4096、B 是 4096×8，只训练 `8×4096+4096×8=65,536` 个参数，约为全量的 0.39%。它省的是可训练参数，不等于总显存也降到 0.39%。

## 5. 练习

### 练习一：跟写

给定三个样本的正确 token 概率 0.9、0.5、0.1，算平均负对数损失；说明为什么平均损失低不代表每个样本都好。完成标准：逐项为 0.105/0.693/2.303，平均约 1.034，并指出 0.1 的样本单点损失最高。

### 练习二：改造

为一个“固定 JSON 格式”的需求设计 SFT 数据：正例、边界、拒答、坏格式；说明为什么不能只用正常样本。完成标准：四类各至少 2 条，ID 与验证/测试集不重叠；坏格式要转成符合 schema 的输出或明确拒答，不能只靠自然语言要求。

### 练习三：独立

比较“RAG / 提示 / SFT / LoRA”四种方案：知识更新频率、可追溯性、数据需求、成本、失败模式各写一行，给出你的选型。完成标准：至少用“频率更新的知识”和“固定输出格式”两个需求分别选型，并给可验证的成功/回退指标。

## 6. 验收与自测

**行为验收：** 能解释损失/梯度/优化器的作用；能区分预训练/SFT/偏好训练；能说出 LoRA 省什么、不省什么。

**原理验收：** 能说明训练目标与业务目标的差异；能判断一个需求不该微调的理由；能解释灾难性遗忘和数据泄漏。

**操作：** 计算 0.9/0.5/0.1 的平均损失，并在标量损失上以学习率 0.1 更新一次。**预期：** 平均损失约 1.034，w 从 3 变 2.6、损失从 4 降为 2.56。**证据：** 逐位置损失、梯度、更新前后参数与独立验证指标都要保留；训练损失单独下降不算业务验收。

## 7. 面试问答与参考回答

**问：预训练和微调的区别？**

预训练用大规模文本学习下一 token 预测，形成基础能力；微调用任务/偏好数据继续训练，改变行为/格式/部分知识。微调不是知识库更新的默认方案。

**问：LoRA 为什么省参数？**

它冻结原权重，只训练低秩矩阵 A/B 表示增量，r 远小于维度时可训练参数大幅减少；但原模型、激活和优化器状态仍占资源，效果需评测。

**问：RLHF 和 DPO 的区别？**

RLHF 通常训练奖励模型再用 RL 优化策略；DPO 直接用偏好对优化，流程更简单。两者都依赖偏好数据质量，都不自动保证事实正确。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** 模型“知道”很多却不会按公司格式回答，该改提示、改检索，还是真的去训练？

**一条主线：**

```text
大规模文本 → 下一 token 损失/梯度更新 → 预训练 → SFT/偏好训练 → 参数与行为改变
```

**三个关键词：** 损失、三阶段、LoRA——损失定义“往哪调”，三阶段决定“调什么”，LoRA 决定“用多少参数去调”。

**最容易错：**

- 把训练损失下降当成业务指标提升，跳过独立验证/测试集；
- 知识每天在变却先微调，而不是先做 RAG 和权限过滤；
- 以为 LoRA 省可训练参数就等于省显存、省时间、效果等同；
- 拿评测题当训练数据，或忽略窄领域微调的灾难性遗忘。

**与前后章：** 上一章讲清 Transformer 的结构与参数，本章回答这些参数怎样被训练出来；下一章转向反面——参数固定后，一次生成怎样采样、怎样省显存。

**学完应能：**

- 用负对数损失说明一个 token 概率变化对训练意味着什么；
- 区分预训练/SFT/偏好训练各改什么，说出 DPO 与 RLHF 的流程差别；
- 为一个需求在提示/RAG/SFT/LoRA 之间给出选型理由；
- 说明 LoRA 省什么不省什么，以及灾难性遗忘的常见缓解手段。

# 第05章　训练：从下一个 token 到人类偏好

[上一章](04-Transformer.md) · [全书目录](教材目录.md) · [下一章](06-推理.md)

## 1. 学习目标与前置知识

能解释预训练、损失、梯度、SFT、RLHF/DPO、LoRA 分别在改什么，能判断一个需求该用提示、RAG、微调还是换模型。前置：第1–4章。

**本章从这里开始：** 模型“知道”很多知识，却不会按公司格式回答；或者回答风格不合适。应该再训练吗？训练改变的是参数，参数不是知识库；先分清“缺事实、缺行为、缺能力”。

## 2. 基础知识讲解

### 2.1 预训练：把下一 token 预测做到极致

预训练数据是大量文本。模型看到上下文，输出下一个 token 的分布，损失是正确 token 的负对数概率：

```text
loss = -log P(正确 token | 上下文)
```

对整段文本的 token 求平均，反向传播算梯度，优化器更新参数。重复数万亿 token，模型学会语法、事实关联、推理模式和世界统计规律。

关键点：

- 训练目标是预测，不是“保证事实正确”；
- 数据规模、质量、去重、配比影响能力；
- 训练损失低不等于业务任务好；
- 训练数据有时间截止，知识会过时。

### 2.2 梯度与优化器直觉

损失对参数的导数告诉优化器“往哪个方向调会让损失小一点”。实际用 Adam/AdamW 等自适应优化器，按小批量数据迭代。学习率、批大小、 warmup、权重衰减都影响稳定性。

不需要手推反向传播，但要能解释：

- 梯度爆炸/消失会让训练不稳；
- 残差、归一化、合理初始化有帮助；
- 小数据微调容易过拟合；
- 训练/验证/测试要分开，不能用评测题训练。

### 2.3 缩放定律与数据质量

经验上，模型能力随参数量、数据量、计算量增加而提升，但有边际收益，且受数据质量/重复/配比影响。缩放定律是趋势/预算工具，不是“参数量翻倍，业务指标必翻倍”。

数据工作常比模型结构更影响结果：去重、清洗、授权、标注一致性、难例覆盖、防泄漏。

### 2.4 SFT：教“怎样回答任务”

监督微调（SFT）用“输入→理想输出”的示例继续训练：

```text
用户：把这段制度总结成三条
助手：1... 2... 3...
```

它主要塑造行为/格式/任务模式，也能注入少量领域知识，但：

- 示例质量比数量重要；
- 覆盖边界/拒答/不确定；
- 训练题不能和评测题重叠；
- 事实更新仍优先检索。

### 2.5 RLHF 与 DPO

人类偏好训练让模型更偏向“人类更喜欢的回答”：

- **RLHF**：训练奖励模型，再用强化学习（如 PPO）优化策略；流程复杂，需防奖励黑客。
- **DPO**：直接用偏好对（chosen/rejected）优化，不需要单独奖励模型和 RL 循环；更简单，但仍需高质量偏好数据。

偏好训练优化的是“被偏好的概率”，不自动保证事实正确；偏好标注者的偏差会进入模型。

### 2.6 LoRA：低秩更新

全量微调更新所有参数。LoRA 冻结原权重 `W`，只训练两个小矩阵 `A`、`B`，用 `ΔW = B A` 近似更新：

```text
W' = W + (alpha/r) B A
```

若 W 是 `d_out × d_in`，A 是 `r × d_in`，B 是 `d_out × r`，r 远小于 d 时，可训练参数显著减少。但：

- 前向仍要加载原模型；
- 激活/优化器状态仍占显存；
- 低秩限制可能不适合所有任务；
- 量化 + LoRA 的组合要明确量化哪部分。

### 2.7 灾难性遗忘与数据配比

只在窄领域微调，可能让通用能力退化。常见做法是混入通用数据、保留基线评测、早停、低学习率、适配器；但不存在“绝不遗忘”的保证。

## 3. 原理讲解与推导

### 3.1 训练目标与业务目标不是同一个

下一 token 损失优化“像训练数据一样预测”，业务要的是“事实正确、引用可靠、权限合规、延迟可接受”。所以训练后必须用独立任务评测；损失下降不能替代业务验收。

### 3.2 预训练/SFT/偏好训练的分工

| 阶段 | 数据 | 主要改变 |
| --- | --- | --- |
| 预训练 | 大规模无标注文本 | 语言/世界知识/基础能力 |
| SFT | 任务示例 | 指令遵循、格式、行为 |
| 偏好训练 | chosen/rejected 对 | 风格、有用性、安全性偏好 |
| LoRA | 小规模任务数据 | 低成本适配 |

### 3.3 什么时候不该微调

- 知识每天变：优先 RAG；
- 只是格式/角色：提示 + 结构化输出可能够；
- 数据不足/授权不清：先补数据治理；
- 基础能力不足：微调小模型通常补不上，换更大模型/工具更直接；
- 需要可追溯：参数记忆不可引用，RAG 更合适。

## 4. 示例与逐步走查

```python
# runnable
from math import log

def cross_entropy(probability_of_target):
    if not 0 < probability_of_target <= 1:
        raise ValueError("概率必须在 (0,1]")
    return -log(probability_of_target)

# 正确 token 的概率从 0.8 降到 0.2，损失变大
assert cross_entropy(0.8) < cross_entropy(0.2)
# 多个位置通常取平均；这里只是单点演示
```

逐步解释：

1. 模型输出词表分布；
2. 取正确 token 的概率；
3. 负对数得到损失；
4. 反向传播求梯度；
5. 优化器更新参数；
6. 在验证集看是否真的变好。

## 5. 练习

### 练习一：跟写

给定三个样本的正确 token 概率 0.9、0.5、0.1，算平均负对数损失；说明为什么平均损失低不代表每个样本都好。

### 练习二：改造

为一个“固定 JSON 格式”的需求设计 SFT 数据：正例、边界、拒答、坏格式；说明为什么不能只用正常样本。

### 练习三：独立

比较“RAG / 提示 / SFT / LoRA”四种方案：知识更新频率、可追溯性、数据需求、成本、失败模式各写一行，给出你的选型。

## 6. 验收与自测

**行为验收：** 能解释损失/梯度/优化器的作用；能区分预训练/SFT/偏好训练；能说出 LoRA 省什么、不省什么。

**原理验收：** 能说明训练目标与业务目标的差异；能判断一个需求不该微调的理由；能解释灾难性遗忘和数据泄漏。

## 7. 面试问答与参考回答

**问：预训练和微调的区别？**

预训练用大规模文本学习下一 token 预测，形成基础能力；微调用任务/偏好数据继续训练，改变行为/格式/部分知识。微调不是知识库更新的默认方案。

**问：LoRA 为什么省参数？**

它冻结原权重，只训练低秩矩阵 A/B 表示增量，r 远小于维度时可训练参数大幅减少；但原模型、激活和优化器状态仍占资源，效果需评测。

**问：RLHF 和 DPO 的区别？**

RLHF 通常训练奖励模型再用 RL 优化策略；DPO 直接用偏好对优化，流程更简单。两者都依赖偏好数据质量，都不自动保证事实正确。

## 8. 本章小结与参考

- 预训练优化下一 token 损失；SFT 教任务行为；偏好训练塑造选择。
- 训练目标不等于业务目标；独立评测不可省。
- LoRA 省可训练参数，不等于零成本/同等效果。
- 知识频繁更新优先 RAG；数据/授权不清不要先训练。

# 第03章　Embedding：把语义变成向量

[上一章](02-Tokenizer.md) · [全书目录](教材目录.md) · [下一章](04-Transformer.md)

## 1. 学习目标与前置知识

能把embedding理解成一组用于比较的数字，计算点积和余弦相似度，并区分单个token的表示与整句检索向量。最后能解释为什么“检索得分高”还需要核对原文。前置：第2章。

**本章从这里开始：** “退款要留凭证”和“退货需要保存单据”字面不同，检索却应把它们排在一起。模型怎样把“意思接近”变成可计算的数字？

## 2. 基础知识讲解

### 2.1 向量是固定长度的数字序列

为了比较两段文字，先让模型把每段文字变成一组固定数量的数字。这组数字叫**向量**，把对象转换成这种表示的过程叫embedding。若每组有`d`个数，就称为`d`维向量。下面先把它当作可计算的表示，之后再学习怎样比较：

```text
"退款" -> [0.12, -0.03, 0.88, ...]  (d=768/1024/...)
```

不要先给每个数字硬贴含义，例如“第3个数代表退款”。这些数字是一起训练出来的表示，通常不能逐项这样解释。检索希望相关文本的向量容易匹配，但能否做到、在哪类文本上做到，要看模型的训练和实际测试。接下来先学习两种比较方法。

### 2.2 点积与余弦

两个等长向量 `a`、`b`：

```text
dot(a,b) = a1*b1 + a2*b2 + ... + ad*bd
cos(a,b) = dot(a,b) / (||a|| * ||b||)
```

取 `a=[1,2]`、`b=[2,1]`，逐项代入：点积 `1×2+2×1=4`，两个范数都是 `√5`，所以余弦 `4/(√5×√5)=0.8`。若只把 b 放大为 `2b=[4,2]`，点积变成 8，范数变成 `2√5`，余弦仍是 `8/(√5×2√5)=0.8`。这解释了长度与方向的区别。

- 点积受长度影响：向量变长，点积可能变大；
- 余弦先归一化，只看方向，范围 [-1,1]；
- 若向量已单位化，余弦等于点积；
- 点积可以为负，余弦为 -1 表示方向相反；零向量无法归一化，应显式报错。

```python
# runnable
import math

def dot(a, b):
    if len(a) != len(b):
        raise ValueError("向量维度不一致")
    return sum(x * y for x, y in zip(a, b))

def norm(a):
    return math.sqrt(dot(a, a))

def cosine(a, b):
    denominator = norm(a) * norm(b)
    if denominator == 0:
        raise ValueError("零向量没有余弦相似度")
    return dot(a, b) / denominator

print("输入:", {"a": [1, 2], "b": [2, 1]})
print("中间结果:", {"dot": dot([1, 2], [2, 1]), "norms": [norm([1, 2]), norm([2, 1])]})
print("输出:", {"cosine": cosine([1, 2], [2, 1]), "same_direction": cosine([1, 0], [1, 0])})
assert abs(dot([1, 2], [2, 1]) - 4) < 1e-12
assert abs(cosine([1, 2], [2, 1]) - 0.8) < 1e-12
assert abs(cosine([1, 0], [1, 0]) - 1.0) < 1e-12
assert abs(cosine([1, 0], [0, 1])) < 1e-12
assert cosine([1, 0], [-1, 0]) == -1.0
```

如果直接用 `zip` 而不检查长度，较短向量会静默截断，得到一个“看起来正常”的错误点积；上面的版本把维度不一致变成显式错误。

### 2.3 token 向量与句子向量不是一回事

| 类型 | 来源 | 用途 |
| --- | --- | --- |
| token embedding | 词表查表/模型内部 | 进入 Transformer 的初始表示 |
| 上下文 token 表示 | Transformer 每层输出 | 结合上下文后的 token 表示 |
| 句子/文档 embedding | 专门池化/对比学习 | 检索、聚类、语义相似 |

一句话包含多个token，生成模型会为各个位置计算表示；检索时却常需要用一个向量代表整段文字。把多个向量直接平均，只是一种合并方法，不保证适合检索。检索模型通常专门学过“问题与相关段落应当接近”这类目标，所以不能只因生成模型也输出向量，就直接拿来当检索表示。

### 2.4 表示学习：相似来自训练目标

句子 embedding 常用对比学习：

```text
正例：问题 + 包含答案的段落
负例：问题 + 无关段落（随机/难负例）
目标：正例相似度 > 负例相似度
```

最小数值目标是让正例分数高于负例。若某问题与正段落余弦 0.90、与难负例 0.85，margin 只有 0.05，微小分布变化就可能换序；训练会推动这个间隔变大。**0.05 是观察量，不是所有对比损失都直接等于它。** 训练后，语义相近的文本在向量空间靠近。但“相近”取决于训练数据和目标：法律条款的“相似”与闲聊的“相似”不是同一个概念；跨语言/跨领域需要相应训练。

### 2.5 维度、归一化与索引

- 维度越高，表达能力可能更强，但存储/计算更贵；
- 归一化后可用内积/余弦；不归一化时，长度会影响结果；
- 向量库用近似最近邻（HNSW、IVF 等）换速度，召回不是精确的；
- 同一索引必须使用同一 embedding 模型、维度、归一化方式和分块策略。

例如 10 万段、每段 768 个 FP32 数，仅向量本体约 `100000×768×4=307,200,000` 字节，约 293 MiB，还未含索引与元数据。ANN 的 Recall@10 若为 8/10=80%，意味着有 2 个相关段落没进候选；这时先查索引/过滤参数，不能直接归因于生成模型。

## 3. 原理讲解与推导

### 3.1 相似度不是事实函数

`cos=0.9` 只表示“在这个 embedding 空间里方向接近”，不表示：

- 文档有权限；
- 版本是当前有效；
- 段落能支持结论；
- 模型会正确使用它。

检索系统要在相似度之外加权限、时间、版本来过滤，再用 rerank/生成/引用验证。

### 3.2 为什么“意思相反”也可能相似

“预付款不得超过20%”和“预付款不得低于20%”共享大量词和句式，embedding 可能很近；但业务含义相反。相似度模型学的是分布相似，不是逻辑否定。高风险场景要字面/规则/重排/人工复核共同约束。

### 3.3 维度灾难与近似检索

高维空间中距离变得稀疏，精确最近邻成本高；ANN 索引用图/聚类近似，召回率与延迟/内存有权衡。索引参数要用真实查询集评估，不能只看构建成功。

## 4. 示例与逐步走查

### 4.1 用三个文档观察相似度排序

```python
# runnable
import math

def cosine(a, b):
    if len(a) != len(b):
        raise ValueError("向量维度不一致")
    dot = sum(x * y for x, y in zip(a, b))
    denominator = math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b))
    if denominator == 0:
        raise ValueError("零向量没有余弦相似度")
    return dot / denominator

documents = {
    "d1": [1.0, 0.0, 0.0],
    "d2": [0.9, 0.1, 0.0],
    "d3": [0.0, 1.0, 0.0],
}
query = [1.0, 0.0, 0.0]
scores = {key: cosine(query, value) for key, value in documents.items()}
ranked = sorted(documents, key=scores.get, reverse=True)
print("输入:", {"query": query, "documents": documents})
print("中间结果:", scores)
print("输出:", {"ranking": ranked, "top1": ranked[0]})
assert scores["d1"] == 1.0 and scores["d3"] == 0.0
assert math.isclose(scores["d2"], 0.9938837346736189, abs_tol=1e-12)
assert ranked == ["d1", "d2", "d3"]
```

逐步解释：

1. 查询与 d1 完全同向，余弦 1；
2. d2 的点积为 0.9，范数为 `√0.82≈0.9055`，余弦 `0.9/0.9055≈0.9939`；
3. d3 正交，余弦 0；
4. 排序只反映这个玩具空间，真实模型由训练决定；
5. 生产还要按租户/日期/版本过滤，再做 rerank。若 d2 属于其他租户，哪怕余弦 0.9939 也不能进入上下文。

### 4.2 检索高分为何仍会答错

把三条文本放进同一空间：`“上限20%”`、`“上限30%”`、`“合同需签署”`。即使前两条分数为 0.92、0.90，它们数值不同、结论相反；只看分数无法判断该用哪条。可观察的操作是打开原文、核对日期和租户，再检查生成结论是否被引用支持。证据是“原文写了什么”，不是“余弦有多高”。

## 5. 练习

### 练习一：跟写

手算 `[1,2]` 与 `[2,1]`、`[-1,0]` 的余弦，说明符号与方向。完成标准：点积分别为 4、-1；余弦分别约 0.8、-0.447；说明后者点积为负、方向部分相反，但不是完全反向（完全反向应为 `[-1,-2]`）。

### 练习二：改造

给 `cosine` 增加非数值、NaN、无穷值的检查；说明入口应该拒绝还是返回错误码。维度不一致已经由 `dot` 拒绝，再补一个测试覆盖它。完成标准：四类输入都有测试；NaN 不能通过普通大小比较悄悄流入排序。

### 练习三：独立

设计一个检索评测：10 个问题、每个标注相关文档；比较字面检索与向量检索的 Recall@3，并列出各自失败例子。完成标准：每题先冻结相关集合， Recall@3 按题算再平均；至少报告一个同义改写失败和一个否定/旧版误召回。

## 6. 验收与自测

**行为验收：** 能解释点积/余弦差异；能区分 token/句子 embedding；能说出至少三种“相似但错”的情况。

**原理验收：** 能说明对比学习目标；能解释 ANN 的召回/延迟权衡；能说明为什么相似度不能替代权限/版本/事实验证。

**操作：** 计算 `[1,2]` 与 `[2,1]` 的余弦，再把 b 放大 10 倍；随后把检索例子的 d2 标记为其他租户。**预期：** 余弦分别约 0.8、0.8，但越权 d2 不得进入上下文。**证据：** 点积/范数中间值证明计算，租户元数据证明过滤；高相似分数不能充当权限证据。

## 7. 面试问答与参考回答

**问：embedding 是什么？**

把对象映射成固定维度向量的表示，通常由训练得到；相似对象在向量空间中更接近。它不是人类可读的规则表，也不保证事实正确。

**问：点积和余弦怎么选？**

向量已归一化时两者排序等价；未归一化时点积受长度影响，余弦只看方向。检索系统要统一归一化/距离度量，不能混用。

**问：相似度高为什么答案还错？**

相似不等于有权、有效、支持结论；否定句、旧版本、跨租户、模板文本都可能高相似。要加过滤、重排、引用和忠实性评测。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** “退款要留凭证”和“退货需要保存单据”字面不同，怎样变成可比较、可排序的数字？

**一条主线：**

```text
文本 → 训练好的 embedding → 向量 → 点积/余弦 → 检索排序
```

**三个关键词：** 向量、余弦、对比学习——向量是表示形式，余弦在同一空间里比方向，对比学习决定“相近”按什么目标定义。

**最容易错：**

- 把 token 向量或最后一层隐藏状态直接当句子向量去检索；
- 看到余弦 0.9 就认定文档有效、有权、能支持结论，跳过权限/版本/原文核对；
- 忽略向量长度对点积的影响，或让归一化与未归一化的索引混用；
- 认为“意思相反”的句子一定不相似——共享句式的否定句可能非常近。

**与前后章：** 上一章把文本变成词表 ID，本章把文本变成可比较的向量；下一章要问这些向量进入 Transformer 后，位置之间怎样互相读取。

**学完应能：**

- 手算两个小向量的点积与余弦，说明符号和长度各起什么作用；
- 区分 token embedding、上下文表示与句子 embedding 的接口和用途；
- 解释对比学习的正负例目标，并举出三种“相似但错”的情况；
- 用 Recall@3 对比字面检索与向量检索，列出各自失败例子。

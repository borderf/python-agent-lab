## 1. 学习目标与前置知识

能解释 embedding 是什么、点积/余弦相似度怎样工作、token 向量与句子向量的区别、表示学习与检索的关系，并知道相似度高为什么不等于答案正确。前置：第2章。

**本章从这里开始：** “退款要留凭证”和“退货需要保存单据”字面不同，检索却应把它们排在一起。模型怎样把“意思接近”变成可计算的数字？

## 2. 基础知识讲解

### 2.1 向量是固定长度的数字序列

一个 embedding 把对象（token、句子、图片）映射成 `d` 维向量：

```text
"退款" -> [0.12, -0.03, 0.88, ...]  (d=768/1024/...)
```

每个维度没有人类可读的固定含义；它是训练出来的表示。相似对象在向量空间中距离更近/方向更一致，但“维度 3 代表退款”这种解释通常不成立。

### 2.2 点积与余弦

两个等长向量 `a`、`b`：

```text
dot(a,b) = a1*b1 + a2*b2 + ... + ad*bd
cos(a,b) = dot(a,b) / (||a|| * ||b||)
```

- 点积受长度影响：向量变长，点积可能变大；
- 余弦先归一化，只看方向，范围 [-1,1]；
- 若向量已单位化，余弦等于点积。

```python
# runnable
import math

def dot(a, b):
    if len(a) != len(b):
        raise ValueError("向量维度不一致")
    return sum(x * y for x, y in zip(a, b))

def norm(a):
    return math.sqrt(dot(a, a))

def cosine(a, b):
    denominator = norm(a) * norm(b)
    if denominator == 0:
        raise ValueError("零向量没有余弦相似度")
    return dot(a, b) / denominator

assert abs(cosine([1, 0], [1, 0]) - 1.0) < 1e-12
assert abs(cosine([1, 0], [0, 1])) < 1e-12
assert cosine([1, 0], [-1, 0]) == -1.0
```

如果直接用 `zip` 而不检查长度，较短向量会静默截断，得到一个“看起来正常”的错误点积；上面的版本把维度不一致变成显式错误。

### 2.3 token 向量与句子向量不是一回事

| 类型 | 来源 | 用途 |
| --- | --- | --- |
| token embedding | 词表查表/模型内部 | 进入 Transformer 的初始表示 |
| 上下文 token 表示 | Transformer 每层输出 | 结合上下文后的 token 表示 |
| 句子/文档 embedding | 专门池化/对比学习 | 检索、聚类、语义相似 |

把最后一层 token 向量简单平均，不一定得到好的句子向量；检索模型通常经过针对“相似问题/文档”的训练。不要拿生成模型内部的隐藏状态直接当检索 embedding，除非验证过。

### 2.4 表示学习：相似来自训练目标

句子 embedding 常用对比学习：

```text
正例：问题 + 包含答案的段落
负例：问题 + 无关段落（随机/难负例）
目标：正例相似度 > 负例相似度
```

训练后，语义相近的文本在向量空间靠近。但“相近”取决于训练数据和目标：法律条款的“相似”与闲聊的“相似”不是同一个概念；跨语言/跨领域需要相应训练。

### 2.5 维度、归一化与索引

- 维度越高，表达能力可能更强，但存储/计算更贵；
- 归一化后可用内积/余弦；不归一化时，长度会影响结果；
- 向量库用近似最近邻（HNSW、IVF 等）换速度，召回不是精确的；
- 同一索引必须使用同一 embedding 模型、维度、归一化方式和分块策略。

## 3. 原理讲解与推导

### 3.1 相似度不是事实函数

`cos=0.9` 只表示“在这个 embedding 空间里方向接近”，不表示：

- 文档有权限；
- 版本是当前有效；
- 段落能支持结论；
- 模型会正确使用它。

检索系统要在相似度之外加权限、时间、版本来过滤，再用 rerank/生成/引用验证。

### 3.2 为什么“意思相反”也可能相似

“预付款不得超过20%”和“预付款不得低于20%”共享大量词和句式，embedding 可能很近；但业务含义相反。相似度模型学的是分布相似，不是逻辑否定。高风险场景要字面/规则/重排/人工复核共同约束。

### 3.3 维度灾难与近似检索

高维空间中距离变得稀疏，精确最近邻成本高；ANN 索引用图/聚类近似，召回率与延迟/内存有权衡。索引参数要用真实查询集评估，不能只看构建成功。

## 4. 示例与逐步走查

```python
# 承接上面的 cosine 定义；单独复制本块时先补 cosine/norm。
documents = {
    "d1": [1.0, 0.0, 0.0],
    "d2": [0.9, 0.1, 0.0],
    "d3": [0.0, 1.0, 0.0],
}
query = [1.0, 0.0, 0.0]
ranked = sorted(documents.items(), key=lambda item: cosine(query, item[1]), reverse=True)
print(ranked)
```

逐步解释：

1. 查询与 d1 完全同向，余弦 1；
2. d2 方向接近，余弦略低；
3. d3 正交，余弦 0；
4. 排序只反映这个玩具空间，真实模型由训练决定；
5. 生产还要按租户/日期/版本过滤，再做 rerank。

## 7. 面试问答与参考回答

**问：embedding 是什么？**

把对象映射成固定维度向量的表示，通常由训练得到；相似对象在向量空间中更接近。它不是人类可读的规则表，也不保证事实正确。

**问：点积和余弦怎么选？**

向量已归一化时两者排序等价；未归一化时点积受长度影响，余弦只看方向。检索系统要统一归一化/距离度量，不能混用。

**问：相似度高为什么答案还错？**

相似不等于有权、有效、支持结论；否定句、旧版本、跨租户、模板文本都可能高相似。要加过滤、重排、引用和忠实性评测。

## 8. 本章小结与参考

- embedding 是训练得到的向量表示；点积/余弦衡量方向相似。
- token 向量、上下文表示、句子向量是不同接口。
- 对比学习让正例靠近、负例远离；相似度不是事实/权限函数。
- 向量检索要统一模型/维度/归一化，并用真实查询评估。

参考：[Sentence-BERT](https://arxiv.org/abs/1908.10084)、[Dense Passage Retrieval](https://arxiv.org/abs/2004.04906)、[HNSW](https://arxiv.org/abs/1603.09320)。

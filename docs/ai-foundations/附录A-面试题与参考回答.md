# 附录A　AI 基础面试题与参考回答

[全书目录](教材目录.md) · [第8章](08-评测与面试.md) · [Python 第18章](../python-book/18-大模型基础、消息与结构化输出.md)

用法：先自己答，再看参考；每题至少补一个项目例子或反例。答案按“定义→机制→例子→边界→验证”组织。

## 一、Token 与表示

**1. token 是什么？为什么不等于汉字？**

token 是模型词表里的离散单位，由 tokenizer 决定；一个汉字可能对应 1 个或多个 token，英文词也可能被拆成片段。上下文和费用按 token 计，必须用目标模型 tokenizer 实测。

**2. BPE 的基本过程？**

从最小单位（字节/字符）开始，统计相邻对频率，反复合并最高频对，直到词表达到目标大小。常见片段变长，生僻内容拆成多个 token，从而用有限词表表示任意文本。

**3. token embedding 和句子 embedding 有什么区别？**

token embedding 是词表查表/模型输入表示；句子 embedding 通常经过池化和对比学习，专门用于检索/聚类。把最后一层 token 向量平均不一定是好的句子向量，必须按任务验证。

**4. 余弦相似度高为什么答案还可能错？**

相似只说明在该表示空间方向接近，不说明有权、有效、版本正确或支持结论；否定句、旧版、模板文本都可能高相似。要加权限/日期过滤、重排、引用和忠实性评测。

## 二、Transformer

**5. Self-Attention 的计算过程？**

输入投影得到 Q/K/V；QKᵀ 点积、除以 sqrt(d_k)、加因果掩码、逐行 softmax 得权重；权重乘 V 得输出；多头拼接后再投影。

**6. 为什么要多头？**

不同头使用不同投影，可在多个子空间学习不同匹配模式；拼接后由输出投影融合。不能简单说“每个头负责一个可解释功能”。

**7. 为什么需要位置编码？**

注意力对排列等变，打乱 token 输出也按同样方式打乱，模型无法区分顺序。位置编码（正弦、可学习、RoPE）提供顺序/相对位置信息。

**8. 残差和 LayerNorm 的作用？**

残差让梯度和信息更容易穿过深层；LayerNorm 稳定每层激活分布、改善训练。具体 pre-norm/post-norm 实现不同，不能只背名词。

**9. 注意力权重能解释模型决策吗？**

不能直接当因果解释。权重是特定头/层的分配，受多层、残差、多头和后续层影响；解释要结合扰动、归因和任务评测。

**10. 长上下文为什么贵？**

注意力分数矩阵随 n² 增长，KV cache 随上下文/并发占显存；计算和内存都不是线性。分块、稀疏注意力、缓存、检索是不同层优化。

## 三、训练

**11. 预训练和微调的区别？**

预训练用大规模文本学习下一 token 预测，形成基础能力；微调用任务/偏好数据继续训练，改变行为/格式/部分知识。微调不是知识库更新的默认方案。

**12. SFT、RLHF、DPO 各做什么？**

SFT 用输入→理想输出教任务行为；RLHF 通常训练奖励模型再用 RL 优化策略；DPO 直接用偏好对优化。三者都依赖数据质量，都不自动保证事实正确。

**13. LoRA 为什么省参数？**

冻结原权重，只训练低秩矩阵 A/B 表示增量，r 远小于维度时可训练参数大幅减少；但原模型、激活、优化器状态仍占资源，效果需评测。

**14. 训练损失低为什么业务不一定好？**

损失只拟合训练分布，可能过拟合/数据泄漏/评测分布不同；事实、引用、权限、拒答等业务要求未被损失覆盖。必须独立评测。

**15. 什么时候不该微调？**

知识频繁更新优先 RAG；只是格式/角色提示可能够；数据/授权不清先治理；基础能力不足换更大模型/工具；需要可追溯/删除用非参数记忆。

## 四、推理

**16. temperature、top-k、top-p 的区别？**

温度缩放整个分布；top-k 固定保留前 k 个；top-p 按累计概率保留动态集合。它们改变采样候选/形状，不改变模型事实能力；temperature=0 也不保证跨环境完全复现。

**17. prefill 和 decode 的区别？**

prefill 并行处理输入、建立 KV cache，决定首 token 延迟；decode 逐步生成、复用缓存，决定每 token 时间。输入长影响 TTFT，输出长影响总时长。

**18. KV cache 为什么省时间又费显存？**

复用历史 K/V，避免每步重算旧 token；但缓存随层数、上下文、并发增长，长上下文/高并发会吃显存。

## 五、RAG 与评测

**19. RAG 答错怎么排查？**

先固定证据：给正确证据能否答对？不能→生成/提示/上下文组织；能→召回/排序/过滤/分块。再查权限、日期、版本和引用是否支持结论，不要同时改多层。

**20. Recall@k 高为什么答案还差？**

召回只说明相关文档进了前 k；排序、上下文选择、生成忠实性、引用和权限仍可能错。要分层评测（召回/重排/生成/引用/端到端），不要只看一个指标。

## 六、系统与面试表达

**21. 怎样证明一次模型/系统升级值得上线？**

固定集 + 未参与调参的留出集 + 关键失败类型 + 延迟/成本 + 小流量在线；预设采用/回退条件。报告样本量、置信区间、数据版本和已知限制。

**22. 你的项目最难的一次失败是什么？**

给具体层：例如“中文被 chunk 切断导致引用错位”；说明如何用中间产物定位、修复后加了跨 chunk/引用支持测试。不要只说“调了提示词”。

**23. 如果面试官追问“为什么不用微调”？**

按四问回答：知识更新频率、可追溯/删除、行为/格式还是能力、数据/成本。知识频繁变、要引用/权限→RAG；固定行为/格式→SFT/LoRA；基础能力→更大模型/工具。

**24. 你怎样判断一个回答是“有依据”的？**

引用文本包含结论所需信息、来源当前有效且有权访问、引用与结论一致、没有断章取义；引用存在只是必要条件，不是充分条件。

**25. 用一句话总结大模型的能力边界。**

它擅长在上下文中做模式补全与表达，不保证事实、权限、可回滚；系统要用检索、工具、校验、审批和评测补这些边界。

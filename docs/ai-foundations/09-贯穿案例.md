# 第09章　贯穿案例：一次“预付款上限”从 token 到评测

[上一章](08-评测与面试.md) · [全书目录](教材目录.md) · [附录A](附录A-面试题与参考回答.md)

## 1. 学习目标与前置知识

把前八章的机制放进同一条订单/制度问答链：同一份问题、同一组来源、同一套指标，观察每一步的输入、中间结果、输出和反例。前置：第1–8章。

**本章从这里开始：** 用户问“2026-07-01 预付款上限是多少？”。知识库里有旧版 30%、新版 20%、另一租户 80% 和一段无关条款。模型可能答对、答错或答“没有依据”；我们要能定位是哪一层出的问题。

## 2. 固定输入

```text
问题：2026-07-01 预付款上限是多少？
租户：tenant=a
来源（valid_to 为 null 表示仍有效）：
A  policy-a v1  30%  tenant=a  valid_from=2026-01-01  valid_to=2026-07-01
B  policy-a v2  20%  tenant=a  valid_from=2026-07-01  valid_to=null
C  policy-b v1  80%  tenant=b  valid_from=2026-07-01  valid_to=null
D  policy-c v1  与预付款无关  tenant=a  valid_from=2026-01-01  valid_to=null
```

先手写预期，并把三个集合分开：

| 集合 | 条件 | 结果 |
| --- | --- | --- |
| 租户/日期可见 | tenant=a 且 `valid_from <= 2026-07-01`，并满足 `valid_to` 为空或 `2026-07-01 < valid_to` | B、D；A 因 `valid_to=2026-07-01` 被半开区间排除；C 跨租户排除 |
| 相关性检索候选 | 在可见集合内按查询相关性排序 | B；D 与预付款无关，得分低/被过滤 |
| 最终证据 | 候选中的相关来源 | B，答案 20% |

如果日期改成 2026-06-30：A、D 可见，B 尚未生效；相关性候选是 A，答案 30%。这两个日期用同一套数据就能复现“换日期换答案”。

## 3. 逐层观察

### 3.1 Tokenizer：先算上下文预算

```text
问题 + 系统提示 + 4 个候选块 + 输出预算
```

不要用 `len(question)` 估算；用目标模型 tokenizer 计数。若候选块很长，先检索/裁剪，不要把 4 篇全文塞入。反例：按字符截断把“20%”所在句子切掉，模型只能猜。

### 3.2 Embedding/检索：先过滤，再相似

| 候选 | 租户 | valid_from | valid_to | 相似度（示意） | 过滤后 |
| --- | --- | --- | --- | --- | --- |
| A | a | 2026-01-01 | 2026-07-01 | 0.82 | 半开区间排除（7/1 已失效） |
| B | a | 2026-07-01 | null | 0.80 | 可见 |
| C | b | 2026-07-01 | null | 0.95 | 跨租户排除 |
| D | a | 2026-01-01 | null | 0.70 | 可见但与问题无关 |

可见集合是 B、D；相关性检索后候选是 B；D 只有在检索/重排失效时才可能混入证据。

注意 C 的相似度最高但不可见：**权限/租户过滤必须在候选进入上下文之前**。如果先按相似度取 top1，再把 tenant 过滤掉，可能得到空结果；正确顺序是先过滤可见范围，再排序。

中间结果：可见集合 `{B, D}`，候选 `{B}`；引用 `source_id=policy-a, version=2, start/end=...`。

### 3.3 Transformer：上下文怎样组合

把问题和 B 的原文放进上下文。注意力让“预付款”“上限”“2026-07-01”“20%”等位置互相读取；位置编码区分“2026-01-01 版”和“2026-07-01 版”。如果误把 A（旧版）或 D（无关）放进上下文，模型可能把 30% 或无关内容与 20% 混在一起——这不是注意力公式错，而是过滤/证据组织失败。

反例：只给 A（旧版），模型可能自信回答 30%；它“有依据”，但依据已失效。

### 3.4 生成：概率与温度

模型在“20%”“30%”“没有依据”等 token 上有分布。温度低更集中，但：

- 如果证据里只有旧版，低温度只会更稳定地输出 30%；
- 如果证据里有新版但被长上下文淹没，温度不保证选对；
- 温度会改变本次答案，不能宣称“对事实无影响”。

中间结果：`answer="20%"`，`citations=[B]`，`needs_review=false`。反例：`answer="30%"` 但引用 B——引用与结论不一致，属于忠实性失败。

### 3.5 引用与校验

检查：

1. 引用文本是否包含“20%”；
2. 来源版本/日期是否匹配问题日期；
3. 是否越权（C 不应出现）；
4. 回答是否超出引用（例如编造“需要财务批准”）。

中间结果：引用 B 的原文“不得超过20%”支持结论；若引用 A 的 30%，则引用不支持当前日期。

### 3.6 评测：用同一组题定位

准备 5 道题：

| 题 | 预期 | 失败层 |
| --- | --- | --- |
| 2026-07-01 上限（tenant=a） | 20%（B） | 基线 |
| 2026-06-30 上限（tenant=a） | 30%（A） | 日期/版本 |
| 以 tenant=b 身份问上限 | 80%（C），且看不到 A/B | 租户映射/过滤 |
| tenant=a 要求打开 C 的来源 | 无权限/不存在 | 对象级权限 |
| 问“需要哪些材料” | 无相关证据→待复核 | 召回/拒答 |

指标：

- Recall@k：相关来源是否进候选；
- RR/MRR：第一个相关结果的位置（多题平均才是 MRR）；
- 引用支持率：引用是否支持结论；
- 任务完成率/错误类型：端到端。

反例：Recall@3=1，但答案仍错——排序/上下文/生成/引用层失败；不要只看召回。

## 4. 一张表复述全链

| 层 | 输入 | 中间结果 | 输出/反例 |
| --- | --- | --- | --- |
| Tokenizer | 问题+候选 | token 数/截断 | 证据句被切断 |
| 检索 | token/向量 | 可见 B/D，候选 B | C 相似度最高但越权 |
| 注意力 | 问题+B | 上下文表示 | 旧版 A 混入导致 30% |
| 生成 | 分布 | “20%”+引用 B | 引用 B 但答 30% |
| 评测 | 5 道题 | Recall/RR/忠实性 | 召回高但答案错 |

## 5. 练习

### 练习一：跟写

把问题日期改成 2026-06-30，重跑过滤/检索/回答，记录答案、引用和指标变化。

### 练习二：改造

删除 B，只留 A/C/D；正确行为应是“没有相关依据→待复核”，而不是拿 C（越权）或 D（可见但无关）作答。写出你期望的 `needs_review` 与引用。

### 练习三：独立

给 3 道题标注相关来源，计算 Recall@3、每题 RR 和 MRR；再故意把 B 排到第 3 位，观察 MRR 变化而 Recall 不变。

## 6. 验收与自测

**行为验收：** 同一案例能依次说出 token、候选、证据、答案、引用和指标；能定位至少 3 种失败层。

**原理验收：** 能解释相似度/权限/日期/版本/注意力/温度/忠实性各自的作用，不把失败都归为“模型不行”。

### 6.1 先预测，再查看解释

C（tenant=b，80%）相似度 0.95，能否先取 top1 再过滤 tenant？

<details>
<summary>完成预测后查看解释</summary>

不能。先取 top1 可能拿到 C，再过滤就变成空结果，而真正可见的 B 从未进入候选。正确顺序是先按租户/日期/权限过滤可见集合，再在集合内排序；否则相似度越高越容易越权或漏召回。

</details>

## 7. 面试问答与参考回答

**问：用这个案例讲一次 RAG 失败，你会怎么讲？**

先固定输入和预期，再按 tokenizer→检索→注意力/上下文→生成→引用→评测逐层给中间结果；指出首个失真层，说明为什么不是其他层，最后给修复和回归指标。

**问：为什么相似度最高的文档不能直接用？**

相似不等于有权、有效、支持结论；跨租户/旧版本/否定句都可能高相似。必须先过滤可见范围，再排序、重排、引用和评测。

**问：怎样证明修复有效？**

同一组题 + 留出题，比较修复前后的 Recall/RR/引用支持率/任务完成率，保留失败类型和反例；不只演示一个成功问题。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** 同一个“2026-07-01 预付款上限是多少”，怎样从 token 走到评测，并在答错时指出首个失真层？

**一条主线：**

```text
问题+候选 → 算 token 预算 → 过滤可见范围 → 检索/重排 → 注意力组合 → 生成+引用 → 分层指标
```

**三个关键词：** 固定输入、逐层中间结果、首个失真层——固定输入让对比可复现，中间结果让每层可检查，失真层让修复有落点。

**最容易错：**

- 先按相似度取 top1 再过滤 tenant，C 相似度 0.95 却越权，过滤后还可能成空；
- 用字符数估 token，截断时把“20%”所在句子切掉；
- 证据只放旧版 A，低温度只会更稳定地答出 30%；
- 看到 Recall@3=1 就判定链路正常，忽略排序、引用和生成层失败。

**与前后章：** 上一章给的是评测方法与口径，本章把这些口径套在同一条链上；下一章（附录A）要你把这条链讲成两分钟的回答。

**学完应能：**

- 用同一组数据复现“换日期换答案”，说清 A/B/C/D 各自为何可见或不可见；
- 按 tokenizer→检索→注意力→生成→引用→评测给出每层中间结果；
- 指出首个失真层，并说明为什么不是其他层；
- 用 Recall、RR、引用支持率、错误类型证明一次修复有效。

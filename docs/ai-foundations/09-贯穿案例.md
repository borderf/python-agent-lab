# 第09章　贯穿案例：一次“预付款上限”从 token 到评测

[上一章](08-评测与面试.md) · [全书目录](教材目录.md) · [附录A](附录A-面试题与参考回答.md)

## 1. 学习目标与前置知识

把前八章放回同一次问答：始终使用同一个问题和同一组制度，逐步查看文本怎样切分、找到了哪些原文、模型用了什么证据、答案怎样验收。每一步都配一个出错情形，练习定位原因。前置：第1–8章。

**本章从这里开始：** 用户问“2026-07-01 预付款上限是多少？”。知识库里有旧版 30%、新版 20%、另一租户 80% 和两段无关条款。模型可能答对、答错或答“没有依据”；我们要能定位是哪一层出的问题。

## 2. 固定输入

### 2.1 固定输入

```text
问题：2026-07-01 预付款上限是多少？
租户：tenant=a
来源（valid_to 为 null 表示仍有效）：
A  policy-a v1  30%  tenant=a  valid_from=2026-01-01  valid_to=2026-07-01
B  policy-a v2  20%  tenant=a  valid_from=2026-07-01  valid_to=null
C  policy-b v1  80%  tenant=b  valid_from=2026-07-01  valid_to=null
D  policy-c v1  与预付款无关  tenant=a  valid_from=2026-01-01  valid_to=null
E  policy-d v1  与预付款无关  tenant=a  valid_from=2026-01-01  valid_to=null
```

有效期判断是半开区间 `[valid_from, valid_to)`：`visible = tenant匹配 且 valid_from<=as_of 且 (valid_to为空 或 as_of<valid_to)`。代入 2026-07-01：A 的最后一项是 `2026-07-01<2026-07-01`，为假；B 的 `2026-07-01<=2026-07-01` 为真且没有结束日期，所以保留。日期相等并不代表两条记录同时有效。

先手写预期，并把三个集合分开：

### 2.2 可见、候选与最终证据

| 集合 | 条件 | 结果 |
| --- | --- | --- |
| 租户/日期可见 | tenant=a 且 `valid_from <= 2026-07-01`，并满足 `valid_to` 为空或 `2026-07-01 < valid_to` | B、D、E；A 因 `valid_to=2026-07-01` 被半开区间排除；C 跨租户排除 |
| 相关性检索候选 | 在可见集合内按查询相关性排序 | B；D、E 与预付款无关，得分低/被过滤 |
| 最终证据 | 候选中的相关来源 | B，答案 20% |

如果日期改成 2026-06-30：A、D、E 可见，B 尚未生效；相关性候选是 A，答案 30%。这两个日期用同一套数据就能复现“换日期换答案”。

## 3. 逐层观察

### 3.1 Tokenizer：先算上下文预算

```text
问题 + 系统提示 + 若干候选块 + 输出预算
```

不要用 `len(question)` 估算；用目标模型 tokenizer 计数。若候选块很长，先检索/裁剪，不要把全部全文塞入。

用一个明确标注为“示意预算”的数字走查：窗口 8192，系统提示 400、问题 80、证据 900、输出预算 300、安全余量 200，总计 1880，还剩 6312。**这个 80 不是字符数，也不是目标模型的真实计数**；真实调用必须用同一 tokenizer 重新填写四项。若证据实际变成 7000，总量 7980 虽小于 8192，却几乎没有给工具回包和模板变化的余量，应优先缩小到相关段落。反例：按字符截断把“20%”所在句子切掉，模型只能猜。

### 3.2 Embedding/检索：先过滤，再相似

| 候选 | 租户 | valid_from | valid_to | 相似度（示意） | 过滤后 |
| --- | --- | --- | --- | --- | --- |
| A | a | 2026-01-01 | 2026-07-01 | 0.82 | 半开区间排除（7/1 已失效） |
| B | a | 2026-07-01 | null | 0.80 | 可见 |
| C | b | 2026-07-01 | null | 0.95 | 跨租户排除 |
| D | a | 2026-01-01 | null | 0.70 | 可见但与问题无关 |
| E | a | 2026-01-01 | null | 0.60 | 可见但与问题无关 |

全局按相似度排序为 `C、A、B、D、E`。先过滤后，可见集合是 B、D、E，集合内排序为 `B、D、E`；再按“预付款”相关性筛选，候选是 B。D、E 只有在检索/重排失效时才可能混入证据。

注意 C 的相似度最高但不可见：**权限/租户过滤必须在候选进入上下文之前**。如果先按相似度取 top1 会得到 C，再把 tenant 过滤掉就变成空结果；正确顺序是先过滤可见范围，再排序。也可只改变可见集合内的顺序为 `D、E、B`：此时 B 降到第 3，Recall@1 从 1 变 0，Recall@3 仍为 1，RR 从 1 变 1/3。候选集合仍是 `{B}`，但“最终只取第 1 条”的系统会漏掉它，这说明召回与证据选择要分开验收。

中间结果：可见集合 `{B, D, E}`，候选 `{B}`；引用 `source_id=policy-a, version=2, start/end=...`。

### 3.3 Transformer：上下文怎样组合

把问题和 B 的原文放进上下文。注意力让“预付款”“上限”“2026-07-01”“20%”等位置互相读取；位置编码区分“2026-01-01 版”和“2026-07-01 版”。第 04 章的三位置玩具中，查询 `[1,0]`、三个键的缩放分数为 `[0.707,0,0.707]`，softmax 后约为 `[0.401,0.198,0.401]`；它演示的是“匹配→权重→加权信息”，不是本案例真实模型的注意力权重。没有运行真实模型，就不能编造本案例每个头的权重。

如果误把 A（旧版）或 D、E（无关）放进上下文，模型可能把 30% 或无关内容与 20% 混在一起——这不是注意力公式错，而是过滤/证据组织失败。可观察证据是上下文字符串中实际出现了哪些 source_id，而不是一句“注意力没学好”。

反例：只给 A（旧版），模型可能自信回答 30%；它“有依据”，但依据已失效。

### 3.4 生成：概率与温度

模型在“20%”“30%”“没有依据”等 token 上有分布。用一个**示意分布**：三候选 logits 为 `[2,1,0]`，温度 1 时概率约为 `[0.665,0.245,0.090]`，温度 0.5 时约为 `[0.867,0.117,0.016]`。真实 token 可能被切成多个片段，不能把这段三候选 toy 当作实际词表。温度低更集中，但：

- 如果证据里只有旧版，低温度只会更稳定地输出 30%；
- 如果证据里有新版但被长上下文淹没，温度不保证选对；
- 温度会改变本次答案，不能宣称“对事实无影响”。

中间结果：`answer="20%"`，`citations=[B]`，`needs_review=false`。反例：`answer="30%"` 但引用 B——引用与结论不一致，属于忠实性失败。可复核证据是 B 原文含“20%”而不含“30%”，不是温度值本身。

### 3.5 引用与校验

检查：

1. 引用文本是否包含“20%”；
2. 来源版本/日期是否匹配问题日期；
3. 是否越权（C 不应出现）；
4. 回答是否超出引用（例如编造“需要财务批准”）。

中间结果：引用 B 的原文“预付款上限为20%”支持“上限20%”；若再声称“无需审批”，原文没有这个 claim，等权支持率为 `1/2=50%`。若引用 A 的 30%，虽然文本能支持“30%”这个数字，却不支持问题日期 2026-07-01，属于版本/日期失败。校验顺序建议为：引用 ID 存在 → 租户有权 → 日期有效 → claim 受支持，任一步失败都进入待复核，而不是只在最后检查字符串。

### 3.6 评测：用同一组题定位

准备 5 道题：

| 题 | 预期 | 失败层 |
| --- | --- | --- |
| 2026-07-01 上限（tenant=a） | 20%（B） | 基线 |
| 2026-06-30 上限（tenant=a） | 30%（A） | 日期/版本 |
| 以 tenant=b 身份问上限 | 80%（C），且看不到 A/B | 租户映射/过滤 |
| tenant=a 要求打开 C 的来源 | 无权限/不存在 | 对象级权限 |
| 问“需要哪些材料” | 无相关证据→待复核 | 召回/拒答 |

指标：

- Recall@k：相关来源是否进候选；
- RR/MRR：第一个相关结果的位置（多题平均才是 MRR）；
- 引用支持率：引用是否支持结论；
- 任务完成率/错误类型：端到端。

| 题 | 独立相关集合 | 预期检索观察 | 端到端预期 |
| --- | --- | --- | --- |
| 7 月 1 日 tenant=a | {B} | B 第 1，Recall@1=1，RR=1 | 20%+引用 B |
| 6 月 30 日 tenant=a | {A} | A 第 1，Recall@1=1，RR=1 | 30%+引用 A |
| tenant=b | {C} | 只在 b 的可见集合内排序 | 80%+引用 C |
| tenant=a 打开 C | 无可见相关来源 | 候选为空，Recall 不适用 | 拒绝/不存在，不泄露 C |
| 问需要哪些材料 | 独立标注为空 | 候选为空，Recall 不适用 | 待复核，不能编造 |

前两题单题 RR 都是 1，若只平均这两题，MRR=1；后两题的相关集合为空，不能硬套 Recall 公式，应作为权限/拒答任务单独计分。反例：Recall@3=1，但答案仍错——排序/上下文/生成/引用层失败；不要只看召回。

## 4. 一张表复述全链

### 4.1 从过滤到指标

用确定性替身复现检索、抽取和校验，不模拟 Transformer；日期按 ISO 字符串比较，有效期采用半开区间。

```python
# runnable
import re

docs = [
    {"id": "A", "tenant": "a", "from": "2026-01-01", "to": "2026-07-01", "score": 0.82, "text": "预付款上限为30%。"},
    {"id": "B", "tenant": "a", "from": "2026-07-01", "to": None, "score": 0.80, "text": "预付款上限为20%。"},
    {"id": "C", "tenant": "b", "from": "2026-07-01", "to": None, "score": 0.95, "text": "预付款上限为80%。"},
    {"id": "D", "tenant": "a", "from": "2026-01-01", "to": None, "score": 0.70, "text": "报销需附发票。"},
    {"id": "E", "tenant": "a", "from": "2026-01-01", "to": None, "score": 0.60, "text": "合同需双方签署。"},
]

def run(tenant, as_of):
    visible = [d for d in docs if d["tenant"] == tenant and d["from"] <= as_of
               and (d["to"] is None or as_of < d["to"])]
    ranked = sorted(visible, key=lambda d: d["score"], reverse=True)
    relevant = [d for d in ranked if "预付款" in d["text"]]
    evidence = relevant[0] if relevant else None
    answer = re.search(r"(\d+)%", evidence["text"]).group(1) + "%" if evidence else None
    return visible, ranked, relevant, {"answer": answer, "citation": evidence["id"] if evidence else None,
                                       "needs_review": evidence is None}

def retrieval_metrics(ranked_ids, relevant_ids):
    if not relevant_ids:
        return {"recall@1": None, "recall@3": None, "rr": 0.0}
    hits = [index for index, source_id in enumerate(ranked_ids, 1) if source_id in relevant_ids]
    return {"recall@1": len(set(ranked_ids[:1]) & relevant_ids) / len(relevant_ids),
            "recall@3": len(set(ranked_ids[:3]) & relevant_ids) / len(relevant_ids),
            "rr": 1 / hits[0] if hits else 0.0}

visible, ranked, relevant, result = run("a", "2026-07-01")
old_result = run("a", "2026-06-30")[3]
ranked_ids = [d["id"] for d in ranked]
reordered_ids = ["D", "E", "B"]
relevant_ids = {"B"}
wrong = {"answer": "30%", "citation": "B"}
print("输入:", {"tenant": "a", "as_of": "2026-07-01"})
print("中间结果:", {"visible": [d["id"] for d in visible], "ranked": ranked_ids,
                    "candidates": [d["id"] for d in relevant]})
print("输出:", result, "旧日期:", old_result)
print("反例:", wrong, "引用支持:", wrong["answer"] in docs[1]["text"])
print("指标:", {"原排序": retrieval_metrics(ranked_ids, relevant_ids),
                "B降至第3": retrieval_metrics(reordered_ids, relevant_ids),
                "citation_support": float(result["answer"] in docs[1]["text"]),
                "task_success": float(result["answer"] == "20%" and result["citation"] == "B")})
assert [d["id"] for d in visible] == ["B", "D", "E"]
assert [d["id"] for d in relevant] == ["B"]
assert result["answer"] == "20%" and old_result["answer"] == "30%"
assert wrong["answer"] not in docs[1]["text"]
assert retrieval_metrics(ranked_ids, relevant_ids) == {"recall@1": 1.0, "recall@3": 1.0, "rr": 1.0}
assert retrieval_metrics(reordered_ids, relevant_ids) == {"recall@1": 0.0, "recall@3": 1.0, "rr": 1 / 3}
assert retrieval_metrics([], set()) == {"recall@1": None, "recall@3": None, "rr": 0.0}
```

先预测可见集合与旧日期答案，再运行核对。**输入**为 tenant=a、日期 2026-07-01；**中间结果**为可见 `[B,D,E]`、排序 `[B,D,E]`、相关候选 `[B]`；**输出**为 `answer=20%、citation=B、needs_review=False`，旧日期输出为 30%/A。**反例**为引用 B 却答 30%，字符串支持检查为 False。**指标**中，原排序 Recall@1/3 都是 1、RR=1；B 降到第 3 后 Recall@1=0、Recall@3=1、RR=1/3；正确输出引用支持与任务成功都为 1。

指标使用独立标注的相关集合 `{"B"}`，而不是把系统自己筛出的候选当作标准答案。相关集合为空时，Recall 返回 `None` 表示不适用，RR 返回 0，不能除零或填 100%。引用支持率与任务成功率是另外两层：前者检查结论是否在 B 原文中出现，后者同时要求答案和引用都正确。这里的单题 RR 不能称为 MRR，真实检索须用目标模型与独立题集评测。

### 4.2 一张表复述全链

| 层 | 输入 | 中间结果 | 输出/反例 |
| --- | --- | --- | --- |
| Tokenizer | 问题+候选 | token 数/截断 | 证据句被切断 |
| 检索 | token/向量 | 可见 B/D/E，候选 B | C 相似度最高但越权 |
| 注意力 | 问题+B | 上下文表示 | 旧版 A 混入导致 30% |
| 生成 | 分布 | “20%”+引用 B | 引用 B 但答 30% |
| 评测 | 5 道题 | Recall/RR/忠实性 | 召回高但答案错 |

## 5. 练习

### 练习一：跟写

把问题日期改成 2026-06-30，重跑过滤/检索/回答，记录答案、引用和指标变化。完成标准：可见 A/D/E，候选 A，答案 30%、引用 A；与 7 月 1 日的 B/20% 对照，说明是日期过滤改变，不是模型参数改变。

### 练习二：改造

删除 B，只留 A/C/D/E；正确行为应是“没有相关依据→待复核”，而不是拿 C（越权）或 D、E（可见但无关）作答。写出你期望的 `needs_review` 与引用。完成标准：7 月 1 日可见 D/E，候选为空，`answer=None`、`citation=None`、`needs_review=True`。

### 练习三：独立

给 3 道题标注相关来源，计算 Recall@3、每题 RR 和 MRR；再故意把 B 排到第 3 位，观察 MRR 变化而 Recall 不变。完成标准：相关集合独立标注，MRR 是三个 RR 的平均；若 B 从第 1 降到第 3，该题 RR 从 1 变 1/3，Recall@3 不变。

## 6. 验收与自测

**行为验收：** 同一案例能依次说出 token、候选、证据、答案、引用和指标；能定位至少 3 种失败层。

**原理验收：** 能解释相似度/权限/日期/版本/注意力/温度/忠实性各自的作用，不把失败都归为“模型不行”。

**操作：** 先预测再运行 7 月 1 日与 6 月 30 日两次流程，然后把 B 降到第 3。**预期：** 可见集合分别为 B/D/E 与 A/D/E，答案为 20% 与 30%；B 降序后 Recall@1=0、Recall@3=1、RR=1/3。**证据：** 保存过滤集合、独立相关集合、排序、输出、反例及指标；A/B/C/D/E 五个来源都要能说明去留原因。

### 6.1 先预测，再查看解释

C（tenant=b，80%）相似度 0.95，能否先取 top1 再过滤 tenant？

<details>
<summary>完成预测后查看解释</summary>

不能。先取 top1 可能拿到 C，再过滤就变成空结果，而真正可见的 B 从未进入候选。正确顺序是先按租户/日期/权限过滤可见集合，再在集合内排序；否则相似度越高越容易越权或漏召回。

## 7. 面试问答与参考回答

**问：用这个案例讲一次 RAG 失败，你会怎么讲？**

先固定输入和预期，再按 tokenizer→检索→注意力/上下文→生成→引用→评测逐层给中间结果；指出首个失真层，说明为什么不是其他层，最后给修复和回归指标。

**问：为什么相似度最高的文档不能直接用？**

相似不等于有权、有效、支持结论；跨租户/旧版本/否定句都可能高相似。必须先过滤可见范围，再排序、重排、引用和评测。

**问：怎样证明修复有效？**

同一组题 + 留出题，比较修复前后的 Recall/RR/引用支持率/任务完成率，保留失败类型和反例；不只演示一个成功问题。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** 同一个“2026-07-01 预付款上限是多少”，怎样从 token 走到评测，并在答错时指出首个失真层？

**一条主线：**

```text
问题+候选 → 算 token 预算 → 过滤可见范围 → 检索/重排 → 注意力组合 → 生成+引用 → 分层指标
```

**三个关键词：** 固定输入、逐层中间结果、首个失真层——固定输入让对比可复现，中间结果让每层可检查，失真层让修复有落点。

**最容易错：**

- 先按相似度取 top1 再过滤 tenant，C 相似度 0.95 却越权，过滤后还可能成空；
- 用字符数估 token，截断时把“20%”所在句子切掉；
- 证据只放旧版 A，低温度只会更稳定地答出 30%；
- 看到 Recall@3=1 就判定链路正常，忽略排序、引用和生成层失败。

**与前后章：** 上一章给的是评测方法与口径，本章把这些口径套在同一条链上；下一章（附录A）要你把这条链讲成两分钟的回答。

**学完应能：**

- 用同一组数据复现“换日期换答案”，说清 A/B/C/D/E 各自为何可见或不可见；
- 按 tokenizer→检索→注意力→生成→引用→评测给出每层中间结果；
- 指出首个失真层，并说明为什么不是其他层；
- 用 Recall、RR、引用支持率、错误类型证明一次修复有效。

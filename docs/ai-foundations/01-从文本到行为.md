# 第01章　一张地图：从文本到行为

[上一章](00-导读与学习方法.md) · [全书目录](教材目录.md) · [下一章](02-Tokenizer.md)

## 1. 学习目标与前置知识

能沿一次回答说明：文本怎样变成模型输入，模型怎样为下一个片段打分、选出片段并继续生成；还要分清训练怎样改变模型，应用程序又要补哪些检查。前置：会基本编程；不要求微积分。

**本章从这里开始：** 用户输入“预付款上限是多少”，模型输出一段流畅回答。中间发生了什么？如果回答错了，是 tokenizer、模型参数、上下文、采样还是检索的问题？这一章先给一张可定位故障的地图。

## 2. 基础知识讲解

### 2.1 模型不是“查数据库”，而是逐步预测

先把生成过程拆成重复的小步骤：模型读到已有文本，为可能接在后面的各个token计算概率，按解码规则选出一个，接到文本后面，再预测下一个。token是模型处理文本的片段，下一章专门解释怎样切分。这样依赖前面内容、逐步生成后面内容的方式，叫**自回归生成**。

```text
输入：查询 预付款 上限 是 多少
预测：下一 token 概率分布
选择：？ -> “预”
追加：查询 预付款 上限 是 多少 预
再预测：下一个 token -> “付”
...
```

“回答”是很多次小预测拼起来的序列，不是一次性从知识库取出完整句子。这解释了三个现象：

- 输出可以很流畅，但事实可能错；
- 同一问题多次调用可能不同（采样）；
- 上下文里给什么证据，会直接影响下一步概率。

### 2.2 五层地图

| 层 | 回答的问题 | 典型失败 |
| --- | --- | --- |
| Tokenizer | 文本被切成什么单位？ | 中文/代码 token 数估算错、特殊字符异常 |
| 表示/Embedding | 每个 token 变成什么向量？ | 把 token 向量当成句子语义向量 |
| Transformer | 上下文怎样互相影响？ | 长文定位差、注意力被无关内容分散 |
| 输出/采样 | 下一个 token 怎样选？ | 温度/截断设置导致重复或跑偏 |
| 系统边界 | 证据、权限、工具、评测 | RAG 没召回、越权、指标选错 |

先按“改了哪里”区分方法：训练调整模型内部的参数；推理通常保持参数不变，处理本次输入；RAG把检索出的资料加入本次输入；微调则再次训练一部分或全部参数。排查问题时，先说明需要补的是当前资料，还是模型的回答行为，再决定改哪一部分。

### 2.3 一个最小概率例子

softmax 的定义是：先把每个 logit 变成正数，再除以所有正数的总和。

```text
p_i = exp(z_i) / Σ_j exp(z_j)
```

假设下一个 token 的 logits 为 `“预”=2.0、 “付”=1.0、 “退”=0.0`。直接代入：

```text
exp(2)=7.389，exp(1)=2.718，exp(0)=1，总和=11.107
p(预)=7.389/11.107≈0.665
p(付)=2.718/11.107≈0.245
p(退)=1/11.107≈0.090
```

预期三者相加为 1。温度 0.5 时代入 `z_i/T`，得到 `4、2、0`，分布约为 `0.867/0.117/0.016`；温度 2 时得到 `1、0.5、0`，分布约为 `0.506/0.307/0.186`。同一组 logits 下，前者更集中，后者更平坦。

- 贪心解码选概率最高的“预”；
- 按分布采样可能选“付”；
- 对原始分布 top-k=2，只保留“预”“付”，重新归一化为约 `0.731/0.269/0`；
- top-p=0.9 也保留“预”“付”，因为累计到 0.910 才达到阈值。

概率高只表示“在这个上下文下更可能”，不表示“事实为真”。模型可能对错误内容给出高概率，因为训练数据里这种说法常见。边界：候选集合为空、温度写成 0、或把温度当事实校验，都会让这段计算失去意义；本章的 `distribution` 用大于 0 的温度，生产服务再说明 0 的贪心语义。

### 2.4 训练与推理不是一回事

| 阶段 | 做什么 | 改变什么 |
| --- | --- | --- |
| 预训练 | 大量文本上预测下一 token | 参数 |
| SFT | 用示例教“怎样回答任务” | 参数（或部分参数） |
| RLHF/DPO | 用偏好让输出更符合人类选择 | 参数/策略 |
| 推理 | 用固定参数处理当前输入 | 不改变参数 |
| RAG | 把检索证据放进上下文 | 不改变参数 |
| 提示 | 改变指令/示例/格式 | 不改变参数 |

面试里常见的错误是把“模型不知道新政策”直接归因于“需要微调”。如果知识每天变化，RAG 通常更合适；如果是固定格式/风格/任务行为，SFT 或提示可能更合适；如果是基础能力不足，才考虑更大模型或训练。

### 2.5 系统边界为什么必须存在

模型优化的是“下一个 token 的预测”，不是“事实正确”“有权访问”“操作可回滚”。所以系统要补：

- 检索与引用：给事实来源；
- 权限与租户：在检索/执行前过滤；
- 工具审批与幂等：写操作不能只靠模型判断；
- 评测：用独立数据证明有效，而不是看一次演示。

## 3. 原理讲解与推导

### 3.1 为什么“预测下一个 token”能表现成理解

为了预测后续文字，模型会学习利用上下文中的语法、词义、人物关系和常见任务模式。注意力负责让当前位置组合其他位置的信息，前馈层继续变换这些表示，多层处理后再预测输出。这能形成很强的语言与任务能力，但训练得到的统计规律，并不等于一份能逐条查证的事实数据库。

### 3.2 上下文是“工作记忆”，不是永久记忆

本次输入、历史消息、检索证据、工具结果都占上下文窗口。窗口是 token 上限，不是字符上限；超出后要截断、摘要或检索。窗口变大不等于模型能同等可靠地使用每个位置，长上下文仍有定位和“中间遗忘”问题。

设窗口 8192，系统提示 400、历史 1200、当前问题 100、证据 5600、输出预算 800，总计 8100，只剩 92 token 余量。预期是“勉强放得下但不安全”；若工具再返回 200 token 就超限。应把证据缩到与问题直接相关的 2–3 段，而不是无声砍掉末尾证据。这里只演示预算算术，真实计数仍由目标 tokenizer 给出。

### 3.3 参数记忆与非参数记忆

- **参数记忆**：训练时压进权重的知识，更新慢、难溯源、可能过时。
- **非参数记忆**：检索库、数据库、文件，更新快、可引用、可权限控制。

RAG 把非参数记忆放进上下文；微调把行为/知识写进参数。两者可以组合，但要先问“更新频率、可追溯性、权限、成本”四个约束。

用同一需求代入：制度每周可能变化，需要引用且按租户授权，四项分别指向外部检索、可引用、可过滤、按本次检索计费；因此优先 RAG。若公司只要求固定 JSON 格式、制度不变，才更偏向提示或 SFT。边界：RAG 不能补基础推理能力，微调也不能让参数自动获得实时权限。

## 4. 示例与逐步走查

### 4.1 温度改变的到底是哪一步

```python
# runnable
import math

logits = {"预": 2.0, "付": 1.0, "退": 0.0}

def distribution(logits, temperature=1.0):
    if temperature <= 0:
        raise ValueError("temperature 必须大于 0")
    scaled = {token: value / temperature for token, value in logits.items()}
    maximum = max(scaled.values())
    exps = {token: math.exp(value - maximum) for token, value in scaled.items()}
    total = sum(exps.values())
    return {token: value / total for token, value in exps.items()}

print("输入:", logits)
for temperature in (0.5, 1.0, 2.0):
    probabilities = distribution(logits, temperature)
    print("中间结果:", {"temperature": temperature, "probabilities": probabilities})
print("输出:", "低温选预；采样可能选付；高温候选更分散")
assert abs(sum(distribution(logits).values()) - 1) < 1e-12
assert distribution(logits, 0.5)["预"] > distribution(logits, 2.0)["预"]
```

模型输出的是 logits，不是概率；softmax 才把 logits 变成概率。温度不改变客观事实，也不保证提升事实性；但它改变生成分布，因此**可能改变本次生成的答案是否正确**。温度小于 1 更集中，大于 1 更分散。减最大值只防止 `exp` 溢出，不改变最终比例。

逐步检查：

1. 输入被 tokenizer 切成 token；
2. 每个 token 变成向量，进入 Transformer；
3. 最后一层输出词表上的 logits；
4. softmax + 温度/截断得到采样分布；
5. 选中的 token 追加回上下文，继续下一轮。

### 4.2 把一次失败定位到层

以“制度已改成 20%，回答却是 30%”为例，先记录每层可观察的中间结果：输入日期是否为 2026-07-01；token 预算是否保住证据句；检索候选是否有新版 B；上下文是否真的含 B；输出是否引用 B。若引用 B 却答 30%，首个失真层至少已缩小到生成/校验，而不能只凭最终文字怪 tokenizer。

| 操作 | 预期结果 | 定位证据 |
| --- | --- | --- |
| 保持模型不变，把正确原文直接放进上下文 | 回答应能使用 20% | 仍答错说明生成/组织需继续查 |
| 恢复自动检索，但记录候选 ID | 当前日期、当前租户应召回 B | 没有 B 时查召回/过滤 |
| 固定候选 B，只检查引用 | 引用文本应含 20% | 引用存在但答 30% 是忠实性失败 |

## 5. 练习

### 练习一：跟写

用三个候选 token 和不同 temperature（0.2、1、2）手算 softmax 分布，说明哪个更集中、哪个更平坦。完成标准：三组概率各约为 1，0.2 的最大概率高于 1，1 又高于 2，并与第 4 节 0.5 的结果连成趋势。

### 练习二：改造

给上面的 `distribution` 增加 top-k：只保留概率最高的 k 个候选，重新归一化。说明 k=1 与贪心解码的关系。完成标准：k=2 后第三项为 0，前两项和为 1；k=1 时最高项为 1。若并列最高，先写清平局规则，不能把字典顺序当成天然语义顺序。

### 练习三：独立

选一个你熟悉的 AI 应用失败案例，画五层地图，标出“首个失真层”和“为什么不是其他层”。例如：回答引用了旧制度，是检索层、上下文层还是模型层？完成标准：至少给两层中间证据，并设计一个只改一层的对照实验。

## 6. 验收与自测

**行为验收：** 能画出自回归循环；能解释 token/概率/采样/上下文/参数各在哪一层；能说出一个“模型没错但系统错”的例子。

**原理验收：** 能说明“预测下一 token”为什么能表现成理解，以及它的边界；能区分参数记忆与非参数记忆。

**操作：** 固定 logits `[2,1,0]`，分别运行温度 0.5/1/2，再把正确证据直接放入上下文。**预期：** 分布从集中变平坦；有正确证据时回答应能引用 20%。**证据：** 保留三组概率、候选来源 ID 和最终引用；概率表证明采样设置生效，引用文本证明证据进入上下文，两者不能互相替代。

## 7. 面试问答与参考回答

**问：大模型生成回答的本质是什么？**

自回归地预测下一个 token：根据已有上下文输出词表上的概率分布，选一个 token 追加，再继续。回答是多次预测拼成的序列，不是从知识库一次取出。

**问：为什么模型会“胡说”？**

训练目标是预测概率，不是保证事实；参数记忆可能过时/缺失，上下文可能没有证据，采样会选到低概率内容。系统要用检索、引用、校验和评测补事实边界。

**问：RAG、微调、提示各改哪一层？**

RAG 改上下文（外部证据），提示改指令/示例，微调改参数/行为；知识频繁更新优先 RAG，固定格式/行为可考虑微调，基础能力不足才考虑更大模型/训练。

## 8. 本章小结与参考

### 8.1 一页知识地图

**本章主问题：** 从用户输入到一段流畅回答，中间经过哪几层，答错时该去哪一层找原因？

**一条主线：**

```text
输入文本 → 切 token → 向量/注意力 → logits → 温度+截断采样 → 拼成回答
```

**三个关键词：** 自回归、五层地图、参数与上下文——自回归决定回答是逐 token 拼出来的，五层地图决定先定位哪一层，参数/上下文的区分决定该训练还是该检索。

**最容易错：**

- 把回答当成一次性从知识库取出，忘了它是逐 token 采样拼成的序列；
- 用温度调事实：概率高只说明在这个上下文下更可能，不说明为真；
- 把“模型不知道新政策”直接归因于微调，而知识高频更新应先考虑 RAG；
- 只盯着模型，不补检索、权限、审批和评测这些系统边界。

**与前后章：** 上一章（导读）只给学习方法和章节链，不碰模型内部；下一章要拆开地图第一层——文本究竟怎样被切成 token。

**学完应能：**

- 画出一次调用的自回归循环，标出 token、logits、softmax 与采样位置；
- 用五层地图给一个真实失败案例定位首个失真层，并说明为什么不是其他层；
- 区分参数记忆与非参数记忆，判断一个需求该改参数、改上下文还是改提示；
- 解释 temperature 为什么改变本次答案却不修复事实。

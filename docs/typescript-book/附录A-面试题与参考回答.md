# 附录A　面试题与参考回答

[全书目录](教材目录.md) · [导读](00-导读与学习方法.md)

答案只给骨架。面试时先给结论，再补机制、边界和项目证据；不要背术语。

## 第1章　类型与运行时

**1. TypeScript 类型在运行时存在吗？**

不存在。编译后擦除，运行时是 JavaScript。类型只约束编译期能看到的代码；网络、文件、存储和用户输入必须运行时校验。

**2. `any`、`unknown`、`never` 分别怎么用？**

`any` 关闭检查，只应在迁移或确实无法建模时短暂使用；`unknown` 表示未知，使用前必须收窄；`never` 表示不可能的值，常用于穷尽检查和抛错函数返回类型。

**3. 结构化类型有什么风险？**

形状匹配不代表业务不变量成立。字段齐全的对象仍可能是旧版本、空字符串或伪造来源；结构类型检查形状，业务规则要另测。

## 第2章　联合与状态

**1. 为什么用联合类型而不是多个布尔值？**

多个布尔值允许“加载中且成功”“失败且有结果”等非法组合；联合让每个状态只带自己的字段，编译期删掉不可能组合。

**2. 判别联合怎样收窄？**

每个分支共享一个判别字段，值为不同字面量；`switch`/`if` 按该字段分支后，编译器自动把值收窄到对应形状。

**3. `never` 检查解决什么问题？**

新增状态后，未处理分支的值不能赋给 `never`，编译失败，提醒补逻辑；它把“运行时漏分支”前移到编译期。

## 第3章　对象与泛型

**1. `interface` 和 `type` 怎么选？**

需要联合、交叉、映射、条件类型时用 `type`；需要声明合并或类实现契约时用 `interface`。同一形状保留一份来源。

**2. 泛型解决什么问题？**

让同一操作对多种类型成立，同时保留具体类型信息，减少复制和 `any`。不同业务规则的类型应先具体，不要用泛型掩盖差异。

**3. `readonly` 能保证运行时不可变吗？**

不能。它只约束通过该类型的编译期赋值；对象仍可能被其他引用修改。运行时不可变需要冻结或复制。

## 第4章　运行时校验

**1. 类型正确为什么还会运行时失败？**

类型在编译后被擦除，外部数据不受编译器控制。`JSON.parse`、网络和用户输入可能返回 `null`、缺字段或错误类型；必须用运行时校验器。

**2. `Result` 和异常怎么选？**

边界解析、可预期失败用 `Result`，调用方必须处理；不可恢复或跨层中断用异常。两者可以组合，但不能让失败静默消失。

**3. 错误为什么要分类？**

UI、重试和日志依赖类型：输入错不重试，网络错可退避，认证错要登录，服务错看可重试标记。统一字符串会丢失决策信息。

## 第5章　异步与取消

**1. `Promise.all` 与 `allSettled` 的区别？**

`all` 任一失败就整体拒绝，其他任务不会自动取消；`allSettled` 等全部结束并保留每项成功/失败，适合仪表盘等部分可用场景。

**2. 取消 Promise 会发生什么？**

Promise 本身不可取消；取消信号要传给底层操作（`fetch`、流、定时器）。被取消的操作通常以 `AbortError` 拒绝，调用方要清理资源。

**3. 哪些请求可以重试？**

先判断动作重放是否安全，再判断错误与预算是否允许。GET也要遵守接收方契约；写操作的稳定键须绑定租户与载荷，接收方持久去重，不能只多加一个Header。429/部分5xx和网络故障可能可重试，仍要尊重Retry-After、总时限和次数上限。结果未知的写入先对账，不因超时换新键。

## 第6章　HTTP 与 SSE

**1. `fetch` 什么时候 reject？**

通常只在网络失败或请求中止时；404/500 是正常 HTTP 响应，必须检查 `response.ok`，并读取错误体。

**2. SSE 为什么不能直接按 chunk 切行？**

一个 chunk 可能在任意字节处结束，行和 UTF-8 字符都可能被切开。要先缓冲，按换行取完整行；`TextDecoder` 用 `{stream:true}` 保留不完整字节。

**3. 流式响应为什么不能直接重试？**

已经渲染或计费的部分无法撤回，重试可能重复文本或调用。续传需要服务端持久事件、重放游标和重新授权；当前基础SSE契约不实现这些能力，明确重新生成更易解释。最终done才给出的answerId也不能拿来取消尚未完成的远端任务；客户端abort不保证远端停止计费。

## 第7章　模块与工程化

**1. ESM 和 CommonJS 的核心区别？**

ESM 是静态模块系统，导入导出可分析，浏览器原生支持；CJS 用 `require` 同步加载。新项目优先 ESM，混用注意 `.mjs/.cjs`、默认导出互操作和 `exports`。

**2. `tsc` 和 Vite 各做什么？**

`tsc` 做类型检查，库项目还生成 `.js`/`.d.ts`；Vite 负责转译、打包、开发服务器。Vite 的 esbuild 转译不等于完整类型检查，CI 要两条都跑。

**3. lockfile 为什么必须提交？**

它固定依赖树与解析结果，保证本机、CI、部署安装同一套版本。只写 `^1.2.3` 不能复现；CI 用 `--frozen-lockfile` 防漂移。

## 第8章　React 数据流

**1. props 和 state 的区别？**

props 由父组件传入、只读；state 由组件拥有，通过更新函数触发重渲染。能由 props 计算的值不要另存 state。

**2. 为什么不能直接修改 state 对象？**

React 用引用比较判断变化；原地修改不产生新引用，可能不重渲染，也破坏历史快照。用展开、`map`、`filter` 创建新对象/数组。

**3. `useEffect` 的依赖数组怎么写？**

包含 effect 读取的所有响应式值；漏依赖读旧值，多写不必要依赖频繁重跑。清理函数负责取消请求、退订和清定时器。

## 第9章　异步数据与错误边界

**1. 客户端状态和服务端状态怎么区分？**

客户端状态由组件拥有（输入草稿、展开状态）；服务端状态是远端副本（搜索结果、用户资料），需要缓存 key、失效、重试和并发控制。

**2. 缓存 key 应该包含什么？**

所有影响结果的输入：查询词、日期、租户、主体、权限版本、索引/模型版本、分页与过滤条件。具体按实际查询决定；身份或权限切换时立即隐藏旧结果并清理/隔离缓存。键不代替后端授权。

**3. 错误边界能替代 try/catch 吗？**

不能。它只捕获子树渲染期异常，不捕获事件处理器和异步回调；异步错误要在数据层转成状态，边界用于隔离 UI 崩溃。

## 第10章　流式 AI 界面

**1. 为什么不能每个 token 都 setState？**

每token更新并非必然错误，但密集流可能增加渲染工作；按测量决定是否用时间窗口或帧合并。终止与停止要先刷新尾部缓冲，再转状态；缓冲和timer归当前run，旧catch/finally不能清新一轮数据。

**2. 停止和失败有什么区别？**

停止是用户主动取消，属于正常结果，保留已生成内容；失败是生成中断，需要错误提示和是否可重试。两者都不能清空已显示文本。

**3. 为什么以 `done` 事件而不是流关闭判断成功？**

流关闭可能是网络断开、代理超时或服务端异常；`done` 带业务完成信号和 `answerId`，才能区分完整回答和半截文本。

## 第11章　Hono BFF

**1. BFF 和 API Gateway 有什么区别？**

Gateway 偏通用流量治理（路由、限流、TLS）；BFF 偏某一客户端的契约适配（会话、字段裁剪、SSE、错误形状）。小项目可合并，但职责要分清。

**2. 为什么浏览器不能直接拿模型密钥？**

浏览器代码和网络请求对用户可见，任何打包进前端的密钥都可被提取。密钥只能放服务端，由 BFF 代理调用，并做身份、配额和审计。

**3. SSE 透传为什么不能先读完整 body？**

response.text()会等流结束而失去增量。可透传upstream.body，也可用流式转换重写协议，但都不能先读完整体；还要验证代理的缓冲/压缩不会延迟事件，并传播取消与超时。当前BFF只实现search，SSE代理仍待接入验证。

## 第12章　SQL 与 Drizzle

**1. ORM 能代替 SQL 吗？**

不能。ORM 帮你映射和组合查询，但不自动优化索引、事务边界和 N+1；复杂查询和性能问题仍要看 SQL 与执行计划。

**2. 唯一约束和唯一索引有什么区别？**

多数数据库用唯一索引实现唯一约束；约束表达业务规则，索引提供执行结构。并发下靠数据库唯一性，不靠应用层先查后插。

**3. SQLite 能直接用于生产吗？**

单机、低并发、嵌入式可以；多用户服务要考虑写并发、备份、迁移和运维。教学先用 SQLite，部署前评估 PostgreSQL。

## 第13章　认证与多租户

**1. Cookie 会话和 JWT 怎么选？**

Cookie是传递方式，JWT是格式，可以组合；HttpOnly限制脚本读Cookie，不自动实现撤销或阻止XSS代发请求。浏览器可用不透明会话ID与服务端状态控制撤销；短寿命JWT可用于受限服务调用。始终明确签发者、受众、过期和权限变化的传播机制，不能只选一个名词。

**2. 认证和授权有什么区别？**

认证确认“你是谁”（登录、会话、令牌）；授权确认“你能做什么”（角色、对象级权限）。多租户还要确认“数据属于谁”，并在查询层过滤。

**3. 为什么跨租户返回 404？**

避免泄露资源存在性，降低枚举风险。同一租户内存在但无权限才返回 403；两种响应语义要统一。

## 第14章　AI SDK 与工具调用

**1. 工具描述和授权是什么关系？**

描述帮助模型选择工具，不是权限。授权由服务端按 Actor、租户、资源和动作判断；模型可以请求，不能决定越权。

**2. 什么时候用 MCP？**

工具在独立进程/服务、需要被多个客户端共享、需要独立权限和部署时用 MCP；同进程简单函数或已有清晰 REST API 时直接调用更简单。

**3. 结构化输出能保证 JSON 正确吗？**

不能保证语义正确。它提高格式概率，仍需运行时校验字段、值域和跨字段规则；失败要有限重试/人工处理。

## 第15章　测试

**1. 单元测试和集成测试怎么划分？**

单元测试隔离外部 I/O，测纯函数/状态机，快且定位准；集成测试走真实路由、中间件、数据库/假上游，验证协作。两层都要。

**2. 契约测试解决什么问题？**

验证前端/后端对字段、类型、错误码的真实理解，能发现“类型没变但服务端字段改了”的漂移；类型检查只在编译期。

**3. 覆盖率越高越好吗？**

不是。覆盖率是信号；关键是权限、金额、状态、错误路径是否覆盖。为 100% 写无意义断言会增加维护成本。

## 第16章　Playwright

**1. E2E 应该覆盖多少？**

少而关键：登录、主任务、核心错误/空状态、一次关键写入。字段级分支用单元/集成测试；E2E 维护成本高。

**2. 为什么用角色选择器而不是 CSS？**

角色/名称对应可访问性树，和用户/读屏看到的结构一致；CSS 类与样式耦合，重构就失败，信号价值低。

**3. 怎样减少 E2E flaky？**

独立上下文/数据、等待可观察状态、固定网络替身、固定浏览器版本、失败保留 trace；不要靠加大超时掩盖竞态。

## 第17章　可观测性与成本

**1. 日志、指标、追踪怎么分工？**

日志记录单次事件与错误细节；指标做聚合/告警；追踪展示一次请求跨层因果。三者用 requestId/traceId 关联，不能互相替代。

**2. AI 应用的成本怎么归因？**

按租户/功能/模型记录输入输出 token、重试、缓存和工具调用，配置化单价并记录版本；估算用于优化，账单以供应商为准。

**3. 提示注入能靠 system prompt 防住吗？**

不能。模型输出不可信；权限、工具白名单、数据过滤、URL 白名单和审批必须在服务端代码里，提示词只是辅助。

## 第18章　部署与 Capstone

**1. 为什么部署要用不可变镜像？**

保证测试/预发/生产运行同一份产物，只换配置；避免服务器现场构建导致“我机器上能跑”。回滚也只需切回上一个 digest。

**2. 数据库迁移怎样支持回滚？**

用扩展/收缩：先加兼容结构、双写/回填、切读、旧实例退出后再删。代码可回滚，数据迁移通常不可逆；破坏性变更要分多次发布。

**3. 健康检查和就绪检查有什么区别？**

health/liveness 表示进程活着，失败可重启；ready 表示能接流量（依赖/迁移就绪），失败只摘流量，不重启。liveness 不应依赖外部上游。

## 通用追问

**“你这个项目最难的部分是什么？”**

给一个具体失败：例如“流式中文被 chunk 切断导致乱码”，说明如何用缓冲和流式解码定位，修复后加了跨 chunk 测试。不要只说“用了某框架”。

**“你怎么证明它不是碰巧成功？”**

给固定输入、失败注入、边界条件、前后指标和已知限制；说明哪些是真实运行，哪些仍是实验。

# 第02章　联合、收窄与不可表示状态

[上一章](01-类型只在编译期.md) · [全书目录](教材目录.md) · [下一章](03-对象泛型与契约.md)

## 1. 学习目标与前置知识

能用联合类型表达“一个值只能是几种状态之一”，用判别字段收窄，用 `never` 检查遗漏，并避免用多个布尔值拼出不可能状态。前置：第 1 章。

**本章从这里开始：** 一个审查任务可能排队、运行、等待批准、完成、失败或取消。用 `loading`、`success`、`error` 三个布尔值表示，会出现“既成功又失败”“未开始却已完成”等组合。类型系统能把这些组合直接删掉吗？

## 2. 基础知识讲解

### 2.1 字面量联合比 string 更精确

`string` 允许任意文本，`"paid" | "pending" | "cancelled"` 只允许三个值：

```ts
type OrderStatus = "paid" | "pending" | "cancelled";

function isPaid(status: OrderStatus): boolean {
  return status === "paid";
}

// isPaid("paidd"); // 编译错误
```

字面量联合适合状态、角色、事件类型和协议字段。运行时数据仍需校验，因为网络可以送来任意字符串；类型只在代码内部约束。

`as const` 可以保留字面量：

```ts
const STATUSES = ["paid", "pending", "cancelled"] as const;
type OrderStatus2 = (typeof STATUSES)[number];
```

`STATUSES` 的类型是只读元组，`OrderStatus2` 是三个字面量的联合。需要运行时遍历时用数组，需要类型约束时用联合，二者可共用一份常量。

### 2.2 判别联合：用字段区分分支

给每个分支一个共同的判别字段：

```ts
type TaskState =
  | { status: "queued" }
  | { status: "running"; startedAt: string }
  | { status: "waiting_approval"; reportId: string; version: number }
  | { status: "completed"; receipt: string }
  | { status: "failed"; error: string }
  | { status: "cancelled"; reason: string };
```

`status` 是判别字段。`switch (state.status)` 后，每个分支自动收窄到对应形状；访问 `reportId` 只在 `waiting_approval` 分支合法。

```ts
function describe(state: TaskState): string {
  switch (state.status) {
    case "queued":
      return "排队中";
    case "running":
      return `运行中，开始于 ${state.startedAt}`;
    case "waiting_approval":
      return `等待批准：${state.reportId} v${state.version}`;
    case "completed":
      return `已完成：${state.receipt}`;
    case "failed":
      return `失败：${state.error}`;
    case "cancelled":
      return `已取消：${state.reason}`;
    default:
      return assertNever(state);
  }
}

function assertNever(value: never): never {
  throw new Error(`未处理的状态: ${JSON.stringify(value)}`);
}
```

新增一个状态而忘记处理时，`state` 在 `default` 分支仍是该新类型，不能赋给 `never`，编译失败。这是“删掉不可能组合”的实用手段。

### 2.3 可选、`undefined` 与 `null`

TypeScript 区分“属性不存在”“属性存在但值为 `undefined`”“属性存在但值为 `null`”。在 `strict` 下，可选属性读取得到 `T | undefined`，必须先判断。

```ts
type Document = {
  id: string;
  title?: string;
  deletedAt: string | null;
};

function displayTitle(doc: Document): string {
  return doc.title?.trim() || "(无标题)";
}
```

`title?: string` 表示可以没有；`deletedAt: string | null` 表示字段必须有，但可以是空值。业务上“从未填写”和“明确删除”不应混成一个 `undefined`。`exactOptionalPropertyTypes` 会进一步区分“没有 title”和“title: undefined”。

不要用 `!` 非空断言掩盖不确定：`doc.title!` 只让编译器闭嘴，运行时仍可能是 `undefined`。

### 2.4 `satisfies` 与 `as const`

`as const` 保留字面量；`satisfies` 检查形状但不拓宽类型：

```ts
type Route = { path: string; auth: boolean };

const routes = {
  search: { path: "/api/search", auth: true },
  health: { path: "/health", auth: false },
} as const satisfies Record<string, Route>;

routes.search.path; // "/api/search"（as const 保留字面量）
```

`satisfies` 只检查“这个值是否兼容目标类型”，**不会自动把属性值保留为字面量**；上面的 `path` 如果没有 `as const`，会被拓宽成 `string`。需要字面量时用 `as const`，需要检查形状时用 `satisfies`，两者解决不同问题。

## 3. 原理讲解与推导

### 3.1 联合是“或”，不是“都可选”

`A | B` 表示值属于 A 或 B 之一。没有判别字段时，编译器只能访问两者共有成员；访问分支独有字段会报错。判别字段把“或”变成可分支的结构。

### 3.2 收窄靠控制流

`if`、`switch`、`typeof`、`in`、`instanceof`、自定义类型守卫都会收窄。收窄只在当前分支有效，函数调用后可能失效；把值存进新变量、传进回调时，要重新确认。

### 3.3 不可表示状态优先于运行时检查

如果类型允许“完成但没有回执”，代码就不得不每次检查。用联合把“完成”分支强制带 `receipt`，把“等待批准”强制带 `reportId` 和 `version`，很多错误在编译期就消失。运行时仍需验证外部数据，因为外部值不受类型系统控制。

## 4. 示例与逐步走查

下面用**同一个** `TaskState`（含 `cancelled`）表示一次审批任务，并实现“允许的动作”：

```ts
function availableActions(state: TaskState): string[] {
  switch (state.status) {
    case "queued":
      return ["cancel"];
    case "running":
      return ["cancel"];
    case "waiting_approval":
      return ["approve", "reject", "cancel"];
    case "completed":
    case "failed":
    case "cancelled":
      return [];
    default:
      return assertNever(state);
  }
}

const waiting: TaskState = {
  status: "waiting_approval",
  reportId: "R1",
  version: 3,
};
console.log(availableActions(waiting)); // approve, reject, cancel
```

逐步检查：

1. `waiting_approval` 分支一定带 `reportId` 和 `version`，调用方不需要再判断字段是否存在。
2. `completed` 和 `failed` 共用空动作，但状态仍可区分；不要为了省分支把两者合成一个 `done`。
3. 如果删掉 `cancelled` 分支，`default` 会编译失败，提醒你补动作；新增其他状态同理。
4. 外部 JSON 仍要先 `parseTaskState` 验证；类型只约束内部值。

## 6. 验收与自测

**行为验收：** 每个状态只能访问自己的字段；新增状态时至少一处编译失败；`availableActions` 不返回未定义动作。

**原理验收：** 能解释判别字段、控制流收窄和 `never` 的关系；能举一个“多个布尔值允许不可能组合”的反例。

### 6.1 先预测，再查看解释

`type Result = { ok: true; value: string } | { ok: false; error: string };` 为什么 `result.value` 不能直接访问？

<details>
<summary>完成预测后查看解释</summary>

`result` 可能是失败分支，没有 `value` 字段。必须先 `if (result.ok)` 收窄；`ok` 是判别字段。用可选 `value?: string` 会让失败分支也能访问 `value`，从而掩盖“失败没有值”的约束。

</details>

## 7. 面试问答与参考回答

**问：为什么用联合类型而不是多个布尔值？**

多个布尔值允许 `loading=true` 且 `success=true` 这类不可能组合；联合类型让每个状态只带自己的字段，编译期删掉非法组合。

**问：判别联合的判别字段有什么要求？**

每个分支都有同一个字段，值是不同字面量；`switch` 或 `if` 才能收窄。字段本身要能唯一区分分支，不能两个分支用同一个值。

**问：`never` 检查有什么用？**

它让遗漏的分支变成编译错误：新增状态后，`default` 里的值不能赋给 `never`，提醒你补处理，而不是运行时落入未定义行为。

## 8. 本章小结与参考

- 字面量联合表达有限取值；`as const` 保留字面量。
- 判别联合把状态和字段绑定，`switch` 自动收窄。
- 可选、`undefined`、`null` 是不同业务状态，不要混用。
- `never` 用于穷尽检查；外部输入仍要运行时验证。

## 为什么在 AI 时代学 TypeScript

AI 应用越来越多地以 Web 界面交付：流式回答、引用来源、工具轨迹、审批按钮、失败重试。Python 擅长后端与模型，但浏览器里的状态、异步流和交互边界需要另一门语言。TypeScript 的价值不在“再学一门语法”，而在三件事：

1. **把接口契约写进编译期**：前端如何使用已校验的数据，在编辑器和 CI 里检查；后端实际响应仍需运行时校验与跨语言契约测试。
2. **把异步与流式状态显式化**：加载、增量、完成、失败、取消是不同状态，不能靠几个布尔值拼。
3. **把 AI 的不确定性放进界面**：引用、待复核、工具执行证据都需要类型和组件承载，不凭空生成一个“置信度”数字。

它不替代 Python 主线。检索、模型、评测和 Agent 后端仍按 Python 教材推进；本书只做交付边界。

## 与 Python 的差异

- Python 的类型标注和 TypeScript 的静态类型都不会自动校验网络数据；TypeScript 编译后运行的是 JavaScript。mypy/pyright与tsc用于静态检查，Pydantic或本书解析函数用于运行时边界。**类型正确不等于数据可信。**
- TypeScript 是结构化类型：只要形状匹配就能赋值，不要求显式继承。
- `undefined`、`null`、可选属性、联合类型需要显式收窄，不能用“先跑起来”代替分支。
- 异步不是线程：Promise 和事件循环负责等待，CPU 密集工作仍会阻塞。
- npm 依赖、`tsconfig` 和构建产物是交付的一部分，版本要锁定。

## 怎样使用本书

1. 先读一章的目标与开场问题，合上资料写下自己的预测。
2. 运行类型检查：先进入 [`typescript-examples/`](../../typescript-examples/README.md)，执行 `pnpm typecheck`；需要 Node 22+。
3. 改一个条件，观察编译错误或运行时行为；错误信息就是反馈。
4. 完成章末练习，保留“输入、预期、实际、首个分叉”。
5. 用自己的话回答面试题，再看参考回答；参考答案只给骨架，项目证据要用自己的代码。

示例不要求先安装所有框架。全书 18 章覆盖 Node 22、TypeScript、React、Hono、Drizzle、Vitest/Playwright 与部署；累计实现按配套工程的文件推进；正文引用同一份源码，独立观察、设计示意和故意失败片段不并入项目。复制单个块到空文件时，先补齐它依赖的类型和辅助函数。

## 片段怎样进入同一个工程

| 标记 | 用法 |
| --- | --- |
| 源码导入/文件链接 | 在typescript-examples对应文件继续修改；同一份代码参与构建与测试 |

前六章涉及的最小工程现在从导读即可运行；第7章深入解释工具配置。每章完成任务后使用新条件检查，不等第15章才首次测试。

## 一个贯穿项目

所有例子围绕同一个 **DocPilot Console**：搜索制度、提问、显示引用、处理流式回答、展示失败与待复核。它消费 Python 教材里的后端契约，不复制检索或审批规则。全书先把类型、运行时、异步和流跑通，再做界面、BFF、数据与交付。

## 本书不覆盖什么

JavaScript 语言大全、浏览器 DOM 全部 API、React 内部实现、Node 运行时源码、完整前端工程体系都不在本册范围。遇到这些内容，先查官方文档，再把与当前交付有关的最小部分带进项目。

## 每章的统一结构

目标与前置 → 基础 → 原理 → 实例 → 练习 → 验收 → 面试 → 小结。练习分“跟写、改造、独立”三层；做完一章至少留一个能运行的类型检查或小脚本，不只看懂。

# TypeScript 与 AI 应用交付

**面向已有 Python/Java 后端经验、希望用 TypeScript 交付 AI 应用界面与工具链的学习者。**

AI 应用的主线仍然是 Python：模型调用、检索、Agent、评测和后端服务在 Python 教材中完成。TypeScript 补的是另一条交付边界：把后端契约变成前端类型，把流式响应稳定地渲染出来，把工具调用、审批和恢复做成可操作的控制台。两本书共用同一个 DocPilot/ProcureAgent 项目，不另起一套业务。

## 与 Python 教材的关系

- Python 教材负责：服务、数据库、检索、模型、评测、Agent 与恢复。
- 本书负责：把服务契约变成前端类型、处理异步与流、渲染证据与不确定性、组织控制台交互。
- 两本书使用同一个DocPilot场景，但内存核心与D2持久参考有不同响应粒度；以[附录B](附录B-与Python后端的契约.md)的显式适配为准。任务、审批与恢复也要核对实际接口，不假定浏览器模板已经接通。
- 前端不直接保管模型密钥；浏览器只访问自己的 BFF 或受控后端。

## 每章怎样读

每章统一为八节：目标与前置 → 基础 → 原理 → 实例 → 练习 → 验收 → 面试问答 → 小结（含参考回答）。先读问题，再运行类型检查，最后合上资料写自己的类型。

示例以Node22、锁定的TypeScript及依赖为基线。累计实现按配套工程文件推进，正文引用同一源码；独立观察、故意失败与设计示意各按说明阅读，不能把一章所有代码块顺序拼成一个文件。跨章复用使用明确导入与文件链接。

配套[工程](../../typescript-examples/README.md)含校验、SSE、控制器、React Hook/组件、Hono和SQLite/Drizzle。使用pnpm typecheck、pnpm test、pnpm start复现当前基线；React在jsdom执行，尚无浏览器宿主页。真实会话、真实流式后端、Playwright、迁移和Docker是后续实施目标，不能由当前通过结果代替。

## 交付物

读完第 1–18 章后，你应能：

1. 为后端 JSON 写出编译期契约，并在运行时验证它；
2. 用联合类型表达任务状态，删掉不可能的状态组合；
3. 处理并发、取消、超时和失败，不留下未处理 Promise；
4. 解析 SSE 流，边收边渲染，并正确处理中止与错误；
5. 解释 TypeScript 类型为什么不能替代运行时校验。

第二至第四部分再把它们接到流式界面、Hono BFF、数据、AI 工具调用、测试和部署。

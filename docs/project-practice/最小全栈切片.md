# 最小全栈切片：搜索页面 → BFF → Python → 来源

[学习导航](../学习导航.md) · [项目交付手册](从实验到项目交付.md) · [TS 第18章](../typescript-book/18-部署与Capstone.md)

**状态：BFF 与 React 最小宿主已实现；浏览器自动化未验证。**

Python 侧有 DocPilot 参考服务，BFF 有 Node HTTP 入口，`host-client.tsx` 由 esbuild 打成 `host/app.js`，复用 `SearchPage` 完成“搜索→结果→来源面板”。独立来源页与 Playwright 仍未接入；不要把这版宿主当成完整 Console。

## 0. 先做更小的 B+ 页面

在进入本切片前，先做一个不依赖 React、认证和数据库的页面：

```text
输入订单金额 → 点击提交 → POST /api/preview → 页面显示计算结果
```

只验证四件事：表单提交、HTTP JSON、DOM 渲染、加载/错误状态。它属于学习导航的 B+ 阶段；跑通后再进入下面的搜索切片。不要一开始同时补 React、BFF、认证和 RAG。

当前仓库的 `typescript-examples/src/host-client.tsx` 是搜索切片的 React 宿主：复用 `SearchPage`，用 esbuild 打包到 `host/app.js`；B+ 的无框架版本可先用原生 HTML/JS 完成，再迁移到 React。

## 1. 这一片要证明什么

```text
浏览器输入问题 → BFF 转发 → Python 检索服务 → 返回来源 → 页面打开原文
```

只证明四件事：

1. 页面能把查询送到 BFF；
2. BFF 能带上可信身份转发，不让浏览器伪造 tenant；
3. Python 返回稳定结构，空结果/越权/上游失败可区分；
4. 目标是浏览器能打开对应版本的完整原文。当前面板仅显示检索命中的引文与定位，不代表原文获取和再次授权已经完成。

不在这一片做：真实模型生成、SSE 流式、完整认证系统、审批、写入、Docker 生产部署。它们接在同一条链上逐步增加。

## 2. 三层契约：浏览器、BFF、Python

现有工程已经有三块可复用实现，不要再造一套平行协议：

| 层 | 现有位置 | 负责什么 |
| --- | --- | --- |
| Python 检索服务 | `practice/learning_projects/service.py`、`practice/integration_labs/docpilot.py` | 授权、日期过滤、检索；线协议用 snake_case |
| BFF | `typescript-examples/src/bff.ts` + `server.ts` | 身份、校验、超时、错误映射；Node HTTP 入口已可启动 |
| 搜索组件 | `typescript-examples/src/search-page.tsx` | 表单、加载/空/错误、结果与来源回调 |
| React 宿主 | `typescript-examples/src/host-client.tsx` + `host/index.html` | 挂载 SearchPage、来源面板；esbuild 打包为 `host/app.js` |
| 浏览器自动化 | **尚缺** | Playwright 未接入；本环境 Chrome headless 启动被沙箱拒绝 |

固定一条浏览器契约，避免 `results/quote/url` 与 `items/source_id/text` 两套各说各话：

```http
POST /api/search
Content-Type: application/json

{ "question": "预付款上限", "as_of": "2026-07-01" }
```

成功（浏览器/BFF 层，camelCase）：

```json
{
  "items": [
    {
      "sourceId": "policy-a",
      "version": "2",
      "title": "预付款制度 v2",
      "quote": "预付款比例不得超过合同金额的20%。",
      "location": { "kind": "chunk", "chunkId": "[\"a\",\"policy-a\",\"2\",0]", "start": 0, "end": 18 }
    }
  ]
}
```

浏览器不直接使用 Python 的 `source_id/text/start/end`；BFF 负责映射成上面的 `SearchHit`。偏移按 Unicode 码点计数，本例引文为18个码点。完整来源页扩展时，可按 sourceId + version 构造路由，但当前页面只调用来源摘要面板，并未实现 `/sources/:sourceId`。完整原文需要重新向后端请求和授权，不能把摘要当作已打开原文。

失败：

| 情况 | 状态 | 页面行为 |
| --- | --- | --- |
| 空查询/非法日期/额外 tenant_id | 422 | 表单旁显示字段错误 |
| 没有可见证据 | 200 + `items: []` | 明确“没有找到可引用来源”，不伪造答案 |
| 身份缺失/越权 | 401/403/404 | 统一错误，不泄漏资源是否存在 |
| Python 不可用或响应结构错误 | 502 | 显示上游失败，保留重试；不冒充空结果 |
| 上游超时 | 504 | 可重试提示，不返回空列表冒充成功 |

**开发期身份：** BFF 的 `authenticate` 适配器可以把开发 token 映射为固定 `tenantId=a`，再以服务端 token 转发给 Python；浏览器不能传 `tenant_id`。这是开发身份，不是生产认证。

## 3. 实施顺序

### 第 1 步：Python 返回稳定 JSON

- 复用 DocPilot 的可信租户、日期过滤、检索与来源结构；
- 用固定数据测试正常、空结果、跨租户、日期边界；
- 先不接模型，不生成自然语言答案。

验收：HTTP 测试能拿到稳定 `items`（snake_case），错误码可区分。

### 第 2 步：BFF 只做转发与身份

- `POST /api/search` 接收 `{question, as_of}`；
- 通过 `authenticate` 取得 `tenantId/upstreamToken`，拒绝浏览器传入的 `tenant_id`；
- 转发到 `DOCPILOT_URL`，超时/错误映射为上面的失败表；
- 用 `parseSearchResponse` 把 Python 的 `items/source_id/text/...` 转成浏览器 `SearchHit`。
- 不复制检索规则，不在 BFF 重新算金额或权限。

验收：浏览器传 `tenant_id=b` 返回 422；BFF 日志不打印密钥；Python 返回坏字段时 BFF 回 502，不静默默认。

启动与最小验证：

```powershell
# 终端1：Python
uv run --frozen --group web uvicorn practice.learning_projects.service:create_app --factory --port 8001
# 终端2：BFF
cd typescript-examples
pnpm build
$env:DOCPILOT_URL="http://127.0.0.1:8001"; $env:BFF_PORT="8787"; pnpm serve
# 终端3：真实 HTTP 探针
node --input-type=module -e "const r=await fetch('http://127.0.0.1:8787/api/search',{method:'POST',headers:{Authorization:'Bearer demo','Content-Type':'application/json'},body:JSON.stringify({question:'预付款',as_of:'2026-08-01'})}); console.log(r.status, await r.text())"
```

这证明 BFF→Python 的 HTTP 链路，不证明浏览器页面和来源页已经完成。

### 第 3 步：最小页面

当前 `src/host-client.tsx` + `host/index.html` 已覆盖：

- 复用 `SearchPage`：查询框、业务日期、提交按钮；
- 用 React 渲染结果，文本走 `textContent` 语义，不拼 HTML；
- 结果为空、加载中、错误分别有文案；
- 每条结果有“打开来源”，在来源面板显示 sourceId、version、quote 和 location。

这不是独立来源页：`/sources/:sourceId` 路由仍待做；来源目前以页面内面板展示。

验收：键盘可提交；空结果不显示空白页；错误不伪装成“没有结果”；来源面板显示 sourceId、version、quote 和 location。

### 第 4 步：浏览器验收

目标是用 Playwright 覆盖：

1. 输入“预付款” + 日期，显示一条结果和来源；
2. 返回空列表，显示“没有可引用来源”；
3. 返回 503，显示可重试错误；
4. 浏览器提交额外 `tenant_id` 时返回422，不请求Python；
5. 点击来源，打开对应版本内容。

**当前状态：Playwright 未安装；本环境 Chrome/Edge headless 启动被沙箱拒绝，尚未取得真实浏览器证据。** 可以在正常桌面环境用 `pnpm serve` 后手动打开 `http://127.0.0.1:8787/?q=预付款&date=2026-08-01&open=1`，或补 Playwright 后按上面 5 条实现。仅用 `page.route` 固定响应不算真实链路。

### 4.1 手工浏览器验收（当前可执行）

Playwright 未接入，但可以先按下面步骤留真实浏览器证据：

1. 启动 Python 与 BFF，打开 `http://127.0.0.1:8787/`；
2. 问题填“预付款”，日期填 `2026-08-01`，提交；确认出现结果和“打开来源”；
3. 点“打开来源”，确认面板显示 sourceId、version、quote、location；
4. 问题改成不存在的词（如“火星报销”），确认显示“没有找到可引用来源”，不是空白；
5. 停掉 Python 再搜索，确认显示“检索暂不可用”类错误，不是伪造空结果；
6. 用键盘 Tab 完成一次提交，确认焦点可见、label 可读。

记录：截图/录屏、请求 URL、响应摘要、控制台错误、仍缺失的检查。没有这些记录，不能宣称“浏览器已验收”。

## 5. 已实现的模型流式协议演示

BFF 新增 `POST /api/answer {question}`：

```text
浏览器 → BFF /api/answer → Ollama /api/chat(stream) → NDJSON 适配器 → 应用 SSE(token/done/error)
```

- `provider-stream.ts` 负责跨字节 UTF-8、done/用量、tool_calls、错误行；
- `stream-answer.ts` 负责预算/取消与 SSE 编码；
- `answer-stream.test.mjs` 用固定 NDJSON 验证 token/done/error/tool 事件；
- `real-http-stream.test.mjs` 用真实 HTTP 假 Ollama 上游验证 BFF → NDJSON → SSE；
- 宿主页有“流式回答”面板，停止会 abort；真实 Ollama 未在 CI/本环境验证。

搜索与模型使用不同地址和凭据。在启动 BFF 的终端中配置后重启：

```powershell
$env:DOCPILOT_URL = "http://127.0.0.1:8001"
$env:OLLAMA_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "你的本地模型标签"
pnpm serve
```

模型代理需要认证时才提供 OLLAMA_API_KEY；Python 教学 token 不会发给模型。未配置模型时本端点返回503，搜索仍使用原 Python 服务。

先观察正常请求的三层行为：供应商写一行 NDJSON，适配器产生 token，Node 入口立即转发对应 SSE；只有正常 stop 才发送 done。然后去掉终止行、改成 length、点击停止，分别观察未完成错误和上游连接关闭。HTTP 回归用“上游尚未结束，客户端先收到首段”验证流式，避免只在最后检查整包文本。

此端点不检索、不检查引用，是模型协议演示；搜索结果不会自动进入模型上下文。工具事件仅映射，前端目前忽略它们，也不会执行工具。真实模型、用量和浏览器仍需另验；HTTP取消已传播，也不证明远端已经停止计费。

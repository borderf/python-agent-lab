## 把20步核心带到持久服务

第23章20步实现的是规范化、分块、检索与回答核心，4.5的HTTP切片直接调用你指定的模块。下面的D2则是另一份持久化参考，当前retrieve使用来源级排序，**没有自动导入你的20步实现**。运行它可以学习数据库、界面与反馈，不能据此声称自己的核心已经完成集成。

先比较契约，再接代码，避免复制路由后默默改变业务：

| 边界 | 20步核心 / 内存HTTP切片 | D2持久化参考 | 集成时要做的决定 |
| --- | --- | --- | --- |
| 身份 | 教学令牌对应a/b | 教学令牌对应tenant-a/tenant-b | 名称不同，语义相同；同一请求使用同一可信映射，禁止由正文覆盖 |
| 文档 | 严格7字段，身份在记录内 | 数据表另含section，上传身份由服务端注入 | 显式投影7字段；section另留作显示元数据，不把额外字段直接塞入normalize_document |
| 来源身份 | tenant/source/version标识一个版本 | 数据库以tenant/source为主键，新内容用新的来源ID | 先沿用D2的新版本ID策略；要让同source存多版本，需单独设计迁移与旧引用兼容 |
| 日期 | YYYY-MM-DD文本，半开区间 | 入口解析date，持久记录用ISO文本 | 统一转换，特别测试valid_to当天不可见 |
| 检索结果 | chunk_id、片段和start/end | source_id、整段来源及section | 不能把来源命中当分块命中；先让搜索接口明确返回哪种粒度 |
| 模型与引用 | 回调返回dict，引用chunk_id | 模型适配器返回带content/model/usage的结果，引用source_id | 两种契约并不直接兼容；先接搜索，再明确适配引用与元数据 |
| 存储 | 启动时内存构建 | 迁移、事务与持久查询 | 保存原文事实，定义何时重建/失效索引；不能启动时读一次后永远不刷新 |

### 先接搜索，再接生成

1. **保留自己的核心。** 指定自己的模块重跑20步契约，记录代码版本。将D2当作外层参考，不用参考核心替换自己的实现来获得全绿。
2. **连接文档读取。** 从数据库按可信租户读取，显式提取7字段，调用自己的build_index与search。小数据首版可在请求时重建授权范围内的索引，便于看清行为；这是教学取舍，不宣称有生产容量。随后再基于测量加入版本化索引和失效策略。
3. **保留定位。** 搜索结果继续携带chunk_id、source_id、version、start/end；来源接口按当前身份重新授权，打开规范化正文后能核对 `text[start:end]`。不要将片段偏移当作原始PDF的字节或页面坐标；页码映射需另做解析定位。
4. **接回回答契约。** 使用核心的answer时，模型适配器应把实际返回转换为它需要的dict，并使用候选chunk_id；D2已有的source_id引用不能仅改字段名。模型用量等元数据留在外层保存，避免被当成核心允许字段。回调只接触证据副本，输出仍经核心检查。
5. **增加持久行为验证。** 导入后查询、同一服务进程内新增后查询、重启后查询都应成立；再补租户、日期和引用边界。数据库事务、反馈和真实模型的检查继续保留。仓库参考测试通过后，还要让测试实际调用自己的接线实现。

| 集成验收输入 | 应观察到的结果 | 仅跑核心契约为什么不够 |
| --- | --- | --- |
| 导入A，服务不停再导入B | B立即或按明确的索引更新约定可查 | 不检查数据库到索引的更新 |
| 停止并重启服务 | 仍可查已提交来源 | 内存列表不能证明持久化 |
| 用另一身份查询/打开来源 | 标题、片段、正文都不可见 | 外层来源接口可能漏掉授权 |
| 查询valid_to当天 | 旧版被排除，新版按自己的区间判断 | 入口日期转换可能改变边界 |
| 长文命中第二块并打开引用 | 能定位同版本规范化正文中的对应片段 | source_id本身没有片段偏移信息 |
| 模型返回真实来源ID但伪造chunk_id | 拒绝或进入明确失败流程 | 来源存在不等于候选引用有效 |

现在用[持久化起始签名](../../practice/learning_projects/persistence_starter.py)实现适配器，并跑[6步契约](../../tests/learner/contract_persistence.py)；细则见[练习说明](../../tests/learner/练习说明.md)。小数据版按可信租户读取已提交原文，每次请求调用注入核心重建索引，便于看清更新与引用行为。它刻意保留20步的分块契约，不改写成D2的来源级结果。

完成自己的20步核心与6步适配器后，将两者接到同一个[HTTP工厂](../../practice/learning_projects/service.py)：

```powershell
$env:LEARNER_MODULE = "learner_docpilot"
$env:LEARNER_PERSISTENCE_MODULE = "learner_persistence"
$env:LEARNER_DOCS_DB = ".learning-labs/learner-docpilot.sqlite"
uv run --frozen --group web uvicorn practice.learning_projects.service:create_app --factory --host 127.0.0.1 --port 8000
```

在 `/docs` 使用教学Bearer令牌demo-a，调用 `/api/sources` 导入，随后搜索与问答；上传字段不含tenant_id。重复相同版本返回created=false，冲突409，非法日期区间422。用demo-b查询、保持进程再导入、重启后查询，逐项保存结果。不设置持久适配器时仍为原内存切片；用后可移除本次环境变量。独立核心契约、适配器契约与HTTP参考测试分别验证不同层，不能相互代替。

这条最小持久路径尚无来源打开路由、反馈、分页与迁移管理；它不自动具备D2的完整产品能力。要继续集成，可并排读[核心契约](../../practice/learning_projects/docpilot_reference.py)、[D2服务](../../practice/integration_labs/docpilot.py)与[数据表](../../practice/integration_labs/database.py)，明确扩展字段与引用粒度后再接后续功能。

## 从空数据库启动 D2

```powershell
uv run --frozen --group web python -m practice.integration_labs.docpilot init
uv run --frozen --group web python -m practice.integration_labs.docpilot seed
uv run --frozen --group web uvicorn practice.integration_labs.docpilot:create_app --factory --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000`。初始化命令将两次 Alembic 迁移写入 `.learning-labs/docpilot.sqlite`，seed 导入原有虚构制度。重复 seed 复用相同来源；同一来源 ID 对应不同内容会报冲突。

1. 使用教学令牌 `demo-a` 查询“本租户预付款比例上限是多少”，日期选 2026-10-01。打开引用，核对有效原文中的 20%。fixture 模型会复述候选原文并提示复核。
2. 将日期改成 2026-06-30，核对旧版 30%。逐层说明变化发生在日期过滤、候选还是生成。
3. 将令牌改成 `demo-b`，查询其 10% 的教学制度。直接请求另一租户的来源应得到 404。去掉身份得到 401，在请求体加 tenant_id 得到 422。
4. 展开导入区，输入自己的资料，查询其中的独特术语，打开新来源。给回答提交一次反馈，再在数据库中查到对应 answer_id。
5. 停止并重新运行服务，查询刚才导入的资料。把结果与内存列表版比较，解释数据为什么保留。

教学令牌由服务端映射到主体，演示身份与数据查询如何衔接。实际试点应接入组织身份或明确的账户会话方案，并验证退出、过期、撤权和对象访问。身份替换练习保留现有业务测试。[参考服务](../../practice/integration_labs/docpilot.py) · [数据模型与迁移入口](../../practice/integration_labs/database.py) · [参考界面](../../practice/integration_labs/docpilot.html)

### 沿一条请求解释每层责任

| 顺序 | 阅读位置 | 解释与验证 |
| --- | --- | --- |
| 输入 | DocumentInput、QuestionInput | Schema 拒绝未知字段，日期转换发生在入口；业务日期怎样进入过滤 |
| 身份 | identity | 令牌怎样被转换为可信租户；模型与正文为什么无法覆盖它 |
| 持久化 | put_document 与 Session | 会话由谁关闭；重复导入与冲突分别发生什么；事务在哪里提交 |
| 检索 | retrieve | 授权范围和日期如何影响候选；何时返回没有依据 |
| 模型 | models.py | fixture、本机、托管结果怎样进入相同内部契约；真实用量缺失时如何表达 |
| 输出与反馈 | validate_answer、AnswerRecord、Feedback | 引用存在和支持结论各由谁检查；回答 ID 如何限制反馈范围 |

服务在等待模型前释放读取事务。先让模型返回不存在的来源 ID，观察 502，再核对没有保存成功回答。手工把回答内容改错但保留真实引文，解释为什么还需要语义评测。

## 将文本 PDF 接到同一条链路

准备一份有权使用的文本 PDF。先用阅读器写下每页的原文和对应问题，再运行导入。CLI 使用本机操作者提供的教学身份，Web 请求仍使用服务端身份。

```powershell
uv run --frozen --group web python -m practice.integration_labs.docpilot import-file --file "your-policy.pdf" --source-prefix manual --valid-from 2026-07-01
```

解析器逐页保留 `PDF 第 n 页`，整批解析和校验完成后才进入导入事务。空页会要求人工检查或另做 OCR。将第二页换成扫描页，核对本次新来源没有只导入一半。TXT 使用相同命令，正文采用 UTF-8。[页码解析实现](../../practice/integration_labs/files.py)

下一步把本机导入改成受控上传。先限制大小与格式，将文件保存为服务端生成的存储标识，接任务表，再返回任务 ID。分别注入解析失败、持久化失败和重复投递，检查状态与用户下一步动作。

### 托管聊天接口

适配器接收 HTTPS、单次 JSON 聊天响应，读取 choices、message、finish_reason 与 usage。先按服务商实际支持情况核对 JSON 输出能力、模型名、地址和凭据。可以对照[千问首次调用说明](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen)准备自己的配置。

```powershell
$env:LAB_MODEL_PROVIDER = "hosted"
$env:LAB_CHAT_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"
$env:LAB_MODEL = "your-enabled-model"
# LAB_API_KEY 使用当前会话或密钥管理器提供的值。
```

结构错误、截断、HTTP 失败和非法引用分别保留失败。当前HTTP调用传入60秒timeout，约束相关阻塞操作，不是整个请求从排队到返回的总截止时间；不能据此承诺端到端最多60秒。为整个请求增加截止时间、对429做有限退避、比较两种模型，是下一轮工程练习。远端调用按实际服务计费，先限制样本与试次。[模型适配实现](../../practice/integration_labs/models.py)

## 用真实 LangGraph 暂停并跨进程恢复

```powershell
uv sync --frozen --group agent --inexact
uv run --frozen --group agent python -m practice.integration_labs.approval_graph prepare --task T1
uv run --frozen --group agent python -m practice.integration_labs.approval_graph resume --task T1 --decision approve --fail-after-write
uv run --frozen --group agent python -m practice.integration_labs.approval_graph resume --task T1 --decision approve
```

第一条在审批节点 interrupt，进程退出后 SQLite 检查点保留状态。第二条在模拟远端已提交、图节点尚未返回时注入异常，命令应失败。第三条用原任务和载荷版本恢复，状态应为 completed；模拟远端 effects 表仍只有一条效果。再恢复一次，结果复用原回执。

分别使用新任务 T2 练拒绝，用 T3 练 `--version 2` 与原版本不一致。`--tenant` 是本机夹具身份参数，接 Web 后必须由授权上下文提供。图检查点与模拟业务账本使用两个数据库；外部效果由稳定键与远端事务保护。[图与恢复实现](../../practice/integration_labs/approval_graph.py) · [官方持久化](https://docs.langchain.com/oss/python/langgraph/persistence)

恢复请求先在应用入口检查决定与版本，再传给图。节点内也保留检查。试着在练习副本只留节点检查：一次错误的 resume 值可能被持久化，使重试继续读到原错误值。用“错误版本被拒绝后，正确版本仍可拒绝或批准”检查恢复边界。

## 将同一只读能力接入 MCP

```powershell
uv sync --frozen --group mcp --inexact
uv run --frozen --group mcp python -m practice.integration_labs.mcp_client
```

客户端用当前 Python 启动真实 Server 子进程，完成初始化、工具发现、调用和关闭。它比较本地政策函数与远程工具的结构化结果，取回授权原文，再检查伪造 tenant_id 和另一租户 source_id 都失败。结果应含 local_equal、identity_injection_rejected、other_tenant_hidden 三个 true。

本实验使用锁文件中的 MCP Python SDK 1.x 接口，依赖约束为 `<2`，对应 [1.x 官方示例](https://github.com/modelcontextprotocol/python-sdk/blob/v1.20.0/README.md#writing-mcp-clients)。升级大版本时先迁移适配器并复跑契约，避免混用不同版本入口。Server 的 stdout 留给协议，调试日志写 stderr。

stdio 子进程固定使用 tenant-a 教学身份，适合观察协议边界。改为多用户 HTTP 服务时，需要从已认证连接取得身份并在资源端授权。自行增加未知工具、坏日期、服务提前退出和超时测试，再把协议结果转换为第24章的内部工具结果。[Client](../../practice/integration_labs/mcp_client.py) · [Server](../../practice/integration_labs/mcp_server.py)

```powershell
uv run --frozen --group web python -m practice.integration_labs.evaluate --trials 2
```

默认写 `.learning-labs/docpilot-eval.jsonl`，包含当前、历史、多证据、无依据和另一租户五类题。每次尝试保存状态、引用、耗时、模型与用量，失败也有记录。fixture 对多证据问题只复述第一条，证据覆盖应失败，适合练习识别“结构正常但任务未完成”。

人工逐条标注引文是否支持结论、是否遗漏必要条件、无证据时处理是否合适。将 `manual_semantic_grade` 填为有评分说明支持的结论，再让另一人复核分歧。冻结一批未调参的题，新增失败进入开发回归集。指标口径沿用[评测手册](评测与故障演练.md)。

## 独立部署和累计验收

已有 Docker 时，可以在仓库根目录运行下面的教学配置。它将服务绑定到本机端口，SQLite 写入独立卷，默认模型为 fixture。

```powershell
docker compose -f practice/integration_labs/compose.yml build
docker compose -f practice/integration_labs/compose.yml run --rm docpilot uv run --frozen --no-sync python -m practice.integration_labs.docpilot init
docker compose -f practice/integration_labs/compose.yml run --rm docpilot uv run --frozen --no-sync python -m practice.integration_labs.docpilot seed
docker compose -f practice/integration_labs/compose.yml up
```

将公开部署作为下一次有明确环境的练习，补 HTTPS 入口、正式身份、限额、日志与备份。先让同伴按 README 完成一条任务，再制造模型故障，核对界面、请求标识和数据库。按[上线手册](../product-founder-book/附录F-上线发布与推广实验.md)记录环境、成功、停止与恢复。

本阶段的完成证据包括自己的改动、自动检查、陌生问题、一次故障定位，以及一个重新设计的边界。学完一周后换一份资料和一项字段要求重做，按[阶段自测](../python-book/附录H-阶段自测与复习.md)复验。

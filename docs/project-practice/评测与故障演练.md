## 先跑一个离线对照

从仓库根目录运行。两组方法共用可见来源和相同的 top 5。第一组忽略问题按来源 ID 排列；第二组按查询与标题、节名、正文共有的相邻双字符数量排序，并列时按 ID。服务身份由测试夹具提供，正式接口从认证上下文取身份。

```powershell
uv run python -m practice.enterprise_ai.retrieval_baseline
```

开发集有来源的 11 道题，每题有 8 个可选制度。当前固定数据中，两种方法的平均 Recall@5 分别为 0.636 和 1.000，MRR@5 为 0.248 和 0.955。后一项是前五个来源中首个相关名次倒数的平均，未命中按 0 计。找一题解释两个指标为何给出不同评价。字面重合的方法易受同义改写影响，可试着把“发票”改成“票面信息”观察名次。

固定实现与参数后运行 `uv run python -m practice.enterprise_ai.retrieval_baseline --split holdout`。这 4 道题包含新的表述与多证据问题。看过结果并据此调参后，把它们转为已知回归题，下一轮重建留出集。在 [retrieval_baseline.py](../../practice/enterprise_ai/retrieval_baseline.py) 中替换排序函数时，只给检索器问题和可见语料，标准答案留在评分端。接向量或重排模型后同时记录耗时、候选深度和索引版本。

程序只给有标准来源的问题算排名分。对另三道题，在实现的应用上单独检查无依据时的答复、另一租户材料是否从候选到输出均不可见，以及放入指定不可信附件后是否仍遵守业务约束。保存实际输出和轨迹，逐项判定。

## 检索指标

本轮先按 source_id 评估；不同版本有不同 source_id。检索返回多个同源 chunk 时先对 source_id 去重。若以后改为 chunk 级指标，要重新标注并在报告中说明，不能混用结果。

对有答案且允许访问的查询 q：

```text
Recall@5(q) = |相关来源集合 ∩ 前5个唯一检索来源| / |相关来源集合|
```

对所有此类查询取均值，并报告样本数。这里是唯一来源层级的 Recall@5；另外记录实际召回的 chunk 数、去重策略和候选上限。无相关来源、越权和证据冲突案例分别统计，避免除零或用它们抬高召回率。

- 引用正确率：被人工核对为确实支持对应结论的引用数 / 已核对引用数；同时记录回答中应有证据但没引用的结论数。
- 来源可定位性：引用是否存在、版本/节号/页码是否正确。它不能替代内容支持性。
- 无答案处理：没有证据时是否说明不足；不能用一个泛泛的回答当作正确。
- 权限隔离：固定越权案例中的不可见来源不能进入候选结果、提示和响应。

## Agent 与审查指标

| 指标 | 记录方法 |
| --- | --- |
| 任务完成率 | 按人工定义的任务结果判定完成数/总任务数；partial 单列 |
| 风险召回 | 命中人工标签风险条目数/应识别风险条目数 |
| 风险精确率 | 命中人工标签风险条目数/输出风险条目数；资料不足单列 |
| 工具正确性 | 工具是否正确选择、参数是否正确、是否执行并回传 |
| 引用与事实 | 原文/规则是否支持结论，金额是否与确定性计算一致 |
| 成本 | 相同计价口径的实际可获得费用；否则记录输入/输出 token、调用数和硬件时间 |
| 延迟 | 相同环境记录每任务耗时、p50/p95、样本数；冷启动单列 |
| 失败 | 网络、解析、检索、权限、预算、模型结构、逻辑、审批等类别 |

零分母指标记 N/A 并说明样本条件，不编成 100%。用重复运行观察模型波动，不用少数样本的 p95 宣称稳定性能。模型评审可以辅助分析，关键风险与证据标准由人工核对。

## 对照实验约束

比较固定工作流/单 Agent/多 Agent 时，共用数据、权限、模型、提示版本、工具、案例和总任务预算。另可做“各自最佳配置”的实验，但不要与受控对照混为一组。

依次只改变一项：检索策略、重排、分工、并行、核验返工。记录额外模型次数、候选数和资源。质量没有提高或改善不足以抵偿代价时，明确保留基线。

## 按项目选取故障案例

DocPilot 先验证文档、授权检索、生成和日志对应的行。ProcureAgent 增加工具、状态与审批；采用多角色后，再测子 Agent 超时。

| 场景 | 必须观察到的行为 |
| --- | --- |
| 空/损坏/不支持文档 | 明确状态，不制造字段/引用 |
| 数字或 JSON 格式错误 | 校验失败，不触发后续业务动作 |
| 旧版本政策与当前政策并存 | 按业务日期选择，无法消除冲突则要求复核 |
| 另一租户数据 | 服务端拒绝或过滤，模型看不到不可访问来源 |
| 文档中的恶意指令 | 当作不可信文档内容，不提升权限或执行指令 |
| 工具/模型超时 | 分类记录，限制重试，任务及连接清理 |
| 子 Agent 超时 | partial/needs_review，说明缺失部分 |
| checkpoint 后重启 | 正确映射任务与身份并恢复，外部动作可对账 |
| 重复提交/重复 resume | 幂等记录可核对，模拟业务效果不重复 |
| 审批拒绝或载荷变更 | 不执行；旧审批不能用于新载荷 |
| trace 输出 | 可以追踪但不泄露凭据、敏感原文和越权数据 |

## 每周记录模板

```text
里程碑：Wxx
问题：上一版有哪些具体失败？
改动：本次加入什么，为什么需要？
复现：命令、依赖锁、代码/数据/模型/提示版本。
验证：自动测试结果、固定评测样本数、人工核对。
比较：基线与本版的质量、耗时、用量和失败类别。
代价：新增依赖、硬件要求、维护与恢复复杂度。
结论：采用/保留实验/回退，依据是什么？
下一步：未完成任务和当前限制。
```

## W16 最终演示脚本

**交付 DocPilot 时演示以下四步。**

1. 请同事按你的 README 启动最小版本，检查就绪状态，用有权限的身份上传样例，让他自己打开回答引用的原文。
2. 对同一问题换业务日期、身份，再提一道无依据的问题。保存允许的来源、实际候选、回答及引用，说明是哪一步作出的限制。
3. 暂停模型服务，检查界面与日志怎样报告失败；恢复服务后重试同一题，核对原文和版本。
4. 导出固定题集与留出题的逐题记录。演示一次失败改进，报告样本数、延迟或用量，附上仍会答错的一题。把这套材料带到第 30 章练第一次面试。

**交付 ProcureAgent 时，在同一检索能力上追加三步。**

1. 在正常、明确异常和资料不足三种采购案例上，比较固定流程与单 Agent，沿一次真实模型调用核对实际选用的工具、参数与返回值。
2. 暂停到审批，分别演示拒绝、批准以及更改载荷后重新审批。在模拟业务方已写入、本地尚未确认时中断，再恢复和重复提交，核对业务记录数。
3. 注入一次只读工具超时，展示失败状态、审计事件和重试预算。采用多角色时加测子任务超时。导出与同一基线的质量、耗时和成本比较，写明下一版保留哪种流程。

这些验证支持学习项目的工程结论。真实上线还需要业务方确认规则、身份与数据权限设计、安全检查、容量、备份恢复和运维要求。

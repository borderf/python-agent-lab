# 学习导航：从 Java 后端到 AI 应用与 Agent 开发

同一位采购专员有两个逐步深入的任务：先找到某天有效的制度并核对原文，再用这份制度审查一个采购项目、补齐缺失资料并申请批准。第一个任务做成 **DocPilot 文档问答**，第二个在它的检索能力上构建 **ProcureAgent 采购审查**。每一步产生的代码、证据或用户反馈都可以带到下一步。

## 找到自己的起点

1. **能用 Java 写服务，Python 主要靠看示例。** 从[第一次开始](../README.md#第一次开始)做一笔 29 分订单。换成零金额、空列表和另一种订单状态，合上示例独立写出汇总。对象与集合、函数、迭代或资源清理卡在哪一项，就从[语言检查表](python-book/附录C-Python能力检查表.md)对应的章节进入。
2. **已经用 Python 交付过程序。** 直接挑战[第 12 章的综合练习](python-book/12-Python综合项目与独立验收.md)。能在新目录运行自己打包的 CLI、定位一条冲突记录，并解释取消时谁关闭资源，就带着实现进入工程阶段。把[六道迁移自测](python-book/附录C-Python能力检查表.md#六道迁移自测)留作逐项复验，其中的缓存题也可到检索阶段再做。
3. **已经独立维护过 Python API。** 用自己的代码演示严格校验、上游超时和取消后的连接清理。对应第 9、11、14 章的能力都能复现，就先做[第 18 章的模型实验](python-book/18-大模型基础、消息与结构化输出.md)。文档上传会用到第 15 章，首次发布再核对第 16–17 章。

## 五个阶段怎么走

下表按**有 Java 后端经验、每周能稳定投入 8–10 小时**估算首轮实践。时间包含编程、调试和复盘。每阶段先做表里的作品，遇到卡点再回读章节；已有同等交付可以直接验收。表中的「Python」指 [Python 与 AI 教材](python-book/教材目录.md)，架构、产品章号各按[架构目录](architecture-book/教材目录.md)与[产品目录](product-founder-book/教材目录.md)查找。

| 阶段与预算 | 动手顺序 | 交付与过关条件 |
| --- | --- | --- |
| 1 · Python 独立项目，3–4 周 | Python 1–6 用订单练对象、函数、迭代和异常；7–12 做文件、模块、类型、测试、并发和打包。产品 1–2 先约一次访谈 | 交付订单库和 CLI。换目录安装运行，重复记录只计一次，冲突时报出 ID 且旧报告可读。记录用户上一次找制度时经过的步骤、耗时和困难 |
| 2 · 把库交付为服务，2–3 周 | Python 13–15 接客户端与 API，16–17 接事务、日志和发布。架构 1–5 用同一个服务核对边界与事务，产品 3–4 写首版范围 | CLI 与 API 复用计算规则。注入上游超时，从日志定位并验证清理。另一人按接口说明成功调用；根据访谈写清 DocPilot 服务谁、帮他完成哪一步 |
| 3 · DocPilot，4–6 周 | Python 18–19 从消息、生成到解析与证据定位；20–21 从关键词基线到真实向量对照；26 取检索评测部分，27 组装发布。架构 6、8–10、12，产品 5–9 | 从一份材料走通授权检索、真实模型回答和可点击或定位的引用。用未调参的问题比较质量与耗时，解释一次召回失败和一次引用错误。请一人独立找依据，与原方法比较。到这里可以准备 AI 应用岗的作品演示 |
| 4 · ProcureAgent，4–6 周 | Python 22 手写有步数上限的工具循环，16、23 做状态、审批与恢复，26 回做轨迹评测，28 集成交付。架构 4–5、7、9–11 检查副作用与恢复 | 用同一批采购案例比较固定流程和单 Agent。演示缺资料交人工、批准后才执行模拟写入、远端成功而本地中断后恢复。对账确认只有一次业务效果，并保留真实模型选工具的轨迹。可用于 Agent 岗答辩 |
| 5 · 试点与迭代，2–3 周启动首轮 | Python 29–30 按作品做面试追问，架构 11、13–14 做发布与评审，产品 10–14 做渠道、定价和经营验证。优先选前面有人愿意再用的一个任务 | 给试用者可复现的入口和回退说明。记录一个渠道的触达、试用、完成任务与再次使用人数，核算每次成功任务的成本，写下继续、缩小范围或停止的依据。实际复用与付费以观察到的行为记录 |

按上述预算，从头到第一份 AI 应用作品约 **9–13 周**，完成 Agent 作品约 **13–19 周**，加首轮试点与复盘约 **15–22 周**。这是排期用的估算；真实招募、复用和付费按实际发生时间跟踪。时间紧时可以先交付一个租户、一种文档格式的正常链路，再用第二个租户、旧版本、无证据题检验边界。

## AI 原理学到什么深度

| 做项目时遇到的问题 | 要能解释并验证什么 |
| --- | --- |
| 回答格式正确，引用却不支持结论 | 第 18 章用小例子理解 token、下一 token 的概率、注意力与上下文，说明训练与推理改变什么。用同一问题删掉关键证据，比较模型回答和人工核对结果 |
| 文档里明明有答案，系统却找不到 | 第 19–21 章沿解析 → 分块 → 权限与日期过滤 → 排名逐层查。给一道题标出正确原文，看它是否进候选、排第几，再决定改分块、换 embedding 或重排；保存改前改后结果 |
| Agent 声称已完成，但业务状态没变 | 第 22–23 章逐步查看模型提出的调用、程序校验、真实执行与结果回传。到第 26 章重复跑同题，核对日志和业务记录，区分选错工具、工具失败和最终回答错误 |

完整训练、微调和 GPU 推理优化留给明确需要它们的岗位或项目。出现跨进程共享工具的需求时再做第 24 章 MCP；单 Agent 已有可复现的失败，并能设计同题对照时再做第 25 章多 Agent。工作流与 Agent 的分界也可对照 [Anthropic 对两种控制方式的解释](https://www.anthropic.com/research/building-effective-agents)。

## 两份作品怎样验收

DocPilot 可先用离线替身把调用链和坏输入跑通。准备作为 AI 应用作品时，接入真实聊天模型和嵌入模型，保存模型标识、业务日期、可见来源、逐题结果及一次失败修复。让同事换一道有版本冲突的新问题，现场区分取错来源和基于正确来源答错。[配套实验与环境](../practice/enterprise_ai/虚构数据说明.md) · [DocPilot 项目章](python-book/27-项目实战一：DocPilot从零到检索系统.md)

ProcureAgent 复用同一个制度检索模块。请同事临时改一次项目或在等待批准时重启，展示哪些证据需要重查、旧批准怎样失效、业务效果如何对账。把正常与失败各一例、一次设计取舍、一次用户反馈放进作品说明。做完第一份作品就可以按第 30 章练习面试，第二份完成后再加恢复案例。[ProcureAgent 项目章](python-book/28-项目实战二：ProcureAgent审查系统.md) · [两种作品的演示脚本](project-practice/评测与故障演练.md#w16-最终演示脚本)

**最后做一道陌生题。** 例如让研发同事给出他有权分享的两版发布规范，让新人回答“某次发布当日适用哪条回退规定”。先听他怎样判断答对，再独立写出验收题、载入材料、运行并请他核对。记录哪些代码直接复用，哪些日期、权限和审批规则需要重写。如果新任务只需查证，就在 DocPilot 结束交付。

## 各方向的实操入口

- Python 需要查漏时，按[覆盖范围](python-book/附录A-知识覆盖与阅读层次.md)定位章节，用[语言练习索引](python-book/附录B-语言练习任务索引.md)选一道变式。查语言规则可用 [Python 3.12 官方教程](https://docs.python.org/3.12/tutorial/)。
- 架构上每次只验证一个取舍，例如文档更新后旧索引如何失效。记下备选方案、故障怎么制造、如何恢复，以及在什么负载下需要重选。[架构实验与评审](architecture-book/附录D-架构实验与评审实操.md)
- 产品上把访谈、原型、上线和反馈用同一个用户任务串起来。已有真实试用机会时，可在 DocPilot 后直接启动第五阶段的渠道实验。[产品思维训练](product-founder-book/附录D-产品思维训练营.md) · [全栈交付](product-founder-book/附录E-全栈产品交付实操.md) · [上线推广](product-founder-book/附录F-上线发布与推广实验.md)
- 实现时以[项目规格](project-practice/项目实践规格.md)核对接口、身份、工具与审批；交付时以[里程碑](python-book/附录E-项目里程碑与交付检查.md)核对证据。W01–W16 是里程碑编号；练习文件名中的 week01–04 也是历史编号。

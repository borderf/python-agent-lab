# 学习导航：一条项目主线，三个学习方向

先把订单数据变成可运行程序，再把程序变成可靠服务，随后完成 **DocPilot：找到适用原文并回答**。需要受保护动作时，再实现 **ProcureAgent：审查、批准与恢复**。架构学习解释系统为什么这样组织，产品学习解释谁需要它、怎样验证采用。

学习进度只按章号记录。每章完成一项累计任务，例子编号、旧周编号和项目版本只用于查找，不同时执行多份计划。

## 一条主线，两层目标

不要按章节平均读，也不要等“全部学完”才做项目。每个阶段同时检查：

- **交付层**：我能不能把当前作品做出来，并保留正常与失败证据？
- **掌握层**：我能不能解释机制、画出路径、处理一个没见过的问题？

| 阶段 | 交付层：做出什么 | 掌握层：解释什么 |
| --- | --- | --- |
| A. 订单 CLI | 读文件、校验、去重、报告 | 名称与对象、可变性、函数输入输出、文件错误 |
| B. Python 服务 | API、持久化、测试、部署 | 请求生命周期、异步等待、事务边界、日志定位 |
| B+. 最小页面 | 输入金额 → 调用 API → 显示结果 | HTTP/JSON、DOM事件、加载/错误/空状态 |
| C. 全栈搜索切片 | 页面 → BFF → Python搜索 → 来源 | React状态、异步取消、BFF身份边界 |
| D. 真实 RAG | 真实资料、模型/向量库、评测 | 检索指标、引用支持、权限、更新与删除 |
| E. 受控动作 | 工具调用、审批、恢复 | 工具契约、幂等、对账、取消的边界 |
| F. 扩展与讲述 | 作品答辩与按需扩展 | 一次失败修复、一项取舍、一次陌生迁移 |

## 每阶段读什么、留下什么

| 阶段 | 必读 | 通过证据 |
| --- | --- | --- |
| A | Python 01–07 | 正常、坏行、冲突三种输入；旧报告不被破坏 |
| B | Python 08–17 | 接口测试、重启恢复、依赖失败有明确反馈 |
| B+ | [附录D](typescript-book/附录D-JavaScript与浏览器基础.md)的HTML/DOM/fetch部分 | 成功、加载、错误三种状态 |
| C | TS 01–05、07–09、11；Python 18–20 | [最小全栈切片](project-practice/最小全栈切片.md)的5条验收 |
| C+（按需） | TS 06、10 | 断流、取消、已有内容保留 |
| D | Python 21–23 + [项目交付手册](project-practice/从实验到项目交付.md) | 10题固定集、失败分类、质量/成本/延迟 |
| E | Python 24–26；TS 14 | 未知工具、越权、预算耗尽、批准后改载荷、失回执恢复 |
| F | Python 29–30；27–28按需 | 一次失败修复、一项取舍、一次陌生条件演示 |

**跳过条件**：只有已经独立完成过同等产物，才可跳过对应必读；不能因为“看起来会”跳过测试与恢复证据。

每阶段先完成最小路径，再补专题和变式。阶段 C 的流式属于 C+，阶段 B+ 不引入 React。每阶段结束保留：运行命令、一个正常结果、一个失败案例、一个未验证边界。

## 每阶段内部走三遍

1. **交付遍**：只读当前作品必需章节，做出最小可运行版本。
2. **专题遍**：按[核心知识依赖图](核心知识依赖图.md)补本阶段必须理解的机制。
3. **变式遍**：换数据或加约束，独立完成一次，不用照着教程的方式验证迁移。

全部 A–F 完成后，再换业务或入口做一次跨阶段迁移。不是先把所有基础学完才开始项目。

- **TypeScript**：需要DocPilot控制台、流式界面或全栈作品时，按[TypeScript教程](typescript-book/教材目录.md)选读；它不替代Python后端主线。

## 每章怎样真正学会

1. 用任务卡说清上一章留下什么、本章只解决哪个新问题。
2. 沿同一个输入读第2–4节，先预测结果，再运行并解释状态变化。
3. 合上参考，完成第5节累计任务；专题练习只补当前卡点。
4. 换一个新输入，记录失败首次出现在哪一步，再进入下一章。

自动检查只覆盖约定行为。现有学习者契约包括DocPilot 20条、工具循环12条、审批8条、持久化6条、恢复6条，命令见[练习说明](../tests/learner/练习说明.md)。默认测试通过不代表自己的实现完成；替身通过不代表真实质量；架构是否适合约束仍需实验或评审。

## 投入范围与部署口径

以下只是规划情景，不是学习承诺；按有后端经验、每周8–10小时估算，前两周记录实际用时后修订。

| 范围 | 内容取舍 | 初始预算 |
| --- | --- | --- |
| 精简交付 | 语言按自测补缺；完成订单、DocPilot、真实调用、评测与一次部署 | 约150–200小时，4–6个月 |
| 完整学习 | 完成Python主线与受控Agent，补恢复、发布、架构/产品与迁移 | 约350–600小时，9–18个月 |

“一次部署”的基础口径是：在本机或自有服务器可复现启动、健康检查通过、配置与数据卷明确、配置一个真实模型并保留逐题评测。公网HTTPS、正式身份、密钥管理、限额和故障恢复属于后续生产验收。

真实客户招募、采购与服务等待另外记录。职业竞争力来自能解释、能独立交付、能验证与改进，教材不承诺固定时长上岗。

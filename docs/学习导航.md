## 你当前的双方向学法

已有Java后端经验可以直接迁移到架构学习，不必等Python教材全部读完。先完成后端服务与调试自查；Python和AI机制按依赖补齐。

1. 架构第1–4章与产品第1–3章：用同一问题同时练约束、用户、边界与定位。
2. 架构第5–7章与产品第4–6章：把产品范围落成数据、接口和可用切片。
3. 架构第8–10章与产品第7–9章：验证性能、安全、用户效果和AI质量。
4. 架构第11–14章与产品第10–14章：练发布演进、团队协作及商业验证，分别完成两套答辩。

每次选择一套书的一项小目标，两条方向可以交替，不在同一晚强行完成多个阶段。各书导读都有前置、掌握等级和成果位置。

## 共用事实，分别形成证据

产品证据说明“为什么值得做、用户是否获益”；架构证据说明“怎样可靠实现、失败时如何恢复”。例如DocPilot检索切片可同时用于可用性测试、权限验证和容量实验，但测试结果分别解释，不能用某一种通过替代其他验证。

## 共同项目的资料职责

| 资料 | 负责内容 | 更新时机 |
| --- | --- | --- |
| 产品教材与规格成果 | 谁的问题、任务、体验和收益目标 | 研究或实验改变判断时 |
| 架构教材与ADR成果 | 结构、质量约束、数据和演进 | 约束或机制证据变化时 |
| [项目实践规格](project-practice/项目实践规格.md) | 现有案例接口、工具、状态与批准契约 | 实现契约改变时统一修改 |
| 两套工作簿 | 各自的设计、验证和未决证据 | 每次实践后 |

为关键要求设ID并关联设计、实现、实验和决定，避免同一规则多份定义。产品任务完成、系统正确可靠和商业可持续分别验收。

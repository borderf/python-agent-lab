# 学习导航：一条项目主线，三个学习方向

先把订单数据变成可运行程序，再把程序变成可靠服务，随后完成 **DocPilot：找到适用原文并回答**。需要受保护动作时，再实现 **ProcureAgent：审查、批准与恢复**。架构学习研究这套系统为什么这样组织、怎样验证；产品学习研究谁需要它、怎样设计、交付与验证采用。

学习进度只按各册章号记录。每章完成一项累计任务；例子编号、旧周编号和项目版本仅供查找。下列入口各有用途，不再同时执行多份周计划。

## 作品主线：一条项目主线，两层知识深度

不要按 85 章平均推进，也不要等“全部学完”才做项目。每一阶段都以一个可演示作品为终点，同时保留“交付层”和“掌握层”两个目标：

- **交付层**：我能不能把当前作品做出来？功能可运行，正常与失败路径有证据。
- **掌握层**：我能不能解释原理，并处理没有照着教程写过的问题？能画机制、解释原因、预测反例、独立迁移。

| 阶段 | 交付层：做出什么 | 掌握层：要能解释什么 |
| --- | --- | --- |
| A. 订单 CLI | 读文件、校验、去重、报告 | 名称/对象、可变性、复制边界、函数输入输出、文件错误分层 |
| B. Python 服务 | API + 持久化 + 测试 + 部署 | 一次请求的生命周期、同步/异步等待、校验/业务/数据库约束、事务边界、日志与测试定位 |
| B+. 最小页面 | 输入金额 → 调用 API → 显示结果 | 浏览器 HTTP/JSON、DOM 事件、加载/错误/空结果状态，不依赖框架 |
| C. 全栈搜索切片 | 页面 → BFF → Python 搜索 → 来源 | React 状态归属、异步取消、BFF 身份边界、错误/空结果状态；流式留到 C+ |
| D. 真实 RAG | 真实资料、模型/向量库、评测 | 检索指标、引用支持、权限过滤、更新/删除、质量/成本/延迟权衡 |
| E. 受控动作 | 工具调用、审批、恢复 | 工具契约、参数校验、审批载荷、幂等/对账、取消≠外部效果停止 |
| F. 扩展与讲述 | 架构/产品选章、作品答辩 | 一次失败修复、一项取舍、一次陌生条件演示 |

第一张表只定义“阶段目标与顺序”；下面第二张表只做“章节映射与证据”，不是第二套阶段顺序。

## 每阶段读什么、留下什么

| 阶段 | 必读（可延后/可跳过条件） | 通过证据 | 产品/架构小任务 |
| --- | --- | --- | --- |
| A. 订单 CLI | Python 1–7 | 正常、坏行、冲突三种输入；旧报告不被破坏 | 写一页“用户是谁、什么任务、先不做什么”，做 1 次任务观察 |
| B. Python 服务 | Python 8–17；其中 13–14 负责环境/分层/HTTP 客户端，不能跳过 | 接口测试；重启恢复；依赖失败有明确反馈 | ADR-001：单体/存储/失败处理，写代价与复查条件 |
| B+. 最小页面 | [附录D](typescript-book/附录D-JavaScript与浏览器基础.md) 的 HTML 表单、DOM 事件、fetch、JSON、错误展示；TS 1–2 可选，不读 TS 6 | 页面提交成功、加载、错误三种状态；一条手动或 Playwright 验收 | 找 1 位用户看一次“输入→结果”，记录卡点 |
| C. 全栈搜索切片 | TS 3–5、7–11；Python 18–20；TS 12–14 按需 | [切片规格](project-practice/最小全栈切片.md) 的 5 条验收 | 做一次任务观察，记录一个被改写的假设 |
| C+. 流式扩展（按需） | TS 6、10 | 断流、取消、已有内容保留 | 记录一次“停止后资源与状态” |
| D. 真实 RAG | Python 21–23 + [项目交付手册](project-practice/从实验到项目交付.md) | 10 题固定集、失败分类、质量/成本/延迟记录 | 写“哪些资料不能进索引”，做一次撤权/删除回归 |
| E. 受控动作 | Python 24–26；TS 14 | 未知工具/越权/预算耗尽；批准后改载荷；失回执恢复效果为 1 | 记录一次“取消请求≠外部效果已停”的对账 |
| F. 扩展与讲述 | Python 29–30 必读；27–28 按需；架构/产品按问题选章 | 一次失败修复、一项取舍、一次陌生条件演示 | ADR 索引 + 一次用户/评审追问回答 |

**跳过条件：** 只有已经独立完成过同等产物，才可跳过对应必读。例如 Java 后端已能锁定依赖、做配置分层、处理 HTTP 客户端四层错误，可只做阶段 B 的验收，不重读 13–14；不能因为“看起来会”跳过测试与恢复证据。

每阶段先做“最小路径”，再做“加深”。阶段 C 只用固定 tenant 和固定结果跑通，认证、SQL、工具调用后补；**流式不属于 C 的最小目标**，放到 C+。阶段 B+ 不引入 React，只验证浏览器到 API 的基本链路。每阶段结束保留：运行命令、正常截图/输出、一个失败案例、一个仍未验证的边界。

## 每阶段内的三遍，而不是全线三遍

不要把“三遍”理解成先做完全部 A–F、最后才补基础。**每个阶段内部走三遍，通过后再进入下一阶段：**

1. **交付遍**：只读当前作品必需章节，做出最小可运行版本；
2. **专题遍**：按[核心知识依赖图](核心知识依赖图.md)补这一阶段涉及的“必须系统学”，能画机制、解释边界；
3. **变式遍**：换数据/加约束，独立完成一次，不照抄教程；用[阶段整合任务](project-practice/阶段整合任务.md)在每个知识节点（约 4–8 章，按依赖拆分）回项目改一处。

全部 A–F 完成后，再做一次**跨阶段迁移**：换业务或换入口，把整套系统重新讲一遍。不是最后才开始补基础。

例如函数不是“项目用到就学一点”：

```text
项目问题：订单规则重复
→ 先写普通函数
→ 专题：参数、帧、作用域、闭包、装饰器
→ 回项目抽取规则、检查副作用、补测试
→ 换一个陌生案例独立实现
```

## 按一个成果继续，而不是按多套编号跳转

| 累计成果 | 主读章节 | 通过后留下什么 |
| --- | --- | --- |
| 订单程序 | Python 1–12 | 新数据可运行、金额与冲突明确、文件入口与检查可复现 |
| 可靠服务 | Python 13–17 | 输入、身份、外部错误、状态与恢复边界 |
| DocPilot | Python 18–23 | 自己的核心通过20步契约，再接HTTP、真实模型与逐题评测 |
| ProcureAgent | Python 24–26 | 受限工具、批准绑定载荷、失回执恢复与效果核对 |
| 作品解释 | Python 29–30 | 一次失败修复、一项取舍、一次陌生条件演示 |

Python 27–28是按需选修：先有跨进程工具或分工问题，再评估MCP与多Agent。DocPilot完成后即可收集AI应用岗位反馈；不必等全部选修完成。

## 架构与产品分别怎样学

**架构：** 按[架构第1–14章](architecture-book/教材目录.md)独立推进，沿任务→约束→模块→契约→数据→协作→容量→恢复→安全→发布→选型→评审。每章更新同一份架构记录，最终形成一个可复查的决策与实验索引。能开发后端服务即可开始，不要求先读产品教材。

**产品与创业：** 按[产品第1–14章](product-founder-book/教材目录.md)沿问题→访谈→定位→规格→交互→全栈切片→指标→实验→AI复核→定价→渠道→运行→资源决定推进。产品型工程师先完成任务与交付，创业再深入购买、成本和资源承诺。不要求先读架构全册。

首次学习以**Python 为主线**；架构与产品是按需旁线，做完 DocPilot 后再按当前问题各选几章。若目标偏架构或产品，可先读对应册，但仍用同一组订单与 DocPilot 材料练习。Agent 方向在第24章 4.2 用 12 步契约实现工具循环，第26章再组合审批与恢复。

**AI 基础原理（配套）：** 做第18章模型调用或第20–22章 RAG/评测前，按[AI 基础原理](ai-foundations/教材目录.md)读第1–8章：tokenizer、embedding、Transformer、训练、推理、幻觉/RAG、评测。它解释“为什么”，Python 第18–22章负责“怎么落地”；面试前用附录A自测。

**TypeScript 与 AI 交付（选修）：** 按[TypeScript 教程](typescript-book/教材目录.md)读全书 18 章，学类型边界、运行时校验、异步取消、SSE、模块工程化、React 数据流、异步缓存、流式界面、Hono BFF、SQL/Drizzle、认证/多租户、AI 工具调用、测试、观测与部署。它不替代 Python 后端主线；适合要交付 DocPilot 控制台、流式界面或全栈作品时并行学习。

## 每章怎样真正学会

1. 用一句话复述上一章留下的程序或决定，以及当前遇到的新问题。
2. 先读原因和完整推演，画数据、执行或用户路径，能解释后再运行。
3. 合上参考，完成本章累计任务；专题练习只用于补当前卡点。
4. 用一组新输入或新约束验收，记录失败的首个环节与修复；下一章沿用该成果。

自动检查不是全能评分。订单TODO检查你的订单实现；[学习者契约](../tests/learner/练习说明.md)检查指定模块；仓库默认测试主要保护参考代码；文档脚本检查结构与链接。用户是否完成任务、架构选择是否适合约束，还要观察或实验。

## 两种投入范围

以下是规划情景，尚不是学习者实测承诺；按有后端经验、每周8–10小时估算，前两周记录实际用时后修订。

| 范围 | 内容取舍 | 初始预算 |
| --- | --- | --- |
| 精简交付 | 语言按自测补缺；完成订单、DocPilot、HTTP、真实调用、评测与一次部署；架构和产品只做当前决定；暂缓Agent与扩展 | 约150–200小时，约4–6个月 |
| 完整学习 | 完成Python主线与受控Agent，两册进阶逐章任务、恢复与发布演练、产品试点与反例迁移 | 约350–600小时，约9–18个月 |

真实客户招募、采购与服务等待另外记录，不假设按编程排期完成。职业竞争力来自能解释、能独立交付、能验证与改进，教材不能承诺固定时长上岗。

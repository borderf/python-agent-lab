# 第7章　指标、埋点、漏斗与留存

[上一章](06-全栈开发与最小产品交付.md) · [本书目录](教材目录.md) · [下一章](08-实验设计与产品迭代.md)

## 1. 目标、前置与问题

前置：第4、6章。能定义可计算指标并检查数据质量。问题：访问量翻倍，为什么产品价值可能没有增加？

## 2. 概念与基础

先观察一批用户：多少人提交问题，多少人打开原文，多少人独立找到了正确依据。提交与打开是过程行为，完成任务才接近用户结果；同时记录错误引用、耗时和费用作为护栏。先明确每个数字想回答什么，再设计事件名称、触发位置和去重规则，避免把点击量直接当作价值。

事件字典写名称、触发、主体、对象、时间、属性和来源。身份、时区、去重、重试及事件版本会影响结果。敏感正文不应为分析方便全部入库，收集范围应服务明确目的。

## 3. 机制与推导

指标从用户结果倒推。按钮点击说明用户尝试，服务端成功说明某个步骤执行，打开来源说明查看，确认找到依据才更接近任务完成。代理指标有价值，但不能把它直接改名为用户收益。

漏斗必须使用同一批主体、同一窗口和约定顺序。用户、账户、企业不是同一单位；本月访问数除以上月付款数也不是转化率。去重规则和失败事件要先写清，再读图。

留存需要固定队列与后续行为。周期低频的工作工具还要区分“没有新任务”和“有任务却不用”；前者仍应保留在标准队列报告里，可另报有复用机会的人群，不能临时换分母让数字好看。

埋点是软件功能，也会漏报、重复和延迟。先核对一条任务在浏览器、服务端与事件表之间的记录，修正数据质量后再判断产品。分渠道和用户类型看差异，但归因标签不等于因果证明。

## 4. 案例逐步推演

教学数据统一为：邀请20个授权账户，12个导入资料，8个完成首次有效检索，次周其中5个再次完成任务。

| 指标 | 公式 | 解释 |
| --- | --- | --- |
| 邀请到激活 | 8/20=40% | 邀请队列中完成首次任务 |
| 导入后激活 | 8/12≈66.7% | 已导入队列的后续完成 |
| 激活队列次周留存 | 5/8=62.5% | 首次激活者次周重复完成 |

再定义事件：question_submitted 在服务端接受合法请求后记录；sources_returned 在授权结果生成后记录；source_opened 在原文展示成功后记录；task_confirmed 由用户明确反馈。事件包含去重ID、主体、任务ID、版本与时间，避免把正文和敏感材料写进分析事件。

若完成事件突然少了，先拿一条已知完成任务检查漏报，再判断是否需要改产品。

### 4.1 用集合亲手核对留存分母

```python
# track-example: P07
invited = set(range(1, 21))
imported = set(range(1, 13))
activated = set(range(1, 9))
returned = {1, 2, 3, 4, 5}
assert activated <= imported <= invited
assert returned <= activated
assert len(activated) / len(invited) == 0.4
assert len(returned) / len(activated) == 0.625
```

这里的编号是虚构账户，不是企业。真实事件还要限定窗口与先后顺序，集合例子只解释同一队列的分子分母。去掉时间条件会把很久以前的任务混进本周。

如果次周只有3个激活者遇到新任务、其中1个继续使用，应同时报告标准队列1/8与有机会者1/3，并解释机会如何判定；不能把后者无说明替换成原留存定义。低频产品更需要任务频率的背景。

事件字典示例：task_confirmed主体为账户，关联task_id，用户明确确认后触发，同一确认事件按event_id去重；“来源打开”另列。数据能否支持判断，比事件数多更重要。

## 5. 分层练习

先完成：给自己的切片建立四条事件字典，写触发、主体、去重、时间与指标用途。用五条手工任务逐一核对，再计算一组同队列漏斗；保存分子与分母明细。

完成后换一个约束或一组输入，解释原决定哪里需要改变。基础任务通过后再做深化；本章不要求把所有扩展同时实现。

## 6. 自测与参考推导

合上正文，复述问题怎样出现、机制为什么有效、哪些条件下仍会失败。再对照下面的诊断检查自己的成果。

保存 `product/measurement.md` 的指标字典和一次核对表。下一章使用这份口径设计实验，避免看完结果才改目标。

验收时由你或同伴用新条件检查，记录输入、实际结果与解释。设计练习以推理和反例判断，代码任务用实际行为检查；涉及用户与商业的结论只使用相应真实证据。

# 第8章　实验设计与产品迭代

[上一章](07-指标埋点漏斗与留存.md) · [本书目录](教材目录.md) · [下一章](09-AI产品体验评估与人工协作.md)

## 1. 目标、前置与问题

前置：第2、7章。能按不确定性选择验证方式并解释结论边界。问题：上线后转化提高，就能归因于新功能吗？

**本章主线：** 先写可被推翻的假设，再选择原型、离线题集、试点或随机实验；预先固定分配单位、主指标、护栏、样本与停止规则。计算结果和实验结论分开验收。

## 2. 概念与基础

### 2.1 验证方式取决于问题

**验证方式**不是越复杂越可靠，而是越能回答当前未知越好。

| 方式 | 适合回答 | 输入 | 结论边界 |
| --- | --- | --- | --- |
| 原型任务 | 用户是否理解状态与动作 | 目标、低保真原型 | 发现理解问题，不估计总体比例 |
| 离线题集 | 系统在固定题上是否正确 | 题目、预期、评分规则 | 只覆盖题集，不代表真实用户 |
| 限定试点 | 任务能否在真实流程交付 | 团队、资料、窗口、支持 | 条件与样本有限，不能自动外推 |
| 前后观察 | 变化发生在何时 | 同口径前后记录 | 受季节、渠道、熟练度影响 |
| 随机A/B | 某变化对指定指标的影响 | 适当分配、足够样本 | 依赖随机化、独立性和测量质量 |

最小例子：先给新人一个原型任务，观察能否找到日期和原文入口；再让真实团队试用，检验任务价值与交付；固定题集另检查系统正确性。不能用一个原型测试同时证明三者。

### 2.2 假设、处理与分配单位

**实验假设**写成“改变X，会通过机制M影响指标Y，但不越过护栏Z”。例如：“在结果卡显示生效区间，会减少日期误用，从而让更多用户独立找到正确原文；关键错误不得增加。”

**处理**是被比较的改变；**分配单位**是被随机分到A组或B组的对象。分配可以按用户、账户、团队或企业，取决于干扰如何发生。

如果同一团队共享资料和新版摘要，A组用户可能影响B组，按个人随机就不再独立。此时更适合按团队分配，但需要更多团队，而不是把团队内点击都当样本。

### 2.3 主指标、护栏与业务最小收益

**主指标**是判断假设的主要结果；**护栏**是限制负面后果的指标；**业务最小收益**是值得为改变付出迁移、支持和维护成本的最小改善。

统计显著不等于业务值得。一个0.1个百分点的稳定变化，可能没有用户价值；一个大但不稳定的变化，也可能只是噪声。

| 计划项 | DocPilot示例 | 为什么提前写 |
| --- | --- | --- |
| 主指标 | 独立找到正确原文 | 防止事后改看好数字 |
| 护栏 | 关键错误、总完成时间 | 防止正确率上升但风险扩大 |
| 最小收益 | 事先约定值得采用的差值 | 区分显著与有用 |
| 窗口 | 每个团队固定7天 | 避免不同观察长度 |
| 停止 | 关键错误超阈值即暂停扩大 | 防止为了样本继续伤害用户 |

### 2.4 样本判断与不确定性

**样本判断**是说明样本单位、数量、选择方式、独立性和不确定性支持哪种结论。小样本可以发现具体障碍，不能可靠检测小差异。

比例指标的两组比较会受基线、目标差异、显著水平、功效和分配单位影响。**显著水平α**控制误报风险，**功效power**表示在真实差异存在时检出它的概率；两者都不是“结果正确的概率”。

未显著不等于完全无效，只能表示当前数据不足以区分假设与随机波动。

## 3. 机制与推导

### 3.1 为什么前后对比容易误归因

上线前后还可能有渠道变化、用户结构变化、季节、资料更新、学习效应和埋点修改。即使总转化上涨，也不能把全部变化归给新功能。

改进前后比较至少要做：

1. 固定同一指标定义与任务样本。
2. 记录期间其他同时发生的变化。
3. 区分新用户与重复参与者。
4. 对照可比任务，控制难度与资料范围。
5. 把仍无法排除的解释写进结论。

### 3.2 样本量公式怎样读

两组比例指标在常见近似下，每组样本量可估算为：

```text
n ≈ 2 × (z(1-α/2) + z(power))² × p(1-p) / δ²
```

其中 `p` 是基线比例，`δ` 是希望检出的绝对差异，`p(1-p)` 反映二项比例方差。α=0.05、power=0.8、p=0.40、δ=0.05时，每组约需1507个独立样本。

这个近似假设两组方差可近似、观测独立且其他条件稳定。真实实验可能因聚集、流失、多重比较或提前查看而需要更复杂设计。

### 3.3 提前停止、多次查看与迭代

反复查看结果并在“显著”时停止，会增加误报机会，这叫**窥视问题**。若必须持续监控护栏，应使用适合序列观察的方法，或把安全停止与效果结论分开。

一次实验失败也可以产生有用信息：假设机制不成立、人群不适合、任务没有频率，或测量不可靠。迭代应修改其中一项，而不是同时改变所有条件后宣称学到很多。

## 4. 案例逐步推演

假设要验证“摘要是否帮助用户完成查证”。先用相同题集核对事实与引用，再观察用户是否把摘要当成无需复核的结论。

虚构数据A完成40/100，B完成45/100。差值是5个百分点，相对变化是12.5%；这只是观察差，不能直接称为稳定提升。继续检查分组、独立性、埋点与样本不确定性。

若B的关键错误从0变为3，即使完成率更高，也应暂停扩大，逐题核对错误后果。下一步可能是保留摘要但强化来源、缩小任务范围，或暂时移除生成。把决定与预设护栏连起来，而不是事后解释所有结果都算成功。

### 4.1 把观察差与结论分开计算

```python
# track-example: P08
from fractions import Fraction
a = Fraction(40, 100)
b = Fraction(45, 100)
absolute_change = b - a
relative_change = absolute_change / a
assert absolute_change == Fraction(5, 100)
assert relative_change == Fraction(125, 1000)
```

代码只证明算术：5个百分点和12.5%相对变化。它没有检查随机分配、样本独立、区间或错误护栏，因而不能得出“B稳定提升”。把计算正确和实验解释正确分开验收。

一份计划可以写：“摘要可能降低查证理解成本；主指标是独立找到正确原文；护栏是关键错误和总完成时间；先做固定题与任务观察，再根据流量决定是否进入随机实验。”若用户只是因为第二次更熟练，记录学习效应并调整比较顺序。

预先决定遇到关键错误如何停止扩大。计划允许坏消息改变范围，才是真正的验证，而不是为已开发功能寻找一个上涨数字。

#### 要检出 5 个百分点，需要多少样本

比例指标的两组比较可按 `n ≈ 2 × (z(1-α/2) + z(power))² × p(1-p) / δ²` 估算每组样本量。取 α=0.05、power=0.8、基线 40%、目标差异 5 个百分点：

```python
# track-example: P09
from statistics import NormalDist
from math import sqrt

z_alpha = NormalDist().inv_cdf(0.975)
z_beta = NormalDist().inv_cdf(0.8)
p, delta = 0.40, 0.05
per_group = 2 * (z_alpha + z_beta) ** 2 * p * (1 - p) / delta ** 2
half_width = 1.96 * sqrt(2 * p * (1 - p) / 100)
assert round(per_group) == 1507
assert round(half_width * 100, 1) == 13.6
```

每组约需 1,507 个独立样本；只有 100 人/组时，95% 区间半宽约 13.6 个百分点，看到“40/100 对 45/100”不能说明 5 个百分点真实存在。样本单位还要与分配单位一致：按团队分配时，团队数才是样本量，不能把每个人的点击当作独立观测。

### 4.2 用一页计划约束实验解释

| 步骤 | 输入 | 判断 | 输出 | 失败信号 |
| --- | --- | --- | --- | --- |
| 固定假设 | 摘要与来源卡片 | 机制是否说得通 | 假设句 | 只写“提升体验” |
| 题集检查 | 固定题与预期 | 引用和事实是否退化 | 可进入试点的版本 | 关键错误增加 |
| 小规模观察 | 目标用户、陌生任务 | 是否出现目标行为变化 | 障碍与迭代方向 | 提示后仍无法完成 |
| 随机实验 | 适当团队与足够样本 | 主指标、护栏、区间 | 采纳、拒绝或继续未知 | 干扰、漏报、样本不足 |
| 决策复核 | 全部结果 | 收益是否超过采用成本 | 扩大、缩小或停止 | 为坏消息更换指标 |

本例100人/组不足以可靠检出5个百分点，且没有给出随机分配、区间和错误后果的完整证据。因此当前最多能说“观察到5个百分点差异，待进一步验证”，不能说“摘要稳定提升12.5%”。

## 5. 分层练习

1. **基础**：把一个功能想法改写成“改变X→机制M→指标Y→护栏Z”的假设，并写一条反例。
2. **改造**：选择原型、题集、试点或随机实验，说明为什么它适合当前未知，以及结论不能推广到哪里。
3. **独立**：写一页实验计划，包含主指标、两条护栏、分配单位、窗口、样本计划和停止规则；样本不足时改用任务观察。

不要把“提升12.5%”当完整报告。至少同时给出原始分子分母、分配方式、不确定性和关键错误。

## 6. 自测与参考推导

<details><summary>完成独立任务后查看诊断</summary>

- 若报告只写“提升12.5%”，缺少原始分母与不确定性。
- 若按团队分配却按个人点击计算样本，独立性被夸大。
- 若指标一涨就停，或看到显著才停，可能引入窥视偏差。
- 若关键错误增加仍扩大，说明护栏没有约束决定。

</details>

**自问：** 为什么“未显著”不能证明新功能完全无效？

**参考推导：** 当前样本可能太少、波动太大，无法分辨真实小差异与随机噪声；测量也可能不够精确。未显著只表示证据不足，应结合区间、机制和业务最小收益决定下一步，而不是直接断言无效。

## 7. 项目交付与验收

在测量文档保存一次实验计划与解释，更新产品范围。下一章专门处理AI错误与人工复核体验。

| 操作 | 预期结果 | 应保留的证据 |
| --- | --- | --- |
| 写假设与机制 | 能被具体结果推翻 | X、M、Y、Z与反例 |
| 固定题集 | 新版本不退化关键正确性 | 题目、预期、评分与版本 |
| 检查分配单位 | 独立单位与干扰方式匹配 | 分组名单、团队边界 |
| 计算观察差 | 百分点与相对变化分开 | A/B原始计数与公式 |
| 检查样本与区间 | 不把小样本噪声当稳定收益 | 样本计划、区间与假设 |
| 执行护栏规则 | 坏消息能暂停或缩小 | 错误记录与停止决定 |

## 8. 迁移与阅读

### 8.1 一页知识地图

**本章主问题：** 上线后转化提高，就能归因于新功能吗？

**一条主线：**

```text
可被推翻的假设 → 合适验证方式 → 分配、样本、主指标与护栏 → 有边界的决定
```

**三个关键词：** 归因、护栏、样本量。观察差要经过分配与不确定性检验，才配叫结论。

**最容易错：**

- 把40/100对45/100说成稳定提升12.5%。
- 按团队分配，却把个人点击当独立样本。
- 事后换指标或只在显著时停止。
- 把未显著直接解释为完全无效。

**与前后章：** 第7章的指标口径在这里预设主指标与护栏；本章定下的自动化边界，第9章要落到人工复核体验上。

**学完应能：**

- 按当前未知选择验证方式并写明结论边界。
- 解释1507/组与100/组时13.6个百分点半宽的含义。
- 写一份允许坏消息改变范围的实验计划。

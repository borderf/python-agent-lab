# 第10章　定价、单位经济与现金流

[上一章](09-AI产品体验评估与人工协作.md) · [本书目录](教材目录.md) · [下一章](11-获客销售与客户成功.md)

## 1. 目标、前置与问题

前置：第3、7章。能比较收费方式、建立成本情景并区分收入、利润与现金。问题：收入高于模型费用，生意就可持续吗？

## 2. 概念与基础

先以一个团队、一个月为单位算账：假设收入2000，模型、基础设施与支持等该口径可变成本合计1100，则贡献为900。再问按团队订阅、按任务收费或另收接入服务费，哪种方式能解释客户获得的价值，也能覆盖交付成本。先明确单位、时间与成本范围，再计算获客与回款，避免直接套一个价格公式。

单位经济需明确单位是账户、团队还是任务，以及时间窗口。客户贡献毛利＝收入－该口径可变成本；获客成本需包括相应销售与营销投入，并匹配销售周期。早期客户少时估计波动很大，不能套用固定“健康比例”。

## 3. 机制与推导

定价先决定计费单位与包含的服务，再计算成本。按团队、席位、任务或用量收费，会改变客户的预算可预测性与重度使用风险。不能先选一个价格，再假设模型费用就是全部成本。

单位贡献等于该单位收入减对应可变成本。模型、检索、基础设施、人工支持和重试要按口径分摊。研发与固定经营支出另列；贡献为正不代表整体盈利，也不代表现金充足。

现金与收入发生时间不同。年度预收后仍有未来交付和可能退款；已开票未收款还不能支付当月支出。经营表要分已收、应收与假设，不把期待成交算成已到账。

本章所有数字是虚构算术训练，用来检查口径和敏感因素，不是价格、投资或财务处理建议。真实合同、税务与账务依据实际业务另行核对。

## 4. 案例逐步推演

虚构每团队月收入2000元，模型400、基础设施200、支持500，贡献为900，贡献率45%。若获客投入3600且该客户持续付费、贡献稳定，简单贡献回本约4个月；这些前提改变时估计也改变。

| 情景 | 月贡献 | 暴露的问题 |
| --- | --- | --- |
| 基准 | 2000-400-200-500=900 | 尚未扣固定支出 |
| 模型成本翻倍 | 500 | 重度使用与额度 |
| 支持成本翻倍 | 400 | 接入与服务边界 |

再看现金：期初10000，每月收到2000，支付可变成本1100与固定支出4000，每月净减少3100，三个月末依次为6900、3800、700。单位贡献为正，现金仍持续减少。

先根据客户任务提出含量、支持与超额规则，再通过真实报价和使用记录验证。不要把本例2000元直接作为建议售价。

### 4.1 让经营口径在代码中可以核对

```python
# track-example: P10
revenue = 2000
variable_cost = 400 + 200 + 500
contribution = revenue - variable_cost
assert contribution == 900
cash = 10000
balances = []
for month in range(3):
    cash += revenue - variable_cost - 4000
    balances.append(cash)
assert balances == [6900, 3800, 700]
```

这里使用同一虚构单位与月份，忽略税费、退款与时间差，只用来展示正贡献和现金减少可以同时发生。真实经营要按实际口径补全，不据这段代码决定投资或融资。

再起草套餐边界：面向一个团队，包含约定任务量与支持时段，超量如何告知、是否限额、额外服务怎样确认。用户需要预算可预测，你需要避免重度使用使成本失控；两者要共同验证。

若客户愿付费但每月支持量无法预测，先记录工单和接入时间，再决定价格和交付形式。低估人工支持会让“软件毛利”看似很高，实际却无法持续。

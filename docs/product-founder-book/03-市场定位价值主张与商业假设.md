# 第3章　市场定位、价值主张与商业假设

[上一章](02-用户研究访谈与证据整理.md) · [本书目录](教材目录.md) · [下一章](04-需求优先级产品规格与路线图.md)

## 1. 目标、前置与问题

前置：第1–2章。能定义初始客户群、比较替代，并构造商业模式假设。问题：为什么“所有企业都需要知识管理”不是可执行定位？

**本章主线：** 用任务、替代和责任链缩小服务对象，再用带来源与假设的乘法估算可触达范围，最后把定位、收益、代价和购买条件写进同一张商业假设卡。

## 2. 概念与基础

### 2.1 市场细分与理想客户画像

**市场细分**是按任务、组织条件或决策方式，把宽泛客户拆成可能具有不同需求的群体。**理想客户画像（ICP）**是从中选出的、当前最值得先服务的一组条件，不是一份人口统计学人物传记。

以 DocPilot 为例，可用的筛选条件是：已有制度维护人、经常核对制度、能够提供授权资料、接受保留原文复核。它们直接决定接入与交付是否可行。

| 筛选维度 | 可观察条件 | 为什么重要 |
| --- | --- | --- |
| 任务 | 最近一个月多次处理制度查证 | 决定问题是否反复发生 |
| 资料 | 有明确来源、版本和维护人 | 决定答案能否可核对 |
| 权限 | 能授权指定人员访问指定资料 | 决定方案是否可合法交付 |
| 流程 | 接受试点和任务观察 | 决定能否获得采用证据 |
| 购买 | 能识别预算与采购角色 | 决定采用能否转成收入 |

最小例子：同样需要知识管理，一家资料归属不清的集团与一家有兼职维护人的小团队，首版成本可能完全不同。前者需要先解决治理，后者可能适合直接试点。

### 2.2 价值主张必须相对替代

**价值主张**是面向特定客户，相对于当前替代方式，在某个任务上提供什么改善，并要求对方承担什么代价。没有“相对谁”的更好，只是广告词。

替代不仅是同类软件，还包括共享目录、询问同事、外包、表格和“暂时不做”。一个现有办法可能效率不高，但熟悉、便宜、无需采购。

| 比较项 | 共享目录与人工确认 | DocPilot 首版假设 |
| --- | --- | --- |
| 找到材料 | 熟悉目录的人较快 | 新人也能按问题检索 |
| 判断版本 | 依赖命名和负责人 | 展示日期、版本与负责人 |
| 接入成本 | 已有流程 | 需要授权与资料整理 |
| 责任 | 人工判断 | 保留原文与复核，不能自动代替批准 |
| 持续成本 | 维护目录与确认时间 | 软件费、更新与支持投入 |

价值主张应写成：“对于谁，在什么任务上，相比什么替代，改善什么，代价是什么。”例如：“为有制度维护人的小团队，相比目录加人工确认，更快定位业务日期适用的原文；需要整理授权资料并保留人工复核。”

### 2.3 TAM、SAM、SOM与估算纪律

**TAM**是在宽泛定义下所有潜在需求；**SAM**是产品当前定位与服务条件下可服务的部分；**SOM**是在给定周期、渠道和交付能力下实际可能触达和赢得的更小部分。它们不是三个必须宣传的大数字。

任何市场数字都要写单位、时间、定义、来源和乘数假设。没有可靠来源时，用情景计算暴露未知，不把它包装成行业事实。

| 层级 | 问题 | 常见错误 |
| --- | --- | --- |
| TAM | 如果按宽泛定义，总需求有多少？ | 用全行业收入代替客户数 |
| SAM | 符合资料、任务和采购条件的有多少？ | 忘记排除无法交付的客户 |
| SOM | 这段时间能接触、转化并交付多少？ | 假设所有适配团队都会成交 |

最小例子：某地区有10个可联系团队只是渠道假设，不是SAM。10个团队全部成交更不是SOM，除非已有转化与交付证据。

### 2.4 责任链与商业模式假设

**责任链**是把使用者、受益者、资料负责人、接入审批者和预算购买者串起来。一个人称赞产品，不代表这条链上的其他角色会放行。

**商业模式假设**则要说明：向谁收费、按什么单位、为什么值得付、怎样触达、怎样交付、哪些成本随客户增加。它与产品价值相关，但不能互相替代。

| 角色 | 希望获得 | 担心什么 | 需要的证据 |
| --- | --- | --- | --- |
| 专员 | 找到适用原文 | 找错版本、入口复杂 | 陌生任务能独立完成 |
| 资料负责人 | 更新清楚、少返工 | 无人维护、错误归责 | 版本、维护与复核流程 |
| 信息部门 | 可接入与可运行 | 权限、数据与支持 | 技术边界和运行计划 |
| 购买者 | 值得投入 | 预算与实际采用 | 任务改善、成本与试点结果 |

## 3. 机制与推导

### 3.1 用总采用成本比较替代

客户采用新产品不仅付订阅费，还要迁移资料、学习流程、接受安全审核、改变复核习惯和承担故障风险。这些构成**总采用成本**。

比较时先固定同一任务和同一周期：

1. 写当前办法的显性支出与人工时间。
2. 列新产品的采购、接入、学习、维护和支持成本。
3. 只比较可观察或可合理估算的部分。
4. 标出无法货币化的风险，例如错误引用或责任不清。

如果现有目录只需一次整理就能解决主要问题，新产品必须证明持续收益超过持续成本。功能数量不能直接进入比较。

### 3.2 自下而上估算与置信度

可触达团队数乘假设价格只是算术，不是收入预测。更完整的乘法链是：

```text
可联系对象 × 适配比例 × 进入试点比例 × 转付费比例 × 实际收费
```

每个比例都应有定义、时间窗口和来源。早期没有数据时，可以设低、中、高三个情景，并说明每个乘数是观察还是猜测。

预期结果不是得到一个看似精确的金额，而是知道哪个乘数最危险。例如适配率可能很高，但采购周期很长，近期现金仍可能不足。

### 3.3 商业假设与产品假设互相约束

定价单位会影响产品设计。按团队收费需要限制重度使用，按任务收费需要可核验计量，按席位收费需要定义席位与外部协作者。没有成本与价值依据时，不应先选一个价格再倒推功能。

商业假设也应能被证据改写：若小团队喜欢但无人维护资料，可能需要更轻的接入服务；若大客户需求强但定制过多，可能应调整定位或承认自己交付的是实施服务。

## 4. 案例逐步推演

**输入**：第2章的任务证据、10个可联系团队的教学假设和四类角色。**判断**：团队必须有维护人、可授权资料和真实查证任务，且收益要覆盖迁移与复核成本。**输出**：定位、排除项、责任链和带乘数的商业情景。**失败信号**：资料责任不清、采购链无人负责、所有适配团队都需长期定制；出现时缩窄人群或停止该场景。

把“企业AI效率平台”改成：“为有制度维护人的小团队，按业务日期找到可核对的制度原文。”然后按2.2的表比较共享目录、人工确认与首版方案。

首版暂不服务资料来源不清、无法确定维护责任的团队。这个排除降低误用和实施未知，也让后续访谈更具体。

若假设能接触10个适配团队、每团队年费24000元，乘积24万元只是“全部成交且能交付”的情景，不是收入预测。下一步应验证接触、采用和付费，而不是把乘积写在宣传页。

### 4.1 将使用与购买拆成责任链

| 角色 | 希望获得 | 担心什么 | 需要的证据 |
| --- | --- | --- | --- |
| 专员 | 找到适用原文 | 找错版本、入口复杂 | 陌生任务能独立完成 |
| 资料负责人 | 更新清楚、少返工 | 无人维护、错误归责 | 版本、维护与复核流程 |
| 信息部门 | 可接入与可运行 | 权限、数据与支持 | 技术边界和运行计划 |
| 购买者 | 值得投入 | 预算与实际采用 | 任务改善、成本与试点结果 |

这条链说明为什么一句用户称赞不能直接变成销售预测。先邀请适配的小团队做有限试点，既观察任务，也验证资料维护与采购步骤。若只有大客户能采用但每家都需数月接入，个人首版可能应调整目标。

定位的排除项也进入发布文案：只处理明确授权、可确定版本的资料；不提供自动法律或采购合规结论。边界应来自实际能力，不能靠“AI平台”模糊它。

### 4.2 从渠道乘数拆出未经验证的收入

以下比例**均为教学假设**：能联系10个团队，其中60%适配，适配团队50%进入试点，试点团队40%在一年内付费，年费24000元。

```python
# track-example: P03
from fractions import Fraction

contacts = 10
fit_rate = Fraction(60, 100)
pilot_rate = Fraction(50, 100)
paid_rate = Fraction(40, 100)
annual_price = 24000

fitted = contacts * fit_rate
pilots = fitted * pilot_rate
paid_teams = pilots * paid_rate
scenario_revenue = paid_teams * annual_price
all_paid_ceiling = contacts * annual_price

assert fitted == 6
assert pilots == 3
assert paid_teams == Fraction(6, 5)
assert scenario_revenue == 28800
assert all_paid_ceiling == 240000
```

预期结果：适配6个、试点3个、期望付费1.2个团队，对应28800元；全部10个成交的上限是240000元。1.2个团队是期望值，不是真的会出现“1.2个客户”。

推导：上限没有扣除适配、试点、采购和交付失败，因此不能当承诺；期望值依赖四个未验证乘数，任何一个变化都会改变结果。下一步应按“适配→试点→付费”逐环收集记录，而不是只复核乘法。

## 5. 分层练习

1. **基础**：用“谁、什么任务、相对哪个替代、改善什么、代价是什么”写一句定位，并选择一个本轮不服务的人群。
2. **改造**：画四角色责任链，为每类角色写一条需要观察的证据，说明哪种反馈不能替代另一种。
3. **独立**：用五个乘数做低、中、高三个收入情景，注明每个数字是观察、外部来源还是猜测，并指出最危险的乘数。

不要引用未核实的行业规模。没有来源时，保留“待验证”比制造精确数字更有价值。

## 6. 自测与参考推导

<details><summary>完成独立任务后查看诊断</summary>

- 若差异化只有“模型更先进”，用户仍不知道任务改善。
- 若购买者与使用者混为一人，就会漏掉预算和接入。
- 若定位越来越宽，应回看哪些新需求有证据。
- 若把TAM、SAM、SOM写成同一数字，说明没有服务条件和周期约束。

</details>

**自问：** 为什么“全部成交的收入”不能用来安排本月支出？

**参考推导：** 它忽略了适配、试点、采购、交付和回款时间，只是条件上限。本月支出需要按已签订单、实际到账、交付成本和现金时点安排，不能用潜在客户数替代。

## 8. 迁移与阅读

### 8.1 一页知识地图

**本章主问题：** 为什么“所有企业都需要知识管理”不是可执行定位？

**一条主线：**

```text
任务与组织条件 → 相对替代的收益和代价 → 责任链与商业假设
```

**三个关键词：** 细分、替代、责任链。先说清服务谁、跟谁比，再说谁被说服、谁付钱。

**最容易错：**

- 把全行业规模当实际可触达客户。
- 把10×2.4万元当收入预测。
- 只写收益，不写迁移、学习、整理与审核成本。
- 把使用者、维护者、接入者和购买者合成一个人。

**与前后章：** 第2章观察到的任务决定先服务哪类客户；本章的定位与排除项，第4章要收成有限范围的规格。

**学完应能：**

- 写一句可筛选、可比较的定位。
- 为责任链每类角色写需要的证据。
- 用带假设的乘法拆解收入，并解释它为什么不是预测。

[SBA商业计划入口](https://www.sba.gov/counseling/plan-your-business/)仅用于学习计划结构，美国制度不可直接当作本地经营要求。

# 全栈产品交付实操：从页面到可用切片

[本书目录](教材目录.md) · [产品思维训练](附录D-产品思维训练营.md) · [上线推广](附录F-上线发布与推广实验.md)

## 一、先定义全栈学习的完成标准

保留后端深度，前端先达到能实现用户任务、解释数据流、处理失败及定位问题。学习次序：HTML语义→CSS布局→JavaScript事件与异步→接口与状态→类型和组件→部署。先完成一个切片，再选一个框架深入，不要求同时学习多个框架或移动平台。

| 层次 | 要掌握 | 当前样例 |
| --- | --- | --- |
| HTML | 表单、标签、结构与键盘 | label关联input，按钮语义 |
| CSS | 盒模型、flex、窄屏与焦点 | 自适应输入及可见焦点 |
| JavaScript | DOM、事件、数组、异步与错误 | 提交、请求、渲染和取消 |
| API | 参数、状态码、JSON与限制 | GET /api/search?q=采购 |
| 工程 | 启动、检查、配置和边界 | 标准库启动与HTTP检查 |
| 后续扩展 | 身份、数据库、模型与部署 | 练习任务，当前没有实现 |

## 二、运行本地只读样例

文件位置：[server.py](../../practice/product_labs/search_slice/server.py)、[index.html](../../practice/product_labs/search_slice/index.html)、[app.js](../../practice/product_labs/search_slice/app.js)、[style.css](../../practice/product_labs/search_slice/style.css)。只使用两份虚构制度，不连接模型或真实数据。

在仓库根目录运行：

```powershell
.venv\Scripts\python.exe -X utf8 practice\product_labs\search_slice\server.py
```

浏览器打开终端显示的本地地址，默认http://127.0.0.1:8765；端口占用可加--port 8766。按Ctrl+C停止。使用同一服务提供页面和接口，便于先理解同源调用，不需要为了运行示例放开CORS。

Python官方说明[http.server不适用于生产](https://docs.python.org/3.12/library/http.server.html)。本样例固定监听本机；学习后需按下一节的增量任务与上线手册建立真实应用。不要将启动成功视为已完成生产部署。

## 三、手动走查数据流

1. HTML的form接收输入，label关联字段；不依赖placeholder代替标签。
2. JS阻止默认提交，创建AbortController，进入加载并清空旧结果。
3. fetch将参数编码后发送到同源接口，服务端校验长度和格式。
4. 服务端用固定数据检索并返回items；错误使用不同状态码。
5. 前端检查response.ok，再区分结果、空结果和错误。
6. 结果用textContent呈现，不把返回文本作为HTML执行。
7. 新请求取消旧等待，并用请求标识避免旧响应覆盖新结果。

取消前端等待不等于撤销服务端业务，本例无写副作用。日志不保存查询原文，样例没有真实权限控制；新增身份功能后必须在服务端检查，而非只在页面隐藏内容。

## 四、按层修改，形成独立实现

### 任务A：结构与布局

先不看完整代码，重新写输入、提交、状态区和结果列表。增加标题、描述、窄屏布局与焦点样式。只用键盘完成查询，检查文字缩放后仍可操作。

验收：页面语义清楚，不横向溢出；加载、空和失败有明确反馈。实际浏览器检查需要亲自执行，HTTP检查不能证明视觉或辅助技术体验。

### 任务B：数据与接口

新增一份虚构资料，给结果增加source字段，同步更新后端输出和前端展示。写正常、空白、超长、无匹配与未知路径案例。观察哪些约束前端有、哪些服务端仍必须有。

验收：不靠修改浏览器就绕过服务端长度限制；无匹配为合法空结果而非服务错误；404不泄露任意本地文件。

### 任务C：状态与异常

使用浏览器网络工具观察请求和JSON，关闭服务后查询；模拟慢网，连续发两次搜索。解释何时触发网络错误、HTTP错误或取消。

验收：旧结果不会覆盖新的查询；停止等待后可再发起；错误不让页面永久停在加载。检查[MDN fetch用法](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)。

### 任务D：类型与组件

掌握原生实现后，将输入、状态和结果拆为职责明确的组件，并迁移到选定框架。TypeScript可描述结果形状，例如下面仅为类型片段，需准备对应编译环境：

```typescript
type Source = { id: string; title: string; version: string; text: string };
type SearchResult = { items: Source[]; mode: string };
```

静态类型不验证网络返回，仍需运行时检查。比较迁移前后的行为，不能只因页面显示相似就认定完成。

## 五、从切片到完整产品的增量顺序

先确认需要的用户任务，再按风险推进：数据持久化→可信会话与对象权限→资料更新与来源→必要的后台任务→观测与部署→按证据加入AI。每轮保留一条完整可用路径和失败演练。

| 增量 | 验收变化 |
| --- | --- |
| 数据库 | 重启后数据仍在，事务与迁移可复查 |
| 登录与权限 | A能访问自己的资料，不能访问B的资料 |
| 后台导入 | 任务ID、状态、重试和未知结果可解释 |
| AI回答 | 引用支持结论，无证据有明确处理 |
| 实际部署 | 独立环境复现、HTTPS、监控与恢复 |

这些是后续任务，不是当前样例已实现的功能。现有项目接口约束以[实践规格](../project-practice/项目实践规格.md)为准，不能为了快速演示取消批准或权限边界。

## 六、检查与交付包

运行HTTP契约检查：

```powershell
.venv\Scripts\python.exe -X utf8 practice\product_labs\search_slice\checks.py
```

它启动临时本机端口并检查页面、静态文件、合法查询、空结果、非法输入与路径限制，然后关闭服务；不检查浏览器布局、真实认证、数据库或模型质量。

最终提交任务流、状态表、运行命令、接口样本、检查结果、浏览器观察及限制。能从用户看到的错误追到对应层，并在改变一个字段后完整修正界面、接口和验证，才算独立掌握这条切片。

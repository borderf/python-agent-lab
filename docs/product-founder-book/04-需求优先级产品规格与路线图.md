# 第4章　需求优先级、产品规格与路线图

[上一章](03-市场定位价值主张与商业假设.md) · [本书目录](教材目录.md) · [下一章](05-交互设计可用性与无障碍.md)

## 1. 目标、前置与问题

前置：第2–3章。能从证据选择最小验证范围，写出开发与验收共用的规格。问题：只有两周，你保留什么？

## 2. 概念与基础

先把“做一个知识库”改写成“新人能独立找到发布当日有效的回退规定”。前者是方案，后者是要验证的用户变化。第一轮可以只给少量授权资料和来源页面，让新人完成陌生任务；这就是围绕关键假设收缩最小方案。确认是否有价值后，再为多格式上传等功能排序，基础权限与失败反馈仍随当前场景一起交付。

优先级考虑影响、频率、信心、投入、依赖和风险。RICE等评分可以帮助显式比较，但主观输入会制造假精确；安全、合同和关键依赖不能只靠分数平均掉。

## 3. 机制与推导

需求优先级取决于当前要减少哪个未知。首轮若验证能否找到有效来源，聊天记忆和多角色并不是前置。先画从进入到完成的最短路径，再选能闭合这条路径的功能，避免把各部门愿望平均分配。

规格连接问题与实现：目标用户、证据、目标、范围、主流程、异常、权限、指标和验收。每条验收应描述可观察行为，不能只写“体验好”“回答准确”。没有结果、依赖失败和无权限同样属于产品设计。

预算训练迫使取舍。给功能估算只用于比较，不是精确承诺；发现隐藏工作后要改范围或时间。路线图按问题与证据推进，近期明确，远期保留不确定性，不把所有反馈永久承诺。

```mermaid
flowchart LR
    A[任务与证据] --> B[本轮目标]
    B --> C[最短用户路径]
    C --> D[范围与异常]
    D --> E[验收与测量]
    E --> F[开发与观察]
```

## 4. 案例逐步推演

一份首版规格可以直接写成：

用户：已有授权资料的专员。问题：难以确认业务日期适用原文。目标：独立完成给定查证任务。主流程：选择日期→输入问题→查看来源→打开原文→确认是否解决。

| 情况 | 应有行为 | 验收输入 |
| --- | --- | --- |
| 有有效来源 | 展示正文、版本和适用日期 | 一份旧版与一份新版 |
| 无证据 | 说明未找到并给下一步 | 无匹配问题 |
| 无权限 | 不展示他人标题或片段 | 替换来源ID |
| 生成超时 | 保留可访问来源并标识 | 模型超时替身 |

教学预算8点：搜索2、来源定位2、状态反馈2、任务反馈1、教学身份适配1，恰好8点。历史聊天3点本轮暂缓。如果客户任务必须导出，应重新比较范围，而不是再叠3点却维持原交期。

这份规格的自动验收可以保护过滤和引用；用户是否理解日期、能否独立完成，要在第5章观察。

### 4.1 把验收写成一次完整任务

正常样本：给定专员A和有权访问的两版制度，当输入6月30日付款问题时，系统返回旧版来源与日期；改成7月1日时返回新版。验收者必须能打开对应原文，不只看到20%或30%的答案。

异常样本：给定无匹配问题，展示未找到及可调整的问题/日期；给定未知身份，提示重新建立会话；给定越权来源，不能泄露标题；给定模型超时，保留授权来源并标识摘要不可用。

这些验收同时指导界面状态、接口字段、服务端检查和埋点。实现任务可以拆成核心过滤、接口和来源展示，但每个增量尽量让一条用户路径可验证。

规格中的不做范围也要有理由：“不做长期聊天记忆，因为本轮验证一次查证；不做自动提交，因为尚无动作需求；不做任意文件格式，因为解析能力未验证。”下一轮出现新证据时再重新排序。

## 5. 分层练习

先完成：写一页首版规格，限制最多三个主要能力，包含至少三种失败状态。收到“加历史记录”反馈后，写它支持哪条任务、会挤掉什么，再决定是否进入本轮。

完成后换一个约束或一组输入，解释原决定哪里需要改变。基础任务通过后再做深化；本章不要求把所有扩展同时实现。

## 6. 自测与参考推导

合上正文，复述问题怎样出现、机制为什么有效、哪些条件下仍会失败。再对照下面的诊断检查自己的成果。

<details><summary>完成独立任务后查看诊断</summary>

若每项都是最高优先级，说明尚未按目标取舍。若验收只写正常页面，联调时会临时发明错误行为。若用户目标是找原文而验收只有聊天生成成功，目标与实现已经脱节。

</details>

## 7. 项目交付与验收

保存 `product/spec.md`，后续原型、代码和埋点都引用这份任务与验收。下一章先在低成本原型中验证用户是否能走通。

验收时由你或同伴用新条件检查，记录输入、实际结果与解释。设计练习以推理和反例判断，代码任务用实际行为检查；涉及用户与商业的结论只使用相应真实证据。

## 8. 迁移与阅读

配合第5–6章将规格落为界面与开发任务；[原项目规格](../project-practice/项目实践规格.md)提供接口与状态约束，新增产品范围不得默默改变安全契约。

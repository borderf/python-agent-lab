# 第14章　综合产品实战与创业验证

[上一章](13-创业路径资源配置与决策.md) · [本书目录](教材目录.md) · [工作簿](附录A-工作簿与模板.md)

## 1. 目标、前置与问题

前置：第1–13章。完成从问题到交付、衡量和经营验证的闭环。可选择DocPilot、ProcureAgent或已确认的真实场景；不要求同时实现两个项目。

**本章主线：** 用同一条原始任务记录串起问题、规格、交互、切片、测量与决定，再分别从产品和创业角度审计每条主张。完成作品不等于商业成功；诚实标明证据状态也是交付。

## 2. 概念与基础

### 2.1 产品作品与创业作品

**产品作品**证明你能定义问题、做出取舍、交付可用方案并观察结果，包括问题、证据、流程、实现、效果和下一步。**创业作品**额外证明购买者、渠道、收费、成本和经营约束。

| 材料 | 产品答辩要证明 | 创业答辩要证明 |
| --- | --- | --- |
| 问题与证据 | 任务真实、解释有边界 | 目标客户与购买条件相关 |
| 规格与切片 | 结果、异常和边界一致 | 交付范围可重复、成本可算 |
| 测量 | 任务结果可复算 | 采用与收入假设可检验 |
| 发布与试点 | 用户能进入并使用 | 渠道、采购和支持可安排 |
| 成本与决定 | 下一步由证据触发 | 投入与风险可承担 |

最小例子：页面能访问只证明发布路径成立；它不能证明用户独立完成，更不能证明有人持续付费。

### 2.2 证据状态与主张边界

每条材料至少标一种状态：**已实现**、**模拟训练**、**真实观察**、**仍待验证**。已实现说明代码或流程存在，不自动说明有效；真实观察说明发生过，不自动说明可外推。

| 状态 | 可以写 | 不可以写 |
| --- | --- | --- |
| 已实现 | 某接口、页面或检查可运行 | 用户价值已经成立 |
| 模拟训练 | 方法按虚构材料演练 | 已访谈真实客户 |
| 真实观察 | 某对象在某时点出现某行为 | 总体比例或稳定因果 |
| 仍待验证 | 当前未知与下一份证据 | 把未知写成成功假设 |

阶段评价看能否独立解决问题，读完不等于掌握。没有真实用户时可以模拟研究与分析方法，但无法由模拟证明真实需求和付费。

### 2.3 主张—证据—决定链

一条完整主张应能回溯：

```text
主张 → 原始材料 → 口径与判断规则 → 结果 → 决定 → 复审条件
```

例如“日期提示减少误用”：原始材料是逐人任务记录，规则是业务日期正确且独立打开原文，结果是新样本中该错误是否减少，决定是保留、修改或撤销提示。若原始记录不存在，主张只能标待验证。

这张链也能暴露断裂：问题卡说查证，规格却做聊天社交，指标只看点击，商业表只算模型费用。每份材料单独漂亮，组合起来仍不是同一产品过程。

### 2.4 产品正确、AI可核对与业务批准

技术测试说明实现能否按约定规则工作；用户行为说明是否有人采用；付费与交付记录说明能否经营。AI回答还多一层证据与人工判断，业务动作再多一层授权与批准。

| 层次 | 问题 | 证据 |
| --- | --- | --- |
| 技术正确 | 代码是否按规则运行？ | 单元、集成与端到端测试 |
| 引用可核对 | 结论能否回到指定版本原文？ | 引用契约与quote核对 |
| 业务适用 | 日期、对象、条件是否适用？ | 规则或适当人员复核 |
| 任务有效 | 用户是否独立完成？ | 观察记录与成功标准 |
| 商业成立 | 是否有人持续采用并付费？ | 购买、回款、交付与续用记录 |

这些层次不能互相替代。引用存在不等于事实正确，用户满意不等于商业成立。

## 3. 机制与推导

### 3.1 就地定义引用契约、quote与批准失效

**引用契约**是回答与证据之间的结构约定：每条结论关联来源文档ID、版本、适用区间、定位信息和quote。**quote**是从该版本原文逐字截取的片段，用于让复核者回到上下文；它本身不保证结论、条件或数值被正确解释。

最小核对顺序：

1. 来源存在且当前身份可访问。
2. quote确实出现在指定版本的对应位置。
3. 业务日期落在来源适用区间内。
4. 结论与quote在对象、条件、数值和方向上一致。
5. 结论仍由本次内容版本支持。

**批准失效**指批准与批准时的载荷版本绑定；载荷、来源版本或适用条件改变后，旧批准不再能授权执行。可用版本号或内容摘要绑定，但执行前仍要重新检查权限与业务状态。

为什么需要这些机制？因为“模型说已提交”不是提交成功，“有引用”也不是事实正确。产品必须让复核者看见原文、条件和本次载荷，并保留真实回执。

### 3.2 样本判断与效果主张

**样本判断**同时说明样本单位、选择方式、数量、窗口、独立性和不确定性。它可以决定一条主张能写到哪里。

| 结果 | 最多能写 | 下一份有判别力的证据 |
| --- | --- | --- |
| 5人中3人完成 | 这5人的记录为3/5 | 可比新任务与更多参与者 |
| 40/100对45/100 | 观察到5个百分点差异 | 随机分配、区间、独立样本 |
| 3家同意演示 | 存在进一步沟通意愿 | 授权资料、试点投入与采购路径 |
| 1家付费试点 | 发生一次限定承诺 | 实际采用、交付成本、续用 |

不要把口头答对、来源返回或第二次更熟练临时改算成功。若成功标准改变，应另立指标并说明，不能回写旧结果。

### 3.3 审计矛盾与决定复审

每条决定写复审条件：出现什么新证据就重新打开。审计时主动寻找矛盾，例如宣传承诺超出规格、成本遗漏复核工时、批准后内容仍可修改。

一次失败的作品也可以很有价值，前提是说明减少了哪个未知、为何改变决定、下一步怎样可逆。失败若没有改变动作，就只是结果，不是验证闭环。

## 4. 案例逐步推演

**输入**：前13章材料、一条陌生任务和一份虚构引用/载荷。**判断**：每条主张都要回到原始记录，任务完成、引用正确、批准有效和商业成立分别检查。**输出**：同一索引页上的产品答辩、创业答辩和证据状态。**失败信号**：数字无原始记录、quote与版本不符、载荷变化后旧批准仍有效；出现时降级主张或阻断执行。

用同一个 DocPilot 做两次答辩。产品答辩：谁要查什么、原来怎样做、哪里阻碍、为何先做来源、用户是否独立完成、哪次错误改变了界面或范围。创业答辩：谁付钱、采用条件、渠道、交付工作量、成本口径与下一轮投入。

准备一条陌生任务：“把采购制度改成发布规范，回答发布当日适用哪条回退要求。”先确认资料与判定规则，再说明哪些代码能复用、哪些权限、日期与流程需要调整。若新任务只需查证，就不加入自动提交。

最终建立一个索引页，链接前13章累计成果。没有真实访谈或支付的地方写待验证，不用模拟材料填成成功案例。

### 4.1 用同一个索引页完成两种答辩

产品部分按“任务记录→问题卡→规格→流程→切片→测量→修改”链接。挑一次错误展开：用户误用当前日期，原型观察发现，界面改文案与位置，随后换新题复测。没有真实观察则展示模拟方法与待做计划。

创业部分按“购买者→采用条件→渠道→试点→成本→资源决定”链接。效果数字回到逐条任务，付费回到实际记录，成本回到口径。没有这些证据时可以完成分析训练，但不能声称商业成立。

技术部分展示你能沿界面、请求、核心、数据和运行解释一条失败。对方临时换任务时，先明确判断规则和资料，再决定复用或修改，不因已经有Agent就强行给新任务加动作。

最终材料不追求文件多：一个索引页、一条能复现的路径、一组可核查证据和一次改变决定的反例，已经比许多没有连贯关系的模板更能展示能力。

### 4.2 一项产品主张怎样经过观察而修改

以下访谈、任务和数字**全部虚构**，用于练习判断，不是本仓库用户研究结果。沿用同一个按业务日期查制度的DocPilot，持续修改前面的问题卡、`product/spec.md` 和决定记录。

**初稿：** “采购人员需要AI聊天，提高效率50%；先做聊天历史和多Agent，上线后推广。”这混合了需求、技术方案和未经测量的收益。评审会问：哪类人员的什么任务？现在怎样完成？完成标准是什么？50%的分母和计时范围是什么？

**把主张改成可观察任务：** “新人面对一份未见过的业务记录，在授权资料中找到业务日期适用的制度，独立打开正确版本原文并指出相关条款。”首次观察固定资料和任务规则，记录求助、错误及从进入到完成/停止的总时长；不只统计模型生成耗时。

| 虚构逐人记录 | 首次结果 | 观察到的首个障碍 | 能否据此判断付费 |
| --- | --- | --- | --- |
| U1、U2、U3 | 各自独立完成 | 暂无阻断，仍记录路径与耗时 | 不能 |
| U4 | 选错适用版本，未完成 | 默认今天，未注意业务日期 | 不能 |
| U5 | 口头答对比例但未完成任务 | 没有找到原文入口 | 不能 |

按事先定义，本轮独立完成是3/5；不能把U5“答对比例”临时改算成功。这个小样本有助发现具体障碍，不证明总体成功率，也不证明“提升50%”。尚未记录可比的旧流程任务耗时，更不能给出效率收益。

**修改规格：** 首屏明确业务日期且在结果区重复显示；来源卡展示版本和“打开原文”；无依据、无权限与生成失败分别给下一步。暂缓历史记录和多Agent，因为它们不直接修复当前两个障碍。服务端日期过滤与来源授权一并验收，不能只改文案。

**再次验证：** 用可比难度的新任务观察新的参与者，记录是否仍误用日期、是否能独立打开正确来源；原参与者可做补充，但需标记熟悉效应。没有随机对照与足够样本时，不把前后小样本差异写成因果提升。先验证障碍是否减少，再决定是否值得做更大实验。

这条记录把第2章任务证据、第4章规格、第5章交互、第6章切片和第7–8章的测量连起来。若真实观察与你的预期相反，就更新同一份决定，而不是再增加一张功能清单。

### 4.3 从“能用”走到“有人购买”，还缺哪些证据

假设使用者愿意再次使用，购买负责人却要求资料留在内网，并需要可核查的原文导出。此时不要直接把“满意”填成收入预测；补问谁有预算、采购/安全条件、替代方案、试点任务与时间窗口，再估算接入、部署、支持和维护成本。

| 产品/创业主张 | 当前材料最多支持什么 | 下一份有判别力的证据 |
| --- | --- | --- |
| 页面能访问 | 发布路径成立 | 陌生用户从新会话独立完成任务 |
| 五个人觉得有用 | 这些人的主观反应 | 在真实任务机会下复用，并记录放弃原因 |
| 三家同意演示 | 有进一步沟通意愿 | 谁愿意提供授权资料、安排试点并承担接入成本 |
| 一家付费试点 | 发生一次限定承诺 | 实际采用、交付成本、后续续用/续费；不推断市场规模 |
| 单次模型成本低 | 直接推理费用有限 | 接入、支持、销售与运行等完整成本口径 |

发布稿此时可承诺已验证的范围：“支持指定授权资料的按日期查证，结果可打开来源；首轮限定任务与支持窗口。”不要使用尚未测量的效率百分比。第11章的渠道材料继续围绕这一任务，逐条记录触达、试用和购买的阻碍。

**本轮资源决定示例：** “先完成一个范围有限的试点，验证内网交付成本与首次任务；不因一次满意评价扩建团队。若资料接入不可行或采用条件超出可承担范围，缩小范围或停止；若出现可重复任务与可接受成本，再增加投入。”这是待验证的决定，实际销售、定价和财务结果仍要用真实材料替换。

独立练习时把购买条件改成“个人按月付费”，重新选择触达渠道、入门路径、支持范围和成本口径。不能原样复制企业试点方案，也不能用模拟购买记录代替真实付费。

### 4.4 核对引用与批准是否仍绑定本次载荷

以下资料、quote和载荷**均为虚构**。程序只检查结构、逐字片段和版本绑定，不能判断业务语义是否正确。

```python
# track-example: P14
from hashlib import sha256

source_v2 = "付款制度版本2：预付款比例不得超过合同金额的20%。"
contract = {
    "claim": "预付款上限为20%。",
    "doc_id": "doc-7",
    "version": 2,
    "effective_from": "2026-07-01",
    "effective_to": "2027-01-01",
    "quote": "预付款比例不得超过合同金额的20%。",
    "locator": "第2节第1段",
}
assert contract["quote"] in source_v2
assert contract["effective_from"] <= "2026-07-01" < contract["effective_to"]
assert not (contract["effective_from"] <= "2027-01-01" < contract["effective_to"])
assert all(contract[key] for key in ("doc_id", "version", "locator"))

payload = "比例20%；来源版本2；业务日期2026-07-01"
approved_digest = sha256(payload.encode("utf-8")).hexdigest()
assert approved_digest == sha256(payload.encode("utf-8")).hexdigest()

changed_payload = payload.replace("20%", "30%")
approval_still_valid = approved_digest == sha256(changed_payload.encode("utf-8")).hexdigest()
assert approval_still_valid is False
```

预期结果：quote能在版本2原文找到，关键定位字段存在；业务日期按左闭右开区间落在适用范围内，到期日 `2027-01-01` 不再适用；把载荷中的20%改成30%后，摘要不同，因此旧批准失效。推导：引用契约让结论可回到原文，批准绑定让执行不脱离复核者看到的内容。

边界：日期字符串比较只适用于本例统一格式；真实系统应使用日期对象和生效区间。内容摘要相同不代表语义正确、权限仍有效或外部系统执行成功，仍需适用性复核、当前授权和真实回执。

## 5. 分层练习

1. **基础**：建一个索引页，把问题、证据、规格、流程、切片、测量和修改按同一任务串起来，给每条材料标证据状态。
2. **改造**：挑一条效果主张，追溯原始记录、分子分母、样本判断和口径；若追溯不到，就降级为待验证。
3. **独立**：从新会话让同伴完成一道新任务，再给一次载荷修改，检查引用、旧批准和执行回执；最后根据产品与创业两种理由分别调整范围或资源。

可以先做模拟答辩，但明确模拟材料不能证明真实需求、持续采用或支付。

## 6. 自测与参考推导

<details><summary>完成独立任务后查看诊断</summary>

- 若效果数字追溯不到逐条记录，不能用于对外承诺。
- 若quote存在就被判事实正确，漏掉版本、适用性和语义核对。
- 若载荷改变后旧批准仍有效，执行授权已经脱离复核内容。
- 若失败没有改变下一轮决定，就没有形成验证闭环。

</details>

**自问：** 为什么一份诚实的“商业未验证”作品仍可以是好作品？

**参考推导：** 综合实战评价的是能否定义问题、交付、测量和决策。明确标出未知、反例和停止条件，说明过程可审计、下一步有依据；虚构成功反而会破坏整条证据链。

## 7. 项目交付与验收

尚未积累真实材料时，先用[原始材料包](../../practice/case_studies/README.md)练一次：从访谈原话、逐条任务观察、成本账中提出改进，先提交自己的规格与决定再看反馈。它与本章案例独立，所有数字和人物均虚构；不能算真实访谈、效率提升或支付。随后以同一记录格式开展自己的验证，继续更新原有product文档。

提交 `product/index.md`，链接问题、证据、规格、流程、代码、测量、发布、经营与决定；只补缺项，不重写整套材料。分别标明已实现、模拟训练、真实观察和仍待验证。

| 操作 | 预期结果 | 应保留的证据 |
| --- | --- | --- |
| 走陌生任务 | 按同一标准记录完成、错误、求助、耗时 | 资料版本、逐步记录、结果 |
| 追溯效果主张 | 数字回到原始材料与口径 | 分子分母、样本判断、窗口 |
| 核对引用 | 来源、版本、quote、定位与适用性一致 | 契约字段、原文、复核结论 |
| 修改载荷 | 旧批准失效，执行前重新检查 | 内容摘要、批准版本、回执 |
| 核对经营材料 | 付费、成本、支持与资源决定相连 | 报价、回款、工时、预算 |
| 完成索引 | 每条主张标明证据状态和下一步 | 链接、状态、未知、复审条件 |

## 8. 迁移与阅读

### 8.1 一页知识地图

**本章主问题：** 怎样证明这十几份材料讲的是同一个产品，而不是彼此漂亮的作业？

**一条主线：**

```text
原始任务记录 → 规格、切片与测量 → 引用和业务证据 → 产品与创业两次答辩
```

**三个关键词：** 贯穿证据、诚实边界、改变决定。主张要能回到证据，换了条件还要能改方案。

**最容易错：**

- 问题卡说查证，规格却做聊天社交，指标只看点击。
- 把quote存在当事实正确，或载荷改变后沿用旧批准。
- 效果数字追溯不到记录，却写进对外材料。
- 用模拟访谈、模拟支付填成真实采用或收入。

**与前后章：** 前13章留下问题卡、规格、切片、测量、发布与经营材料；本章只补缺项并标出证据状态，之后交给真实工作里的一次产品结果。

**学完应能：**

- 用一个索引页串起任务、规格、流程、切片、测量和修改。
- 对引用、批准和效果分别说明检查规则与结论边界。
- 对每条主张标出已实现、模拟训练、真实观察或待验证，并给出下一份证据。

# 第2章　用户研究、访谈与证据整理

[上一章](01-产品型工程师与机会判断.md) · [本书目录](教材目录.md) · [下一章](03-市场定位价值主张与商业假设.md)

## 1. 目标、前置与问题

前置：第1章。能招募相关用户、设计非诱导问题，并从记录形成可追溯结论。问题：如何避免只听到自己希望听到的答案？

## 2. 概念与基础

先选一位最近查过制度的人，请他复述上一次怎样找到文件；这一步是访谈。再观察他实际打开哪些页面、找谁确认版本，检查叙述与行为有哪些差别。最后给他一个原型任务，观察是否能独立完成，这才是在做可用性测试。三种方法分步使用，各自留下原记录，再决定是否需要问卷扩大调查。

样本应覆盖关键差异，如新手与熟手、使用者与购买者、常见与异常任务。小样本可发现机制和线索，不能直接推出总体比例。研究前明确用途、记录许可及保留范围，避免收集不必要的敏感信息。

## 3. 机制与推导

访谈不是收集支持想法的赞美，而是重建用户已经发生的行为。问“你会用AI吗”得到的是预测和态度；问“上次核对规定时从哪里开始”才可能得到步骤、资料、参与者和失败后果。

样本要由任务筛选。找最近实际做过这件事的人，同时找顺利完成或选择不用工具的人，避免只采访抱怨者。样本少时主要用于发现解释和反例，不据此声称整个市场的比例。

记录要分层：原话是用户说了什么，观察是你看见什么，解释是你认为为何如此，待验证是假设还缺什么。一个人说等待很久，并不自动证明搜索差；可能是权限、责任或制度本身不明确。

研究必须改变决定。访谈后把发现写成“在什么任务中，什么行为导致什么后果，证据是什么，还有什么解释”。下一步可能是改范围，也可能是补访买方或停止开发，而不一定新增功能。

## 4. 案例逐步推演

沿用问题卡，写一段可以直接练习的访谈：

| 提问 | 想了解什么 | 避免怎样引导 |
| --- | --- | --- |
| 最近一次需要查制度是什么时候？ | 具体任务是否发生 | 不先问是否喜欢AI |
| 当时先打开哪里，之后找了谁？ | 实际步骤与参与者 | 不暗示共享目录很差 |
| 怎么确认这份是当时有效版本？ | 判定依据 | 不提示应该显示日期 |
| 哪一步花时间，最后怎样完成？ | 阻碍与替代 | 不将等待都算成搜索耗时 |
| 若当时不解决，会发生什么？ | 问题后果 | 不替用户夸大损失 |

虚构 R01 原话：“我主要在等负责人确认。”O01 观察：目录中两版文件名相近。H01 解释：显示日期可能减少部分确认。反例 R02：“即使日期明确，负责人也要求确认。”下一步就要访谈负责人，而不是直接宣称日期展示能省20分钟。

整理时让每条结论链接 R01、O01 等材料 ID；这些是证据索引，不是额外学习进度。

### 4.1 看三条材料怎样改变最初结论

虚构R01：“文件夹里两个版本，我问负责人哪份生效。”R02：“日期写清也要找负责人，因为需要确认适用项目。”R03：“熟悉流程后我用目录很快，新人更容易找错。”这些材料既支持版本问题，也限制了“全员节省20分钟”的推断。

先归纳共同事实：查证不仅是找文本，还涉及适用性与责任。再分群：新人可能需要检索与定位，熟练人员可能需要快速确认，负责人关心更新责任。不要把三条不同任务平均成一个“用户画像”。

下一轮提纲围绕分歧：“最近一次必须找人确认，是日期不清、项目不同，还是流程要求？”可以请求观察经授权的操作，不能要求对方提供无权分享的合同。记录匿名任务细节与同意范围。

访谈结束后写一条决定：“先测试新人查证路径；暂不承诺自动适用判断；补访负责人。”如果研究后产品规格完全没变，检查是否真的允许证据反驳自己。

## 5. 分层练习

先完成：完成一次20分钟任务访谈，或与同伴用虚构材料训练。当天整理三条原话、两种解释和一条反例，明确哪一个产品决定因此变化。记录前确认参与方式与资料范围。

## 8. 迁移与阅读

### 8.1 一页知识地图

**本章主问题：** 怎样避免只听到自己希望听到的答案？

**一条主线：**

```text
最近一次真实查证 → 原话、观察、解释分层 → 一条被改写的产品决定
```

**三个关键词：** 行为重建、证据分层、反例——先记用户做过什么，再谈他为什么这样做。

**最容易错：**

- 问“你会用AI吗”，得到的是预测和态度，不是上次核对规定的步骤。
- 把 R01 的“等负责人确认”直接读成“日期展示能省20分钟”，跳过 R02 这条反例。
- 只采访抱怨者，样本里没有顺利完成或主动不用工具的人。
- 研究做完，规格一个字没变。

**与前后章：** 第1章的问题卡给出待验证假设；本章的证据，第3章用来选择目标人群与要比较的替代方案。

**学完应能：**

- 设计五条不诱导的提纲，覆盖任务是否发生、实际步骤、版本判定依据与后果。
- 把三条原话整理成带 R/O/H 编号的证据表，并保留一条与结论相反的材料。
- 写出“先测新人路径、暂不承诺自动适用判断、补访负责人”这类可执行决定。

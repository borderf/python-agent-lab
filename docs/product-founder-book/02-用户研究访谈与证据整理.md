# 第2章　用户研究、访谈与证据整理

[上一章](01-产品型工程师与机会判断.md) · [本书目录](教材目录.md) · [下一章](03-市场定位价值主张与商业假设.md)

## 1. 目标、前置与问题

前置：第1章。能招募相关用户、设计非诱导问题，并从记录形成可追溯结论。问题：如何避免只听到自己希望听到的答案？

**本章主线：** 从最近一次真实任务出发，把原话、观察、解释和待验证分开保存，再用反例检查结论，最后让证据改变一个产品决定。以下 R01、O01 等编号都是虚构教学材料。

## 2. 概念与基础

### 2.1 访谈、观察与可用性测试

**访谈**是让参与者重建过去发生的行为和原因；**观察**是记录现场实际动作、工具、等待和环境；**可用性测试**是给参与者一个目标，观察他能否使用当前设计独立完成。三者回答的问题不同。

| 方法 | 输入 | 能得到什么 | 不能直接得到什么 |
| --- | --- | --- | --- |
| 访谈 | 最近一次任务经历 | 步骤、理由、参与者、替代办法 | 实际点击是否顺畅 |
| 现场观察 | 真实工作过程 | 叙述与行为差异、隐藏等待 | 新设计是否有效 |
| 可用性测试 | 原型与目标任务 | 理解、误用、阻断、求助 | 总体成功率、付费意愿 |
| 问卷 | 明确问题和适当样本 | 结构化回答的分布 | 深层原因与未列出的行为 |

为什么先访谈和观察？因为如果用户从未完成过该任务，让他评价原型可能只得到想象。可用性测试也不等于问“喜欢吗”，它要求实际完成动作。

### 2.2 样本选择与样本判断

**样本判断**是说明当前这些人、这些任务和这些情境能支持到什么结论，不能支持到什么结论。研究通常采用**目的抽样**：按关键差异选择参与者，而不是追求随机代表总体。

最小样本可以覆盖：新手与熟手、使用者与批准者、最近成功与最近失败、常规任务与异常任务。例如只找三位抱怨搜索慢的新手，无法判断熟手是否也有同样问题。

| 样本设计 | 适合发现 | 结论边界 |
| --- | --- | --- |
| 3位最近失败者 | 失败路径和共同阻碍 | 不能说问题影响所有人 |
| 失败者加顺利者 | 哪些条件导致不同结果 | 仍不能推算比例 |
| 使用者加负责人 | 操作与责任之间的冲突 | 需继续找预算和接入角色 |
| 同类任务多次观察 | 某机制是否重复 | 新情境可能改变机制 |

常见错误是为了“样本足够大”收集很多无关访谈，却没有覆盖关键角色。样本数量不能弥补选择偏差。

### 2.3 原话、观察、解释与待验证

研究材料必须分层：

- **原话**：参与者说了什么。访谈中的 **quote** 指逐字引用的原话片段，不应偷偷改成自己的总结。
- **观察**：研究者实际看见的动作或环境，例如目录中两版文件名相近。
- **解释**：研究者对原因的判断，例如日期标签可能减少部分确认。
- **待验证**：解释还缺哪些证据，例如负责人是否仍要求人工确认。

一个人说“我主要在等负责人”，并不自动证明搜索差。等待可能来自权限、责任分工或制度本身不明确。把解释当原话，会让证据链在起点就失真。

### 2.4 同意、隐私与最小化记录

研究前说明目的、参与方式、记录范围、保存时间和退出方式。只收集回答问题所需的信息；合同号、个人信息和正文可以按权限用脱敏任务描述替代。

“客户上传了”不等于研究者有权录音、公开引用或用于其他目的。需要展示材料时，应确认引用范围与匿名方式。无法获得授权时，用虚构材料练方法，并把真实研究标为待验证。

## 3. 机制与推导

### 3.1 用非诱导问题重建行为

“你会用AI吗”问的是预测和态度；“上次核对规定时从哪里开始”才可能得到步骤、资料、参与者和后果。访谈按时间顺序追问，比先介绍产品更容易减少引导。

| 提问方式 | 为什么有偏差 | 改写 |
| --- | --- | --- |
| 日期标签是不是很方便？ | 预设方案有价值 | 你当时怎样确认哪版适用？ |
| 你是不是经常找不到文件？ | 预设频率和根因 | 最近一次找文件经历了哪些步骤？ |
| 如果省20分钟你会买吗？ | 把虚构收益当事实 | 这次任务花了多久？不解决会怎样？ |
| 还有什么需求？ | 太宽，容易得到功能愿望 | 哪一步最想先改变？为什么？ |

访谈中以复述确认理解：“我听到你先问负责人、再打开目录，对吗？”复述不是诱导，而是检查研究者有没有理解错。

### 3.2 编码、三角核对与反例

**编码**是给材料贴上有意义的分类标签，例如“等待确认”“命名混淆”“权限不足”。标签要能回到原记录，不能只留在研究者脑中。

**三角核对**是比较不同来源：同一事件的原话、现场观察和系统记录是否一致。一致会增强信心，不一致则应保留矛盾并继续调查，而不是删掉不方便的材料。

反例搜索可以问：谁顺利完成？谁主动不用工具？什么情况下等待反而必要？如果所有记录都支持最初想法，先检查提问和抽样，而不是宣布结论可靠。

### 3.3 从发现到产品决定

一条可执行发现应包含：“在什么任务中，什么行为导致什么后果，证据是什么，还有什么解释。”然后再写决定。

例如：“新人在版本相近时容易误选；R01显示等待，O01显示命名相近，R02说明日期明确后仍需确认。先测试新人路径与版本提示，暂不承诺自动适用判断，并补访负责人。”

如果研究后规格完全没变，有两种可能：证据确实支持原方案，或研究没有允许方案被推翻。应在记录中说明是哪一种。

## 4. 案例逐步推演

**输入**：一位最近查过制度的专员、经同意的记录范围和三类虚构材料。**判断**：等待是最大阻碍，但日期不清与流程要求都仍可能成立。**输出**：带支持与反例的证据表，以及“先测新人路径、暂不承诺自动判断、补访负责人”的决定。**失败信号**：材料无法授权、只有态度没有行为、所有解释都缺少反例；出现时不扩大结论。

沿用问题卡，写一段可以直接练习的访谈。先确认同意范围，再从最近一次任务开始，不先演示产品。

| 提问 | 想了解什么 | 避免怎样引导 |
| --- | --- | --- |
| 最近一次需要查制度是什么时候？ | 具体任务是否发生 | 不先问是否喜欢AI |
| 当时先打开哪里，之后找了谁？ | 实际步骤与参与者 | 不暗示共享目录很差 |
| 怎么确认这份是当时有效版本？ | 判定依据 | 不提示应该显示日期 |
| 哪一步花时间，最后怎样完成？ | 阻碍与替代 | 不将等待都算成搜索耗时 |
| 若当时不解决，会发生什么？ | 问题后果 | 不替用户夸大损失 |

虚构 R01 原话：“我主要在等负责人确认。”O01 观察：目录中两版文件名相近。H01 解释：显示日期可能减少部分确认。反例 R02：“即使日期明确，负责人也要求确认。”下一步就要访谈负责人，而不是直接宣称日期展示能省20分钟。

整理时让每条结论链接 R01、O01 等材料 ID；这些是证据索引，不是额外学习进度。

### 4.1 看三条材料怎样改变最初结论

在R01、R02之外，补一条熟手记录R03：“熟悉流程后我用目录很快，新人更容易找错。”这些材料既支持版本问题，也限制了“全员节省20分钟”的推断。

先归纳共同事实：查证不仅是找文本，还涉及适用性与责任。再分群：新人可能需要检索与定位，熟练人员可能需要快速确认，负责人关心更新责任。不要把三条不同任务平均成一个“用户画像”。

下一轮提纲围绕分歧：“最近一次必须找人确认，是日期不清、项目不同，还是流程要求？”可以请求观察经授权的操作，不能要求对方提供无权分享的合同。记录匿名任务细节与同意范围。

访谈结束后写一条决定：“先测试新人查证路径；暂不承诺自动适用判断；补访负责人。”如果研究后产品规格完全没变，检查是否真的允许证据反驳自己。

### 4.2 检查一条结论是否追溯得到材料

下面的程序检查教学证据表的三件事：材料ID不重复、每个引用存在、结论至少保留了一条反例。它检查的是**记录结构**，不自动判断原话是否可信。

```python
# track-example: P02
materials = {
    "R01": {"kind": "quote", "text": "我主要在等负责人确认。"},
    "R02": {"kind": "quote", "text": "日期明确后负责人仍要求确认。"},
    "O01": {"kind": "observation", "text": "两版文件名相近。"},
}
assert len(materials) == 3
conclusion = {
    "claim": "日期提示可能帮助新人，但未必消除确认。",
    "support": ["R01", "O01"],
    "counter": ["R02"],
    "unknown": "负责人的确认要求是否属于固定流程。",
}
references = conclusion["support"] + conclusion["counter"]
assert all(item in materials for item in references)
assert materials[conclusion["counter"][0]]["kind"] == "quote"
assert conclusion["unknown"]
```

预期结果：断言全部通过，因为支持与反例都能回到具体材料。若删除 R02 或把它改成不存在的 ID，引用检查会失败；若只换成一个无关但存在的 ID，结构仍可通过。程序只检查引用与字段形状，不判断反例是否相关，因此不能替代研究者主动寻找矛盾。

推导：原话提供参与者的视角，观察提供独立行为，解释把两者连接起来。只有解释被记录为“待验证”，下一轮才知道该问谁、看什么。

## 5. 分层练习

1. **基础**：设计五条按时间顺序排列的问题，覆盖任务发生、步骤、判定依据、阻碍和后果，并逐条去掉诱导词。
2. **改造**：与同伴模拟三人研究，整理至少三条原话、两条观察、两种解释和一条反例，保留材料ID。
3. **独立**：根据证据改写一条产品决定；再设想一条相反材料，说明你会保留、缩小还是停止原方案。

无法接触真实用户时可用虚构材料训练，但交付物必须写明“模拟研究，真实需求待验证”。

## 6. 自测与参考推导

<details><summary>完成独立任务后查看诊断</summary>

- 若所有记录都支持最初想法，检查是否一直问“是不是”。
- 若把用户建议直接放入需求列表，尚未理解背后任务。
- 若没有反例，不必编造，应写当前未找到并安排进一步调查。
- 若引用原话时改写了关键词，quote 已变成研究者的转述。

</details>

**自问：** 为什么三条访谈也能有用，却不能证明“大多数人”？

**参考推导：** 小样本可以揭示具体机制、角色冲突和反例，帮助改进下一轮验证；它没有概率抽样和足够精度，不能估计总体比例。样本判断要求把“发现了什么”和“能推广到哪里”分开。

## 7. 项目交付与验收

更新同一问题卡，附一页证据表。下一章根据已观察的任务选择目标人群与替代方案。

| 操作 | 预期结果 | 应保留的证据 |
| --- | --- | --- |
| 确认研究同意 | 知道可记录、可引用和可保存的范围 | 同意说明与脱敏规则 |
| 完成一次任务访谈 | 得到具体步骤而非产品赞美 | 原话、时间线、参与者 |
| 观察或测试 | 叙述与行为可比较 | 动作、停顿、求助与任务结果 |
| 整理证据表 | 每条结论可追溯且保留反例 | R/O/H编号、支持与矛盾 |
| 写产品决定 | 研究改变下一步 | 继续、缩小、补访或停止 |

## 8. 迁移与阅读

### 8.1 一页知识地图

**本章主问题：** 怎样避免只听到自己希望听到的答案？

**一条主线：**

```text
最近一次真实任务 → 原话、观察、解释分层 → 反例检查 → 一条被改写的产品决定
```

**三个关键词：** 行为重建、证据分层、样本判断。先记用户做过什么，再说这些材料能支持到哪一步。

**最容易错：**

- 问“你会用AI吗”，把预测当行为。
- 把R01直接读成“日期展示能省20分钟”，跳过R02。
- 只采访抱怨者，没有顺利案例和批准者。
- 研究做完，规格一个字没变。

**与前后章：** 第1章给出待验证假设；本章的证据，第3章用来选择目标人群与要比较的替代方案。

**学完应能：**

- 设计五条不诱导的提纲。
- 整理带R/O/H编号的证据表并保留反例。
- 写出研究支持什么、不支持什么，以及下一份有判别力的证据。

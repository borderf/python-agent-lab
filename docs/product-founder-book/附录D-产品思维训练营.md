# 产品思维训练营：从问题到证据的六轮练习

[本书目录](教材目录.md) · [工作簿](附录A-工作簿与模板.md)

每轮可分数次完成，先交答案再看参考。使用同一个DocPilot或ProcureAgent项目累计练习。访谈与数字若为模拟须标明，模拟不能证明真实采用或付费。

## 第1轮：把功能愿望改成问题（第1–2章）

题目：“做一个AI采购助手，自动生成报告。”请先写用户、最近任务、障碍、替代和后果；列出三条尚未确认假设及五个访谈问题。

参考推导：使用者可能是采购专员，购买者可能是部门负责人。问题不能凭想象确认；追问最近一次报告、材料从哪里来、哪步返工、谁决策及结果。避免“你是不是需要AI”。若主要耗时是等资料，自动生成报告未必优先。

交付：一页问题卡、访谈提纲、匿名记录或明确模拟、至少一个反例。评分：能否将原话、观察和解释区分，并提出会推翻想法的证据？

## 第2轮：比较机会和替代（第3章）

题目：A是制度来源查询，B是缺件追踪。客户有共享目录与表格，两人维护，资料权限尚未确认。比较问题频率、影响、替代优势、触达、采用和交付门槛。

参考推导：不能仅凭“B技术更容易”或“A市场更大”决定。若资料访问未获允许，两项都存在关键阻塞；先确认授权。为每项给支持与反例，再选一个最便宜的验证。客户画像应说明适配与排除条件。

交付：替代比较、定位、最危险假设和下一步。评分：排序依据是否可复查，是否将未知偷偷写为事实？

## 第3轮：两周范围与方案取舍（第4章）

题目：搜索、聊天、历史记录、报告导出和自动提交中，本轮只能实现一个完整任务。目标是验证新人能否找到依据。

参考推导：搜索和来源定位可构成第一路径；自动提交引入批准和幂等，暂时不帮助核心验证。若导出是进入真实流程的必要条件，需重新比较范围。取舍依任务与证据，不依固定功能排名。

交付：产品规格、范围与不做、验收和异常。再把时间减半，写怎样降低验证成本，哪些结论因此不能获得。

## 第4轮：设计并观察真实操作（第5–6章）

题目：画查询页、结果页以及加载、空、失败、无权限状态。给测试者一个情境，让他找出依据；观察而不教点击。

参考推导：若找不到来源按钮，先检查信息组织和文案；若看到了却不信任，可能缺版本和上下文；若没有权限，不能靠界面绕过。问题不同，修法不同。

交付：任务流、线框、状态表、测试脚本、观察与一轮改版。没有真实测试者可先自测，但不得写“用户验证通过”。实现步骤见[全栈手册](附录E-全栈产品交付实操.md)。

## 第5轮：指标、实验与坏消息（第7–9章）

题目：A方案40/100完成，B方案45/100完成，但B出现更多需返工报告。你会发布B吗？

参考推导：观察差5个百分点，相对差12.5%，仍需分析分组、样本、不确定性及错误后果。先按预设护栏判断，再调查错误。小样本探索不能声称已证明稳定提升。指标可包含总耗时、任务完成、关键错误和成本，不能只看生成速度。

交付：指标字典、实验计划、结果与继续/修改/停止决定。记录哪条证据改变了原先判断，防止事后挑选有利结果。

## 第6轮：上线、采用和经营（第10–14章）

题目：邀请100个目标用户，20人试用，2人完成任务；有人表示喜欢，但购买者拒绝。每客户收入2000，可变成本1100，支持成本可能翻倍。

参考推导：先检查事件与口径，再看人群、入门和任务失败；扩大流量未必解决问题。购买者拒绝需调查价值、预算、采购和风险。贡献900不是净利润，支持增长会改变交付模式。写下一轮有限成本验证，而非统一降价或加功能。

交付：上线门槛、落地页草稿、渠道实验、试点及成本情景，参考[上线推广手册](附录F-上线发布与推广实验.md)。

## 把六轮练习放到自己的第一个试点

先选能接触的人群。采购、研发查规范、售后查手册均可。下面用研发新人查发布规范演示如何把访谈变成规格，再把规格交给工程和推广。表中的转折是假设情境，做自己的项目时用真实观察替换。

| 时间点 | 实际动作 | 示例中的决定，以及什么会改变它 |
| --- | --- | --- |
| 写第一行产品代码前 | 找最近亲手查过规范的人，请他还原上次从哪里找、怎么确认版本、谁最后拍板。记录任务频率、现用替代和卡住的位置 | 若他能很快找到文档，却要等人确认版本，首版应突出适用日期和来源负责人。若瓶颈是等待审批，回到问题选择 |
| 只做一个可用任务 | 写一条验收情景：给定环境与发布日期，新人能找到适用规范并指出出处。画出搜索、查证、没有依据时找谁三个状态 | 先用纸面或本地只读界面验证任务，再决定是否需要问答生成。把“引用能打开”同时交给前端和检索测试 |
| 让人操作时 | 给两条难度相近的陌生任务，分别使用旧流程与原型，交替先后顺序。记录是否独立完成、总耗时、错用版本、求助点 | 若耗时下降但多次错用旧版，先修索引更新或版本标识。若来源正确却找不到入口，优先改界面。小样本保留逐人记录 |
| 首次使用之后 | 在约定窗口回访：是否遇到第二次真实任务、用了哪种方法、为何回来或放弃。向使用者、资料维护者、预算负责人分别核对成本和约束 | 没有第二次任务与有任务却放弃是两种结果。前者提示频率假设待验，后者需要定位价值、信任或接入障碍 |
| 决定下一轮投入 | 把反馈变成一个小改动，注明负责人、验证窗口、可推翻条件。若现有工具已能解决问题，记录停止理由 | 例如只改善版本切换，在相同题集重跑并让用户完成新任务；用错版本仍然出现时暂缓扩大试点 |

**第一次访谈可以照着问。** “最近一次你必须确认一条规范是什么时候？请从收到任务开始讲。”“你当时还开了哪些工具？最后凭什么认定找对了？”“这件事出错会返工哪一步？能举最近的例子吗？”结束时询问能否在下一次同类任务观察过程，并约定资料使用范围。整理时保留一条与你的解释相冲突的记录。

**把决定写成一行可追溯的记录。** 例如“观察到两人打开过期文档 → 猜测缺少适用日期 → 本轮添加版本与生效日 → 保留旧版查询回归题 → 下次观察能否独立找对”。这条记录可以同时改变 DocPilot 的数据模型、界面和验收题。若只有模拟访谈，先练提问与任务脚本；真实采用、续用、购买三栏留到发生时填写。进入试点后接[推广与经营实操](附录F-上线发布与推广实验.md#一个小规模试点怎样记账和决策)。

## 每轮复盘与最终评价

```text
原假设与依据：
本轮实际做了什么：
观察、原始证据和反例：
解释及其他可能原因：
改变的决定与未改变的理由：
下一步最小验证、投入与停止条件：
```

按问题清晰、证据质量、方案取舍、用户任务、结论边界和迭代六项评分：0未做，1能解释，2独立应用，3能用反例修改并迁移。定义或术语背得熟不能替代任务结果；真实证据与模拟分开评价。

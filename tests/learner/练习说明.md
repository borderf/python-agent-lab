## DocPilot 契约

- `normalize_document(raw)`：返回新字典，必含 source_id、tenant_id、version、title、text、valid_from、valid_to，拒绝其他字段。前五项为去掉首尾空白的非空文本；日期为 YYYY-MM-DD，valid_to 可为空，区间为左闭右开。输入不变。偏移针对规范化后的文本，不代表原文件字节或 PDF 页码。
- `build_index(documents, chunk_chars=120)`：返回片段列表，保留上述元数据，text 为切块内容；新增 chunk_id、start、end。按码点等长不重叠切块是第一版教学策略。稳定身份至少区分租户、来源、版本与起点；同一来源版本重复入库不加倍，内容不同报 ValueError。输入不变，布尔值不能充当切块长度。
- `search(index, question, *, tenant_id, as_of, limit=3)`：先过滤可信租户与生效日期，再按问题和标题加片段的公共字符二元组数量降序，分数为0不返回；并列按 source_id、version、start。词项生成先转小写并移除空白，再取相邻两字符。limit 为1–10的整数，拒绝 bool。返回独立数据，不能改坏索引。
- `answer(index, question, *, tenant_id, as_of, model)`：检索后调用 `model(question, evidence)`。无证据时不调用，返回非空说明、空 citations、needs_review=True。模型候选仅允许 answer、citations、needs_review；answer 非空文本，needs_review 是 bool。每项引用仅含 chunk_id 与非空逐字 quote，必须属于本次证据，不得重复。无引用不能标为无需复核。输出引用补充 source_id、version、start、end，保留原 chunk_id 与 quote。

模型回调得到独立证据副本，不得篡改校验依据。模型异常继续交由调用层处理，不能静默换替身或伪装无结果。本地回调不是供应商 SDK 协议；接真实模型时在外层适配，并记录实际模型标识。

**重要边界：** 本套检查覆盖程序契约与引用位置，不证明语义支持、真实检索质量、认证、HTTP 入口、并发吞吐或生产安全。第22章负责逐题语义评分，第15–17章负责服务与部署，项目规格负责完整产品能力。

## 审批与幂等契约

新建 `learner_approval.py`，参考[起始签名](../../practice/learning_projects/approval_starter.py)。

```powershell
uv run --frozen python -m pytest tests/learner/contract_approval.py --learner-module learner_approval -q
```

`payload_hash(payload)` 接收 JSON 字典，用 UTF-8、键排序、无额外空白的规范 JSON 计算 SHA-256，拒绝非有限数。`submit(db_path, *, tenant_id, action_id, payload, approved_hash, fail_after_commit=False)` 返回非空回执文本。租户与动作键非空；摘要不符抛 PermissionError；同键同载荷返回原回执，同键不同载荷抛 ValueError。

效果执行点使用 SQLite 表 `effects(tenant_id, action_id, payload_hash, receipt)`，主键为 tenant_id 与 action_id。效果与回执同事务保存，不能只在内存去重。`fail_after_commit=True` 在提交后抛出包含 `after commit` 的 RuntimeError，用于模拟回执丢失；恢复后仍只有一条效果。检查会换进程读取原数据库。

本练习把 approved_hash 当作来自可信批准记录的输入，不实现批准签发、身份认证和失效查询。接真实服务时需要补这些边界。SQLite 是模拟接收方的实际效果，不承诺任意远端都支持同样语义。

## 工具循环契约（Agent）

新建 `learner_agent.py`，参考[起始签名](../../practice/learning_projects/agent_starter.py)。第24章 4.2 给出 12 步的累计实现与定位。

```powershell
uv run --frozen python -m pytest tests/learner/contract_agent.py --learner-module learner_agent --through-step 1 -q
```

函数与边界：

- `tool_specs()`：两个只读工具，参数分别为 `user` 与 `order_id`；租户不出现在参数里。
- `execute_tool(name, arguments, *, tenant_id, repo)`：名称、参数集合与文本类型先校验，再调用 `repo.all()`；未知工具、额外参数（含伪造 tenant_id）、空文本都抛 ValueError，仓储调用次数为 0。返回值只允许白名单字段：`get_paid_total` 先对本次查询涉及的全部记录校验状态与金额，再筛选 `status == "paid"` 汇总（bool、float、字符串、负数、未知状态都拒绝），`get_order` 返回 `{id, user, amount_cents, status}`，tenant_id、access_token 等内部字段不进入模型。
- `parse_decision(raw)`：只接受两种精确结构：`{"type","call_id","name","arguments"}` 与 `{"type","content"}`；字段多余、空 call_id、空 content、未知工具都拒绝。它不执行任何业务。
- `run(question, *, model, tenant_id, repo, max_steps=4)`：每轮调用 `model(deepcopy(messages))`，把同一 call_id 的结果追加为 tool 消息；返回 `answer`、`steps`（模型调用次数）、`tool_calls`（实际执行次数）与 `trace`。未到 final 且预算耗尽抛 RuntimeError；重复 call_id 抛 ValueError。

模型回调只拿到问题与工具结果，拿不到凭据或可改写租户的参数。这里的 repo、模型和审批都是本机替身；真实供应商协议、流式参数分片、持久审批与跨进程恢复分别在第18、25、26章和审批契约中验证。

常见失败：第2–5步先调用仓储再校验参数或把内部字段原样返回；第8–9步把 tool 消息放到下一轮才追加；第10步重复 call_id；第11步坏决策先执行再报错。先定位失败的步骤，再对照 4.2 的累计代码。

## 把自己的核心接到持久服务：6步

复制[持久化起始签名](../../practice/learning_projects/persistence_starter.py)为 `learner_persistence.py`，从第1步开始：

```powershell
uv run --frozen python -m pytest tests/learner/contract_persistence.py --learner-module learner_persistence --through-step 1 -q
```

逐步增加至6：规范化后写入 → 新增立即可查 → 重复与冲突 → 租户和日期 → 换进程读取 → 回答仍调用注入的核心。`put_document(db_path, raw, *, core)` 返回新建bool；相同规范化内容返回False，版本内容冲突抛ValueError。`search(..., core)` 与 `answer(..., core, model)` 保留核心的查询参数和输出契约。数据库是持久原文事实，不能改成进程内全局列表。

验收器注入已知核心，检查适配层有没有绕过它；这**不代表你的核心已通过20步**。组合验收还需把自己的核心与适配器接入[HTTP工厂](../../practice/learning_projects/service.py)：设置 `LEARNER_MODULE=learner_docpilot`、`LEARNER_PERSISTENCE_MODULE=learner_persistence` 后启动原工厂。详细命令见[项目交付](../../docs/project-practice/从实验到项目交付.md#把20步核心带到持久服务)。HTTP上传不接受tenant_id，身份由教学令牌注入。当前没有来源打开路由、反馈、分页和持久向量索引，按需向D2扩展。

## 自己实现任务恢复：6步

复制[恢复起始签名](../../practice/learning_projects/resume_starter.py)为 `learner_resume.py`。本练习继续使用上一节审批练习的SQLite接收方，但新增你自己的任务状态机，不是只测接收方幂等。

```powershell
uv run --frozen python -m pytest tests/learner/contract_resume.py --learner-module learner_resume --through-step 1 -q
```

逐步增加至6：保存/读取 → 错租户与未批准拒绝 → 改载荷使批准失效 → 重放只有一次效果 → 回执丢失时冻结载荷 → 新进程对账完成。函数参数见起始签名；`prepare/load/change_payload/approve` 返回含payload、version、payload_hash、approved_hash、status、receipt的独立字典，`resume` 返回回执。新任务version=1、waiting_approval；未知或非本租户任务抛LookupError；过期版本、未批准或摘要不符抛PermissionError。变更仅允许waiting_approval/approved，版本加1并清批准；executing/completed时抛ValueError。重复创建同租户同任务抛ValueError，不覆盖原状态。

`approve` 只可由可信批准边界调用，须核对展示时的expected_version与expected_hash。resume从approved进入executing并冻结载荷，按稳定任务/版本动作键调用接收方；`fail_after_commit=True`模拟远端已提交、本地未保存回执，随后恢复不得换键。最终状态completed且receipt与接收方一致。效果表沿用审批契约的schema，便于实际核对，不只检查状态字符串。

这里不是完整LangGraph训练，也不提供登录、审批权限签发、审计历史、撤销、调度器或不支持幂等的真实支付保证。先掌握这条因果链，再按第25章迁移同样行为到框架；两者必须使用相同失败案例。

## 如何阅读失败

先找失败的步骤和断言，再写当前输入、预期、实际与首个分叉点。常见原因：第7步先截断再过滤；第8步把区间右端当包含；第12步暴露索引内对象；第16步接受模型编造来源；第19步回调修改可信证据；恢复检查只把任务标成完成却未核对效果。

想确认环境和验收器可用，可用参考模块运行相同命令：

```powershell
uv run --frozen python -m pytest tests/learner/contract_docpilot.py --learner-module practice.learning_projects.docpilot_reference -q
uv run --frozen python -m pytest tests/learner/contract_approval.py --learner-module practice.learning_projects.approval_reference -q
```

这两次的结果只记录为“参考基线通过”。你的完成证据必须保留自己模块名、命令、结果与一组新输入。参考实现用于卡住后的局部对照，先写推理再查看。

## 从契约检查继续做逐题评测

```powershell
uv run --frozen python -m practice.learning_projects.evaluate --implementation learner_docpilot --split development --output .learning-labs/evaluation-dev.jsonl
uv run --frozen python -m practice.learning_projects.evaluate --implementation learner_docpilot --split holdout --output .learning-labs/evaluation-holdout.jsonl
```

默认模型明确标为 `fixture-quote`，只用于检查证据链。输出逐题来源、引用、模型模式、数据摘要、耗时和错误；有答案题计算来源Recall@3与倒数排名，无依据题单列，失败不从总数消失。基线会漏掉示范题中的同义问法，这正是关键词方法的限制，不应靠把正确来源写进模型输入刷高分。

数据文件是一个很小的公开机制题集；其中holdout仅演示分组，不能声称是真实未知测试。自己的项目应另行标注足够任务、冻结未参与调参的题，并人工核对语义支持。默认脚本不自动评估事实正确性。

接真实模型时用 `--model-module your_adapter --model-id 实际模型及版本`，适配模块暴露 `answer(question, evidence)` 并返回相同候选结构；缺少标识会明确报错，不悄悄回退替身。SDK协议、流式完成、工具参数分片、用量与取消需要在适配层另外验证。
